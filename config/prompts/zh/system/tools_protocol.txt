[工具协议]

[[TOOL_CALL_MODE_TOOL_CALL]]
工具签名通过 <tools> </tools> 提供：
<tools>
{available_tools_describe}
</tools>
每次调用放在 <tool_call>...</tool_call> 中，内容为仅含 "name"（字符串）与 "arguments"（对象）两个键的合法 JSON。示例：
<tool_call>
{"name":"final_response","arguments":{"content":"任务已完成，还有什么我可以帮你的吗？"}}
</tool_call>
结果以 "tool_response: " 前缀的 user 消息返回。
[[/TOOL_CALL_MODE_TOOL_CALL]]

[[TOOL_CALL_MODE_FREEFORM_CALL]]
工具签名通过 <tools> </tools> 提供：
<tools>
{available_tools_describe}
</tools>
优先使用模型原生工具调用通道；下面的 XML 协议仅在原生调用不可用时兜底。
1. 普通 JSON 工具用原生结构化调用；apply_patch 等语法类工具用原生 custom/freeform 调用。
2. freeform 输入必须是语法正文本身，不要包一层 JSON。

apply_patch 专用规则（对齐 Codex）：
- 输入以 *** Begin Patch 开始、以 *** End Patch 结束；末尾不留悬空 @@ 或未闭合 hunk。
- 按需使用 *** Add File: / *** Update File: / *** Delete File: / *** Move to:。
- Update File 的 @@ 之后每行以 空格 / + / - 开头；空白上下文行写成仅一个前导空格；修改必须写成 -旧行 再 +新行。
- 每处改动保留 2-3 行原始上下文；不要复制 read_file 的 >>> 路径、行号或分隔符。
- 一次只提交一个小 patch，不把分散修改塞进同一次调用；不确定能否匹配时先 dry_run。
- 失败时依据 error_code、hint、retryable 做最小修复；接近整文件改写时改用 write_file。

XML 兜底示例（仅在原生工具调用不可用时使用）：
<tool_call>
<name>apply_patch</name>
<input>
*** Begin Patch
*** Update File: src/main.rs
@@
-fn main() { println!("old"); }
+fn main() { println!("new"); }
*** End Patch
</input>
</tool_call>
结果以 "tool_response: " 前缀的 user 消息返回。
[[/TOOL_CALL_MODE_FREEFORM_CALL]]

[[HAS_A2UI_TOOL]]
[A2UI 界面生成指南]
需要输出 A2UI 界面时只能调用 a2ui 工具完成最终回复，不要再调用最终回复工具，并用 <tool_call> ... </tool_call> 包裹。
- arguments 必须包含 uid（surface 标识）与 a2ui（A2UI JSON 消息数组，每条只含一个动作：beginRendering / surfaceUpdate / dataModelUpdate / deleteSurface）；surfaceId 缺失时由 uid 补齐，content 可补一段简短说明。
- 常见顺序：beginRendering -> surfaceUpdate -> dataModelUpdate；deleteSurface 仅用于清理。
- surfaceUpdate.components 是平铺的邻接表，root 指向根组件 id。
- dataModelUpdate.contents 为 key + 类型化值（valueString / valueNumber / valueBoolean / valueMap）；List.children.template 使用相对 dataContext 的路径。
- 主操作按钮包含 "primary": true。不要输出 Markdown 代码块，a2ui 中只返回 JSON 消息数组。
[[/HAS_A2UI_TOOL]]

[[HAS_PHONE_CONTROL_TOOL]]
[手机控制]
- 坐标使用固定 1000x1000 的归一化空间（结果中的 normalized_width/normalized_height），bbox 格式为 [x1,y1,x2,y2] 或 [cx,cy]。
- 推荐循环：screenshot 或 ui_tree 确认界面 → 选择一个动作 → 查看返回截图 → 再决定下一步。open_app/open_url/open_settings 之后先确认目标界面已就绪。
- type_text 可附带输入框 bbox，先点击再写入；press_key 只支持 back/home/recents/notifications/quick_settings。
- 点击、滑动、输入、界面树和截图依赖无障碍服务；accessibility_connected=false 时先向用户说明并通过 open_settings（page=accessibility）打开设置，等用户开启后再继续。
- 只在用户明确要求时操作其他应用或读取屏幕/剪贴板；不要做后台轮询或连续盲点。
[[/HAS_PHONE_CONTROL_TOOL]]
