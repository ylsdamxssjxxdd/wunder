# 媒体、字幕与音频

只在处理用户提供的音视频、字幕、旁白或音频驱动效果时读取本文件。

## 先探测，再排时间线

- 先确认媒体的时长、尺寸、帧率、音轨与编码，再决定 composition 的时长和裁切策略；不要凭文件名或播放器显示猜测。
- 项目已有 Mediabunny 时可用其 `Input` 和 `FilePathSource` 读取时长与视频 track；完成后调用 `dispose()` 释放文件句柄。没有相应依赖时，优先使用可用的 `ffprobe` 做只读探测。
- 原始素材保持不变，派生的音频、关键帧、转码文件放在明确的派生目录；给出它们和来源的关联，避免覆盖用户文件。

## 字幕

- 字幕在项目内保存为 JSON，时间单位使用毫秒，至少包含 `text`、`startMs`、`endMs`、`timestampMs`、`confidence`。SRT/VTT 先解析、校验时序，再转为该结构；相邻字幕不得产生无法解释的重叠或倒序。
- 字幕文字要短、对比度高，并在视频安全区内。逐字、逐词动画只在确实改善可读性时使用，不能掩盖转录不准或时轴错误。
- 用户未提供文字或可用转写能力时，不能伪造完整逐字字幕；可交付字幕占位结构和清楚的待补输入。

## 旁白与音乐

- 旁白先确定脚本、语言、语速、停顿和时长，再让镜头围绕音轨排布。若合成语音能力不可用，保留可替换音轨槽位和时长假设。
- 背景音乐、音效和网络下载素材必须有明确授权或用户提供。不要把来源不明的媒体作为默认资源。
- 使用 Remotion 的 `<Audio>` 驱动音轨，并将淡入、淡出、音量和裁切写在时间线附近；不要依赖播放器的全局音量。

## FFmpeg 边界

FFmpeg 适合确定性的探测、抽音频、转码、截取、静音检测与简单拼接。把复杂的场景布局、文字动画、字幕可编辑性和帧同步留给 Remotion。运行 FFmpeg 前先检查可执行文件与输入路径，输出到新文件；失败时保留简洁错误和可复现命令。
