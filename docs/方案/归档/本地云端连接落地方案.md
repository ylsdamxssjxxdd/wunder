# 本地云端连接落地方案

> 适用范围：蜂窝（desktop）、舵机（cli）登录舰体（server）云端账户，使用云端开放模型、共用额度与基础设置，本地请求在云端留痕。
> 对齐基线：《总体设计.md》《本地易用重构方案.md》《云端易用重构方案.md》《线程日志重构方案.md》《API文档.md》。
> 前提：三端共享 `wunder-runtime` 引擎与 `wunder-core` 契约；蜂窝与舵机默认本地 SQLite、可离线启动；舰体为唯一账号与额度权威。
> 落地状态：已实施（2026-10-08）。T0–T7 全部完成：契约与配置（wunder-core CloudConfig/`expose`/CloudStore）、三表存储双实现、服务端 cloud API 与调用代理（计费+排队+记账）、日志接收与舰桥「云端接入」三页、本地引擎云渠道（CloudService/合成模型/排队重试/上报器）、桌面设置页云端账户卡与 façade、舵机 cloud 命令组与 TUI。产物路径见「附：关键产物路径」。T8 端到端联调（真实服务器+双端）待部署环境执行。掉线自愈已按大厂标准补齐（2026-10-08）：服务端刷新令牌轮换 + 复用检测连坐 + 同作用域重登踢族（`POST /wunder/auth/refresh`，access 7 天 / refresh 30 天）；引擎单飞静默续期（401 自动换发并重试原请求）、连接状态机（online/reconnecting/expired/logged_out）、5 分钟空批量心跳、72h 主动续期与启动自愈探测；蜂窝/舵机状态显性化（四态徽标、重试倒计时、重连中黄标）。

## 一、背景与目标

### 1.1 现状

- 蜂窝与舵机是完全本地形态：本地 SQLite、本地模型配置（`config/wunder.yaml` → `llm.models`）、本地单用户（desktop/cli 自建本地管理员身份）。《API文档》§4.0 明确「蜂窝现仅保留本地模式，不再提供服务端连接切换与端云协同入口」。
- 舰体已有完整账号体系：`/wunder/auth/login` 签发 Bearer `user_token`（`wund_<uuid>`，TTL 7 天，`session_scope` 语义，同 scope 新登录顶旧登录）；账户额度 `quota_balance/quota_used_total/daily_quota_grant`，普通用户每日 1000 次，**每次真实模型请求准入时原子扣 1**（`consume_user_quota` 与扣费同事务，管理员豁免）；并发与排队为全局 `server.max_active_sessions`（默认 300）+ 持久化 `agent_tasks` 队列，**没有每用户并发配置**。
- 舰体模型由管理侧维护（`/wunder/admin/llm`），用户侧 `GET /wunder/agents/models` 只选不建；`provider/base_url/api_key` 只存服务端；模型条目有 `enable` 字段但用户模型列表不过滤它——**当前没有生效的「开放给用户」开关**（本方案新增 `expose`）。
- 云端线程日志已收敛为 ThreadLog 六表（`thread_logs/thread_turns/thread_items/thread_item_blocks/thread_log_changes/thread_log_metrics`），`change_seq` 为唯一 durable 游标。

### 1.2 目标

1. **登录云端**：蜂窝（Slint 设置页）与舵机（`cloud` 命令组）登录同一账号体系；**登录时必须指定舰体服务地址（`http://ip:port`）**。
2. **使用云端开放模型**：登录后云端开放的模型直接出现在本地模型列表，调用经舰体代理转发，本地不接触上游真实密钥。
3. **额度共享**：每次云端模型调用在舰体扣减额度（与网页端同一账户、同一扣费单位：1 次/调用）；余额不足明确报错并在本地展示额度状态。
4. **并发排队**：舰体按用户限制云端调用并发，达到上限进入排队，本地显示排队位置并自动重试接入。
5. **云端留痕**：本地发起的请求在云端有记录——(a) 每次云端调用留记账记录；(b) 本地运行日志（分级、脱敏）批量上报到云端设备日志命名空间；(c) 网页端既有线程日志体系不受影响。
6. **端云独立**：本地线程与网页线程互不可见；共享的只有账号身份、额度账户与基础偏好白名单。

### 1.3 设计原则

- **复用引擎，不加第二套执行语义**：模型调用继续走本地 `LlmClient`（OpenAI 兼容路径），云模型只是 provider=`wunder_cloud`、base_url 指向舰体的普通模型条目。
- **密钥不出舰体**：上游 `api_key` 永不下发本地；本地只持有会话 token。
- **计费与网页端同源**：复用 `consume_user_quota` 与 `UserQuotaStatus`，同一 `user_id` 天然共享余额。
- **登录互不干扰**：本地登录使用独立 `session_scope`（`local_desktop`/`local_cli`），与网页端 default scope 互不顶下线；登出只失效本地 scope。
- **有界、限量、可离线**：所有队列/缓冲/列表有硬上限；未登录时本地功能完整可用（纯本地模型），云端模型置灰。
- **留痕隔离**：云端设备日志写入独立命名空间，不触碰 `thread_logs/monitor` 表，蜂巢用户端零感知。

### 1.4 非目标（本期不做）

- 本地线程/对话内容完整镜像到云端（仅可选的关键事件摘要，见 §4.5.4 二期）。
- 本地智能体、知识库、记忆与云端双向同步。
- 网页端调用本地模型（端云反向代理）。
- Token 计费（当前额度单位沿用「1 次/模型调用」，与网页端一致；改 token 计费是另一专题）。
- 云模型之外的云能力（云端工作区、云端定时任务）。

## 二、核心范式转变

| 维度 | 现状（旧） | 目标（新） |
|---|---|---|
| 身份 | 本地自建单用户（desktop/cli 各自 admin） | 本地用户 + 可选云端账号绑定；本地数据仍归本地身份 |
| 模型来源 | 仅本地 `config/wunder.yaml` 手配 | 本地模型 + 云端开放模型合并展示（云模型条目由登录态合成） |
| 模型调用 | 直连上游 provider | 云模型经舰体代理（计费+并发排队+留痕）；本地模型直连不变 |
| 额度 | 本地不参与额度 | 云模型调用扣共享账户额度；本地展示余额 |
| 日志 | 仅本地 SQLite/tracing | 本地为主 + 分级上报云端设备日志（独立命名空间） |
| 设置 | 仅本地 settings | 基础偏好白名单随账号共享 |

## 三、数据模型与接口契约（冻结）

### 3.1 本地配置

本地会话状态独立文件（桌面 `<temp_root>/config/cloud.session.json`，默认 `~/.wunder/config/`；CLI `~/.wunder/cloud.json`；与 `desktop.settings.json` 分离，便于收紧权限并从诊断导出中排除）：

```jsonc
// cloud.session.json（仅登录后存在；写入时置 0600/Windows 用户级 ACL）
{
  "server": "http://192.168.0.10:8000",     // 登录时指定的舰体地址（ip:port）
  "user_id": "alice",
  "username": "alice",
  "scope": "local_desktop",                 // 或 local_cli
  "token": "wund_<uuid>",                   // 会话令牌（服务端 TTL 7 天）
  "device_id": "<uuid>",                    // 服务端签发的设备号
  "device_name": "pc-01",                   // 展示用设备名
  "client": "desktop",                      // desktop | cli
  "logged_in_at": 1764000000.0,
  "account": {                              // 最近一次 /wunder/cloud/account 快照
    "quota": { "balance": 980, "granted_total": 1000, "used_total": 20,
               "daily_grant": 1000, "last_grant_date": "2026-01-15" },
    "max_concurrent_calls": 2,
    "preferences_synced_at": 1764000001.0
  },
  "log_report": { "enabled": true, "level": "warn", "last_synced_seq": 0 }
}
```

服务端配置新增 `cloud` 段（`config/wunder.yaml`，舰桥可改）：

```yaml
cloud:
  enabled: true
  max_concurrent_calls_per_user: 2        # 每用户云端模型调用并发上限
  queue:
    retry_after_ms: 3000                  # 排队 429 建议重试间隔
    max_wait_s: 300                       # 单次排队最长等待（客户端放弃）
    max_queue_per_user: 32                # 每用户排队深度上限（超出直接拒绝）
  log_retention_days: 30                  # 设备日志保留天数（0=不过期）
  expose_models: []                       # 空 = 开放全部 expose=true 的 llm 模型；非空 = 白名单
```

`LlmModelConfig`（wunder-core config.rs）新增一个字段：

```yaml
llm:
  models:
    glm-5:
      provider: openai_compatible
      base_url: https://example.test/v1
      api_key: secret
      model: glm-5
      expose: true        # 新增：true 才出现在 /wunder/cloud/v1/models 并对本地客户端开放；缺省 false
```

### 3.2 云端存储表（新增三张，SQLite/PostgreSQL 双实现，纳入 StorageBackend）

`cloud_devices`：设备注册表

| 字段 | 类型 | 说明 |
|---|---|---|
| device_id | TEXT PK | 服务端签发 uuid |
| user_id | TEXT | 归属账号（多设备可同账号） |
| client | TEXT | desktop / cli |
| name | TEXT | 设备展示名 |
| os / arch / app_version | TEXT | 诊断信息 |
| last_seen_at / created_at | REAL | 心跳时间戳 |
| revoked | INTEGER | 吊销标记 |

`cloud_call_records`：云端调用记账（本地请求在云端的第一类记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| call_id | TEXT PK | 服务端 uuid，经 `x-wunder-request-id` 回传本地 |
| device_id / user_id | TEXT | 归属 |
| client | TEXT | desktop / cli |
| local_session_id | TEXT | 本地线程 id（仅关联用，不创建云端线程） |
| model | TEXT | 云端模型配置键 |
| provider | TEXT | 上游 provider（归一化名） |
| status | TEXT | admitted / upstream_error / quota_blocked / queue_timeout / ok |
| quota_consumed | INTEGER | 0/1（准入即扣） |
| queue_waited_ms | INTEGER | 排队等待时长 |
| prompt_tokens / completion_tokens | INTEGER | 上游 usage（有则记） |
| started_at / finished_at / duration_ms | REAL/INTEGER | 时间与耗时 |
| error_summary | TEXT | 脱敏错误摘要 |

`cloud_device_logs`：本地运行日志（append-only，独立命名空间）

| 字段 | 类型 | 说明 |
|---|---|---|
| seq | INTEGER | 设备内单调序号（幂等键：device_id+seq 唯一） |
| device_id / user_id | TEXT | 归属 |
| client | TEXT | desktop / cli |
| level | TEXT | critical/error/warn/info |
| category | TEXT | chat/tool/model/queue/system 等 |
| event | TEXT | 事件名（如 turn_failed、model_call、queue_wait） |
| message | TEXT | 脱敏摘要 |
| local_session_id | TEXT | 本地线程 id（可空） |
| created_at | REAL | 本地时间戳 |

### 3.3 云端端点清单（新增，全部需 Bearer token）

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/wunder/cloud/devices` | 注册/复用设备，返回 `{device_id, max_concurrent_calls}` |
| GET | `/wunder/cloud/account` | 账号+额度+并发概览（§3.4 示例） |
| GET | `/wunder/cloud/v1/models` | OpenAI 风格开放模型列表 |
| POST | `/wunder/cloud/v1/chat/completions` | OpenAI 兼容模型调用代理（流式/非流式，计费+排队） |
| POST | `/wunder/cloud/logs` | 批量上报本地运行日志（幂等） |
| GET | `/wunder/admin/cloud/devices` | 舰桥：设备列表（分页） |
| GET | `/wunder/admin/cloud/calls` | 舰桥：调用记账（分页+user/device/model/status 筛选） |
| GET | `/wunder/admin/cloud/device_logs` | 舰桥：设备日志（分页+筛选） |
| DELETE | `/wunder/admin/cloud/devices/{id}` | 舰桥：吊销设备并清理其日志 |

路由约束：

- `wunder-core/src/auth.rs` 的 `is_admin_path` 白名单新增 `path_is_prefix_or_child(path, "/wunder/cloud")`（用户面免 API key，端内 bearer 鉴权）；舰桥面走既有 `/wunder/admin/*` 守卫。
- 云端用户面端点只接受 scope 为 `local_desktop`/`local_cli` 的 token（网页 default scope token 调用 → 403 `CLOUD_SCOPE_FORBIDDEN`），把本地会话与网页会话在协议层也隔离开。
- `api/build_router` 合并 `cloud::router()`；舰桥路由并入 `admin::router()`。
- `/wunder/cloud/v1/*` 为 OpenAI 兼容面：`v1/models`、`v1/chat/completions` 请求/响应/SSE 结构与上游一致，保证本地 `LlmClient` 零适配。

### 3.4 关键契约（JSONC 示例）

登录（复用既有端点，唯一新增是必须携带 scope 头）：

```http
POST /wunder/auth/login
X-Wunder-Session-Scope: local_desktop
{ "username": "alice", "password": "***" }
→ 200 { "data": { "access_token": "wund_<uuid>", "user": { "user_id": "alice", ... } } }
```

账号概览（登录后本地缓存、定期刷新、调用后按响应头增量刷新）：

```jsonc
GET /wunder/cloud/account
→ { "data": {
    "user_id": "alice", "username": "alice",
    "quota": { "balance": 980, "granted_total": 1000, "used_total": 20,
               "daily_grant": 1000, "last_grant_date": "2026-01-15" },
    "concurrency": { "max_per_user": 2, "active": 1, "queued": 0 },
    "device": { "device_id": "<uuid>", "revoked": false }
} }
```

并发已满（排队准入拒绝，客户端带 `queue_id` 退避重试）：

```jsonc
HTTP/1.1 429
{ "error": {
    "code": "CLOUD_BUSY",
    "message": "cloud call concurrency limit reached",
    "queue_id": "<uuid>",
    "queue_ahead": 2,          // 前方等待数
    "retry_after_ms": 3000
} }
```

额度不足（复用网页端错误结构）：

```jsonc
HTTP/1.1 429
{ "error": {
    "code": "USER_QUOTA_INSUFFICIENT",
    "message": "<i18n error.user_quota_insufficient>",
    "quota_account": { "quota_balance": 0, "quota_granted_total": 1000,
                       "quota_used_total": 1000, "daily_quota_grant": 1000,
                       "last_quota_grant_date": "2026-01-15" }
} }
```

调用成功响应头（本地即时刷新额度与关联记账）：

```http
x-wunder-request-id: <call_id>
x-wunder-quota-balance: 979
x-wunder-quota-used: 21
```

日志上报（幂等批量）：

```jsonc
POST /wunder/cloud/logs
{ "device_id": "<uuid>", "client": "desktop",
  "logs": [
    { "seq": 41, "level": "warn", "category": "tool",
      "event": "command_failed", "message": "exit code 2 (redacted)",
      "local_session_id": "<local-thread-id>", "created_at": 1764000000.0 }
  ] }
→ 200 { "data": { "accepted": 1, "last_seq": 41 } }
```

## 四、关键流程

### 4.1 登录 / 登出 / 令牌刷新

1. **登录（桌面/CLI 同流程）**：用户填服务地址（必填，`http://ip:port`，允许 https）、用户名、密码 → 客户端探测地址可达性（`GET /wunder/auth/settings` 或直接 login）→ `POST /wunder/auth/login` + `X-Wunder-Session-Scope: local_desktop|local_cli` → 成功签发 token → `POST /wunder/cloud/devices` 注册/复用设备 → 拉取 `/wunder/cloud/account` 与偏好 → 写 `cloud.session.json`（0600）→ 合成云模型条目（§4.2）→ 启动日志上报器。
2. **scope 隔离**：本地登录 scope 与网页端 default scope 不同，互不顶下线；同一设备重复登录同 scope 顶掉旧 token（服务端既有语义），多设备并行合法。
3. **登出**：`POST /wunder/auth/logout`（失效本地 scope token）→ 删除 `cloud.session.json` → 移除本地合成云模型条目 → 停止上报器。本地线程与数据保留。
4. **令牌失效**：任一云端调用返回 401 → 本地标记会话过期 → UI 提示重新登录；本地模型功能不受影响。
5. **心跳**：日志上报本身即心跳（30s 批量周期）；设备 `last_seen_at` 更新走 `/wunder/cloud/logs` 附带更新，不另开端点。

### 4.2 云端模型发现与本地合成

1. 登录后 `GET /wunder/cloud/v1/models` → `[{id, object:"model", owned_by, context, is_default}]`，服务端只返回 `expose=true`（或 `cloud.expose_models` 白名单内）的 llm 模型，**绝不返回 api_key/base_url**。
2. 本地以只读方式合成条目写入本地 `config/wunder.yaml` 的 `llm.models`（键 `cloud/<id>`）：

```yaml
llm:
  models:
    cloud/glm-5:
      provider: wunder_cloud
      base_url: http://192.168.0.10:8000/wunder/cloud/v1
      api_key: wund_<token>          # 登录时写入，登出移除，token 刷新时原地更新
      model: glm-5
      model_type: llm
```

3. 合成条目走 `ConfigStore::update`，与本地模型共用同一套选择/列表/校验路径（桌面模型列表、输入区下拉、CLI `-m` 参数全部自动生效）；`api_key` 沿用「密钥投影留空」惯例，诊断导出不含 token（现有 `export_diagnostics` 已只导出 key/provider/model）。
4. 云端模型条目**只读**：桌面模型编辑器对 `cloud/` 前缀条目禁用编辑/删除（删除按钮改为「移除云模型」，实际是登出/断开时统一移除）；重新登录后按最新列表刷新合成条目。
5. 多形态一致性：CLI 同样支持 `-m cloud/glm-5` 显式指定；`llm.default` 不写云条目键，默认模型优先取本地模型（本地无任何可用模型时才回退到云条目）；用户可在 UI 自行切换默认。

### 4.3 调用与计费

1. 本地 orchestrator 按既有路径取 `llm.models["cloud/<id>"]` 构建 `LlmClient`；`provider=wunder_cloud` 走 OpenAI 兼容分支（`endpoint()=base_url+/chat/completions`、`headers()=Bearer token`），payload/SSE 解析零改动。
2. 舰体 `POST /wunder/cloud/v1/chat/completions`：
   - bearer 鉴权（`authenticate_token_details`，校验 scope 为 local_*）；
   - 模型白名单校验（expose/白名单，不通过 → 404 `MODEL_NOT_EXPOSED`）；
   - **额度准入**：`consume_user_quota(user, today, 1000, 1)`，不足 → 429 `USER_QUOTA_INSUFFICIENT`（管理员账号豁免，与网页端一致）；
   - **并发准入**（§4.4）；
   - 用服务端模型配置（含真实 api_key）构造上游 `LlmClient` 转发，SSE 透传；
   - 记账写 `cloud_call_records`（准入即扣 1，失败不退还，与网页端 quota admission 语义一致，本期不做退款）；
   - 响应头回传 `x-wunder-quota-balance/used/request-id`。
3. 本地收到响应后按响应头增量更新 `cloud.session.json` 的账户快照并刷新 UI 额度显示。
4. 扣费单位说明：沿用现有「1 次/模型调用」（网页端 `orchestrator/quota.rs` 同款语义），本地一次线程回合含多次模型调用则计多次；将来若迁移 token 计费，两端同步改。

### 4.4 并发准入与排队

1. 舰体维护**每用户内存准入器**：`HashMap<user_id, Arc<UserCloudAdmission>>`（Mutex，条目 TTL 10min 惰性回收），内含活跃计数（上限 `cloud.max_concurrent_calls_per_user`，默认 2）与有界 FIFO 等待表（上限 `queue.max_queue_per_user`，默认 32，超出直接 429 拒绝不排队）。
2. 请求流：到达时带 `x-wunder-queue-id` 头 → 若该 queue_id 为队首且有空位：放行（移除等待表，活跃+1，响应带 `x-wunder-queue-started: 1`）；否则：首次生成 queue_id 入队尾，返回 429 `CLOUD_BUSY`（queue_ahead=队列位置、retry_after_ms=3000，响应头同时回 `x-wunder-queue-id`）。无 queue_id 且有空位：直接放行。
3. 客户端（`LlmClient` 云渠道，见 §4.7）：收到 `CLOUD_BUSY` 后按 retry_after_ms（+抖动）带同 queue_id 重发完整请求（**在流开始之前**，不存在续传问题）；总等待超过 `queue.max_wait_s` 放弃 → 本地报「排队超时」。等待条目 TTL 兜底清理（服务端 300s）。
4. 排队可见性：`LlmClient` 增加 `on_cloud_queue_position(pos)` 回调 → orchestrator 转成 `cloud_queue` 增量事件 → 桌面消息区状态条「云端排队中，前方 N 人」、CLI 状态行同文案。流结束后服务端自动释放活跃计数并唤醒队首（下一次重试放行）。
5. 与既有 `agent_queue`（任务级可见队列）/`server.max_active_sessions`（服务端 orchestrator 会话上限）的关系：本准入器是**云代理端点专有、模型调用粒度、按用户**的轻量内存队列，不落 `agent_tasks` 表；网页端排队语义完全不动。

### 4.5 云端留痕（本地请求在云端的记录）

1. **调用记账**（`cloud_call_records`）：每次云模型调用一条（含排队等待、状态、token 用量、错误摘要），舰桥「云端调用」页可查。这是「本地请求在云端有记录」的第一层。
2. **设备日志上报**（`cloud_device_logs`）：本地 `CloudLogReporter` 收集**引擎显式事件**（默认 `warn` 及以上 + 模型调用摘要、排队事件、线程轮次失败摘要；本地当前没有文件 tracing，桌面原生进程甚至未装 subscriber，因此上报源为结构化事件而非 tracing 层，不改变本地日志现状），有界内存缓冲（≤500 条，溢出落本地 SQLite 暂存表）→ 每 30s 或满 50 条批量 `POST /wunder/cloud/logs` → 服务端按 `(device_id, seq)` 幂等入库，`last_seq` 回执推进本地游标（断点续传）；失败指数退避（30s→5min 封顶），离线期间落盘不丢、登录后补传。
3. **脱敏默认**：上报不带上行消息正文、prompt、工具参数与路径；只带事件类型、状态、耗时、模型名、线程 id、错误摘要（截断 512 字符）。`include_content` 不做开放开关（本期硬性脱敏）。
4. **线程事件镜像（二期，本期不做）**：可选按线程开关把 ThreadLog 关键 Item 摘要（turn 完成/失败、工具调用次数、额度消耗）上报为设备日志 `category=thread`，供舰桥诊断；完整对话内容永不上报。
5. **隔离性承诺**：三类云端数据均写入新表，**不写** `thread_logs/thread_turns/monitor_sessions`，蜂巢（网页用户端）无任何展示入口，不参与网页端线程目录、监控聚合与清理；仅舰桥新增「云端设备」导航可见。

### 4.6 基础设置共享

1. 白名单（本期）：`theme`（映射 `theme_mode`/`theme_palette`）、`avatar_icon`、`avatar_color`、`send_key`（映射桌面 send_key ↔ 服务端偏好扩展字段）。语言不进白名单（本地环境语言）。
2. 登录时拉取 `GET /wunder/auth/me/preferences` 并应用（桌面映射到 `settings.json` 对应字段）。
3. 登录态下本地修改白名单字段 → debounce 5s `PATCH /wunder/auth/me/preferences` 回推；冲突策略：服务端 `updated_at` 旧值丢弃（以服务端为准），本地下次拉取时收敛。
4. 未登录：偏好仅本地生效；登出后不回推、不拉取。

### 4.7 本地引擎改动点（LlmClient 云渠道）

1. `provider.rs`：`normalize_provider` 识别 `wunder_cloud`（别名 `cloud`）；`is_openai_compatible_provider` 对其返回 true；`PROVIDER_PRESETS` 不收录（必须显式 base_url，防止误连）。
2. `llm.rs`：云渠道包装器在 `complete/stream_complete` 外层处理：
   - 401 → `CloudSessionExpired` 错误（上层标记需重新登录）；
   - 429 `CLOUD_BUSY` → 解析 queue_id/queue_ahead/retry_after_ms，回调位置、退避重试（上限 max_wait_s，jitter）；
   - 429 `USER_QUOTA_INSUFFICIENT` → 透传结构化错误（含额度快照）供 UI 显示；
   - 成功响应头解析 `x-wunder-quota-*` 增量刷新账户快照。
3. 服务地址变更/断网：请求超时（沿用模型 `timeout_s`）→ 本地报错并保留队列状态，UI 提示「云端不可达」，不影响本地模型。

## 五、安全设计

1. **密钥不出舰体**：上游 api_key 只在服务端 `llm.models`；本地仅持 `wund_<token>`（7 天 TTL、可服务端吊销）。
2. **scope 隔离**：`local_desktop`/`local_cli` scope 与网页 default scope 分离；登出仅失效本地 scope（`force_logout_user_scope`），不影响网页会话；舰桥可对可疑设备直接吊销（device revoked → 该设备 token 服务端拒用）。
3. **本地存储**：`cloud.session.json` 写入 0600（Windows 为用户级 ACL），密码不落盘、不在日志出现；`export_diagnostics` 保持无密钥约定（token 不在导出集）。
4. **传输**：默认 HTTP（内网 ip:port 场景）；支持 `https://` 前缀走 TLS；不引入额外自签证书信任链（需要 HTTPS 时由部署方提供可信证书）。
5. **服务端**：cloud 用户面端点不做 API key 豁免（不在 `/wunder/auth` 开放前缀内），一律 bearer 鉴权；`/wunder/cloud/logs` 限 body ≤256KB/批、≤100 条/批；排队等待表有深度与 TTL 上限（防占用）；设备日志按 `log_retention_days` 定期清理（复用监控日志清理任务模式）。
6. **权限对齐**：云端点仅暴露用户自身数据（devices/account/calls 均按 token user_id 过滤），管理端点走舰桥既有 admin 鉴权链。

## 九、验收标准

### 功能

1. 桌面与 CLI 均能：指定 `ip:port` 登录 → 看到账号+额度 → 模型列表出现云模型 → 选择云模型发起对话成功。
2. 每次云模型调用后，网页端/舰桥查看该用户 `quota_used_total` 增加 1，本地额度显示同步减少。
3. 额度耗尽后调用返回结构化 429 且本地展示「额度不足」文案，本地模型不受影响。
4. 并发：服务端设上限 1 时，同用户两路并发，第二路进入排队（本地显示「云端排队中，前方 0 人」）并在前一路结束后自动接通；排队超 300s 报超时。
5. 留痕：舰桥「云端设备/调用/日志」三页可见设备、每次调用记账、本地 warn 日志；蜂巢（网页用户端）任何页面不出现本地线程或设备日志。
6. 独立性：本地登录/登出不影响网页端会话（scope 隔离验证：网页端登录后本地登录同账号，网页会话不掉线）；本地线程不出现在网页线程列表。
7. 偏好共享：桌面改主题 → 5s 内服务端 `/wunder/auth/me/preferences` 可见；另一设备登录拉取后应用。
8. 离线：断网时本地模型可用、云模型报「云端不可达」；恢复后补传缓冲日志。

### 性能与边界

- 本地启动耗时增量 ≤ 200ms（未登录时为 0：CloudService 惰性初始化）。
- 日志上报缓冲 ≤500 条内存 + 磁盘溢出，批量 ≤50 条/30s，不阻塞线程执行主链。
- 排队等待表/准入器有深度与 TTL 上限；服务端云端点无无界缓存。
- 云模型调用比直连上游延迟增量 ≤ 20ms（不含排队等待）。

### 安全

- 本地诊断导出不含 token；`cloud.session.json` 权限 0600。
- 上游 api_key 不出现于任何下发/日志/导出。
- 未登录时 `/wunder/cloud/*` 全部 401；非 expose 模型调用 404。
- 设备吊销后该设备所有端点 401。

## 十、清理、风险与注意事项

### 清理与移除

- 不新增本地「服务端模式切换」入口（历史《桌面版本实现方案》中已移除的端云切换不回潮），云能力以「模型渠道」形态存在。
- 不复制网页端会话/线程目录逻辑到本地；本地线程主链保持 ThreadLog 本地六表。

### 风险与对策

| 风险 | 对策 |
|---|---|
| token 明文落盘 | 0600 + 独立文件 + 7 天 TTL + 可吊销；后续可换 OS 凭据库（本期不引入新依赖） |
| 排队重试放大服务端压力 | 每用户排队深度上限 32、retry_after 3000ms + jitter、TTL 兜底；客户端总等待 300s 封顶 |
| 流式调用中断后重试语义 | 排队只发生在流开始前（429 阶段），流中途断连不重试，报错由本地 orchestrator 既有恢复路径处理 |
| 本地 config.yaml 含 token | 与本地模型 api_key 同待遇（本就明文在本地配置）；密钥投影/诊断导出已排除；登出即移除 |
| 设备日志泄露敏感信息 | 硬性脱敏（无正文/prompt/路径/参数），服务端保留天数上限，舰桥权限收敛 |
| scope 机制误用 | `normalize_session_scope` 已限 32 字符白名单字符集；云端端点只接受 `local_desktop`/`local_cli` 两种 scope |

### 注意事项

- 服务端 `is_admin_path` 白名单必须带单测（既有 `route_prefixes_do_not_unlock_similar_admin_paths` 模式：`/wunder/cloudx` 不得被豁免）。
- 命名防混淆：`user_agents` 是「用户的智能体实例」，不是设备；本地设备登记一律用新增的 `cloud_devices`，不要复用 user_agents 或 gateway node 概念（gateway 是 WS 长连接协议，形态不同）。
- `wunder-cli` 与 `wunder-desktop` 均以 `wunder_server`（wunder-runtime lib 名）访问引擎，CloudService 放 engine 层，两端零重复实现。
- 完成后按仓库约定执行 `python scripts/update_feature_log.py --type 新增 --scope 蜂窝/舵机/舰体 ...` 记录到 `docs/功能迭代.md`。
