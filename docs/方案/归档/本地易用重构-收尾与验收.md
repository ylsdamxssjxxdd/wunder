### 2.2 时间线性能（2560×1476 视口，50 轮 × 24 条目 = 1400 模型行）

| 状态 | 布局行数 | 首帧 | 帧中位 | 帧最大 |
|---|---|---|---|---|
| 默认折叠 | 76 | 150 ms | 31.9 ms | 38.2 ms |
| 展开全部历史（修复前） | 1399 | 1957 ms | 447 ms | — |
| 展开全部历史（修复后） | **243** | **192 ms** | **36.0 ms** | 45.7 ms |

- 修复方式是 reducer 侧上限 `MAX_OPEN_TURNS = 8`（超出时把最旧一轮折回并隐藏其分隔条），而不是投影侧按滚动窗口改写 `visible`：后者需要一条当前不存在的"滚动→投影"反馈回路，且每帧要重写约 1400 行的可见标志，等于把布局成本换成每帧全数组重写加窗口边缘抖动。
- 上限给的是**布局行数的全局硬上限**（8×(24+3)+27 = 243），与滚动解耦，且每一轮仍可单独展开。
- 一次点开全部历史的交互成本 `opening_every_turn_ms` = **5.5 ms**。
- **结论：加上限后展开态与折叠态基本持平，可接受，无需进一步虚拟化，也没有回到 `ListView`。**

### 2.3 §十二.2 其余规则（规则 → 落点）

| 规则 | 落点 |
|---|---|
| 事件缓冲有界 | `native_stream.rs` `CAPACITY = 128`；每拍排空 `0..128` 并限 5 ms 预算 |
| 观察者通道有界 | `native_chat_observer.rs` 通道 8，每拍 ≤8 次更新 + 5 ms |
| 按帧合并 | `native_chat.rs` 33 ms 定时器，每拍一次 `flush()` |
| 只更新活动尾块 | `timeline.rs` `flush_body` 以 `body.pending` 为门；已冻结块只在 `close_body` 触碰一次（由句柄同一性测试保证） |
| 无整列重算 | 行只有 append/patch；`set_history` 是 `VecModel::set_vec`，仅在观察者置脏时调用 |
| 无无界缓存 | 轮次 ≤50、每轮条目 24、活动工作流 24、正文 8 MiB + 显示 16 KiB/160 行、补丁 8×200 |

流式实测（release，50999 字节回复）：**160 次 UI 更新，单次应用最大 2.00 ms，积压峰值 13/128，进程峰值工作集 105.5 MB**。

## 三、未实现项（已记录，非遗漏）

均在方案中标为"可选"，且都被禁改文件挡住：

- **§7.5 目标条**：`main.slint` 只有 `goal-active`，没有 `goal-objective`（该字段只存在于 `Conversation` 行）；
  `NativeGoal` 是 `{objective, status}`，**没有开始时间**，因此"已用时"在不动 `crates/wunder-desktop` 的前提下算不出来；
  编辑/删除/继续三个动作既无回调也无 façade 方法。
- **§7.7 块导航**：`main.slint` 刻意不导出 `TimelineView`（导出一个不继承 `Window` 的组件只会换来一条构建警告），
  因此没有可达的视口 y 或轮次索引，刻度命中测试需要同时改 `ui/timeline.slint` 与 `main.slint`。

两项都属于新功能而非收尾，需要单独排期。

## 四、本阶段修掉的产品缺陷清单

1. 时间线每条思考/工具条目 54px → 28px（绝对定位命中层被算进布局高度）。
2. 补丁卡内嵌 `ScrollView` 溢出卡片并裁掉末行（改为内容推导高度，不再自建滚动视口）。
3. 时间线展开全部历史时首帧 1957ms、每帧 447ms（改为 reducer 侧限制同时展开轮次）。
4. 智能体设置保存：原生路径**此前没有 `on_save_agent` 处理器**（只有预览路径有），点保存静默无效。
5. 设置页内容列按旧宽度计算导致保存/新建按钮被切；旧「我的概况」死面板移除。
6. 4 个设置页回调指向不存在的处理器（有一个连声明都没有），3 个确实缺失的在 Rust 补齐。
7. 两条 smoke 都在点已被两栏布局删除的图标栏，导致整条原生验收链路从第一阶段就失效。
8. 原生发送在被动观察者未就绪时会静默丢弃输入（harness 据此误判；产品侧待评估是否补提示）。
9. `--native-restore` 阶段从未实现（不生成 `restore.txt`），durable 恢复验收此前是空的。
10. 预览路径两处与生产不一致：`slot()` 恒为 0（切线程不换时间线）、模型清单与内置智能体从不填充。
11. 旧图标栏遗留的 `DesktopPage::{agents,tools,profile}` 不只是死枚举：`channel_ui` / `cron_ui` 读它决定是否预选智能体，该页已无渲染器，**预选被静默跳过**；枚举收敛为 `{messages, settings}`。
12. 三张 smoke 截图（`native-agents` / `native-tools` / `native-profile`）一直是**假图**——它们先"导航"到已无渲染器的页面再截图，`native-tools.png` 与 `native-workspace.png` 曾同为 243774 字节。

## 六、构建与实测交接

### 6.1 构建

```powershell
cd frontend-slint
cargo build --release
```

产物是**单文件自包含**可执行程序，无需附带任何资源目录：

```
frontend-slint/target/release/wunder-frontend-slint.exe
```

release profile 为 `strip = "symbols"` + `lto = "thin"` + `codegen-units = 1` + `panic = "abort"`，
图标、`msyh.ttc` 字体等资源在 `build.rs` 里编译期内嵌（字体走 lz4）。

无参数启动即为蜂窝正式形态（同进程原生调用后端，不经本机 HTTP/WebSocket）。
`--demo` 为纯内存预览（截图与 UI 走查用），其余参数为开发期的自检入口。

### 6.2 手工实测建议清单

以下路径本轮已自动化验证，实测时按同样的顺序走一遍即可复现：

| 顺序 | 操作 | 期望 |
|---|---|---|
| 1 | 启动 | 两栏：左 240px 侧栏（新任务 / 搜索 / 工作区树 / 底部「设置」），右侧聊天区 |
| 2 | 侧栏底部「设置」→ 逐个点 12 个分类 | 每类都有内容，无横向溢出；「← 返回应用」回到聊天 |
| 3 | 设置搜索框输入「模型」 | 导航只剩「模型设置」；清空后恢复 12 项 |
| 4 | 设置 →「模型设置」→ 添加模型并发一条消息 | 对话能跑通 |
| 5 | 设置 →「智能体设置」→ 改问候语 → 保存 | 保存生效、脏标记清除（此前原生路径点保存是静默无效的） |
| 6 | 聊天页输入区右下模型选择器 | 浮层含搜索、模型列表（默认标记 / 当前打勾）、底部推理强度七档 |
| 7 | 发一条会调用工具的消息 | 时间线：用户气泡右对齐；「执行工具 N 次」分组条可展开；展开后为竖线时间线；条目行距紧凑（28px，此前是 54px） |
| 8 | 点开一个「编辑文件」条目 | 补丁卡完整可见、**不被卡片边框裁掉末行**；行号列右对齐；删除行红底、新增行绿底 |
| 9 | 长回复流式输出中向上滚动 | 视口不被抢回；底部出现「回到最新」 |
| 10 | 连续展开很多轮历史 | 界面不卡（上限 8 轮，超出自动折回最旧一轮；展开态每帧约 36ms） |
| 11 | 关闭再启动 | 会话与正文完整恢复（durable 恢复，已由 `--native-restore` 阶段验证） |

### 6.3 本轮已自动验证的产物自检入口

```powershell
# 预览渲染自检（不需要后端），产出 7 张界面截图
frontend-slint\target\release\wunder-frontend-slint.exe --smoke-check <输出目录>

# 时间线性能探针，产出 timeline-metrics.json 与 timeline-rows.png
frontend-slint\target\release\wunder-frontend-slint.exe --timeline-probe <输出目录>

# 完整原生链路：SQLite / 发送 / 流式 / 历史 / 中断 / 导航 / 滚动 / 智能体 / 工具 / 设置 / 文件
#   第一阶段后再跑阶段二做 durable 恢复核验（脚本自动串起来）
cd frontend-slint
python scripts/check-native.py --ui target/release/wunder-frontend-slint.exe --output <空目录>
```

`--native-smoke` / `--native-restore` **不能手工直接跑**：它们要求传入一个已准备好的隔离运行时目录
（含 `runtime/config/wunder.yaml`），该目录由 `check-native.py` 连同本地 mock 模型服务一起搭建。
手工直接调用会明确报 `native smoke requires an explicitly prepared isolated runtime`，这是设计如此。

### 6.4 已知非缺陷现象

- 控制台可能打印 `ComboBox: current-value was set to "…", which is not in model`。这是 Slint 1.18
  的告警（见 slint-ui/slint#11970），出现在模型清单尚未投影完成时，选择随后自动恢复，不影响功能。
- `docs/功能迭代.md` 与 `docs/经验教训.md` 带 UTF-8 BOM；用脚本追加时不要用会去 BOM 的写盘方式。
