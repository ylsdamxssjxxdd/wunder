# 蜂巢体验测试方案

蜂巢是随舰体提供的云端 AI 工作台。本方案用独立 Docker Compose 环境启动正式舰体、PostgreSQL 和受控模型，再调用蜂巢聊天页实际使用的 HTTP/WebSocket API，持续寻找后端瓶颈。与[蛹体验测试方案](蛹体验测试方案.md)共用正确性优先、分段计时和基线比较原则，各自保存结果，不混比不同形态的耗时。

## 执行与隔离

入口为 [`measure-hive.py`](../scripts/experience-bench/measure-hive.py)，栈定义为 [`docker-compose-experience.yml`](../packaging/docker/docker-compose-experience.yml)。依赖与完整命令见[驱动说明](../scripts/experience-bench/README.md)。

```powershell
python scripts/experience-bench/measure-hive.py --server-binary target/x86/release/wunder-server --output temp_dir/hive-run --profile daily
```

每次创建独立 Compose 项目、数据库卷和数据目录，端口只发布到本机随机端口。生成管理员与两个普通用户，只通过正式 API 创建用户、线程与测试数据；业务测试使用用户令牌，管理员仅准备大线程。没有浏览器、真实账号、真实模型密钥或公网模型请求。已有服务和数据不作为测试对象。结束时清理本次栈；构建、模型配置和数据生成不混入聊天计时。

## 当前自动化场景

| 场景 | 指标与用户体验 | 正确性条件 |
| --- | --- | --- |
| `login` | 登录至收到有效凭证 | 身份存在，后续使用新凭证 |
| `session_catalog` | 新建、最近线程列表、空聊天打开 | 目录有刚创建的线程，分页有界，空线程没有历史 |
| `large_chat` | 大线程聊天首屏、上一页、下一页、正文补水 | 非降级页、线程归属正确、分页不重复、双向往返一致、最终回复身份和模型请求数准确、正文与权威消息全文一致 |
| `stream` | 发送至真实首段文本、正式终态、落盘聊天读取 | 多段真实增量、UTF-16 偏移正确、完整原文一致、模型只调用一次、落盘提问与回复一致 |
| `slow_consumer` | 延迟读取流式帧后的完成时间 | 和正常流相同的原文与落盘要求；默认每帧暂停 20 ms |
| `cancel_resume` | 模型输出中取消确认、取消至终态、同线程再次发送 | 确认实际取消、持久化取消终态、后续完整回复 |
| `queue` | 活动线程中入队、查询、调序、撤回 | 两条消息确实排队、调序生效、撤回后队列成员准确 |
| `parallel_threads` | 两个普通用户分别执行独立线程 | 两条回复都完整、各自落盘提问正确、记录整体和单线程耗时 |
| `isolation` | 越权与未登录请求拒绝延迟 | 他人线程的聊天与队列返回 403/404，未登录返回 401 |
| `workspace` | 目录分页和文件读取 | API 写入 24 个合成文件；两页各 12 个，数量、顺序、去重与文件原文准确 |
| `restart_recovery` | 重启舰体至可用、历史恢复、再次发送 | 正常重启后凭证可用、原文保留、同线程可继续执行 |
| `storage_audit` | 服务持久化核验与容量快照 | canonical ordinal 连续、展示水位不领先、记录数据库及关系字节，应用数据目录无 SQLite 或会话 JSONL |
| `idle_storage` | 请求完成后的空闲 CPU、RSS 与业务写入 | 完成一轮真实请求并关闭连接、等待所有准入轮次结束，静置后观测 12 秒；单核平均 CPU 不超过 1%，八张线程业务表没有 insert/update/delete |

另外单列 Compose 启动至 API/模型健康检查通过的时间、运行镜像 ID、Docker 版本与容量、二进制哈希及数据生成耗时。启动时间包含 Compose 调度和 PostgreSQL 初始化，只作为一次启动观察，不参与各请求指标的 P50/P95 门禁。模型源端记录自身时钟下的首块等待和输出持续时间，用来判断变慢是否来自受控模型。

## 大线程口径

默认通过正式管理员压力线程 API 生成 100 用户轮次 × 每轮 100 模型请求，固定 seed=42、typical 场景，同时会生成额外工具调用。报告分别保存用户轮次、模型请求、工具调用、模型动作和存储字节数，比较基线时核对实际数量。这里不能写成严格 10,000 个模型动作，也不能直接与蛹严格 100×100 动作的结果比较。

服务数据通过 PostgreSQL 准入与 canonical 写入链路生成；复用共享的提示、回复、推理和工具采样器，按记录数及字节数分批提交。`fixture_contract=postgres-canonical-with-tools-v2` 显式区分新服务写入器，旧报告不得直接作为优化对照。报告另存实际条目数与 canonical 记录数；生成器未提供物理字节快照时 `fixture.storage_bytes=null` 表示未测量，不能当作零字节。`storage_audit` 另外记录全栈 canonical 逻辑字节、数据库及各关系物理字节，不能当成某一个线程的独占空间。测试会拒绝漏掉工具记录的简化负载。

`large_chat` 测量的是聊天页 `/view/bootstrap?kind=chat`、`/view/chat` 与 `/bodies/`，不是轨迹页。分页、正文读取与首屏分别计时；生成数据不在首屏计时内。当前首轮读数只表示新启动服务上的首次应用读取，后续为应用缓存读取，没有清理操作系统缓存，不能称为磁盘冷读。

PostgreSQL 展示索引在 canonical 追加事务内维护有界预览、每用户轮次的紧凑摘要和投影水位，聊天读取不遍历整轮模型动作。旧线程按访问分批补建，聊天页与水位使用同一读快照。独立存储回归覆盖 25 个用户轮次、每轮超过 100 个动作、长中文及 emoji 正文、多页读取、权限隔离、索引重建和删除级联，且断言不创建本地 SQLite 历史。使用专用空 PostgreSQL 数据库运行，不能指向已有服务数据库：

```powershell
# 先将 WUNDER_TEST_POSTGRES_DSN 设置为专用空测试数据库连接串
cargo test -p wunder-runtime --no-default-features --features postgres-storage --lib postgres_views_page_complete_chat_and_rebuild_without_local_history -- --ignored --nocapture
```

初始化与生命周期改动还需从另一个全新空库运行整组 PostgreSQL 线程回归，保留默认并发执行。该组覆盖并发建表与索引、分支、正文读取及压力线程统计；不能用串行执行掩盖初始化竞争。

```powershell
cargo test -p wunder-runtime --no-default-features --features postgres-storage --lib storage::postgres::thread_ -- --ignored --nocapture
```

压力线程生成完成后，外部驱动直接核对该线程的 canonical 行数、下一 ordinal 和 API 返回的 `rollout_records` 三者相等，计数包括线程初始化元数据。该核验放在数据准备阶段，不进入聊天读取耗时。

## 持续测试与瓶颈定位

每次修改先跑 smoke；daily 预热 1 次、采样 10 次；发布验收预热 2 次、采样 30 次。失败、超时、HTTP 200 降级空页、丢字和重复执行均导致失败。成功样本生成 P50/P95/最大值，失败次数继续保留；比较场景缺失或环境不一致时拒绝给出“优化通过”。P50/P95 同时超过相对 20% 与绝对 5 ms 的增幅触发回归。

聊天打开慢，先比较首屏、分页、正文补水和响应字节，排查 catalog 水合、存储索引、投影回建和正文解压。首字慢而源端节奏稳定，排查鉴权、线程准入、上下文准备、排队和传输；终态慢，排查持久化、订阅收尾与数据库争用。取消与排队慢，优先查运行时锁和同步落盘。测试栈没有反向代理，部署代理带来的额外延迟要另设场景。

当前不宣称已覆盖：浏览器首帧/交互/滚动、强制溢出后的 WebSocket 断线回放、工具阻塞取消、模型工具协议、多条队列实际执行顺序、服务强杀/数据库故障/磁盘满、长时间泄漏和大并发容量。后续依此顺序补充；资源瓶颈需要另配容器与数据库采样，当前不把 CLI 进程资源采样当作舰体资源。

空闲场景的 CPU/RSS 只统计服务主进程，采样器和数据库查询开销不计入其中；数据库自动维护不属于业务表写入计数。12 秒窗口用于发现请求结束后的持续工作，长期定时服务与资源趋势仍需另设持续运行测试。

## 已归档实测

2026-10-25：修复初始化竞争并加入空闲存储检查后，独立 Compose API smoke [13/13 通过](性能基线/2026-10-25-hive-api-final.md)；同一二进制的 100×100 聊天 [daily 预热 1 次、正式 10 次通过](性能基线/2026-10-25-hive-large-daily-final.md)。首屏 P50 25.84 ms、P95 27.54 ms；上页 P50 23.15 ms、下页 22.63 ms、正文 13.60 ms。空闲 12 秒的服务平均单核 CPU 约 0.083%，八张线程业务表零写入。

读数、实际负载、二进制哈希及环境限制随报告保存。首屏测量为后端聊天数据可读，不包含浏览器绘制；共享环境同期编译，不能将两次独立 daily 的差值当作优化因果证据。早期 [12 场景 smoke](性能基线/2026-10-25-hive-api-smoke.md) 与 [daily](性能基线/2026-10-25-hive-large-daily.md) 原样保留，不能用其中少记初始化元数据的自报 canonical 数代替后来加入的数据库独立核验。

同日存储回归：独立全新空库、默认并发的 8 项线程存储用例全部通过，覆盖分支、压力统计、正文及分页边界、展示重建。外部体验驱动 18 项单元回归通过。响应字节边界夹具使用引号和反斜杠扩大 JSON 转义体积，不能以原始字符串字节数推断最终响应大小。
