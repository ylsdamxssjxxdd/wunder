# 聊天流式管线根治：前端协议与性能执行书

## 任务定位

你是从智能体二，负责用户侧 Vue 聊天 watcher、durable reducer、tail 投影和性能验证。目标是让前端只从服务端定义的身份、序号和 offset 更新状态。

不创建分支、不提交 git，不修改 Rust 存储提交语义，不新增轮询写入路径，不恢复字符串匹配、评分合并或全量消息覆盖。

## 工作范围

1. 审计 `chatWatcher`、`chatThreadRuntime`、`chatThreadState`、`chatThreadProjection` 及 WS 多路复用器。
2. durable `thread_change` 只按 `change_seq` 幂等折叠；revision 回退、重复和乱序必须安全处理。
3. tail 按 `(item_id, field)` 保存，检查 `base_seq`、UTF-16 offset、gap 暂存和有界容量；tail 早于 durable 基线时不得应用。
4. snapshot-required 使用原子快照并更新 cursor；snapshot cursor 小于本地 cursor 时拒绝覆盖。
5. 连接内冻结 v1/v2 协议选择，切换或重连时取消旧 watcher，禁止双重订阅和双重 reducer 写入。
6. 验证长消息增量投影、虚拟列表、滚动位置、输入框、复制和选择不会被 token 处理阻塞。

## 执行方法

1. 先搜索 `event_id`、`after_event_id`、`sessionMessages`、`coalesce`、评分合并和全量 `messages` 替换，标记 v2 路径中的旧逻辑。
2. 检查每个 reducer 分支的身份键：assistant 气泡按 `item_id`，模型轮次按 `(turn_id, model_round)`，不得按文本相似度归并。
3. 对 gap 设置明确上限和单飞恢复；恢复未结束时抑制重复请求，收到控制帧后按协议终止或重建。
4. 对 tail 测试 offset 0、连续 offset、乱序 offset、重复 offset、跨 item offset 和超限缓存。
5. 使用已有 npm 测试和必要的浏览器性能采样验证 1000 token 连续输出、断线恢复和滚动交互。

## 必须满足的验收条件

- durable 重复帧不重复渲染，乱序帧不会倒退状态。
- tail 只有在 durable cursor 到达 `base_seq` 后应用；缺口会被 durable block 修复。
- snapshot 不覆盖更新状态；恢复请求不会形成无限循环。
- 一个会话同时只有一个协议分支和一个 writer/reducer 入口。
- 1000 token 输出按帧合并，不每 token 重建全部历史；输入、滚动、选择和复制保持可用。
- 现有聊天管线测试、WS multiplexer 测试和 Vue 类型检查通过。
