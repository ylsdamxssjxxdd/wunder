# 蜂巢网页端「云端易用」重构方案

> 适用范围：`frontend/`（Vue3 + TypeScript，舰体蜂巢·用户前端）、`web/`（HTML + JS，舰桥·管理前端）；配套后端为舰体 `crates/wunder-runtime`（server 形态）。
> 对齐基线：`docs/本地易用重构方案.md`（蜂窝桌面端已落地）。蜂巢的页面、功能、视觉尽量与其完全一致，仅按云端形态做必要适配。
> 前提：当前为原型阶段，**不考虑兼容性**，老旧/不合适的字段与架构直接移除，保持项目干净。
> 开工方式：本方案 §十二已拆分为**三个可并行的工作流**（后端 / 蜂巢前端 / 舰桥前端），供 3 个智能体同时开工。

---

## 一、背景与目标

### 1.1 现状问题

蜂巢（`frontend/`）当前是「信使（Messenger）」形态的四区界面，继承了历史多形态包袱，对云端个人用户过重：

1. **多智能体并列**：左栏智能体列表 + 智能体网格总览 + 创建/删除/排序/共享，每个智能体各自配置模型、提示词、工具、定时任务、渠道、记忆；管理侧维护的「预设智能体」到用户侧会变成可增删的多实例，配置重复、体验割裂。
2. **以信使为中心**：左 Rail + 中栏列表 + 聊天 + 右 Dock 四区结构，注意力被「智能体 / 联系人 / 群组 / 蜂群 / 广场」占据，而非「要做的工作」；用户世界（IM）、智能体广场、外部应用市场等社交/市场概念与个人工作无关。
3. **蜂群编排已过重且不再维护**：beeroom（蜂房）、orchestration（编排）两套可视化、`agent_swarm`/`swarm_control` 蜂群工具、团队运行（team_runs）与蜂群概览，在前后端与管理界面都有大量残留，消耗维护成本。
4. **工作目录是隔离沙箱且藏在 section 里**：文件能力（`/workspace/*` 浏览/上传/下载/编辑）藏在「文件」section，与聊天脱节；容器概念（用户容器 + 1–10 号智能体容器）让用户面对「目录到底在哪」的困惑，本地绑定对话框（`WorkspaceBindingDialog`）是桌面遗留，与云端无关。
5. **消息为 IM 形态**：用户/智能体带头像气泡、工具过程折叠在循环里；补丁（apply_patch）缺少清晰的 diff 呈现。
6. **配置散落**：常规设置在「更多」section，智能体设置/定时任务/记忆/渠道/运行记录/归档挂在「智能体」section 的 tab 里，提示词包、帮助手册另散他处；模型无法在输入区直接切换。
7. 桌面遗留：`desktopMode` 分支、`/desktop` 路由、`Desktop*` 面板（模型/LAN/容器/运行环境）随 Electron/Tauri 前端壳停维护后仍存在于蜂巢代码中。

### 1.2 重构目标

1. **单智能体**：每个用户有且仅有一个智能体实例，由管理侧预设智能体 1:1 绑定生成，用户无需创建/切换/重复配置。
2. **工作区锁定为一个云端目录**：核心对象是「工作目录」——每个用户在服务端拥有**唯一固定目录**（数据根下的用户目录），不提供文件夹选择/更换/多目录；工具直接以该目录为根读写。
3. **工作目录区域挪进网页左栏**：因为云端目录无法像桌面那样在操作系统里浏览，把文件交互做成蜂巢**左栏「工作区」下方的常驻「工作目录」区域**（文件树 + 工具栏 + 预览弹层），与桌面端左右两栏布局一致，方便用户从云端直接与文件打交道。
4. **聊天条目化**：去掉头像气泡与「智能体循环」，改为全宽时间线——每个思考、每次工具调用、每次正式输出都是独立条目；补丁以 diff 卡片呈现（与桌面端完全一致）。
5. **输入区直接切模型**：输入框右下角直接切换模型与推理强度（模型清单由管理侧维护，用户侧只选不建）。
6. **配置全部收进设置页**：把原先散落的配置拆出来，集中为全局唯一的设置页（12 个分类，与桌面端对应，云端化适配）。桌宠（动态形象）沿用桌面端思路，作为「桌宠」分类在设置中统一开关。
7. **移除蜂群编排**：前端（蜂巢 + 舰桥）与后端全链路移除，不再支持与维护。
8. 风格统一为桌面端已落地的**简约、专业、浅色、低饱和暖色**风格（主色 `#C96443` 系），整体与桌面端一样是**左右两栏布局**。

### 1.3 设计原则

- **简约**：整体左右两栏，无四区、无营销化装饰、无冗余入口；一处设置只出现一次。
- 配置最小化：能复用的不重设，能默认的不询问；管理侧能定的不放用户侧。
- 主操作路径短：登录 → 新任务 → 干活；文件在左栏随手可取。
- 密集、清晰、可扫描（蜂巢沿用桌面端可扫描性；舰桥继续遵循治理界面规范）。
- **性能默认**：列表虚拟/限量、事件缓冲有界、增量更新、不整列重算、上传/下载并发受限、目录懒加载。
- 一切从后端/源头解决，不在表层缝补。

### 1.4 非目标（本次不做）

- 不做多智能体、不做智能体市场（广场）、不做智能体卡片导入导出/工蜂卡（智能体维度）。
- 不做用户世界（IM）、联系人/群组、外部应用市场（helper apps）等社交/门户概念（与桌面端一致）。
- 不做蜂群编排（本次直接移除，见 §四.5 与 §十四）。
- 不做远程协作、LAN 节点、站点、自动化、扩展市场等概念。
- 不做 Markdown 富文本扩展（图片、表格、公式等仍降级处理，沿用既有约束）。

## 二、核心范式转变

| 维度 | 旧（当前蜂巢） | 新（云端易用） |
|---|---|---|
| 中心对象 | 智能体 / 信使会话 | **工作目录（云端目录）+ 工作区线程** |
| 智能体数量 | 多个，可创建/删除/排序/共享 | **每用户固定一个**，由管理侧预设 1:1 绑定，不可创建/删除 |
| 工作目录 | 用户容器 + 1–10 号智能体沙箱容器，可绑定本地路径 | **唯一固定云端目录**（服务端用户根），不可更换 |
| 文件交互 | 藏在「文件」section，与聊天脱节 | **左栏工作区下方的常驻「工作目录」区域**（文件树 + 上传/预览 + 引用到聊天） |
| 线程归属 | 绑定智能体 | 归属用户工作区（即云端目录），按线程隔离 |
| 主导航 | 左 Rail + 中栏 + 聊天 + 右 Dock（四区） | **左 Sidebar + 右主区（左右两栏）**，与桌面端一致 |
| 左栏内容 | 头像/导航/联系人/群组/蜂群/广场列表 | 新任务、搜索、工作区/线程树、**工作目录区**、底部设置 |
| 配置位置 | 散落在各 section 与智能体 tab | **全局设置页 12 分类，集中配置** |
| 用户消息 | 带头像气泡 | 无头像、右上浅灰气泡 |
| 智能体消息 | 带头像气泡 + 折叠「智能体循环」 | 无头像气泡、**全宽时间线条目** |
| 补丁呈现 | 折叠在循环里的文本 | **独立 diff 卡片（行号 + 高亮）** |
| 模型切换 | 静态文本，跳转设置 | **输入框右下角直接切换** |
| 权限模式 | 审批模式（all/approve/none）+ 桌面遗留切换 | 审批模式收敛为输入区下拉（云端安全边界） |
| 蜂群编排 | beeroom + orchestration + 蜂群工具 + 蜂群测试 | **全链路移除** |

## 三、总体信息架构

### 3.1 顶层视图状态

与桌面端一致，窗口只有两种顶层模式，互斥切换：

```
ViewMode
├── workbench   // 工作区（默认）：左 Sidebar + 右聊天主区（左右两栏）
└── settings    // 设置页：全屏覆盖，左设置导航 + 右内容
```

- 从左侧栏底部「设置」进入 `settings`；设置页左上角「返回应用」回到 `workbench`。
- 模型切换浮层、线程删除确认、清空工作目录确认、文件预览/在线编辑等均为**模态层**（Overlay），不改变顶层模式。

### 3.2 页面地图

```
workbench（左右两栏）
├── 左侧栏 Sidebar（固定 240px，自上而下）
│   ├── 新任务按钮
│   ├── 搜索框（过滤线程/文件）
│   ├── 「工作区」分组（上半区，独立滚动）
│   │   └── WorkspaceRow（云端目录图标 + 名称 + 用量/状态）
│   │       └── ThreadRow（缩进，线程标题 + 状态）
│   ├── 分隔线（可拖动，调整上下区高度）
│   ├── 「工作目录」分组（下半区，独立滚动）
│   │   ├── 工具栏：上传 / 新建 / 刷新 / 多选
│   │   ├── 文件树（目录懒加载展开）
│   │   └── 用量条
│   └── 底部：设置按钮
└── 右侧主区
    ├── 无选中线程 → 欢迎页（空状态，含工作目录概览与快捷入口）
    └── 选中线程  → 聊天页（顶栏 + 时间线 + 输入区）

settings（全屏）
├── 左：返回应用 + 搜索 + 12 个分类导航（含桌宠）
└── 右：分类标题 + 分组卡片（设置项行）

overlay（模态）
├── 模型切换浮层
├── 文件预览/在线编辑（文本/图片/Office/Drawio）
├── 线程重命名/归档/删除确认
└── 目标（暂停任务）条内联操作
```

### 3.3 选中态模型（前端状态）

- `active-session-id`：当前线程（工作区唯一，即用户自己的云端工作区）。
- 工作区行恒展开（唯一工作区）；线程列表与文件树各自维护展开状态：`expanded-threads`、`expanded-file-dirs: [string]`（文件目录懒加载，展开才拉子目录）。
- 选中工作区行时：有线程则选中最近线程，否则显示欢迎页（可直接输入创建首个线程）。
- 文件树选中与聊天选中线程相互独立（保持各自主状态，避免互相打扰）。

## 四、数据模型与后端改造

> 原则：云端目录是**每用户唯一固定目录**；智能体是**每用户唯一实例**（由预设绑定生成）；会话归属用户工作区；工具以云端目录为根。蜂群编排全链路移除。

### 4.1 云端工作目录（单根锁定）

> **实现口径（已核实，勿与 CLI/蜂窝的 `single_root` 混淆）**：`services/workspace.rs` 里存在两件不同的事：
> - `single_root`（`WUNDER_WORKSPACE_SINGLE_ROOT`，由 `wunder-cli/runtime.rs:102` 与 `wunder-desktop/runtime.rs:261` 显式开启）：把**裸用户 id 直接映射到 `root`**，因为 CLI/蜂窝是单机单用户、root 就是用户的文件夹。**服务端不能开它**——`USER_PRIVATE_CONTAINER_ID = 0`，`extract_container_id_from_scoped_user("alice")` 返回 0，开启后所有用户都会落到同一个共享 root，多租户隔离被破坏。
> - **云端口径 = 扁平化智能体作用域**：新增 `WorkspaceManager::set_flatten_agent_scope(true)`（默认 false，仅舰体 `core/state.rs` 构造后开启），使 `scoped_user_id*` 恒返回 `safe_user`、不再产生 `__a__` / `__c__` 目录，同时保留 `workspace_root(bare_user) = root/<user>` 的**每用户一个目录**语义。
>
> 本阶段（已落地）：`set_flatten_agent_scope` / `flatten_agent_scope_enabled` 与三处 `scoped_user_id*` 分支 + 单测。仍待落地：舰体开启开关、`container_id` 参数收敛、存量目录迁移。

1. 云端形态启用**扁平化智能体作用域**：`scoped_user_id(user, agent)` / `scoped_user_id_by_container` / `scoped_user_id_variants` 恒等于用户自身作用域，用户工作目录 = 服务端数据根下的用户目录（一个用户一个目录）。
2. 前端不再出现容器选择：`/workspace/*` 接口的 `container_id` 参数在服务端统一按用户根解析（过渡期保留参数兼容，随后移除），删除「用户容器 vs 智能体容器」「容器生命周期」等展示概念。
3. 存量目录迁移：历史按智能体隔离的目录（`__a__` / `__agent__` / `__c__` 等作用域）合并/归入用户根（重名追加后缀并生成迁移清单），`scoped_user_id` 内的历史兼容迁移逻辑保留至迁移完成后移除。
4. 路径安全：`is_within_root` 以用户根为界，禁止越界读写；上传限制大小与类型清单；公开下载仅走鉴权链接，不暴露服务端绝对路径。

### 4.2 会话归属工作区

- 会话沿用 `chat_sessions`，弱化 `agent_id`（固定为每用户唯一智能体实例），新增/复用 `workspace_id` 概念映射到用户根目录（可沿用存储的 workspace 键，或直接以用户 ID 表达）。
- 列表按线程最近活跃排序；`session` 投影增加工作区名（固定「工作目录」或可改显示名）与状态。
- 新建线程落在用户唯一工作区下；旧数据迁移：全部会话挂到该工作区，不再保留多智能体维度。

### 4.3 单智能体固化 + 预设 1:1 绑定

- 启动/开户时确保每个用户存在唯一智能体实例（`agent_id` 沿用 `__default__` 或预设生成的卡名），记录 `preset_binding`（绑定的预设 ID）。
- 用户侧移除「创建智能体 / 删除智能体 / 排序 / 共享 / 网格总览」能力；智能体的可配置内容（system prompt、欢迎语、默认模型、推理强度、工具启用集合、审批模式、定时任务、记忆、渠道、预设问题）全局唯一一份，全部迁入设置页对应分类。
- 管理侧（舰桥）保留多个预设模板；每用户 1:1 绑定一个预设；预设更新可同步到所有绑定用户的那一个实例（见 §十.2）。
- 系统提示词冻结规则不变：线程首次确定后保持冻结，长期记忆仅在线程初始化时注入一次；预设同步不得改写已冻结线程的 system prompt（仅影响新建线程）。
- `user_agents` 收敛：`hive_id` 固定 `default` 后整体移除列与相关查询；`sandbox_container_id` 收敛为单根后移除。

### 4.4 工具根注入

- 发送线程消息时，工具（read/write/list、command、`apply_patch` 等）的 **cwd / root 统一为用户云端目录根**。
- 工具返回的文件路径相对/锚定到用户根，前端展示工作区相对路径（如 `src/foo.rs`），不暴露服务端绝对路径。
- 复用现有 `WorkspaceManager` 单根能力，去掉按智能体/容器派生根的分支。

### 4.5 蜂群编排移除（后端）

- 移除蜂群工具：`agent_swarm`、`swarm_control`（工具注册、呈现、cli 映射、文档）。
- 移除团队运行 API：`crates/wunder-runtime/src/api/team_runs.rs`（`/wunder/chat/team_runs*`）与管理端点（`/admin/team_runs`、`/admin/hives/{id}/team_runs`）。
- 移除存储：`hives`、`team_runs`、`team_tasks` 表与仓储方法、`HiveRecord`/`TeamRunRecord`/`TeamTaskRecord`、`user_agents.hive_id` 及蜂群相关索引。
- 移除配置：`config.agent_swarm_*`（runner、max_active_team_runs、max_parallel_tasks_per_team、timeout、retry、depth）与默认值。
- 移除压测/仿真：`swarm_sim`、`swarm_flow_sim` bin 与对应测试、sim-lab 管理端点。
- 移除蜂群包（hive pack）导入导出、工蜂卡导出及其测试；广场（plaza）发布/导入路线一并按 §1.4 移除。
- 子智能体（subagent）工具不属于蜂群，**保留**（AGENTS.md：子智能体是主智能体临时创建的新工作单元）。

### 4.6 现状锚点（落地时的事实依据）

> 以下为方案落地前实测代码得到的事实，供三个工作流直接引用，避免重复摸底。

**预设绑定已有半成品，需从「多实例」收敛为「单实例」**：

- `user_agents` 表已有 `preset_binding` 列（`crates/wunder-core/src/storage_records.rs:135`；SQLite/PG schema 均含该列与迁移补齐逻辑）。
- 现有 `ensure_user_preset_agents`（`crates/wunder-runtime/src/services/user_agent_presets.rs:395`）会为**每一个**已配置预设创建/匹配一个用户智能体 → 这正是「多智能体」的来源；A2 要改为：只保证**绑定预设的那一个**实例存在，其余实例归档只读（不物理删除历史线程）。
- 预设定义来自 `config.user_agents.presets`（`crates/wunder-core/src/config.rs:336-422`），管理侧通过 `/wunder/admin/preset_agents` 覆盖（`crates/wunder-runtime/src/api/admin/resource_admin.rs:40-49`；upsert 结构见同文件 709 行，其中 `sandbox_container_id` 要随单根目录移除，`worker_card` 路由要随蜂群移除）。
- 同步接口 `POST /wunder/admin/preset_agents/sync`（同文件 219 行；请求体 `PresetAgentsSyncRequest{preset_id, mode, dry_run, scope_unit_id}`）保留，语义改为「更新绑定用户的那一个智能体」，并返回影响用户数。
- 用户侧现有 `GET /wunder/agents` 返回 `{data:{total, items}}`，`agent_payload` 已包含 `preset_binding`（`crates/wunder-runtime/src/api/user_agents.rs:88-122`、1592 行）→ A3 的 `GET /user/agent` 直接复用该 payload，只收敛为单实例。

**云端目录作用域：用「扁平化智能体作用域」，不要复用 CLI/蜂窝的 `single_root`**：

## 六、工作目录（左栏云端目录交互区）

> 这是云端版相对桌面版的核心差异点：桌面版的「新建/编辑工作区对话框 + 操作系统文件浏览」整体替换为**左栏工作区下方的常驻文件区域**。文件能力全部复用既有 `/workspace/*` 接口与 `WorkspacePanel` 逻辑，去掉容器概念、收敛为窄栏文件树交互。

### 6.1 区域框架

```
─ 工作目录 ─────────────────────
[⬆ 上传] [＋ 新建] [↻ 刷新] [☑ 多选]
📁 src/
  📄 foo.rs        [⋯]
  📄 bar.md
📁 docs/            ▾
  📄 方案.md
（空目录 → 空态提示「拖拽文件到此处上传」）
────────────────────────────────
已用 128 MB                ▓▓░░（quota_bytes 为 null 时只显示已用值，不显示配额分母）
```

- 分组标题行右侧显示「更多」：清空目录（危险，二次确认 + 确认语）、打包下载当前目录。
- 文件树：目录**懒加载展开**（点开才拉子目录）、条目虚拟滚动、大目录分页拉取；行 = 图标 + 名称（超长省略，hover 显示全名/大小/修改时间 tooltip）。
- 行菜单（右键或 ⋯）：打开/预览、下载、重命名、移动、复制、删除、**引用到聊天**（`@`）。
- 「多选」进入选择模式：复选行 + 批量删除/下载打包；完成或按 Esc 退出。
- 上传：点击或**拖拽到文件树区域**即上传到当前选中目录；显示行内进度条（并发 ≤2，可取消/重试），上传完成后自动刷新并高亮新文件。
- 搜索：焦点在文件树时输入搜索框 → 按当前目录递归搜索文件名/内容（复用 `/workspace/search`），结果以平铺列表呈现，点击定位。

### 6.2 文件操作清单（复用 + 收敛）

| 操作 | 接口 | 云端约束 |
|---|---|---|
| 列表/分页 | `GET /workspace` | 分页 + 排序，目录懒加载，不一次性拉全量 |
| 上传 | `POST /workspace/upload` | 大小/类型限制、并发 ≤2、进度与取消 |
| 下载/打包 | `GET /workspace/download` `/archive` | 鉴权链接，多选打包为 zip |
| 新建目录/文件 | `POST /workspace/dir` `/file` | 名称校验，禁越界 |
| 移动/复制/重命名 | `POST /workspace/move` `/copy` | 冲突提示 |
| 批量 | `POST /workspace/batch` | 批量删除/移动 |
| 删除 | `DELETE /workspace` | 二次确认（不进回收站则明示） |
| 清空 | `POST /workspace/clear` | 高危险：输入确认语 |
| 内容读取/保存 | `GET /workspace/content`、`POST /workspace/file` | 文本类文件在线编辑 |

### 6.3 预览与在线编辑（模态弹层）

左栏空间窄，预览/编辑一律用**居中/大尺寸模态弹层**（Overlay），不挤压侧栏：

- 文本/代码：`WorkspaceTextPreview` + `CodeMirrorEditor`（限大小，如 ≤ 2 MB；超大仅下载）。
- 图片：`MessengerImagePreviewDialog` 内联预览。
- Office 文档：OnlyOffice 在线编辑（复用 `fetchWorkspaceOnlyOfficeConfig`）；流程图：Drawio（复用 `fetchWorkspaceDrawioConfig`）。均以鉴权 token 打开，回调保存后刷新文件树。
- 其它类型：显示类型图标 + 下载按钮（不尝试渲染）。

### 6.4 引用到聊天

- 文件行菜单「引用到聊天」：在输入区插入引用 chip（文件名 + 相对路径），发送时把相对路径/必要内容注入给模型；时间线中引用以标签呈现，点击在左栏文件树中定位该文件。
- 补丁/工具条目中的文件路径同样可点击定位（`[src/foo.rs]` 标签 → 左栏工作目录区定位并展开所在目录），打通「聊到哪、看到哪」。

### 6.5 用量与安全

- 文件区底部展示用量条（复用 `/workspace/stats`；`quota_bytes` 为 `null` 时只显示已用容量与文件数，不画配额分母）；`truncated=true` 时标注「统计为大目录下界」；若后续配置了配额，超限时上传按钮禁用并提示清理。
- 所有删除/清空/批量操作二次确认；前端确认不替代后端鉴权（沿用服务端 `workspace` 校验）。
- 不展示服务端绝对路径；路径始终为相对工作区根。

### 6.6 性能要求（专项）

- 目录懒加载 + 条目虚拟滚动 + 大目录分页；任何一次渲染不超过一屏条目。
- 上传/下载并发有界（≤2 / ≤3），队列长度有界；事件缓冲有界、按帧合并。
- 文件树更新采用**增量 patch**（单目录重取，不整树重建）；不使用深层 watch、不整列重算。
- 打开/预览弹层不阻塞聊天流式输出与滚动。

## 七、聊天时间线（条目化）

### 7.1 结构总览

```
顶部：工作区名 / 线程名
─────────────────────────────────────
[用户消息]                          （右上浅灰气泡，无头像）
   已处理  ▸                         （折叠组：已完成的模型/工具轮次）
   正文段落……（每次正式输出一块，直接打印）
   执行工具 6 次  ▸                   （折叠组）
   正文段落……
   执行工具 11 次  ▾                   （展开组）
     ├─ ✅ 已思考 · 摘要
     ├─ ✅ 读取文件   [file.rs]
     ├─ ✅ 已思考 · 摘要
     ├─ ✅ 编辑文件   [file.rs]
     │     └─ [补丁 diff 卡片]
     └─ ✅ ……
   正文段落……（含下载/复制按钮，hover 显示）
   [已暂停目标条 · 计时 · 描述  编辑/删除/继续]
```

### 7.2 用户消息

- 无头像、右对齐浅灰气泡（`#F3F2F0`），圆角 12px，14px，最大宽 70%；支持纯文本/段落/列表/代码块（沿用最低必要 Markdown），原始内容完整保留。

### 7.3 智能体条目类型（无头像、无气泡、全宽）

- **A. 正文块**：每次正式输出聚合为一个正文块，流式追加，完成后稳定；hover 显示「复制」「下载」（.txt/.md）。
- **B. 思考条目**：对勾圆 + 「已思考」+ 摘要（一行省略）；点击展开完整思考（限高可滚动）；流式中显示「正在思考…」+ spinner。
- **C. 工具调用条目**：对勾圆（执行中 spinner / 成功 / 失败红）+ 工具显示名 + 目标标签（文件名，浅灰底圆角，点击在左栏工作目录区定位）；失败可展开错误详情；长输出限高折叠。
- **D. 工具分组折叠条**：「执行工具 N 次」+ 箭头；展开后为竖线时间线逐条列出 B/C；较早轮次整体折叠为「已处理 ▸」。
- 上下文压缩（compaction）作为条目呈现（「上下文压缩」+ 摘要）。

### 7.4 补丁 diff 卡片（重点：编辑文件 / apply_patch）

与桌面端 §7.4 同一标准样式（蜂巢实现为 `PatchDiffCard` 组件）：

```
┌─────────────────────────────────────────────────────────────┐
│  📄 patch_log.rs                              +41   −41       │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ 变更片段                                                 │ │
│  ├──────┬──────────────────────────────────────────────────┤ │
│  │  行号 │ 代码（等宽，12.5px）                              │ │
│  │  136 │  fn run(...) {                                    │ │
│  │  137 │ -     let old = ...;                    （红）    │ │
│  │  138 │ +     let new = ...;                    （绿）    │ │
│  └──────┴──────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- 卡片头：文件图标 + 工作区相对路径 + `+N`（绿）/`−N`（红）统计；表头浅灰底；行号列固定宽右对齐。
- 新增行 `#EAF7F0` 底、删除行 `#FDECEC` 底；多文件按文件分组；默认展示前 8 个文件、每文件限量（约 200 行），超出可展开。
- 补丁在工具结果返回前显示「待应用」预览标记；成功后为正式 diff。
- 数据沿用后端结构化字段（`files[]`、`diff_blocks[]`、`added_lines/deleted_lines` 等）。

### 7.5 目标条（暂停 / 继续任务）

- 时间线底部粉色条：「已暂停的目标 · 已用时 · 目标描述」，右侧编辑/删除/继续。
- 云端支持从服务端中断/恢复；目标条交互沿用桌面端规格（若后端缺开始时间等字段，与桌面端遗留项一起排期）。

### 7.6 流式与折叠状态

- 沿用既有 WebSocket/SSE 事件流（`reasoning*`、`tool_call/start/result/output`、`llm_output_delta`、`compaction*`、`turn_terminal`）与去重/replay/补水语义。
- 事件缓冲有界、按帧合并（约 16–33ms）；只更新活动尾块/尾条目，不重算整段历史。
- 用户在底部自动跟随；上滚查看历史时保持位置并显示「回到最新」。
- 同时展开的轮次设上限（桌面端实测 `MAX_OPEN_TURNS = 8` 有效，云端沿用同样策略），防止展开全部历史拖垮渲染。

- 触发器：模型图标 + 模型名（13px）+ 推理强度（灰）+ 下拉箭头。
- 浮层（贴输入框上方，约 300px，白底圆角 12px）：
  - 模型列表（来自管理侧可见模型）：每行图标 + 名称 + 上下文长度/来源标签 + 默认标记；当前模型打勾；顶部搜索过滤。
  - 底部：推理强度档位（沿用 `reasoning-effort` 档位）。
- 选择后：立即切换当前线程的模型与推理强度（复用 `set_default_model` / `save_session_reasoning_effort` 语义）；可勾选「设为我的默认」。
- 无可用模型时：提示「联系管理员在舰桥配置模型」（用户侧不提供建模型入口）。

### 8.4 审批模式（云端安全边界）

> **落地口径（B4 已核实后端）**：后端 `exec_policy` 只有 `full_auto` / `auto_edit` / `suggest` 三档，**没有「只读」档**；因此输入区呈现三档真实语义，不伪造第四档：
> - 「自动执行」= `full_auto`（写/命令/控制类全放行）；
> - 「工具需确认」= `auto_edit`（写放行；`execute_command`/`ptc` 与桌面控制类需确认）；
> - 「全部需确认」= `suggest`（写与命令都需确认）。
>
> 切换即时生效的实现：发送请求时以**请求级** `approval_mode` 下发（后端优先级 request > agent > config），同一轮后续工具调用即按新档位判定；同时 `PUT /wunder/agents/{id}` 持久化到智能体。确认条沿用 `ToolApprovalComposer`，后端鉴权不因前端省略而弱化。

### 8.5 模型切换的粒度（现状与待办）

- **现状**：用户侧「切模型」= 更新该用户唯一智能体实例的 `model_name`（`PUT /wunder/agents/{id}`）+ 本地 profile 重载，标签同帧更新、下一轮即生效；推理强度走既有 `POST /chat/sessions/{id}/reasoning-effort`。
- **待办（A3）**：`GET /wunder/agents/models` 补齐 `{id,name,context,source,is_default}` 与 `user_default_model_name`，并新增「用户默认模型」的**写**接口（建议 `PUT /wunder/user/agent`，受 `customizable.model_name` 约束）；后端交付前后端保持降级禁用。
- **可选（若要做真正的「线程级模型」）**：需会话级 model 字段与端点，前端再加「仅本线程」一层；当前不做，避免自造字段。

### 8.5 状态栏

- 输入框下方一行（12px 灰）：工作区名（📁 工作目录）、云端状态（● 在线 / ○ 重连中）、上下文用量（进度条，如 58%，沿用 `context-usage`；超额提示压缩）。
- 不显示本机路径/分支（云端无本机文件系统语义；分支信息仅当工作目录为 Git 仓库且服务端提供时展示）。

### 8.6 发送键与中断

- 发送键沿用偏好设置（Enter / Ctrl+Enter / 无）。
- 执行中发送按钮变为停止；中断后线程状态及时落地（沿用既有 durable/replay 语义）。

## 十、舰桥（管理侧）调整

> 舰桥继续遵循治理界面规范：密集、清晰、可扫描；操作默认高风险，有清晰状态、错误反馈、确认边界。本轮调整围绕「预设智能体 1:1 绑定」「移除蜂群」与「云端单根目录」三件事。

### 10.1 总原则

- 预设智能体是**模板**，可以保持多个；但**每个用户最终只有（且只有）一个智能体实例**，由其一 1:1 绑定生成。
- 移除一切蜂群编排相关面板、字段、图标与残留 i18n/API 封装。
- 舰桥的模型、用户、渠道、工具、提示词、全局形象、监控、评估等面板继续维护，仅按上述三件事做适配。

### 10.2 预设智能体面板改造（核心）

现状（`web/modules/preset-agents.js` + `web/index.html` 预设面板）：多预设 + 目标用户/模板用户同步 + 导出工蜂卡 + 同步未自定义项/强制覆盖 + 可见范围树 + 三个 tab（智能体设置/定时任务/渠道配置），表单含蜂群字段与容器 ID。

改造为：

1. **预设列表保持多个**：每行显示预设名、描述、绑定用户数、启用模型、更新时间；新增/删除/重命名照旧。
2. **每个用户绑定一个预设**：
   - 面板内新增「绑定用户」区块：列出绑定该预设的用户（分页/筛选），支持批量绑定/换绑/解绑（解绑需指定新预设，保证用户始终有一个智能体）。
   - 新用户开户（用户管理面板或渠道舰桥中心自动开户）时从**默认预设**创建唯一智能体实例；每个用户 `preset_binding` 唯一。
3. **表单收敛**：
   - 移除「蜂群」字段（`hive_id`）与相关固定文案。
   - 移除「智能体工作目录」容器 ID 字段（云端单根目录，无容器选择）。
   - 移除「导出工蜂卡」（蜂群包概念，随蜂群移除）。
   - 保留：名称、描述、系统提示词、预习技能、启用模型、头像（静态/全局形象）、预设问题（用户侧输入区快捷问题）、工具列表、审批模式。
4. **允许自定义开关组**（新增）：逐项声明「用户可否自定义」——system prompt、欢迎语、默认模型、默认推理强度、工具集合、审批模式。用户在蜂巢「智能体设置」中只能改被允许的字段，其余只读。
5. **同步语义更新**：
   - 「同步未自定义项」：把预设内容同步到所有绑定用户实例上用户未改动过的字段。
   - 「强制覆盖同步」：全字段覆盖绑定用户实例（不改写已冻结线程的 system prompt，仅影响新线程）。
   - 同步前显示影响用户数并二次确认；同步结果日志可查。
6. 定时任务/渠道配置 tab 保留（作用于绑定用户的那一个智能体）。

### 10.3 用户管理面板

- 用户列表新增列：「绑定预设」「智能体」（唯一实例名/ID）「自定义状态」；开户表单增加「预设」下拉（默认取系统默认预设）。

### 10.5 渠道舰桥中心与外部嵌入

#### 12.2.1 契约细则（字段级，冻结）

统一响应包裹（**按现有约定，不要一刀切**）：
- `/wunder/workspace*` 系列沿用**裸对象**响应体（与既有 `workspace_list` / `workspace_content` 一致，例如 `{ "entries": [...], "total": 12 }`）；
- `/wunder/user/*`、`/wunder/agents/*`、`/wunder/admin/*` 系列使用 `{ "data": { ... } }` 包裹（与既有 `list_agents` 一致）；
- 错误统一 `{"error": {"code": "...", "message": "..."}}`（HTTP 状态码语义不变）。

```jsonc
// 1) GET /wunder/workspace?path=<rel>&offset=&limit=&sort_by=name|mtime|size&order=asc|desc
{ "user_id": "u_1", "path": "src", "parent": "", "tree_version": 12, "total": 123, "offset": 0, "limit": 200,
  "entries": [ { "name": "foo.rs", "path": "src/foo.rs", "type": "file", "size": 2048,
                 "updated_time": "2026-01-01T12:00:00+08:00" } ] }   // path 恒为工作区相对路径；无 container_id 参数

// 2) GET /wunder/workspace/stats?path=<rel>&recent_limit=8   ← 已实现（裸对象）
{ "user_id": "u_1", "path": "", "files": 120, "dirs": 18, "used_bytes": 134217728,
  "truncated": false, "quota_bytes": null,
  "recent": [ { "name": "foo.rs", "path": "src/foo.rs", "type": "file", "size": 2048,
                "updated_time": "2026-01-01T12:00:00+08:00" } ] }
// truncated=true 表示有界遍历提前结束（计数为下界）；quota_bytes 为 null 时前端不渲染配额条
// recent_limit 上限 32（USAGE_STATS_RECENT_MAX）；结果按用户+子树键做 15s TTL 缓存，树变更(mark_tree_dirty)即失效

// 3) GET /wunder/user/agent（新增；单智能体 + 预设绑定 + 可自定义标记）
//    注意：`agent` 载荷就是既有 `agent_payload`，其标识键是 `id`（与 /wunder/agents 的 items 完全同构），
//    不是 `agent_id`；`customizable` 为预设声明的六键布尔。
{ "data": { "agent": { /* 复用现 agent_payload 字段 */ "id": "agent_x", "name": "...",
                        "icon": "...", "model_name": null, "approval_mode": "full_auto",
                        "tool_names": [], "preset_questions": [] },
            "preset_binding": { "preset_id": "preset_xxx", "name": "..." },
            "customizable": { "system_prompt": false, "welcome": false, "model_name": false,
                              "reasoning_effort": false, "tool_names": false, "approval_mode": true } } }

// 4) GET /wunder/agents/models（用户视图，字段补齐）
//    `context` 允许省略（配置未给上下文长度时省略而不是编造）；`source`/`is_default` 必须存在
{ "data": { "items": [ { "id": "gpt-x", "name": "gpt-x", "context": 128000, "source": "admin",
                         "is_default": true } ],
            "default_model_name": "gpt-x", "user_default_model_name": "gpt-x" } }

// 5) GET /wunder/admin/preset_agents（列表带绑定数）
{ "data": { "items": [ { /* 现字段，去掉 sandbox_container_id */ "preset_id": "preset_xxx",
                          "name": "...", "bound_users": 12, "updated_at": 1735689600,
                          "customizable": { /* 同 3) 的键 */ } } ] } }

// 6) GET /wunder/admin/preset_agents/{preset_id}/bindings?page=&page_size=&keyword=
//    page_size 上限 100（前端默认 20，适配层统一 clamp）
{ "data": { "total": 12, "items": [ { "user_id": "u_1", "username": "...", "agent_id": "agent_x",
                                      "customized": ["approval_mode"] } ] } }

// 7) POST /wunder/admin/preset_agents/bindings  { preset_id, user_ids: [], action: "bind|unbind", new_preset_id? }
//    action=bind 的语义 = 「确保这些用户有且仅有一个绑定到 preset_id 的实例」：
//      已绑定同预设 → 幂等；绑定别的预设 → 换绑并计入 rebound_agents；尚无实例 → 新建并计入 created_agents。
//      用户管理面板的「重建智能体」复用同一语义（preset_id 传该用户当前预设）。
//    action=unbind 必须显式给出 new_preset_id（解绑即迁移），否则 400。
{ "data": { "preset_id": "preset_xxx", "affected_users": 12, "created_agents": 3, "rebound_agents": 9 } }

// 8) POST /wunder/admin/preset_agents/sync  { preset_id, mode: "safe|force", dry_run: true|false }
{ "data": { "preset_id": "preset_xxx", "mode": "safe", "dry_run": false, "affected_users": 12,
            "updated_agents": 7, "skipped_customized": 5, "created_agents": 0 } }

// 9) 管理侧用户列表（**两个列表语义不同，别混用**）
//    GET /wunder/admin/user_accounts —— 权威账户列表，`{data:{items:[…]}}`，必须含绑定三字段：
{ "data": { "items": [ { "user_id": "u_1", "username": "...", "preset_id": "preset_xxx",
                          "agent_id": "agent_x", "customized_fields": ["approval_mode"] } ] } }
//    GET /wunder/admin/users —— **监控口径的会话汇总**（裸 `{users:[…]}`，由会话投影而来，
//    没有会话的用户不会出现）。items 亦携带 `preset_id`/`agent_id`/`customized_fields`
//    （实现为「按本页 user_id 一次性批量查询」，不得 N+1）；列表为空属正常（新库无会话）。
//    若将某用户的绑定信息展示到线程面板，请接受「无会话用户不出现」这一既有语义。
```

约束：
- B 侧只消费 1)–4)；C 侧只消费 5)–9)。字段增删必须先改本小节。
- `path` 一律工作区相对路径，禁止下发服务端绝对路径。
- **`customizable` 的语义**：`system_prompt` / `model_name` / `tool_names` / `approval_mode` 是**真正的持久化写字段**（未放开时 `PUT /wunder/user/agent {field}` 返回 4xx + `FIELD_NOT_CUSTOMIZABLE`）；`welcome` 由 `description` + `preset_questions` 承载、`reasoning_effort` 是会话/消息级（随请求下发），二者只作为「前端可否放开该开关」的标记透出。
- **写路径**：`PUT /wunder/user/agent` 接受上述持久字段（当前用户作用域，无需前端知道 agent_id），响应回显 `{data:{agent,preset_binding,customizable}}`；被预设锁定的字段必须拒绝而不是静默忽略。
- `/wunder/user/agent` 必须走**用户 Bearer**鉴权（`is_admin_path()` 已豁免 `/wunder/user` 前缀；`/wunder/user_tools/*` 不受影响）。
- 所有列表接口必须分页（`/workspace*` 用既有 `offset`/`limit`；管理侧列表用 `page`/`page_size`），`limit` / `page_size` 上限固定并在契约中写明，禁止无分页全量返回。
- 蜂群相关端点（`/chat/team_runs*`、`/admin/team_runs*`、`/admin/hives/*`、sim-lab、beeroom、plaza、user_world）**整体删除**，不再是契约的一部分。

## 十三、验收标准

### 13.1 功能

- 每用户只有一个智能体（无创建/切换/删除入口），由绑定预设生成；预设未授权字段只读。
- 工作区为唯一云端目录：不可新增/删除/换目录；文件全操作（浏览/上传/下载/新建/移动/复制/批量/清空/打包/预览/在线编辑/引用到聊天）在左栏工作目录区可用。
- 整体为左右两栏布局（与桌面端一致）：左栏 = 新任务/搜索/线程树 + 工作目录区 + 设置，右栏 = 聊天。
- 线程归属工作区并在左栏树形展示；归档/恢复可用。
- 模型可在输入区直接切换、推理强度即时生效；审批模式三档可用。

## 十五、风险与注意事项

1. **存量多智能体收敛**：历史用户可能拥有多个智能体与线程。迁移策略：保留绑定预设的默认智能体及其线程，其余智能体归档只读；已冻结线程的 system prompt 不得因收敛/同步被改写（遵守提示词缓存规则）。
2. **存量目录合并**：多作用域目录（`__a__`/`__agent__`/容器目录）并入用户根时可能出现同名冲突；采用「重名追加后缀 + 迁移清单」且保持文件可访问；迁移完成后删除旧作用域分支。
3. **云端目录安全**：上传大小/类型限制、路径穿越校验、OnlyOffice/Drawio 回调鉴权、下载链接鉴权与时效；删除/清空必须后端确认与审计日志，前端确认不能替代后端鉴权。
4. **预设绑定与同步**：换绑/强制覆盖影响面大，必须有影响用户数预览与二次确认；同步不得破坏线程级提示词冻结；用户自定义字段与预设字段的冲突规则需明确定义（未自定义项才同步）。
5. **蜂群移除的连带影响**：渠道桥、定时任务、评估等引用 hive/preset 的地方逐一核对；运行中的 team_runs 数据在移除前清理或归档导出；外部嵌入与自动开户链路回归。
6. **单根目录与多租户隔离**：单根模式必须仍按 `user_id` 严格隔离（沿用 `safe_user_id` 机制），不得出现跨用户可见/可写。
7. **左栏工作目录区性能**：目录懒加载、虚拟滚动、分页、上传并发上限缺一不可；窄栏内不渲染大文件内容（一律走预览弹层）；分隔条拖动与树滚动互不阻塞。
8. **窄屏适配**：< 1024px 时左栏转为抽屉 Overlay（点开覆盖在聊天上方），聊天与输入不被挤没；恢复宽度后回到两栏。
9. **三工作流并行**：严格按 §12.7 并行纪律执行；契约表是唯一事实来源，任何偏差先改方案再动代码。
