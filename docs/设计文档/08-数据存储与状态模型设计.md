# 数据存储与状态模型设计

> 本册约束事实归属、数据库职责、提交顺序和生命周期。实现清单见 [数据存储、工作区与配置](../技术说明书/06-数据存储、工作区与配置.md)，重构依据见 [对齐 Codex 存储设计方案](../对齐codex存储设计方案.md)。

## 1. 事实归属

蛹是本地 AI 工作台。重新打开线程、恢复模型上下文、查看已完成工作过程，都围绕同一份 canonical rollout。舵机和舰体复用这套引擎能力。

| 数据 | 权威来源 | 恢复与保留原则 |
| --- | --- | --- |
| 模型执行历史、已完成条目、上下文检查点 | rollout JSONL 及其 lineage | 显式删除；可以无损冷压缩，不能由投影保证还原 |
| 分页历史、轮次索引、限量预览、根轮次计数 | `thread_history_1.sqlite` | 可从 rollout 重建，不能反向决定执行语义 |
| 线程当前 rollout、名称、置顶、工作区和业务目录 | `state_1.sqlite`，舰体另有控制面数据库 | 用户状态不能当作可丢弃缓存 |
| 已接受输入、幂等键、用户轮次、队列与执行租约 | `queue_1.sqlite` 或对应控制面仓库 | 输入首次进入 rollout 后清除待执行正文；保留必要的幂等事实 |
| 当前目标与长期记忆 | `goals_1.sqlite`、`memories_1.sqlite` 或对应业务仓库 | 独立业务状态，不能假定由历史完整重建 |
| 监控、工具计量和诊断 | `logs_1.sqlite`，舰体控制面可保存有限运维事件 | 保存有界事实，不复制请求、正文、完整工具输出和事件队列 |
| 活动条目与 token 尾部 | 进程内有界状态 | 实时传输；完成态进入历史，逐 token delta 不落历史 |

本地 `thread_items` 不保存完整正文，只保存未压缩日志的记录偏移、长度、条目字节数、SHA-256 校验值及有界预览。完整条目按需从 canonical rollout 读取，分页仍走索引；分支保留来源 rollout 身份，不复制共享前缀。模型上下文的 `ResponseItem` 和展示用 `ItemCompleted` 仍可表达同一内容的不同语义，不能宣称所有正文在日志内也只出现一次。Codex 参考快照的分页库实际保存 `item_json`，本地轻量索引是 Wunder 为磁盘占用作出的进一步优化。

已有当前格式的本地历史库首次打开时，逐条核验原始记录与旧正文，分批建立轻量索引，核验完整后原子切换，再执行一次性空间回收。源文件缺失、损坏或正文不一致时停止迁移并保留旧表；重启可以重试，不能为瘦身丢弃唯一副本。此迁移不导入更早的单体数据库。后续删除使用增量回收，不为每次消息写入执行全库整理。

## 2. 契约与实现

| 层 | 落点 | 职责 |
| --- | --- | --- |
| 核心契约 | `wunder-core/src/thread_store/`、`storage_policy/` | 强类型身份、历史位置、线程生命周期、持久化选择与专用输出限制 |
| canonical 协调器 | `storage/thread_store.rs` | 单线程写入协调、flush、投影、上下文恢复和 lineage |
| 文件记录器 | `storage/rollout.rs`、`rollout_compression.rs` | 有界 writer、完整 JSONL 记录和显式压缩/恢复 |
| 历史投影 | `storage/thread_history.rs` | 只消费已 flush 的完整记录；分页索引和投影水位原子更新 |
| 应用查询适配 | `storage/canonical_thread_log.rs` | 为传输 DTO 提供统一只读快照、分页与正文读取 |
| 业务仓库 | `storage/{sqlite,postgres}/` | 用户、权限、队列、目标、记忆等独立状态 |

原有 `ThreadLogStore` 入口委派到 canonical 协调器及投影，不代表仍有一套 SQL 执行日志。禁止重新引入旧 `thread_logs`、`thread_log_changes` 或独立 `thread_view_*` 正文表。

## 3. 写入和可见性

一次持久化追加遵循固定顺序：

1. 在任务线程写锁内确认当前 RolloutId、所有权和生命周期。
2. 统一 policy 选取可持久化的 canonical 记录，拒绝不完整或超出资源预算的追加。
3. 有界 writer 写入完整 JSONL 记录并经过 flush barrier。
4. projector 消费完整记录前缀，在短事务内更新完成条目、轮次和水位。
5. 成功后发布历史位置，唤醒订阅者。

JSONL 与 SQLite 不具备跨介质事务。投影允许落后，绝不允许领先；追加已成功而投影失败时保留 rollout，后续明确恢复从记录边界续投。未以换行结束的文件尾部不投影，投影事务失败不推进水位。

模型恢复读取 canonical 上下文记录和检查点，不能从展示摘要反推工具结果或 system prompt。线程首次确定的 system prompt 保持冻结，长期记忆只在初始化时注入一次。

## 4. 数据库隔离与 schema

蛹和舵机使用独立角色数据库。state、queue、goals、memories、logs 由各自 DAO 按需打开，连接池和 WAL 生命周期独立；常驻连接不永久 ATTACH 其他角色库。明确的管理查询可以使用请求级关联读取，不能扩大为跨库写事务。

`thread_history_1.sqlite` 只承载可重建的完成态投影。SQLite 角色建表定义位于 `storage/sqlite/schema_*.sql`，投影 schema 位于 `thread_history.rs`。文件名中的 `_1` 标记本次新格式的初始代际，不代表引入了旧格式迁移链。

本次不读取、不修复、不自动迁移旧单体数据库。新角色 schema 以干净的初始定义创建；后续修改须明确区分可重建投影与不可丢弃业务数据。PostgreSQL 控制面使用自身的 schema 指纹检查，不能把该标记误作 rollout 历史版本。

## 5. 舰体边界

舰体中的 PostgreSQL 承担用户、组织、鉴权、调度和治理控制面。canonical rollout 与本地历史投影仍由执行所有者管理；压测、读取和删除使用与蛹相同的 ThreadStore。

一个线程只有一个执行所有者。当前 PostgreSQL schema 在首次启动时绑定一个持久 canonical 根标识；其他独立根会在启动失败，`auto` 后端也不能绕过失败创建独立 SQLite 控制面。这只是单节点 root 部署保护，不提供多节点路由、所有者转移或故障接管。多节点部署必须在此基础上把线程的执行、补水和订阅路由到所有者，或提供等价的所有者转发。把 PostgreSQL 设为后端不会自动使任意节点都能读取另一节点的文件；本地 hub 也不是跨节点总线。禁止通过复制完整执行正文到 PostgreSQL 来隐式绕过这个边界。

## 6. 有界读取与重建

聊天页、轨迹页、响应字节预算与正文块大小统一取自 `wunder-core/src/thread_view.rs`。查询使用索引和 keyset cursor，只解码本页需要的完成条目；预览列和写时计数避免列表页反复解析全部正文或重算历史。

正文按需从完成条目读取，再按 UTF-8 安全边界分页返回。块是传输单位，不另落一份永久 body chunks 表。输出是否完整由持久化 policy 决定：用户与助手文本按原文保存，命令/MCP 展示输出采用专用限制并标记截断，不能承诺任意工具原始字节永久完整保留。

投影只在追加、明确恢复或显式重建时推进。启动不扫描所有 rollout，页面打开不触发全量重建，空闲不做投影发现、轮询、压缩或维护写入。`services/thread_view_rebuild.rs` 仅保留诊断快照，报告后台重建关闭。

## 7. 删除与诊断保留

| 操作 | 允许影响 |
| --- | --- |
| 按时间范围清理诊断 | 有界 monitor、stream、工具计量等临时数据；不删除 canonical 历史和线程目录 |
| 仅删除会话目录，`delete_logs=false` | 删除调用者指定的目录及关联业务项；保留历史 |
| 显式删除线程历史 | 按同一线程生命周期协调 rollout、投影、状态与 admission 清理 |
| 显式删除用户全部历史 | 按用户 owner 索引分批读取线程，再逐线程协调删除；失败可重试，不全表装载 |
| 冷压缩 | 仅显式调用，默认关闭；遵守年龄阈值和活动线程保护 |

诊断不能承担用户历史。monitor 持久化只允许有限身份、状态、数值、布尔与有界轮次计数；完整实时事件留在有界内存快照。工具日志只保留计量事实，不重复保存参数、schema、错误栈和完整结果。

数据库空间回收由实际写入/删除驱动的有限维护承担，不为“保持健康”启动空闲写入循环。服务端文件日志拥有独立保留配置，不与 rollout 生命周期混淆。

## 8. 验收

- SQLite 与 PostgreSQL 控制面入口均使用同一 canonical 历史，用户轮次、幂等受理、分页与删除口径一致。
- rollout flush、投影失败/续投、半行尾部和 lineage 切换均有针对性验证，投影从不领先原件。
- 重新打开线程可以按持久化策略查看完成内容与过程；实时 delta 数量不会放大持久历史行数。
- 空闲线程没有 writer flush、history polling、后台重建或租约写入；活跃执行才维护执行租约。
- 压测通过生产 policy、writer 和 projector 生成历史，不能直接造旧 SQL 表或额外日志副本。
- 日志清理保留目录与 canonical 历史，显式用户历史删除不会影响其他用户。
