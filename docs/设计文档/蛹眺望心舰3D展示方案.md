# 蛹与蜂巢“眺望心舰”浏览器入口

## 当前方案

蛹是本地 AI 工作台，蜂巢是随舰体提供的云端 AI 工作台。两者的设置导航均不再提供独立的“眺望心舰”分类，也不在应用内解析模型或渲染 3D。入口统一放在“设置 → 账号”页面底部，点击“眺望心舰”后在外部浏览器窗口打开舰桥展示。

本方案替代此前的 Slint 软件光栅化与 Win32/X11 子画布方案。蛹原有模型解析、光栅化、帧调度、原生 presenter、画布组件和内嵌模型资产已移除；蜂巢原有内嵌查看器及渲染依赖导入、样式、生命周期逻辑已移除。

## 展示与部署

舰体提供 `/bridge/wunder-model.html` 独立静态入口，直接复用舰桥 `web/modules/wunder-model.js`，共用模型目录、默认视角、材质、交互、自动旋转与资源释放逻辑。页面不加载管理业务或调用管理 API，无需管理员登录即可查看展示；舰桥管理接口继续使用已有鉴权。

蜂巢的开发代理与生产 Nginx 均转发 `/bridge/` 到舰体。因此蜂巢与舰体使用不同端口时，浏览器入口及其脚本、样式、模型仍能通过同一地址访问，无需硬编码端口。

## 蛹入口

账号页通过强类型 `NativeDesktop::open_bridge_model` 调用系统默认浏览器，系统调用放在后台执行，重复点击期间最多保留一次打开操作。Windows 查询系统协议关联，Linux 查询默认浏览器，对常见浏览器传入新窗口参数；无法识别时交给系统默认打开方式。

展示地址来自账号页舰体服务地址：接受 HTTP/HTTPS，保留反向代理路径前缀，去掉末尾 `/wunder` 后追加 `/bridge/wunder-model.html`，清除 query 与 fragment。地址为空、协议无效、含嵌入账号密码或浏览器启动失败时显示错误，不传递登录口令或会话令牌。

蛹本地使用不依赖舰体；只有打开这项可选展示时，需要填写可访问的舰体服务地址。

## 蜂巢入口

账号页根据已有运行时/环境 API 地址解析展示链接，保留代理路径与 IPv6 主机格式。按钮在同步点击回调中请求独立浏览器窗口，并断开 `opener`；浏览器阻止弹窗时给出明确提示。蜂巢页面本身不请求模型、不创建 WebGL 上下文。

## 验证

- Slint Viewer 检查主界面并渲染账号页，确认按钮位于页面底部、导航没有独立展示分类。
- Rust 校验原生 UI 接线，并覆盖服务根地址、API 地址、代理前缀、IPv6、无效协议与嵌入凭据的链接处理。
- 前端类型检查与生产构建。
- 浏览器回归覆盖独立页面无管理会话加载、舰桥默认视角、满窗口画布与持续动画，以及蜂巢账号页新窗口、无内嵌模型请求、弹窗拦截反馈。

本次验证结果：Slint 主界面检查与账号页渲染通过，蛹与舰体 `cargo check` 通过；蛹单元测试 188 项通过、3 项既有窗口测试按默认跳过；新增浏览器模块独立编译测试 3 项通过，设置搜索独立测试 4 项通过；蜂巢类型检查、生产构建与 3 项相关浏览器回归通过。额外执行桌面库测试时，既有 `native_observer.rs` 的三处调用缺少参数，导致该测试集未能编译；此问题位于本次变更之外。

使用新入口需要更新蛹程序及舰体静态资源/路由；生产蜂巢同时应用新的 Nginx 代理配置。
