# 工具设计

> 本册于 2026-09-25 按 0.4.3 代码现状重写。工具系统的实现主体在 `crates/wunder-runtime/src/services/tools/`（目录）与 `services/tools.rs`，执行编排在 `orchestrator/`。现行细节与本文冲突时，以代码为准。

## 1. 目标

工具系统承担三件事：

- 把后端能力稳定地暴露给模型。
- 把高风险能力纳入统一治理，而不是只靠提示词约束。
- 让模型看到的是"简洁工具面"，让运行时保留"完整兼容面"。

工具定义与工具执行是明确分开的：模型侧工具面（catalog + schema 压缩）、运行时兼容解析（别名归一）、执行调度（dispatch + orchestrator 治理）、结果归一（信封 + observation 投影），四层各司其职。

## 2. 命名与别名

### 2.1 三层名字

wunder 的工具名有三层：

| 层 | 例子 | 说明 |
| --- | --- | --- |
| canonical 名（中文） | `读取文件`、`执行命令` | spec 定义名，对中文模型最稳 |
| 英文别名 | `read_file`、`execute_command` | 静态别名表，供英文模型与历史调用 |
| 模型 function 名 | 由 `build_model_function_name`（`orchestrator/prompt.rs`）生成 | sanitize 成 `[A-Za-z0-9_-]`，上限 64 字符，MCP 工具优先用 runtime name，重名自动加后缀 |

英文展示名的选择由 `preferred_english_alias()` / `select_english_tool_alias()`（catalog.rs）决定；运行时展示名映射由 `build_runtime_tool_display_map` 维护。

### 2.2 别名解析

`builtin_aliases()`（catalog.rs）返回静态别名表，`resolve_tool_name()` 单次查表，查不到原样返回（即 MCP/知识库/A2A 这类动态名）。dispatch 入口与内建派发各解析一次。

别名只进不出：历史调用形态（如 `final_response`、`update_plan`、`get_goal`、`browser_navigate`）长期保留解析，但不再出现在模型 spec 里。目前唯一被彻底移除的旧工具是 `replace_text`（specs 与 aliases 均无，有测试守着）。

### 2.3 动态名字空间

- MCP：`server@tool`；packaged 服务器只暴露一个 `mcp_package` 工具。
- A2A：`a2a@服务名`。
- 知识库：以库名为工具名，schema 要求 `query` 或 `keywords`。
- 用户自定义工具、技能（`skill_call`）单独注册。

## 4. 模型侧 schema 与压缩

### 4.1 全量 spec 约定

每个工具 input_schema：顶层与嵌套 items 一律 `"additionalProperties": false`；枚举与数值边界用 enum/minimum/maximum/minItems/maxItems/minLength/maxLength；描述走 i18n key（`config/i18n.messages.json` 的 `tool.spec.*`），保证多语言一致。

### 4.2 模型侧压缩（compact.rs）

`compact_tool_spec_for_model()` 把全量 spec 压成模型侧形态：

- 每个 canonical 工具有一句固定的中文短描述；未知工具规范化空白后截断 240 字。
- schema 走 `compact_schema_value(value, registry)` + `SCHEMA_KEYS` 白名单：保留 required/enum/数值边界/`allOf|oneOf|anyOf|not`，丢弃 `title/examples`，不使用 `if/then/else`。
- 关键规则：`properties`、`$defs`、`definitions`、`patternProperties`、`dependentSchemas` 是"名字 → schema 的注册表"，不是 schema 本身——压缩时保留键名，只递归压缩值；字面量关键字（`"type": "string"` 这类）原样保留。这条规则修复过一次线上问题：早期版本把 properties 当 schema 过滤，导致模型收到空参数结构（2026-09-24 修复，配套回归 `compact_schema_preserves_argument_names_and_nested_definition_names`）。

### 4.3 模型 function 名生成

`build_model_function_name()`：sanitize、限长、去重；描述里的 `/workspaces/{user_id}/` 占位符会替换为实际 workspace 路径。MCP YAML schema 经 `normalize_tool_input_schema()`（wunder-core）归一。

## 5. 执行治理

### 5.1 派发顺序

`execute_tool`（tools/dispatch.rs）：别名解析 → 用户工具绑定 → 技能 → A2A 服务 → MCP → 知识库 → `execute_builtin_tool` 内建 match。新增能力优先做成独立工具文件接入 catalog，不在 dispatch 里堆业务。

### 5.2 超时

`resolve_tool_timeout()`（orchestrator/tool_exec.rs）：默认 `DEFAULT_TOOL_TIMEOUT_S=120`、下限 1 秒。例外：蜂群 send/wait 类不设默认超时（等显式 timeout_s）；`a2a等待` 叠加 wait_s；sleep 取 seconds+10；`@` 工具回落 config.mcp.timeout_s；沙盒取沙盒超时与默认的较大者。超时统一转 `TOOL_TIMEOUT` 失败信封（retryable=true）。

### 5.3 并行

`execute_tool_calls_parallel()`：并行度 `min(calls, 4)`（`DEFAULT_TOOL_PARALLELISM`）。安全模型是读写锁：并行安全工具（read_file/list_files/search_content/read_image/web_search/web_fetch/browser/self_status/sleep/a2a_observe/a2a_wait）取读锁并发，其余取写锁串行；memory 只有 list/get/search/recall 只读动作可并行，写动作排他；apply_patch、edit_file2 强制排他。结果 meta 记 `parallel_execution.mode = parallel_read | exclusive_write`。

### 5.4 审批

`exec_policy::evaluate_tool_call` 决策；需要审批时发 `ApprovalRequest`，kind 由工具类型路由：`执行命令`/ptc → Exec，桌面控制 → Control，其余 → Patch。响应支持 ApproveOnce / ApproveSession / Deny；ApproveSession 会给 args 注入 `approved: true` 重新评估。事件为 `approval_request` / `approval_result`，线程进入 `WaitingApproval`；会话取消时挂起审批自动置 cancelled。

### 5.5 每轮预算与轮数

- 工具调用预算：默认每用户轮 10000 次；数据库查询类 2000（问题含"全量/all rows"等语义时放宽到 10000）；记忆召回 2000。
- 预算拦截生成 `ToolBudgetBlock` 并向模型发通知，而不是静默失败。
- 非管理员默认最大 1000 轮（下限 2）。

### 5.6 失败与循环保护

三层防线都在 `orchestrator/retry_governor.rs` + `empty_output_guard.rs`：

| 防线 | 触发 | 行为 |
| --- | --- | --- |
| RetryGovernor | 同指纹不可重试失败 5 次（参数/schema 类仅 2 次）、可重试失败 5 次、同工具失败 5 次、apply_patch 失败 5 次 | 触发 `tool_failure_reroute` 通知；每轮无效调用重路由上限 2 次 |
| SuccessProgressGovernor | `执行命令`/ptc 连续 4 次成功但无进展（指纹 = 命令哈希 + stdout/stderr/returncode） | 以 stop_reason `tool_no_progress_guard` 停轮，answer 附带排查建议（先 read_file、拆小、dry_run 等） |
| empty_output_guard | 模型空回复/仅思考/截断 JSON | 每用户轮 1 次恢复机会：注入 notice、恢复轮禁用 thinking；再失败以 `LLM_OUTPUT_LOOP` 终态，默认思考预算 2048 |

### 5.7 规划阶段

`build_planned_tool_calls()`（execute_support.rs）在执行前过滤：空名、未知/未授权工具、参数 JSON 未闭合（`TOOL_ARGUMENTS_INCOMPLETE`）。缺 call id 自动补齐。`a2ui` 与 `最终回复` 是终局工具，出现即截断同批后续计划。

## 6. 挂载与可见性

### 6.1 可用集合

`collect_available_tool_names()`（catalog.rs）逐层并集：内建 spec（经 runtime 特性开关过滤：web_fetch/web_search/browser/desktop/多模态）或配置显式启用表 → browser 单独受 `tools.browser.enabled` 控制 → MCP（packaged 收敛为 `mcp_package`）→ `a2a@服务` → 技能 → 知识库 → 用户工具绑定 → 已启用内建的别名并入。

### 6.2 请求级过滤

`resolve_allowed_tool_names()`（prompt.rs）：请求带工具表时按 `declared_tool_names / declared_skill_names` 收口。两条互斥策略：默认模式剔除 `a2ui`；出现 `a2ui` 时剔除 `最终回复`。预览技能时剔除 `技能调用`。模型无视觉能力时剔除 `read_image` 与桌面控制。

### 6.3 会话生效链

`build_effective_tool_names()`：用户访问 allowed_tools 交集 → 会话 `tool_overrides`（或冻结覆盖，或智能体默认）→ `apply_tool_overrides`（`__no_tools__` 表示全空）→ 排序收口。智能体配置 `declared_tool_names` 非空时覆盖 legacy `tool_names`。

默认工具档 `curated_default_tool_names()`：13 个内建 + 技能"技能创建器"；显式不含 `self_status` 与 `edit_file2`。

goal 有独立校验：目标续跑与 API 设置目标都要求生效工具里含 `goal`（`tool_names_contain_goal_tool`），否则跳过或返回 400。

## 7. 返回结构与双通道

### 7.1 信封

成功：`build_model_tool_success()` → `{ok, action, state, summary, data}`，需要引导时加 `next_step_hint`。
失败：`build_failed_tool_result()` → `{ok:false, error, data(含 error_meta), error_meta:{code, hint, retryable, retry_after_ms}, sandbox}`。

### 7.2 双通道

一次工具调用产生两个视角，不混用：

- **模型观察**：`to_compact_payload()` 去掉 meta、压缩字段、去噪后进入消息流（原生 API 为 role=tool 带 tool_call_id，兼容路径为 role=user 前缀 `tool_response: `）。
- **前端事件**：`to_event_payload()` 保留全量 data+meta；`tool_result` 事件里额外内嵌 `model_observation` 字段，同一事件即可对照"原始结果 vs 模型实际看到的内容"。

### 7.3 预算常量

| 层 | 常量 |
| --- | --- |
| 事件/持久化（`TOOL_RESULT_*`） | 字符上限 20000（头尾各 10000），marker `...(truncated)...`；数组 128（头 48/尾 16）；分页信号数组放宽到 500（头 180/尾 60） |
| 模型观察（`OBSERVATION_*`） | 字符上限 20000（头尾各 10000）；数组 32（头 20/尾 8）；表格采样 4 行；搜索 12 hits；read_file 最多 8 文件 |
| finalize meta | `duration_ms/truncated/output_chars/truncation_reasons/continuation_required`（hint 固定指向分页或缩小查询）/`exit_code`；workspace 树变化时附 `workspace_changed/workspace_version` |

`技能调用` 与 `应用补丁` 跳过事件截断。失败结果的 observation 只留合并后的错误，不回放 data。

### 7.4 工具自身的预算

- 文件读取：单文件 1MiB / 2000 行，行窗口默认 200、跨度上限 2000，批量最多 20 文件；搜索 max_matches 默认 200。
- 命令输出：stdout 头 24KiB/尾 40KiB，stderr 头 8KiB/尾 56KiB，总量 128KiB（4KiB–4MiB 可调），超限插 `...(truncated command output, omitted N bytes)...`。
- web_fetch：重定向 ≤10，响应 ≤8MiB；read_file 截断标记中的省略字节数可被解析回 `read_output_omitted_bytes`，供微压缩复用。

## 9. 测试守则

工具面的关键约束都有测试锁定，改动前先看这些断言：

- `services/tools/catalog.rs`（内嵌 tests）：spec 字段白名单、MCP 别名唯一性、packaged MCP 单工具、web_fetch 描述反猜测、知识库挂载可见性。
- `services/tools/tests.rs`：read specs 别名与行窗口归一、list_files 分页、命令输出 GBK/UTF-16 解码回退、specs/aliases 不含 `replace_text`、无视觉能力屏蔽 `read_image`。
- `services/tools/compact.rs` tests：schema 压缩保留 required/enum/$defs 与嵌套参数名（回归）、未知工具描述 ≤240 字。
- `orchestrator/tool_result_payload/tests.rs`（34 例）：各层截断、分页数组放宽、失败观察去 data、read_file content 统一预算。
- `orchestrator/tool_parallel.rs` tests：读并行/写排他矩阵。
- `orchestrator/execute_support/tests.rs`、`retry_governor.rs` tests、`empty_output_tests.rs`：规划过滤、审批 kind 路由、循环保护阈值。
