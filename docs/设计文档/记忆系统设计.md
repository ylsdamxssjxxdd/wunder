# 记忆系统设计

## 1. 目标

长期记忆需要同时满足两件事：

1. 对模型友好：系统提示词只注入轻量索引，不灌入大段正文。
2. 对工程友好：前端、后端、工具、提示词统一使用同一套结构和动作。

当前设计以“索引标题 + 完整详情”为核心抽象：提示词注入只包含 `memory_id + title` 索引，正文按 `memory_id` 拉取。协议结构上保留完整的语义字段集（摘要 `summary_l1`、标签数组 `tags`、实体 `entities`、置顶 `pinned`、状态 `status`、层级 `tier`、置信度等），由评分召回决定哪些记忆进入注入清单（2026-06 后已从“极简字段”方案回摆为“注入极简 + 结构完整”）。

> 本册 2026-09-25 修订：原“彻底移除摘要/置顶/作废字段”的结论已被实现反转，现按当前代码更新。

## 2. 设计原则

- 一条记忆只保留一个主标题，作为索引入口。
- 详情正文只在真正需要时按 `memory_id` 拉取。
- 系统提示词中注入的是索引，不是完整内容。
- 模型侧 `memory_id` 保持 8 个字符以内，便于搜索、比对和二次调用。
- 检索以 `list` 和 `search` 为主，`get` 只在确认目标后使用。
- 用户侧编辑结构与模型侧写入结构保持一致。
- 外显协议统一使用 `tag`，旧 `category` 仅保留兼容解析。

## 3. 核心结构

### 3.1 记忆碎片结构

| 字段 | 含义 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `memory_id` | 记忆索引 ID | 系统生成/可传入 | 对模型展示时压缩到 8 字符以内 |
| `title_l0` | 索引标题 | 建议填写 | 例如“用户姓名”“回复语言” |
| `content_l2` | 内容详情 | 必填 | 完整事实、约束、上下文 |
| `tag` | 记忆标签 | 建议填写 | 例如 `profile`、`response_preference` |
| `supersedes_memory_id` | 关联记忆 | 选填 | 表示当前记忆替代/承接哪条旧记忆 |
| `valid_from` | 记忆时间 | 选填 | 事实生效时间或事件时间 |
| `source_type` | 来源类型 | 系统维护 | 例如 `manual`、`auto_extract` |
| `updated_at` | 最后更新时间 | 系统维护 | 前端排序与展示使用 |

### 3.2 正式结构中的其余字段

除 3.1 的核心字段外，`MemoryFragmentInput`（`services/memory_fragments.rs`）与建表结构还包含以下正式字段：

- `summary_l1`：一行摘要（对外可见）。
- `tags` / `entities`：标签数组与实体。
- `fact_key`：事实键，用于去重与合并。
- `tier` / `status`：记忆层级与状态（含作废语义，`superseded_by_memory_id` 指向承接记忆）。
- `pinned`：置顶，参与列表排序与提示词【置顶】标记。
- `confirmed_by_user` / `importance` / `confidence`：用户确认与置信度量。

注意：外显协议以 `tag` 为主、`category` 仅兼容解析；`memory_id` 对模型压缩到 8 字符以内不变。

## 5. 提示词注入策略

### 5.1 注入内容

线程初始化时，通过 `recall_for_prompt_inventory` 做评分召回（lexical / semantic 向量 / freshness / importance 多维评分，`MemoryRecallHit`），只注入入选记忆的索引：

```text
[长期记忆]
- 当前可用长期记忆总条数：3。本次注入：3 条（上限 30 条）。
- 下方注入的是记忆索引（memory_id + 标题），不是完整内容。需要完整细节时，请使用 memory_manager get 并指定 memory_id。
- [2026-04-12 08:37] 0695f345 | 用户姓名
- [2026-04-12 08:38] preftone | 回复风格
- [2026-04-12 08:40] replyzh | 回复语言
```

### 5.2 注入流程

```mermaid
sequenceDiagram
    participant Store as 记忆存储
    participant Prompt as 提示词构建器
    participant Thread as 会话线程
    participant Model as 大模型
    Store->>Prompt: 评分召回记忆清单（上限 30）
    Prompt->>Prompt: 格式化为 memory_id + 标题
    Prompt->>Thread: 仅在线程初始化时注入
    Thread->>Model: 冻结后的 system prompt
    Model->>Store: 如需正文，调用 memory_manager.get(memory_id)
```

### 5.3 关键约束

- 线程第一次确定 system prompt 后保持冻结。
- 长期记忆只允许在线程初始化时注入一次。
- 后续轮次不得再次改写线程 system prompt。

## 6. 记忆管理工具

### 6.1 动作集合

| 动作 | 用途 | 返回特点 |
| --- | --- | --- |
| `list` | 浏览最近记忆索引 | 默认 30 条，只返回索引信息 |
| `search` | 按标题/详情搜索 | 默认 10 条，返回标题与片段摘要 |
| `get` | 读取完整详情 | 返回单条完整内容 |
| `add` | 新增记忆 | 使用当前精简结构 |
| `update` | 更新记忆 | 按 `memory_id` 修改 |
| `remove` | 删除记忆 | 返回删除结果 |
| `clear` | 清空当前作用域记忆 | 返回删除数量 |

### 6.2 推荐调用路径

```mermaid
flowchart TD
    A[模型需要长期记忆] --> B{已知道 memory_id?}
    B -- 否 --> C[list 或 search]
    C --> D[确认目标 memory_id]
    D --> E[get]
    B -- 是 --> E[get]
    E --> F[读取完整详情并继续推理]
```

### 6.3 写入结构

```json
{
  "action": "add",
```

## 7. 用户侧前端设计

### 7.1 记忆卡片

卡片只展示当前版本需要的核心信息：

- 记忆标签
- 索引标题
- 内容预览
- 来源类型
- 关联关系
- 更新时间

### 7.2 编辑页

编辑页只保留：

- 索引标题
- 内容详情
- 记忆标签
- 关联记忆 ID
- 记忆时间

### 7.3 展示与操作口径

摘要（`summary_l1`）、标签数组、实体、置顶、作废状态（`status` + `superseded_by_memory_id`）均为正式能力：置顶参与排序并显示【置顶】标记，作废记忆保留承接关系，用户确认走 `confirmed_by_user`。卡片区仍提供删除等管理操作；最近提炼任务（`recent_jobs`）在用户 API 中返回。

自动记忆提取（`services/memory_auto_extract/`）会在对话后自动沉淀候选记忆，配合 `memory-settings` 的 `auto_extract_enabled` 开关控制。

### 7.4 新增记忆复刻

用户可以在记忆面板点击“记忆复刻”，将当前智能体的记忆复制并覆盖到另一个已存在智能体。

复刻规则：

- 只能选择其他已存在智能体
- 目标智能体原有记忆先清空
- 然后复制源智能体全部记忆
- 源智能体记忆不会被清空
- 目标侧会重新生成 `memory_id`，避免把“复制”误写成“移动”

```mermaid
sequenceDiagram
    participant Source as 源智能体
    participant API as replicate API
    participant Target as 目标智能体
    Source->>API: 提交 target_agent_id
    API->>Target: 清空原有记忆
    API->>Source: 读取源记忆
    API->>Target: 生成新 memory_id 后批量写入
    API-->>Source: 返回 copied / deleted_target
```

## 8. 用户 API 设计

| 接口 | 说明 |
| --- | --- |
| `GET /wunder/agents/{agent_id}/memories` | 记忆列表 |
| `POST /wunder/agents/{agent_id}/memories` | 新增记忆 |
| `GET /wunder/agents/{agent_id}/memories/{memory_id}` | 记忆详情 |
| `PATCH /wunder/agents/{agent_id}/memories/{memory_id}` | 更新记忆 |
| `DELETE /wunder/agents/{agent_id}/memories/{memory_id}` | 删除记忆 |
| `POST /wunder/agents/{agent_id}/memories/replicate` | 记忆复刻到其他智能体 |
| `POST /wunder/agents/{agent_id}/memories/migrate` | 记忆迁移 |
| `POST /wunder/agents/{agent_id}/memories/{memory_id}/confirm` | 确认候选记忆 |
| `GET /wunder/agents/{agent_id}/memory-settings` | 读取记忆设置（当前承载 `auto_extract_enabled`） |
| `POST /wunder/agents/{agent_id}/memory-settings` | 更新记忆设置 |

## 9. 落地要点

- 模型与前端统一使用 `tag`
- 系统提示词只注入 `memory_id + title`
- 完整内容必须通过 `get` 获取
- 记忆复刻按 agent scope 批量复制，避免前端循环搬运
- embedding 缓存（`memory_fragment_embeddings`）支撑语义评分召回，命中解释与评分轨迹记录在 `memory_hits`
- 旧 `category` 等字段只在解析层兼容，不再向模型和用户侧扩散
