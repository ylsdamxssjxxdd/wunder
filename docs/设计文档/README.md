# wunder 设计总纲

> 本册约束一类改动：新能力该落在哪个层级、哪些语义必须长期稳定、哪些边界不能被短期实现反向侵蚀。凡是要写「怎么接、怎么跑、怎么改」，请写进 `../技术说明书/`；凡是要写「用户点哪里」，请写进 `../使用说明书/`。

## 1. 文档定位与三层分工

`docs/设计文档` 是 wunder 的正式设计母本，只回答三类问题：**为什么这样设计、边界在哪里、长期目标是什么**。

| 文档层 | 回答 | 典型内容 | 不该出现 |
| --- | --- | --- | --- |
| `docs/设计文档` | 为什么、边界、不变量 | 分层职责、状态语义、契约、反例 | 命令、端口、配置键、字段清单、界面步骤 |
| [`../技术说明书/`](../技术说明书/README.md) | 怎么接、怎么跑、怎么改 | 目录职责、链路时序、端点与常量、部署与排障 | 产品承诺、设计动机长文 |
| [`../使用说明书/`](../使用说明书/README.md) | 用户与管理员怎么操作 | 页面动作、能力可用范围 | 内部模块名、协议细节 |

判据很简单：一段文字里出现了可直接执行的命令、端口号、配置键或完整字段清单，它属于技术说明书；出现了「进入某页勾选某项」，它属于使用说明书。设计文档只在章末用链接把事实交出去。

## 2. 系统总述

wunder（心舰）是面向组织与个人的**多形态的智能体工作台**：把目标交给智能体，它拆解任务、调用工具、交付结果。

| 形态 | 定位 | 进程与代码位置 | 前端 |
| --- | --- | --- | --- |
| 蛹（desktop） | 本地 AI 工作台，个人默认入口，主推应用 | 本地桌面进程 `crates/wunder-desktop/`（同进程原生调用引擎） | `frontend-slint/`（Rust + Slint） |
| 蜂巢（web） | 云端 AI 工作台，随舰体提供，浏览器访问 | 无独立进程，只消费舰体接口 | `frontend/`（Vue3 + TypeScript） |
| 舵机（cli） | 手工本地操作入口，终端驱动、脚本化、自动化 | 本地进程 `crates/wunder-cli/` | ratatui TUI |
| 舰体（server） | 用户与智能体管理平台：多租户、用户与单位、智能体应用构建发布、网关接入与调度，内置工具链/知识库/长期记忆 | `crates/wunder-server/` + 引擎 | 提供蜂巢接口，自带舰桥 |
| 舰桥 | 舰体自带的治理界面，面向管理员 | 随舰体 | `web/`（原生 HTML + JS） |

两条不可动摇的事实：

- 蛹与舵机**不依赖舰体**，可独立运行与分发。
- 四个形态共享同一引擎（`crates/wunder-runtime/`）与同一核心（`crates/wunder-core/`），**差异只允许出现在接入层**。可验证判据见 [01 册 §4](./01-系统总体设计.md)。

系统的核心不是一次问答，而是**可持续执行、可恢复、可观察、可治理的智能体运行时**。围绕这个核心，长期特色稳定为下表，代码域按当前真实结构标注。

## 3. 长期特色

| 特色能力 | 设计含义 | 关键代码域 |
| --- | --- | --- |
| 智能体核心 | 线程、用户轮次/模型轮次、prompt、context、工具、恢复拥有稳定语义，集中在一处 | `crates/wunder-runtime/src/orchestrator/`、`crates/wunder-runtime/src/services/runtime/thread/` |
| 实时投影（四层） | 执行快照、durable 提交、变更唤醒、有界展示投影四层分离；前端只消费公开游标，不定义后端真相 | 执行侧 `orchestrator/event_stream.rs`、`orchestrator/thread_log_committer.rs`、`orchestrator/thread_change_hub.rs`、`services/thread_change_feeder.rs`；展示侧 `crates/wunder-core/src/thread_view.rs`、`crates/wunder-runtime/src/storage/thread_view_*`、`services/thread_view_rebuild.rs` |
| 多任务线程 + 子智能体派生 | 一个智能体可同时拥有多个独立任务线程，调度、锁与实时状态按线程隔离；复杂任务临时派生子智能体，任务结束即回收 | `services/runtime/thread/`、`services/subagents/`、`orchestrator/thread_runtime.rs` |
| 多根工作区 | 工作区按形态解析：本地目录、云端目录、互通远程设备目录并存，工具执行始终被路径围栏约束 | `services/workspace.rs`、`crates/wunder-core/src/path_utils.rs` |
| 工具化运行时 | 对开发者来说一切都是接口，对大模型来说一切皆工具 | `services/tools/`、`services/skills.rs`、`services/mcp.rs`、`services/abilities/` |
| 长会话能力 | 冻结 prompt、一次性记忆注入、上下文压缩、恢复链统一治理 | `orchestrator/prompt.rs`、`orchestrator/compaction_policy.rs`、`orchestrator/microcompaction.rs` |
| 云端-本地互通 | 本地节点只出不入，一条隧道承载三平面；影子投影、命令台账、审批工单与 L0–L3 风险分层 | `services/interlink/`、`crates/wunder-core/src/interlink.rs`、`api/interlink*` |
| 多入口共核 | HTTP、WS、gateway、channels、desktop façade、cli 都落到同一 `AppState` 与同一 orchestrator | `crates/wunder-runtime/src/api/`、`gateway/`、`channels/`、`crates/wunder-desktop/`、`crates/wunder-cli/` |
| 双存储形态 | 舰体 PostgreSQL、蛹与舵机 SQLite，共享同一套分域存储契约 | `crates/wunder-core/src/storage_backend.rs`、`crates/wunder-runtime/src/storage/` |

## 4. 设计基线（不变量）

本目录所有分册共同遵守：

- **认知态冻结**：线程首次确定后的 `system prompt` 必须冻结；长期记忆只允许在线程初始化时注入一次。理由是模型侧提示词缓存依赖稳定前缀，也保证线程认知态可复现（[02 册 §7](./02-智能体核心设计.md)）。
- **追加式历史**：线程历史只追加不重写；可见输出项与模型轮次一一对应，身份稳定，补水才能幂等。
- **Snapshot + Delta + Replay**：所有对外实时契约都提供快照、增量与断线补齐三件套；客户端不能自造终态（[03 册 §5](./03-实时投影系统设计.md)）。
- **单写者**：一个事件目标只有一个发布路径；会话锁 + 全局活跃上限 + 引擎级排队与协作让位构成执行准入，不按「一人一会话」设计。
- **展示不反噬执行**：展示读模型只能读、只能限量、只能失效重建，不得参与执行语义判定，也不得改写 durable 内容。
- **有界是默认要求**：队列、缓存、分页、日志、订阅都必须有上界；避免无界队列、无界缓存、无分页查询、全量重算、深层 watch、大对象复制和长时间持锁。
- **治理靠结构**：权限、审批、配额、预算、重试熔断由程序结构保证，不靠 prompt 约定。
- **三形态共核**：`server / desktop / cli` 共享核心语义，只允许接入面差异，不允许分裂成三套系统。
- **原型阶段可删旧实现**：不为低价值兼容性背负长期债务；删除要同步删文档。

## 5. 当前交付边界

设计基线之外，还要如实描述当前可交付范围。旧口径「一人一会话、各自分散聊天」已经过时，按现状替换为：

| 维度 | 当前边界 | 设计后果 |
| --- | --- | --- |
| 并发单位 | 同一用户可**并发多个任务线程**；会话锁保证单线程内顺序，全局活跃上限约束总量 | 准入、排队与观测都以**任务线程**为键，不以用户或会话页为键 |
| 排队与让位 | 引擎级持久队列 + 协作让位：繁忙时新轮次入队，运行中轮次可在动作边界让出槽位；人类消息优先于自动续跑 | 「让位/插话/撤下」是运行时能力，不是前端交互补丁 |
| 恢复 | 启动扫描把遗留 queued/waiting/running/cancelling 收敛为一致状态；断线走 replay 或要求重同步 | 崩溃与断线是显式状态，不靠前端猜 |
| 协作形态 | 只有**子智能体**（临时派生、可复用、有界登记）；蜂群编排能力已从引擎与协议层移除，仅前端标签与兼容垫片残留 | 任何「多智能体群、房间、广场、编排态」相关的表意不得进入设计口径 |
| 工作区 | 多根：本地根、云端根、互通远程根按形态解析；云端读/写/执行在沙盒内完成，租户隔离由沙盒承担 | 路径围栏负责「不出根」，不负责「隔离租户」 |
| 云端-本地互通 | 隧道、影子、命令台账、审批、审计已落地于蛹与舵机；治理面当前是后端 API only，舰桥尚无互通面板 | 文档与验收不得声称「舰桥互通治理面板」 |
| 蜂巢交付 | 蜂巢是舰体的接口消费者；其构建产物由独立静态服务器只读挂载下发，舰体不提供蜂巢页面 | 「蜂巢随舰体提供」指功能依赖，不指静态资源托管 |
| 渠道 | 渠道以 adapter 契约扩展，仅注册进 registry 的平台才是能力承诺；未注册平台不得写进任何文档 | 渠道清单以 [07 册](./07-接入、网关与渠道系统设计.md) 与代码 registry 为准 |
| 本地前端 | 蛹默认且唯一现役前端是 `frontend-slint/`；网页壳形态已停止日常维护与功能迭代，不作为能力描述 | 停止前端壳 ≠ 停止蛹后端 |
