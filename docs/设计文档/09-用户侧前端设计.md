# 用户侧前端设计

> 约束范围：本册约束四个前端形态（蛹 Slint、蜂巢 Vue、舵机 TUI、舰桥 HTML+JS）的职责边界、渲染与实时消费纪律、以及「幽灵能力」判定口径。能力矩阵不在本册维护（唯一来源是使用说明书的能力清单）；目录结构与构建细节见 `../技术说明书/02-仓库结构与模块职责.md`。

## 1. 总不变量：前端不是状态真相源

四个前端共享同一纪律：

| 允许 | 禁止 |
| --- | --- |
| 消费后端投影（snapshot / delta / replay / 补水端点） | 自建线程状态机或用前端推导定义终态 |
| optimistic 交互，接受后端回压校正 | 用页面特判规避后端状态不一致 |
| 本地缓存，明确版本与失效 | 以强制重建组件树掩盖副作用边界问题 |
| 有界缓冲、限量加载 | 全量拉取历史、整表重渲染 |

后端 durable 层（`thread_log_changes` 等，见 `08-数据存储与状态模型设计.md`）是唯一真相；「连接控制器断线/替换」不等于「任务终态」这类区分在四端都成立。

## 2. 四形态职责边界

| 形态 | 技术 | 定位 | 边界 |
| --- | --- | --- | --- |
| 蛹 | Rust + Slint（`frontend-slint/`） | 本地 AI 工作台默认前端 | 同进程强类型 façade 调引擎（`wunder-desktop::NativeDesktop`），不经本机 HTTP/WS；能力面是本地单用户全集 |
| 蜂巢 | Vue3 + TS（`frontend/`） | 云端 AI 工作台（随舰体，nginx 分发） | 单一 `/chat/ws` 连接多路复用（`utils/ws.ts` + `chatWatcher`），不得同时开多条 WS；面向多用户与云端工作区语义 |
| 舵机 | ratatui TUI（`crates/wunder-cli/`） | 手工本地操作入口 | TTY 三端判定进 TUI，非 TTY 降级一次性 exec；`exec --json` 的 JSONL 是脚本契约 |
| 舰桥 | 原生 HTML+JS（`web/`） | 治理与调试面 | 归 `10-管理员侧与运营后台设计.md` 约束，本册只记其前端纪律 |

蛹与蜂巢**不共享实现**，只共享体验语义（工作过程、线程轨迹、目标态等同名概念）。不要求 Slint 复刻 TS 端全部视觉效果——Markdown 最低必要能力（纯文本保底，段落/列表/代码块可逐步支持），复杂内容降级为可读文本时原始消息与复制内容必须完整。

## 3. Slint 侧渲染纪律（蛹）

以下纪律来自工程基准并在代码中兑现，验收时逐条对应：

| 纪律 | 要求 |
| --- | --- |
| 按帧合并增量 | token 增量按约 16–33ms 节奏合帧，按实测调整；不得每个 token 重建消息列表、复制全部历史或重解析长消息 |
| 有界缓冲 | 事件缓冲必须有界，合并文本增量不丢字；完成与错误状态及时落地 |
| 块级组织 | 长消息按块组织，已完成块保持稳定，**只更新活动尾块** |
| 虚拟列表 | 历史消息限量加载与增量行更新；用户停留在底部才自动跟随，上滚时保持位置 |
| 行高单一来源 | 行高计算只允许一个来源，滚动与测量不得各算各的（改高才重建前缀） |
| 后台解析 | 网络读取、事件处理、较重解析放后台线程，UI 线程只应用必要增量 |
| 输入不阻塞 | 接收输出期间输入、选择、复制、滚动不能被长任务阻塞 |

主窗结构保持克制：页面枚举只有 `messages | settings`（`ui/theme.slint:144`，已实测），其余能力以面板/对话框挂载（终端、工作区文件、线程轨迹、子智能体详情、渠道、定时等）。设置页 12 个分类。新增页面能力走 `crates/wunder-desktop/` 的强类型 Rust façade（façade 公开函数在 `src|ui` 都有同名调用点），不新增 IPC 协议层。

i18n 纪律：`ui/i18n.slint` 是生成物（GENERATED 头），唯一写入口是 `scripts/build_i18n.py`；Rust 侧直接消费 `I18n.*` 的模块极少，其余为手写双语——新增文案先确定归属通道，不制造第三个来源。

## 4. 蜂巢大数据量渲染边界

蜂巢把「渲染重活」推到明确边界内：

| 机制 | 落点 | 边界语义 |
| --- | --- | --- |
| Worker 渲染 | `workers/chatRender.worker.ts`、`chatThreadSnapshot.worker.ts` | Markdown/正文解析在 Worker，主线程只收渲染产物 |
| 虚拟窗口 | `views/messenger/messageVirtualWindow.ts`、`messageViewportRuntime.ts` | 按列表身份与布局版本缓存高度前缀；滚动只查找窗口，行高变化才重建前缀 |
| 有界尾窗 hydrate | `realtime/chat/threadBodyReader.ts` + `components/chat/ThreadBodyViewport.vue`、`stores/threadViewLoader.ts`（bootstrap / chat-page / search 三类视图请求） | 详情补水先建立 canonical 顺序（消息/用户轮次/模型轮次），再重放活跃尾部；重复补水保留未入 transcript 的实时尾部，不删已进事件去重索引的消息 |
| 版本化投影 | canonical reducer + `markRaw` 投影，按结构版本与消息级内容版本发布 | 文本增量只唤醒对应正文组件；历史行按对象身份复用；HTTP 快照带请求版本与序号，旧响应不覆盖更新的 WS/本地状态 |

缓存必须有上界（HTML 缓存与历史正文缓存各有项数与体积上限），流式正文用单 Text 节点追加、结束后再渲染 Markdown，不设超阈值反复全量渲染的分支。

## 5. 幽灵能力纪律（本册核心口径）

**写了属性、声明了 i18n 键、实现了后端 façade，但 UI 没有渲染引用——不算已实现能力。** 判定方法：从 `ui/*.slint` 与 `src/*.rs` 检索键名/回调标识的引用数，引用为零即幽灵。已实测两例：

| 案例 | 现象 | 证据 |
| --- | --- | --- |
| 蛹设置页「设备互通」面板 | 组件声明了属性/回调与状态纯函数，Rust 侧 `src/native_interlink.rs` 在填数据，但为其准备的 i18n 键（`stc_interlink`、`il_tunnel_title` 等）在 `ui/` 与 `src/` 的引用数为 0（已实测） | 「实现了但没接线」；蛹真实可用的互通面只有侧栏云端工作区与远端命令审批弹窗 |
| 蛹 TTS | 只有语音**输入**链路；可配置 tts 模型但没有任何播放调用点 | 蛹语音条目只能写「输入」，写「双向语音」即失实 |

幽灵能力在文档中只允许出现在「缺口/未接线」语境；写进用户能力清单属于文档缺陷。同类残留（蜂群文案、`hive_id` 前端读写、`vite.config.ts` 无消费者的 desktop 构建注入）记录在 `10` 册与工程缺口清单。

## 7. 验收判据

- 流式验收：长消息连续增量下 UI 更新耗时、积压、内存可控；输出期间输入/滚动/选择不卡；断线恢复后文本完整无丢字。
- 渲染纪律验收：改坏任一有界常量（缓冲上限、缓存上限、页大小）应能在压力用例中变红。
- 能力清单验收：文档每条目都能在渲染层找到引用；幽灵项只出现在缺口章节。
- 效果检验优先用 `slint-viewer` 即时预览，完整构建截图不是默认验收手段。
