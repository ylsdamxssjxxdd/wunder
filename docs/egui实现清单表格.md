# wunder-egui 实现清单

> 状态：实验性验收清单，用于验证 egui 可行性；后续 `crates/wunder-egui` 的功能、视觉与发布工作以本清单为参照。  
> 更新：2026-10-20；优先级：**蜂巢视觉和交互样式优先，蛹的本地能力与运行语义随后对齐**。  
> 范围：egui 原生蛹候选与 egui WASM 蜂巢用户工作台候选；不包含舰桥治理界面。  
> 远期方向（本阶段不做）：WASM 工作台成熟后可由 wunder-server 直接托管静态产物，收敛掉 docker-compose 中的 node 构建容器与 nginx；可行性验证阶段不改动 compose 拓扑。

## 1. 使用规则

1. 每项只能在同时满足“目标与验收标准”“性能/平台约束”“验证方式”后改为 `完成`。只有界面外形的项目使用 `已呈现，待验收`，不能等同于功能已完成。
2. 样式冲突时依次以蜂巢实际页面、蛹 Slint 行为、本文清单、egui 当前实现为准。不得从截图臆测后端状态，也不得复制蜂巢的业务逻辑到 UI 层。
3. egui 只通过 `BackendPort` 和平台适配器提交命令、消费事件；本地语义复用 `wunder-desktop::NativeDesktop`，WASM 复用舰体既有 HTTP/WebSocket 契约。
4. 每完成一项，在本表更新状态、证据路径和日期，并通过 `python scripts/update_feature_log.py` 写入 `docs/功能迭代.md`。发现反复问题时同步记录至 `docs/经验教训.md`。
5. 所有截图、性能样本和测试 fixture 使用合成数据；不写入真实账号、路径、密钥、用户内容或业务场景。
6. 原生模式保持同进程后端（NativeDesktop worker），不引入本机 HTTP/WebSocket；WASM 是唯一走网络的形态。WASM 产物以 Trunk release 预构建为发布资产，运行环境不要求 node 或 nginx。

### 状态定义

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚无可用实现。 |
| 已呈现，待验收 | 有 UI 或演示实现，但缺真实行为、自动验证或视觉对照。 |
| 部分完成 | 核心路径可用，仍缺本行定义的能力或边界。 |
| 待修复 | 已证实存在错误，必须修复后才能继续依赖该能力。 |
| 阻塞 | 依赖的协议、Façade 或目标平台尚不可用。 |
| 完成 | 本行验收、性能约束及验证证据均已满足。 |

## 2. 固定视觉验收基线

除特别说明外，视觉验收使用浅色主题、100% 缩放、1440×900 逻辑像素、固定合成聊天 fixture，并在同一系统字体与 DPI 条件下比较。先校验几何和状态层次，再处理文字栅格差异。

| 项目 | 蜂巢/蛹目标值 | 验收尺度 |
| --- | --- | --- |
| 页面与侧栏 | canvas `#FBFAF8`；侧栏 `#F6F5F3`；240px 固定基线；二栏满高；无通用主顶栏 | 面板边界、分割位置和主要控件尺寸误差不超过 1px；位置误差不超过 2px。 |
| 阅读列 | 聊天和 Composer 共用居中、最大 1000px；活动多轮时右缘预留 18px 刻度通道 | 阅读列、输入卡、刻度通道必须同轴，窄窗不横向溢出。 |
| 色彩与文本 | 文本 `#1F2329/#3D3D3D/#8A8F99`；边框 `#E8E6E3/#D8D5D0`；默认强调 `#C96443`；中文优先复用蛹字库，代码回退等宽字体 | 非文字实色区域 RGB 偏差不超过 3；字号、粗细、行高和换行按对照逐项核对。 |
| 尺寸节奏 | 字号 11/12/13/14/15px；圆角 6/10/12/22px；工作区 34px、线程 28px、目录 26px、底部账户 32px | 鼠标命中区不因 hover、加载或选中改变尺寸。 |
| 状态与动效 | hover、active、focus、selected、disabled、loading、error 均有非颜色提示；支持 reduced-motion | 流式输出以真实事件为准；关闭动效后不影响状态、焦点、阅读位置。 |
