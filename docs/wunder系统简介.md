# wunder 心舰简介

wunder（心舰）是一个**多形态的智能体工作台**：把目标交给智能体，它把目标拆成任务，在带工具的执行环境里一步步做完，最后交付结果。

## 上手方式：蛹（desktop）

**蛹（desktop）是 wunder 的本地 AI 工作台，也是主推的应用。** 个人用户下载安装即可使用，不需要先部署任何服务，打开就能把目标交给智能体。

蛹在本地运行：默认前端 `frontend-slint/`（Rust + Slint 原生界面、软件渲染），启动后在**同一进程内**直接调用引擎，不经本机 HTTP / WebSocket；SQLite 本地存储；兼容目标下探到 Windows 7 32 位，Linux 侧按 ubuntu18.04 基线打包（x64 / arm64 AppImage）。它可以操作本地文件、窗口和浏览器，也可以在需要时经互通隧道连接云端。Electron / Tauri 前端壳已停止日常维护——停止的是壳，不是蛹后端。

## 核心概念

```text
wunder
├─ 用户
│  ├─ 智能体（worker card 定义的干活角色）
│  │  └─ 任务线程（可多个并行，互相隔离）
│  └─ 工作区（本地目录 / 云端目录 / 远程设备工作区，可并存）
└─ 渠道 / 网关 / 互通（外部接入面）
```

- **用户**：资源与数据的归属主体，相互隔离。舰体形态下按单位树组织（最深 4 级），单位负责人（leader）只在授权范围内管理后代单位的用户。
- **智能体**：具体干活的角色，有自己的模型配置、工具集、知识库和长期记忆。智能体以 worker card（`.worker-card.json`）作为可移植定义，由管理侧构建与发布，会话通过 agent_id 绑定智能体。
- **线程**：智能体里连续的执行上下文，一次任务的全过程都发生在线程里。**一个智能体可同时拥有多个独立任务线程**，调度、锁与实时状态都按任务线程隔离。
- **工作区**：工具执行的工作目录。蛹是本地目录，可直接读写本机文件；舰体形态下智能体的云端目录呈现为 `/workspaces/<用户>/workspace`；互通场景还允许把远程设备的工作区作为目标。三者可以并存。
- **子智能体**：主智能体在任务中临时派生的工作单元，任务结束即回收，不是独立智能体。子智能体是 wunder 唯一的协作形态（旧的蜂群编排已从引擎与协议层移除）。

线程内部按两级计量：**用户轮次**每发送一条消息记 1；**模型轮次**是引擎主循环每发起一次模型调用记 1——一个模型轮次内可以包含一批工具调用，工具调用本身不额外计轮次。一个用户轮次里往往有很多个模型轮次，工具循环就发生在这里。

## 它怎么干活

1. 目标进入线程。system prompt 在首次确定后冻结，长期记忆以索引形式只注入一次，之后不再改写，以保住模型的提示词缓存。
2. orchestrator 组装上下文，发起模型调用。运行中再发消息会进引擎级会话队列（排队条可见、按序执行）；智能体也可以主动「会话让出」，稍后再被唤起。
3. 模型返回工具调用时，运行时解析参数、按需请求审批（读 / 写 / 执行 / 控制四档，执行策略支持 Allow / Audit / Enforce 三态），并行执行工具（可并行白名单内并发不超过 4），把裁剪后的结果喂回模型，进入下一轮循环。文件、命令、浏览器、桌面控制、网页抓取、外部渠道，全部走这一条治理链路。
4. 全程以流式事件对外发布（六个 WebSocket 通道）。桌面端、网页端都只是这些事件的投影：按帧合并增量、分页读取投影表、有界缓冲；断线后靠游标快照与补水端点恢复现场。
5. 上下文快满时，先对更旧的可复现工具观测做本地微压缩，还不够再触发历史压缩生成交接摘要、重建历史。长会话因此可以一直工作下去。
6. 任务完成或用户停止后，线程状态落库，重新打开都能原样恢复。治理限额（会话锁、活跃会话上限、日配额、轮次上限、重试熔断）贯穿全程。

## 形态与定位

wunder 的四个形态各有明确分工：

- **蛹（desktop）——本地 AI 工作台**：主推应用，个人用户默认入口。本地运行、离线可用，直接操作本机文件、窗口与浏览器。
- **蜂巢（web）——云端 AI 工作台**：随舰体提供的网页端（Vue3 + TypeScript），浏览器访问，供多人使用。构建产物 `frontend/dist` 由独立的 **nginx 容器**只读挂载对外服务（默认端口 18001）；舰体本身只托管舰桥和少量静态资源，不托管蜂巢。
- **舵机（cli）——手工本地操作入口**：终端 TUI（ratatui），面向手工操作、脚本化与自动化；`exec --json` 提供 JSONL 契约，`cloud` 子命令族走互通与云工作区。舵机默认关闭定时任务。
- **舰体（server）——用户与智能体管理平台**：需要多用户、多租户、组织治理时才部署。管理用户与单位、构建与发布智能体应用（worker card）、接入渠道与网关，内置工具链、知识库和长期记忆；PostgreSQL 存储，Docker 部署。

舰体自带治理前端**舰桥**（`web/`，原生 HTML + JS，无构建步骤，挂载于舰体 `/`），面向管理员，按系统 / 智能体 / 调试 / 文档四组共 19 个面板组织。舰桥是治理面，不提供普通用户的聊天工作台——那属于蜂巢与蛹。

各形态共享同一套引擎（wunder-runtime）与核心（wunder-core）：线程、工具、存储抽象、实时事件和权限语义是同一份代码，差异只在接入层。蛹和舵机不依赖舰体，可独立运行与分发。

## 设计上的几条硬规则

- 对开发者来说一切都是接口，对大模型来说一切皆工具。
- 线程 system prompt 一旦确定就冻结；长期记忆只在初始化时注入一次，中途不改写。
- 前端不是状态的真相源。后端发事件流，前端消费投影；乐观更新最终要被事件回压校正。
- 所有外部能力都是工具，走统一的审批、超时、预算和结果裁剪，不靠提示词自觉。展示裁剪与模型输入裁剪是两条独立通道。
- 舰体用 PostgreSQL（日志大表按月分区、用量走增量计数与水位对账），蛹与舵机用 SQLite，共享同一套分域存储契约。
- 有界优先：队列、缓存、分页、事件缓冲一律有界；列表与日志面板必须分页或限量。

## 能力概况

- **多线程与目标态**：单智能体可并行多个任务线程；目标态由单一 `goal` 工具驱动（`action=get|create|edit|pause|resume|complete|blocked`），phase 只有 active / paused / blocked / complete，靠轮次计数推进（默认目标轮上限 256，连续无进展 3 轮自动 block）。没有 token 预算与冷却机制。
- **协作**：子智能体（list / history / send / report / spawn / batch_spawn / status / wait / interrupt / close / resume 共 11 种动作）。蜂群编排已移除，不作为能力提供。
- **工具链**：文件、命令与命令会话、浏览器（单一严格 `browser(action=...)` 工具）、网页抓取、桌面控制与监视、读图、多模态四件套（语音生成 / 声转文 / 图像生成 / 视频生成）、计划 / 问询面板、定时任务、记忆管理。扩展机制三层：**工具 = 执行体，技能 = 可调用知识与脚本（技能名本身可直接被调用），能力（abilities）= 管理员治理面的选择单元**。MCP 双向：既是客户端（`server@tool` 命名、支持打包折叠），也内置服务端端点 `/wunder/mcp`。`网页搜索` 与 `ptc` 代码保留、当前临时下架。
- **知识库三型**：内置词面检索、内置向量检索（分块 + embedding 检索）、外部 RAGFlow 数据集，按库动态注册为可调用能力。
- **长期记忆**：片段三层（L0 标题 / L1 摘要 / L2 正文）加 core / working / peripheral 分级与升级规则，线程初始化注入一次，轮末自动提取候选；作用域为「用户 + 智能体」。
- **渠道接入**：已注册 7 个渠道 adapter——飞书、QQ 机器人、Weixin、微信、微信公众号、WhatsApp Cloud、XMPP。其中飞书 / QQ 机器人 / Weixin / XMPP 有长连接支持（XMPP 在默认 feature 关闭时为占位实现），微信、微信公众号、WhatsApp Cloud 仅 webhook 形态。Telegram、Discord、Slack、LINE、DingTalk **没有实现**，只是通用 webhook 的目录项。入站有界队列、出站持久 outbox 加退避与令牌桶限流。
- **网关**：不是 HTTP 反向代理，而是接入注册表 + 定向 RPC + presence 广播的 Hub，走 `/wunder/gateway/ws` 一个 WebSocket 传输面，operator / node / channel 三角色。
- **互通（interlink）**：云端（舰体/蜂巢）与本地设备（蛹/舵机）之间的反向隧道与命令面：节点、影子投影、命令台账、审批工单、审计，命令按 L0–L3 风险分层——`tool.exec` / `agent.spawn` 属 L3，默认设备能力集不含 L3，高危命令需人工审批且审批不可记忆。
- **定时任务**：`at` / `every` / cron 三种排程（5–7 字段 + 时区，支持自然语言），租约与并发上限、退避阶梯、连续失败自动禁用。
- **认证与治理**：口令 Argon2；token 为不透明随机串（非 JWT），刷新走 OAuth 式族轮换、重放即整族吊销；管理面经 api-key / 管理员 Bearer 双重门，leader 按单位开孔。
- **形象系统**：ZIP 包 + 精灵表驱动的桌面浮窗（蛹为 Win32 分层窗口）与网页端悬浮层。
- **观测**：结构化日志（JSONL）、运行时指标与告警、渠道运行日志（内存环形有界）、监控状态机与线程轨迹；吞吐压测与渲染压测端点内置。

## 上手

- **个人用户**：从 Releases 下载蛹安装包，装上就能用（本地 AI 工作台），见[蛹入门](docs/使用说明书/zh-CN/start/desktop.md)。
- **团队**：需要统一治理时部署舰体（用户与智能体管理平台），成员通过浏览器访问蜂巢（云端 AI 工作台），管理员用舰桥治理，见[舰体部署](docs/使用说明书/zh-CN/start/server.md)。
- **开发者与自动化**：用舵机（手工本地操作入口）或直接调 API，见[舵机使用](docs/使用说明书/zh-CN/start/cli.md)。

对外集成面一览：REST `/wunder/*`、WebSocket 实时通道（聊天、core、网关、互通、世界会话、LAN）、MCP 端点 `/wunder/mcp`、外部工作流 SSE `/wunder/external/workflow*`、渠道 webhook 回调。错误统一返回 `{ok:false, error:{code, message, hint, trace_id}}` 包络并回写 `x-trace-id` 响应头。
