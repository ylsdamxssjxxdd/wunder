# 2026-10-24 蛹发送、取消与收尾优化

本轮按发送准备、取消及队列撤回、执行收尾的顺序优化正式后端。测量通过外部 Release 探针调用 `NativeDesktop`，无需最终蛹程序、前端或独立 bridge。模型使用进程内固定合成服务，结果不代表公网模型或界面响应时间。执行方案见 [蛹体验测试方案](../蛹体验测试方案.md)，结构化测量与逐次指标见 [JSON](2026-10-24-desktop-latency.json)。

## 实现

- 线程状态、接入队列和历史投影复用 SQLite 连接，每个池最多保留 2 个空闲连接，每连接配置约 1 MiB 页缓存。SQL 执行期间不持有池锁；连接归还时回滚未完成事务，回滚失败则丢弃。分支读取带临时视图，继续使用独立只读连接，避免作用域串用。此上限限制空闲保留量，活动操作仍受既有后台并发门控制。
- 取消等待接入已有线程通知与子执行取消令牌，先订阅再检查权威取消状态，保留 200 ms 检查作为旧路径兜底。正常停止无需等下一次轮询；取消来源、线程隔离和持久终态保持原有契约。
- 撤回操作直接返回已验证归属的目标任务正文，去掉撤回前额外列举队列的读取。
- 流式完成信号通过有界队列可靠送达；事件泵同时等待执行任务与消费队列，执行结束后排空尾部事件。完成信号与清理交叠时不会忙循环，多次完成通知也能正常排空。
- 外部探针读取正式运行时后台操作计数器，保存测量窗口内调用次数、累计排队和执行时间。它们包含断言读取与并发工作，用于定位重复操作，不能相加作为单请求分段耗时；亚毫秒操作可能被整数毫秒计数记为 0。

## 对照方法与结果

Windows 11 x64，32 个逻辑处理器，约 64 GiB 内存，Rust 1.95.0 MSVC，Release、thin LTO，启用 `sqlite-storage,desktop-control`。保存修改前后二进制；各场景先预热一组，再交替执行 20 组，每组交换先后顺序。每次使用独立进程和隔离合成目录。P50/P95 采用 nearest-rank，预热不入统计。

| 操作与计时终点 | 优化前 P50 / P95 ms | 优化后 P50 / P95 ms | P50 耗时减少 |
| --- | ---: | ---: | ---: |
| 发送 → 模型请求到达 | 309.963 / 358.536 | 162.244 / 181.006 | 47.7% |
| 发送 → 首个文本增量 | 318.596 / 368.770 | 172.401 / 190.290 | 45.9% |
| 停止 → 流关闭并完成清理 | 265.871 / 282.975 | 28.547 / 36.839 | 89.3% |
| 队列撤回并返回正文 | 186.117 / 390.529 | 28.191 / 64.992 | 84.9% |
| 源端最后增量 → 正常流关闭 | 124.999 / 134.334 | 33.969 / 39.514 | 72.8% |

以上每版各 80 次正式进程调用及 4 次预热均通过正确性断言；撤回指标每进程含 2 条，共 40 个值，不能当作 40 个独立进程。另一普通流式场景的模型请求 P50 为 309.661 → 173.644 ms，收尾为 122.907 → 35.680 ms。

**首轮总门禁未通过**：插话 P95 为 22.797 → 57.002 ms，超过默认相对 20% 且绝对 5 ms 的阈值，其余指标未触发门槛。保留该告警后，固定相同负载补做 30 组队列交替对照，前后各 30 次正式调用及 1 次预热全部通过；插话 P50/P95 为 7.099/30.815 → 8.218/25.869 ms，补测所有队列指标均未触发退化门槛。没有调整阈值或删除异常样本。两批数据不能拼成同一稳定分布，插话尾延迟仍需无并行负载的正式复核。

当前共享工作区存在其他开发者编译。首轮期间观察到 cargo/rustc；队列补测记录了每次启动时的进程名，两个版本各 31 次均存在构建进程。交替顺序降低负载漂移影响，但不能消除干扰，因此这些数值用于开发优化判断，不能作为发布性能承诺。

## 资源成本与剩余瓶颈

首轮发送场景，进程 CPU 的 P50 从 437.500 降至 203.125 ms；进程逻辑读取中位数从约 7.18 降至 2.76 MiB，读取次数从 1,996 降至 756。采样 RSS 峰值的中位数从约 39.55 增至 40.30 MiB，句柄峰值中位数从 173 增至 188，私有内存峰值中位数约 15.09 → 12.56 MiB。资源窗口含探针模拟服务、断言和后台工作，不能解释为某函数的独占资源。

连接保留有固定内存及句柄成本，不能称为零成本缓存；长期有界性仍须在固定工作集 soak 和目标平台复核。没有降低 SQLite 持久化配置、移除权限检查、绕过执行锁或修改冻结系统提示词。

优化后计数器提示下一轮可追踪：

1. 发送窗口的 `native.goal.check`，每次约 15.7 ms 累计执行；线程状态读平均仍有约 76 次，虽然累计仅约 5.0 ms，仍可审查调用合并空间。
2. 队列窗口的 `thread_change_feeder.read`、`native.follow.control` 与 `native.follow.control_history` 反复读取。累计耗时互有重叠，先定位队列订阅与持久状态投影的重复查询，再决定是否合并读取，不能直接用累计值推算接口提速量。
3. 插话尾延迟和目标平台上的连接保留成本，优先在无并行编译时重复采样并抓取等待栈。

## 验证与限制

- Rust 152 项通过，1 项既有 Release 压力实验忽略；覆盖存储、事务归还、跨连接提交可见性、分支、取消唤醒、队列权限与终态、流尾清理及背压。
- Python 外部基准测试 18 项通过。既有统计测试补足模型请求登记，修改前测试二进制也可复现其原来的失败，未调整生产统计语义。
- 完整统一 smoke 通过：100×100 日志七项读取及 11 个体验场景；恢复仅指正常退出后重启，短时持续运行不证明长期稳定。
- 100×100 日志每场景另测 10 次及 1 次预热，共 77 次读取全部通过，权威日志哈希不变。首次打开 P50/P95 为 14.136/16.827 ms，历史翻页 5.694/8.440 ms；本轮未保存恰好对应修改前的聊天探针，因此这组不是严格同期前后对照，不能据此宣称新的打开收益或全部尾延迟无回退。
- 1024 块、配置源间隔 1 ms、每次增量消费暂停 20 ms 的压力通过，缓冲峰值达到 128 条，实时原文、最终回复与权威正文一致，完成正常关闭，资源采样未截断。约 4.94 秒的源端结束后耗时包含消费者主动等待与排空，不是普通收尾耗时。
- 早期修改前探索运行曾有 1 个 stream 失败；另一次完整修改前基线及本轮交替对照均通过。没有确证该次失败根因，不能据此断言本轮修复已消除它。失败记录在 JSON 中保留。
- 未执行 Win7 x86、Ubuntu 18.04 x64、2 小时 soak、实际工具阻塞取消、强杀恢复及前端布局绘制验收。

## 持续复测

常规 daily 使用正式外部驱动生成新 Release 探针与匹配负载的基线；更换代码后不要复用旧探针。前后比较必须使用相同配置、构建参数、环境和夹具。

```powershell
python scripts/desktop-bench/measure-experience.py --profile daily --cases submit,stream,cancel_resume,queue --output target/desktop-experience/latency-daily-next
python scripts/desktop-bench/measure-experience.py --profile daily --cases submit,stream,cancel_resume,queue --baseline target/desktop-experience/latency-daily-next/report.json --output target/desktop-experience/latency-daily-compare
python scripts/desktop-bench/measure-experience.py --profile smoke --output target/desktop-experience/unified-next
python scripts/desktop-bench/measure-experience.py --cases slow_consumer --chunks 1024 --interval-ms 1 --output target/desktop-experience/backpressure-next
```

本地完整原始产物保存在 `target/desktop-experience/latency-paired-001/`、`latency-queue-paired-002/`、`latency-unified-001/`、`latency-backpressure-001/`，大日志另测保存在 `target/desktop-chat-open/latency-regression-001/`。归档 JSON 保存构建哈希、汇总、逐次指标、资源与诊断摘要，不含实际用户数据或机器绝对路径。
