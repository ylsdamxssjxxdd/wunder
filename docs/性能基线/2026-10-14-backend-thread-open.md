# 2026-10-14 线程打开与历史分页验收

## 环境与方法

蜂巢通过 `docker-compose-x86.yml` 的 nginx 访问舰体，存储为 PostgreSQL 16；浏览器为 Playwright Chromium。重启服务端、重建前端后，使用已有大历史压力线程做只读检查，不发送模型任务。账号、令牌、线程标识及消息内容不写入报告。

先测 5 个普通线程，随后对大线程连续打开 6 次、进行两组各 4 路并发打开、读取 8 页历史（160 个互不重复的用户轮次）及 3 页轨迹。浏览器打开 5 个普通线程，再重复打开大线程 3 次、向上翻页 9 次，最后进入轨迹页。每个请求同时检查 HTTP 状态、页面非降级、行数上限和游标推进。

## 本次结果

| 指标 | 实测 |
| --- | --- |
| 普通线程 bootstrap | 11–15 ms，5 次 |
| 大线程 bootstrap | 69–73 ms，6 次，约 32 KiB/次 |
| 大线程 4 路并发 bootstrap | 74–81 ms，8 次 |
| 历史页，每页 20 个用户轮次 | 106–146 ms，8 次，约 47–54 KiB/页 |
| 轨迹页，每页最多 80 项 | 14–17 ms，3 次，约 47–48 KiB/页 |
| 浏览器会话打开失败提示 | 0 |
| 浏览器 pageerror / console.error | 0 / 0 |
| 浏览器展示接口 HTTP 错误 / 降级页面 | 0 / 0 |
| 应用状态初始化 | 289.3 ms（不含源码编译） |
| 空闲服务端 CPU 抽样 | 约 0.5%–1.3%（Docker 百分比） |

之前单次历史页约 1066 ms；本次测量与此前不是严格同负载、同缓存对照，不据此声称确定的加速倍率。重启后的 Rust 源码编译持续数分钟且 CPU 很高，必须与二进制启动和运行期分开统计。

## 实现与复杂度

- 页内最新执行、统计、消息、正文块、思考块最多五组数据库往返；每个子查询先限制结果，再 `UNION ALL`，没有把统计恢复成全线程聚合。
- 最新执行每个根轮次仅取 1 条；统计每轮最多读取 512 个可见条目，属于有界指示值，完整工作过程从轨迹分页读取。
- 消息定位继续依赖索引。实库执行计划显示最新执行命中 `idx_thread_execution_view`；消息读取使用分区复合索引，本次末轮用户/助手代表项分别返回 1/2 个候选，未扫描整线程。索引过滤成本仍取决于数据分布与分区数量，不能把返回 LIMIT 当作任意数据下恒定扫描量的证明。
- 同会话共享尚未取消的打开请求；快速切换同步移除取消任务，退出清理预取与请求；较新的同版本页面先到时保留它，不把正常竞态当打开失败。
- 智能体终态状态集合移到共享模块，避免跨安装函数引用导致 Vue 捕获 `ReferenceError` 后状态更新中断。

## 回归入口

```text
cargo test -p wunder-runtime storage::sqlite::thread_view_store::tests --lib
npm run test:thread-view --workspace frontend
npm run test:chat-thread-pipeline --workspace frontend
npm run test:chat-perf-heavy-history --workspace frontend
npm run test:agent-runtime-state --workspace frontend
```

存储测试 10 项通过、1 项显式大规模磁盘基准未运行；打开竞态测试 5 项通过，另有展示窗口协议回归；聊天管线 55 项、历史性能指标 5 项、智能体状态 10 项通过。浏览器 mock 生命周期用例也通过。

生产只读脚本为 `frontend/scripts/verify-thread-view-live.mjs`，从标准输入读取 JSON 字段 `username`、`password`、`session` 及可选 `origin`，使用独立登录 scope，不替换用户正常网页登录。脚本只输出耗时、字节数、类型和计数，不持久化凭据或会话内容。页面控制台出现错误也会判失败。

## 边界与未通过项

这是大历史读取回归和小规模并发验收，不是多租户容量认证。元数据仍使用普通数据库通道；高并发排队、冷缓存、分区长期增长以及不同单轮数据分布仍需容量测试。数据增长不再让本次聊天页读取全部历史，但不能据此承诺任意用户量下无延迟。

全量 Vue 类型检查仍被已有 `__mci_check.ts` 临时文件错误阻塞；旧 `test:chat-consistency` 中六项仍使用此前详情/events/workflow mock 协议，与当前展示 bootstrap 不一致，尚未迁移。新行为回归和生产页面验收不替代这些全量检查。
