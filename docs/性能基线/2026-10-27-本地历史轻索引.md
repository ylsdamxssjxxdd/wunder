# 本地历史轻索引性能基线

## 结论与边界

本轮补测蛹与舵机共享的本地历史存储路径，不测模型网络请求、渲染或整个应用启动。普通未压缩历史的固定大小分页在两档样本中保持毫秒级；压缩正文读取和全文扫描存在明确代价，不能宣称所有操作都比重构前快。

- 环境：Windows 11 x64、Ryzen AI Max+ 395、约 64 GiB 系统可见内存，Rust debug 未优化构建。
- 使用独立临时目录和生产 `generate_stress_thread` writer/projector，复杂场景、seed=7，每个用户轮次请求 4 次模型动作；不发出真实模型调用，不打开已有用户历史。
- 普通读和重开各采样 30 次，搜索和压缩正文各采样 10 次。中位数与最近秩 P95 均以单次 API 返回为界，返回对象的释放不计入时间。
- 未清理操作系统文件缓存；首次读取也不是冷盘测量。未测 Win7 32 位、Ubuntu 18.04、机械硬盘、并发负载或 CPU/RSS 峰值。
- 没有同环境重构前的端到端延迟基线，不报告加速倍数。迁移数据由生产日志反构旧 `item_json` 表并恢复同组条目索引，其余表保留当前结构，不能代表所有旧安装的迁移耗时。

## 读取延迟

每格为“中位数 / P95”，单位 ms。

| 操作 | 1,118 条目 | 5,591 条目 |
| --- | ---: | ---: |
| 存储重开，无迁移 | 3.74 / 4.85 | 3.86 / 4.69 |
| 聊天预览页，12 用户轮次 | 11.53 / 13.84 | 11.39 / 11.84 |
| 轨迹预览页，80 条目 | 9.53 / 12.46 | 9.86 / 10.65 |
| 完整条目页，20 条目 | 4.56 / 5.01 | 4.96 / 5.61 |
| 单项完整正文 | 2.10 / 2.65 | 2.28 / 2.92 |
| 无命中全文搜索 | 237.14 / 244.35 | 303.56 / 303.70 |
| 压缩后聊天预览页，12 用户轮次 | 9.26 / 9.56 | 11.02 / 11.38 |
| 压缩后完整条目页，20 条目 | 13.62 / 14.13 | 46.53 / 48.17 |
| 压缩后单项完整正文 | 11.92 / 13.19 | 42.95 / 44.61 |

重开后的第一张完整条目页分别为 6.66 ms 和 5.96 ms，仅各一次，不计算分位数。存储重开不包括应用装配、设置、模型连接等启动工作。

聊天预览与完整条目分页不是同一路查询：前者还装配轮次、执行状态、反馈等信息，不能直接按两行数字判断预览设计优劣。普通/压缩预览的差异包含采样顺序和缓存噪声，不表示压缩加速预览。

全文搜索不建立另一份正文或 FTS 副本，最新优先扫描原件；当前预算为 8,192 条、64 MiB、约 300 ms。较小样本无命中扫描完成，较大样本触及预算，返回 `has_more=true`；当前没有续扫游标。300 ms 不是可打断解压、单条解析或 SQL 的硬超时，完整搜索能力仍有待优化。

压缩正文每次操作先将整个日志解压到匿名临时文件，然后定位条目；一次分页内复用 reader，跨操作不复用。因此约 20.56 MiB 原始日志的单项读取明显慢于未压缩日志。预览不读正文，不承担这项解压成本。自动冷压缩仍默认关闭，不以无界正文缓存掩盖此代价。

## 迁移与容量

| 项目 | 1,118 条目 | 5,591 条目 |
| --- | ---: | ---: |
| 合成旧历史库字节 | 6,594,560 | 32,964,608 |
| 轻索引历史库字节 | 4,300,800 | 21,204,992 |
| 历史库减少 | 约 34.8% | 约 35.7% |
| 首次打开、核验、迁移及空间整理 | 304.01 ms | 1,576.23 ms |
| 日志压缩维护，单次 | 204.25 ms | 1,002.56 ms |

数据库文件大小在关闭连接后读取，非整个目录占用；日志容量单独列出。轻索引仍保存有限预览、轮次、定位、摘要和多个索引，短消息混合负载不会获得长正文样本约 97.5% 的库体积降幅。数据库体积变小也不自动构成读写更快的证据。

旧库首次启动需要顺序核验原件与旧正文并执行空间整理，耗时随旧库增长，且需要临时磁盘空间。正常版本重开不再做这次全量迁移。以上迁移样本不能线性推算 GB 级真实库、压缩原件或旧机器的时间。

## 复现

```powershell
cargo run -p wunder-runtime --no-default-features --features sqlite-storage --example storage_history_probe -- 100 30
cargo run -p wunder-runtime --no-default-features --features sqlite-storage --example storage_history_probe -- 500 30
rustfmt --edition 2021 --check crates/wunder-runtime/examples/storage_history_probe.rs
```

探针限制用户轮次为 1..=500、采样数为 10..=200，逐条转换迁移样本，不把全部正文读入集合。压缩前后核验抽样完整条目及聊天预览不变。两个最终运行均退出 0，格式检查通过。

后续优先补齐 release、目标平台与大型真实分布的隔离样本，再根据测量优化可续扫搜索和压缩日志随机读取；不以增加长期正文副本换取表面提速。
