# 2026-10-24 蛹大线程聊天打开后端优化

蛹读取 100 个用户轮次、每轮 100 个模型动作的合成线程时，首次打开的后端耗时显著下降。以下为开发机测量，测试入口是独立工作进程中的 `NativeDesktop::open_chat_snapshot()`，首批返回最近 12 个用户轮次；不构建或启动最终蛹程序，不包含前端布局与绘制。

## 实现

1. 正式日志投影同步维护紧凑聊天摘要：最终回复、用户输入和计划的消息身份，思考与工作过程计数，工作区变更水位。读取按身份查消息预览，避免逐轮扫描全部模型动作。摘要与原投影在同一事务内提交；分支保留按截止 ordinal 查询的检查点，源线程续写不污染旧分支。
2. 聊天页复用同一连接完成权限、待恢复状态和谱系解析；首次访问继续校验对应线程的日志后缀，普通独立线程不再创建临时视图。权限检查和待删除、回退恢复边界保留。
3. 初始聊天页直接携带同一读事务的重放游标，移除打开快照中的独立游标读取。读取过程中发生的提交仍可通过该游标重放。

旧数据按访问到的 rollout 分批补建摘要，每批最多 128 条或约 2 MiB，使用可恢复水位；没有全库启动扫描，也不改写权威日志。

## 数据与方法

- 固定 100×100，10,000 个模型动作、100 条用户消息，共 10,100 个可见条目。每轮 67 次模型请求与 33 次工具执行；文本、思考、工具结果主体分别为 1,024、512、4,096 字节。总目录约 124 MiB。
- Windows 11，32 个逻辑处理器，约 64 GiB 内存；Rust 1.95.0 MSVC，Release、thin LTO，功能为 `sqlite-storage,desktop-control`。工作区存在其他开发者的并行改动，测试二进制哈希另行记录。
- 优化前后复用同一份夹具；每次首次打开均新建进程。准备数据与启动不计时，系统文件缓存未清空，不能称为磁盘冷读。
- 全场景前后各 30 次、各 1 次预热；随后对首次打开、存储页与翻页各做 30 对交替复测，每对交换先后顺序。P50/P95 使用 nearest-rank。
- 测量期间存在并行编译。交替复测记录到两个版本各 93 次样本均有构建进程，因此结果用于开发优化判断，不能当作无干扰的发布验收数字。两组测量绝对耗时有所变化，改善方向一致。

## 结果

交替复测：

| 场景 | 优化前 P50 / P95 ms | 优化后 P50 / P95 ms | P50 耗时减少 |
| --- | ---: | ---: | ---: |
| 首次打开 | 42.993 / 49.223 | 15.238 / 18.408 | 64.6% |
| 存储首批聊天页 | 34.549 / 39.812 | 10.701 / 14.421 | 69.0% |
| 历史翻页 | 28.929 / 37.061 | 4.280 / 5.749 | 85.2% |

首次打开在该组中的最大进程逻辑读取量从 8.29 MiB 降到 0.95 MiB，最大读取次数从 2,150 降到 259；最大采样 RSS 增量从 4.62 MiB 降到 1.92 MiB。资源窗口包含外部握手与后台活动，RSS 为采样峰值，不能直接解释为函数独占分配。

此前的全场景测量首次打开 P50/P95 为 60.875/78.144 → 23.886/28.307 ms；存储页为 54.537/65.125 → 16.710/27.454 ms；历史翻页为 45.200/53.568 → 6.712/8.349 ms。全部场景兼容性检查通过，没有达到默认退化阈值的场景；独立游标场景的 P95 有波动，初次打开已不再单独调用它。

## 成本与正确性

- 已有 100×100 投影第一次补建摘要的单次打开为 382.325 ms，不能把这一次成本隐藏为稳定打开耗时。新日志同步维护摘要，不需要再次补建。
- 本夹具新增 100 个摘要头、10,100 个紧凑检查点及 1 个水位。历史 SQLite 页数从 15,576 增到 16,607，增加 4,222,976 字节，约 4.03 MiB、原历史投影的 6.6%。检查点正文不重复存消息内容。
- 摘要增加投影写入工作，本次未做隔离的持续写入吞吐比较，不对写入成本作零开销承诺。
- 两组前后对比共 620 次调用（含预热）全部通过，rollout SHA-256 保持不变；另有 16×6、16×100 新夹具各 7 个场景通过。
- 存储回归 122 项通过、1 项既有压力实验忽略；桌面租约与快照回归 1 项、聊天投影回归 11 项通过；外部基准 Python 测试 9 项通过。
- 新增回归覆盖摘要幂等、隐藏项、源线程同根续写后的分支截止、旧数据补建恢复及删除重建。确定性并发测试在读页途中提交新回复，验证旧快照一致且游标重放包含新提交。
