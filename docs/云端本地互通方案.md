# 云端本地互通方案

> 适用范围：舰体（server）统一监控蜂巢（web）、蜂窝（desktop）、舵机（cli）三端在线状态；蜂巢工作区可见本地已登录设备的工作区并可远程控制；蜂窝/舵机可见云端工作区并可反向控制。即「统一在线状态 + 跨端工作区互见 + 双向远程控制」。
> 对齐基线：《总体设计.md》《本地云端连接落地方案.md》（T0–T7 已实施）、《设计文档/03-实时投影系统设计.md》《设计文档/11-Desktop-CLI本地形态设计.md》《技术说明书/04-实时投影与通信链路.md》《技术说明书/06-数据存储、工作区与配置.md》《API文档.md》。
> 前提：三端共享 `wunder-runtime` 引擎与 `wunder-core` 契约；本地已通过既有 cloud 连接方案登录舰体（持有 `wund_<token>` + `device_id`）；舰体为账号、设备、额度与策略的唯一权威。
> 与既有方案的关系：本文是《本地云端连接落地方案》的**第二阶段**（下称「互通方案」，前者下称「云渠道方案」）。云渠道方案已交付设备注册、心跳、scope 隔离、刷新令牌与日志上报；本文在其上新增互通隧道、统一 Presence、工作区投影与远程控制，**不改动云模型代理链路与计费语义**。
> 落地状态：方案设计（待实施）。
> 企业对标：VS Code Remote Tunnels / GitHub Codespaces（出站隧道与远程开发面）、Kubernetes hub-spoke / Open Cluster Management（agent 主动建链的纳管模型）、Azure Arc（跨环境统一治理与设备影子）、AWS IoT Device Shadow / MQTT（影子投影与最终一致）、Cloudflare Tunnel（零公网入口反向隧道）、TeamViewer/AnyDesk（设备授权、人在回路审批与会话审计）。具体映射见 §2.6。

## 一、背景与目标

### 1.1 现状

- **已落地（云渠道方案 T0–T7）**：蜂窝/舵机可登录舰体账号（scope=`local_desktop`/`local_cli`），云端 `cloud_devices` 登记设备并以日志上报（30s 批量）兼作心跳更新 `last_seen_at`；云模型经舰体代理并计费；舰桥已有「云端设备/调用/日志」三页；令牌支持刷新轮换与 401 静默续期；本地连接状态机四态（online/reconnecting/expired/logged_out）。
- **Presence 能力现状**：舰体 `services/presence/` 记录「哪些用户在线、哪些连接存在」，是进程内观测状态，可丢失可重建；蜂巢浏览器会话经 `chat_ws`/`user_world_ws`/`core_ws` 天然在线。三套链路各管各的，**没有跨端统一的在线状态视图**。
- **工作区现状**：云端口径为一用户一固定目录（`/workspaces/{user_id}`），蜂巢经 `/wunder/workspace/*`（list/content/search/stats/dir/move/copy/batch/clear/upload）管理；本地口径为 `single_root + container_roots` 多根，数据存本地 SQLite 与本地磁盘。**两侧工作区互不可见**。
- **线程现状**：本地线程（ThreadLog 本地六表）与云端线程（舰体六表）按云渠道方案约定**刻意隔离、互不可见**。
- **先例**：`desktop_lan`（`/wunder/desktop/lan/{peers,envelope,ws}`，HMAC 信封、peer 快照）证明「设备发现 + 信封路由 + WS」的工程形态在本仓库可行，互通方案复用其模式而非机制。

### 1.2 需求与差距

| # | 需求 | 现状差距 |
|---|---|---|
| R1 | 云端统一监控蜂巢/蜂窝/舵机在线状态 | 三端各有连接踪迹，无统一节点目录与状态聚合；本地端仅靠 30s 日志心跳，精度粗、无状态语义 |
| R2 | 蜂巢工作区中可见已登录本地设备的工作区 | 本地线程/文件刻意隔离，云端零投影；蜂巢无节点概念 |
| R3 | 从云端控制本地（蜂巢 → 蜂窝/舵机） | 本地处于 NAT 之后且无公网入口，舰体无法直连；无任何下行控制通道 |
| R4 | 从本地控制云端（蜂窝/舵机 → 云端） | 本地只能把云端当「模型渠道」，没有把云端当「可达节点」的抽象与 UI/命令入口 |

### 1.3 目标

1. **统一在线状态（R1）**：舰体建立跨端节点目录（Node Registry），三端统一状态模型（online/away/busy/reconnecting/offline），秒级（本地）/准实时（网页）精度；舰桥提供治理监控面，蜂巢提供用户侧「我的设备」视图。
2. **工作区云端可见（R2）**：本地工作区以**影子投影**（元数据摘要：线程目录、目录树摘要、定时任务、用量）出现在蜂巢；文件内容**不镜像**，按用户操作经互通隧道**按需拉取**。
3. **云端控制本地（R3）**：蜂巢可对在线本地节点发起分级操作（查询 / 会话控制 / 工作区写 / 工具执行），敏感操作经本地**人在回路审批**，全程审计。
4. **本地控制云端（R4）**：蜂窝/舵机把云端当作对称节点：浏览云端工作区、向云端线程发消息、读取线程事件流；舵机提供脚本化命令组。
5. **全程企业级安全**：零公网入口、最小能力、显式授权、逐级审批、完整审计、用户一键关停（kill switch）。

### 1.4 非目标（本期不做）

- 本地/云端线程**数据合并**或互相搬迁成彼此的持久线程（互通是「远程操作」，不是「数据同步」；远程线程在对方侧始终以「远端」标识存在）。
- 本地工作区文件的云端全量镜像、双向文件同步（syncthing 式）；仅元数据投影 + 按需拉取/推入。
- 云端对本地桌面的图形化远控（TeamViewer 式屏幕控制）；控制粒度止于引擎与文件 API。
- NAT 穿透打洞（P2P）；所有流量经舰体中继。
- 蜂窝/舵机之间直接互通（P2P）；本地互访一律经舰体中转，视为 R3/R4 的特例。

### 1.5 设计原则

- **零公网入口**：本地设备只出站长连接（443/既有端口），不开监听端口、不要求公网 IP；与 Cloudflare Tunnel/k8s agent 同一安全模型。
- **同一套引擎，不加第二套执行语义**：远程控制落到本地后复用既有 orchestrator/工具/工作区实现；远端发起的线程与本地线程共用 ThreadLog 语义，差异仅在「控制来源」标记。
- **Snapshot → Delta → Replay 铁律不破坏**：投影、远程会话视图全部沿用既有实时模型；互通隧道只是新增一条事件传输路径。
- **最小能力，显式收敛**：每类远程操作是声明式能力（capability），默认仅开只读；写与执行类必须本地用户授权且可被管理员在舰桥再收敛。
- **有界、限量、可离线**：所有队列/缓冲/投影有硬上限；断网时本地功能完整可用，隧道静默退避重连；云端侧对离线节点只读拒绝。
- **内容不上云**：投影只含元数据与统计；消息正文、文件内容、工具参数仅在用户主动远程操作时才经隧道传输，且全程审计；本地诊断导出红线不变。

## 二、总体架构

### 2.1 架构总览

```
                     ┌──────────────────────── 舰体（server）────────────────────────┐
                     │                                                              │
   蜂巢(web)         │   ┌─────────────┐   ┌──────────────┐   ┌─────────────────┐   │
  ┌──────────┐  WSS  │   │ Presence    │   │ Interlink    │   │ Shadow Store    │   │
  │ 用户前端  │◄─────►│   │ Registry    │◄─►│ Gateway      │◄─►│ (节点/工作区投影)│   │
  │(节点类型A)│       │   │ (统一在线状态)│   │ (隧道聚合与路由)│   │ 审计 Audit      │   │
  └──────────┘        │   └─────▲───────┘   └──────▲───────┘   └─────────────────┘   │
       ▲              │         │                  │                                │
       │ 既有 WSS      │   ┌─────┴──────────────────┴──────┐                         │
       │ chat_ws 等    │   │ 互通隧道 /wunder/interlink/ws  │ ← 本地出站持久 WSS       │
       │              │   └─────▲──────────────────▲──────┘                         │
       └──────────────┼─────────┘                  │                                │
                     └─────────│──────────────────│────────────────────────────────┘
                               │                  │
                     蜂窝(desktop)                舵机(cli)
                  WSS 出站隧道 ◄┘                  └► WSS 出站隧道
                  (进程内引擎直调)                    (同一引擎云渠道)
```

- **蜂巢 ↔ 舰体**：沿用既有 WS/API；新增「节点目录 / 远程操作 / 远程会话视图」API 与 WS watch 目标。
- **蜂窝/舵机 ↔ 舰体**：新增**互通隧道**（单条出站 WSS，复用已有 cloud 登录凭证）；隧道承载控制帧、事件帧、影子增量与文件数据块。
- **舰体内**：Presence Registry 聚合三端连接；Interlink Gateway 持有隧道并做命令路由；Shadow Store 存投影与审计。

### 2.2 核心范式：反向隧道（Reverse Tunnel）

本地设备广泛位于 NAT/防火墙之后，舰体不能向其发起连接。因此控制流的拓扑必须是：

1. **数据连接方向**：本地 → 舰体，持久 WSS 出站（TLS）。
2. **控制流方向**：舰体在已建立的连接上**复用同一通道**下发命令帧——「连接自下而上，命令自上而下」，即 VS Code Remote Tunnel、Cloudflare Tunnel、k8s hub-spoke 的成熟模型。
3. **拒绝替代方案的确定性理由**：
   - 云端直连本地 HTTP：依赖公网可达，90% 场景不可用，否决。
   - 本地短轮询（long polling）：延迟与吞吐差、服务端状态难做、与既有 WS 基础设施割裂，仅作为隧道断建时的 presence 兜底（复用 30s 日志心跳），不作为控制路径。
   - P2P 打洞：引入 TURN/STUN 复杂度且企业网络常禁 UDP，本期否决，保留为后续增强选项。

### 2.3 三个平面

| 平面 | 职责 | 载体 |
|---|---|---|
| 控制平面 | 节点注册、能力协商、命令下发/回执、审批流转 | interlink WS 隧道（控制帧）、舰体 REST（`/wunder/interlink/*`） |
| 数据平面 | 工作区文件块、远程会话事件流、投影增量 | 同一隧道内的数据帧（文件块用二进制帧分片） |
| 观测平面 | 在线状态、命令审计、隧道质量指标 | Presence Registry、`interlink_audit`、舰桥监控页 |

单隧道多平面复用（head-of-line 风险由 §10 的帧优先级与数据帧限速治理）。

### 2.4 节点目录（Node Registry）——统一身份模型

**节点（Node）** 是互通体系的一等公民，抽象三类端实例：

| node_type | 实例 | 身份键 | 在线判定 |
|---|---|---|---|
| `web` | 蜂巢浏览器会话 | `(user_id, connection_id)` | 既有 chat_ws/core_ws 连接存活 |
| `desktop` | 蜂窝设备 | `(user_id, device_id)`（复用 `cloud_devices`） | interlink 隧道存活；未开隧道时退化为日志心跳（≤2 个周期） |
| `cli` | 舵机设备 | `(user_id, device_id)`（复用 `cloud_devices`） | 同上 |

- `cloud_devices` 扩展为互通节点登记（加字段不新建表，避免与既有设备吊销、设备日志联动割裂）；`web` 节点是**易失节点**（只在内存 Presence 中，不落库）。
- 每个持久节点有一枚**节点密钥** `node_secret`（注册时签发，HMAC 通道握手用，可轮换，见 §9.1）。
- 节点对用户的展示名：`{client}·{device_name}`（如 `desktop·pc-01`）。

### 2.5 远程操作的两种形态

互通控制统一收敛为两种原语，避免功能发散：

1. **远程查询（L0，只读）**：对端状态/元数据/文件内容/线程历史的读取。云端读本地经隧道 `command`；本地读云端经既有 REST/WS。
2. **远程驱动（L1+，写/执行）**：在对端创建或推进智能体活动。统一抽象为「远程驱动远端线程」——**所有控制最终翻译为对端引擎的既有动作**（创建线程、投递消息、答复问询、取消、工具白名单调用）。不为互通发明新的执行体。

> 这一收敛是本方案的关键简化：云控本不是「蜂巢 UI 反向操作 Slint」，端控云也不是「蜂窝内嵌网页」，而是**双方向对方的引擎提交结构化动作，并以对方的事件流回显**。

### 2.6 企业对标映射

| 对标系统 | 借鉴点 | 本方案对应 |
|---|---|---|
| VS Code Remote Tunnels / Codespaces | 出站隧道零入站；远端环境在本地客户端一等可见；按需文件访问不镜像 | §4 互通隧道；§6 蜂巢节点切换器；§6.4 按需拉取 |
| Kubernetes hub-spoke / OCM | agent 主动建链、hub 路由命令、能力注册 | §4.3 命令模型；§9.2 能力协商 |
| Azure Arc / AWS IoT Device Shadow | 设备影子承载期望态/报告态，最终一致 | §6 `interlink_node_shadows` 投影与 revision |
| TeamViewer/AnyDesk | 设备授权、人在回路审批、会话审计 | §7.3 审批矩阵；§9.4 审计链 |
| Cloudflare Tunnel | 连接器单出站位、token 鉴权、QUIC/WS 复用 | §4.1 通道生命周期（WS 版，QUIC 列为演进项） |
| Slack/Discord Presence | 多端在线状态聚合与冲突裁决（以「最近活跃者优先」） | §5.1 状态聚合规则 |

## 三、数据模型与接口契约（冻结）

### 3.1 舰体存储表（新增 5 张 + 扩展 1 张，SQLite/PostgreSQL 双实现）

**(1) `cloud_devices` 扩展**（不新建设备表；既有字段保持）：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| node_secret_hash | TEXT | 节点密钥 HMAC-SHA256 哈希（仅存哈希，密钥本体仅在注册响应出现一次） |
| secret_version | INTEGER | 密钥版本（轮换 +1，握手携带版本号） |
| interlink_enabled | INTEGER | 节点级互通开关（用户授权态，0/1；对应 kill switch 的设备侧状态） |
| capabilities | TEXT | JSON 数组：节点声明且被允许的能力集（§9.2） |
| policy_overrides | TEXT | JSON：管理员 per-device 收敛（禁用的 command kind、强制审批级别） |
| tunnel_connected | INTEGER | 隧道当前是否在线（Presence 落影子段，便于监控页 SQL 直查） |
| last_tunnel_at | REAL | 最近隧道建立时间 |

**(2) `interlink_channels`**（隧道连接登记；每条活跃隧道一行，进程内为权威、DB 为快照）：

| 字段 | 类型 | 说明 |
|---|---|---|
| channel_id | TEXT PK | 每次建链签发 uuid |
| device_id / user_id / client | TEXT | 归属 |
| instance_id | TEXT | 持有该连接的舰体实例 id（单实例恒 `local`，为多副本路由预留 §10.4） |
| protocol_version | INTEGER | 互通协议版本（握手协商） |
| caps | TEXT | 本次会话实际生效能力集（∩ 节点声 ∩ 管理员策略 ∩ 服务端许可） |
| connected_at / last_seen_at | REAL | 时间与心跳 |
| rtt_ms / resumed_count | INTEGER | 通道质量指标 |
| closed_reason | TEXT | 关闭原因（保留最近 N 条历史，滚动覆盖） |

**(3) `interlink_node_shadows`**（节点影子：工作区与环境投影，每节点一行）：

| 字段 | 类型 | 说明 |
|---|---|---|
| device_id | TEXT PK | 节点（仅持久节点：desktop/cli） |
| user_id | TEXT | 归属账号 |
| revision | INTEGER | 影子版本，每次变更 +1（Delta 游标） |
| summary | TEXT | JSON：节点概要（os/arch/app_version/引擎版本/模型清单键/用量统计） |
| threads | TEXT | JSON 数组：线程摘要（≤200 条：`{local_thread_id,title,status,agent,updated_at,message_count,duration_ms}`，无正文） |
| tasks | TEXT | JSON 数组：定时任务摘要（≤100 条） |
| workspace | TEXT | JSON：根目录树摘要（深度 ≤3、条目 ≤500：`{path,kind,size,mtime}`，无内容）+ 用量 |
| synced_at | REAL | 最近一次影子同步时间 |

**(4) `interlink_commands`**（远程命令台账：幂等键 + 状态机 + 审计锚点）：

| 字段 | 类型 | 说明 |
|---|---|---|
| command_id | TEXT PK | 发起方生成 uuid（幂等键） |
| direction | TEXT | `c2l`（cloud→local，云控本） / `l2c`（local→cloud，本控云） |
| actor_user_id | TEXT | 发起人账号 |
| from_node / to_node | TEXT | 源/目标节点描述（web:conn / device_id / `cloud`） |
| kind | TEXT | 命令类型（§7.1 目录，如 `thread.message`） |
| args_digest | TEXT | 参数脱敏摘要（SHA256 + 结构化关键字段；**不存明文正文**，正文仅存在于结果点击穿透的隧道流量中） |
| approval_state | TEXT | `none/pending/approved/rejected/expired` |
| status | TEXT | `issued→acked→running→succeeded/failed/canceled/timeout` |
| created_at / acked_at / finished_at | REAL | 生命周期时间戳 |
| error_code / error_summary | TEXT | 失败分型与脱敏摘要 |

**(5) `interlink_approvals`**（审批单：人在回路的凭证）：

| 字段 | 类型 | 说明 |
|---|---|---|
| approval_id | TEXT PK | uuid，与 command_id 一对一 |
| device_id / user_id | TEXT | 被控端 |
| prompt | TEXT | 本地弹窗展示文案（含操作类型、来源节点、目标路径/线程、参数摘要） |
| risk_level | TEXT | low/medium/high（由命令 kind 映射） |
| state / decided_by / decided_at | TEXT | 状态、决策人、时间 |
| expires_at | REAL | 审批超时（默认 120s，超时=拒绝） |

**(6) `interlink_audit`**（追加式审计日志，与 `cloud_call_records` 风格一致）：

| 字段 | 类型 | 说明 |
|---|---|---|
| seq | INTEGER PK AUTOINCR | 全局序号 |
| command_id / approval_id | TEXT | 关联 |
| actor / from_node / to_node | TEXT | 主体与链路 |
| action | TEXT | `command.issue/ack/finish`、`file.read/write`、`approval.decide`、`channel.open/close` |
| detail_digest | TEXT | 脱敏详情（路径、大小、hash、结果码），不落正文 |

## 四、互通隧道协议（Interlink Protocol v1）

### 4.1 通道生命周期

```
登录态前置：已完成云渠道登录（持 wund_<token> + device_id + node_secret）
│
1. POST /wunder/interlink/channel_ticket   (Bearer token)
   → { ticket: "itk_<uuid>", expires_in: 60 }     // 一次性、绑定 device
2. WSS  {server}/wunder/interlink/ws?ticket=itk_<uuid>
3. 本地 → 服务器  hello  { device_id, protocol, caps, hmac(node_secret, ticket) }
4. 服务器 → 本地  hello_ack { channel_id, protocol=min(...), caps_granted, server_time }
5. 稳态：ping/pong(25s) + presence beat(60s) + 影子增量 + 命令/事件帧
6. 关闭：close { reason }；服务端更新 channels/audit
```

- **握手签名防重放**：`hmac = HMAC_SHA256(node_secret, ticket)`，ticket 一次性且 60s 过期；服务端用存的 `node_secret_hash` 反推验证不了 HMAC，因此服务端另存 `node_secret` 的 **KDF 校验盐**（`secret_version` + 注册时下发的 `verify_token`，等价实现为：注册响应返回 `node_secret`，服务端存 `HMAC(server_pepper, node_secret)`，握手比对 `HMAC(server_pepper, 提交值)`）。
- **新链顶旧链**：同 device 已有活跃隧道时，新 `hello` 生效，旧链收到 `close{reason:"superseded"}`；本地端旧链收到 superseded 后**不再自动重连**（防止双进程互踢循环），等下一个随机退避窗口由最新进程持有。
- **版本协商**：`protocol` 取双方 min；服务端拒绝低于 `min_supported` 的连接并回 `close{reason:"upgrade_required"}`。

### 4.2 帧格式

WS 文本帧（JSON 信封，控制/事件）+ 二进制帧（文件块，首 16B 头：`stream_id(8) + flags(4) + offset(4)` + payload）。

```jsonc
// 统一信封
{
  "v": 1,
  "type": "command",            // hello|hello_ack|ping|pong|
                                // command|command_ack|command_result|command_event|
                                // shadow_delta|shadow_full|event|error|close
  "id": "frm_<uuid>",           // 帧 id（日志关联）
  "ts": 1764000000.0,
  "channel_id": "ch_<uuid>",
  "corr": "cmd_<uuid>",         // 关联 id（命令帧=command_id）
  "payload": { /* 类型负载 */ }
}
```

**命令三阶段（对企业级可运维性至关重要）**：

```jsonc
// 1) 舰体 → 本地（云控本方向）
{ "type":"command", "corr":"cmd_01", "payload":{
    "kind":"thread.message", "risk":"medium", "requires_approval":true,
    "approval_id":"apr_01", "timeout_s":120,
    "args":{ "local_thread_id":null,          // null=新建线程
             "agent":"default", "message":"帮我整理 d:/proj 下的日报",
             "title":"远程会话 来自 蜂巢·Chrome" } } }
// 2) 本地 → 舰体（审批与受理）
{ "type":"command_ack", "corr":"cmd_01", "payload":{
    "accepted":true, "approval_state":"approved", "eta_s":null } }
// 3) 本地 → 舰体（终态）
{ "type":"command_result", "corr":"cmd_01", "payload":{
    "status":"succeeded",
    "result":{"local_thread_id":"th_local_88","first_turn_ms":18450},
    "usage":{"model_calls":3},
    "error":null } }
```

`command_event` 承载命令执行期的进度/审批提示/远程线程关键增量；远程会话的完整消息流**不走命令帧**，走 §7.4 的远程会话视图通道（订阅式），避免命令帧被流式 token 淹没。

### 4.3 命令模型与状态机

- **幂等**：`command_id` 由发起方生成，服务端与本地各保留 24h 去重窗口（`interlink_commands` 唯一键）；网络重发不产生二次执行。
- **状态机**：`issued → acked → running → succeeded | failed | canceled | timeout`；`approval pending` 期间停在 `issued`（超时即 `rejected`）。
- **并发与排队**：服务端每节点 `inflight` 上限；超限命令 `queued`（每用户有界队列），本地繁忙回 `accepted:false, error:"NODE_BUSY", retry_after_ms`，由舰体排队面承担重试（客户端不重发来打满节点）。
- **超时**：每命令 `timeout_s`；超时服务端落 `timeout` 并向本地下发 `cancel`（best-effort）；本地收到超时取消时若已执行完仍回 `command_result`（服务端按 `command_id` 幂等落终态，后者不覆盖前者——**先到达的终态获胜**，审计两条都留痕）。
- **离线目标**：`interlink.offline_queue_per_user > 0` 时入用户离线队列，节点上线后按 FIFO 下发；为 0 时立即 `failed{code:"NODE_OFFLINE"}`。离线队列**不放 L2/L3 级命令**（写/执行必须当面授权）。

### 4.4 心跳、断线与重连

| 层 | 机制 | 参数 |
|---|---|---|
| 传输 | WS ping/pong | 25s，连续 2 次未回判死链 |
| 应用 | presence beat（本地→舰体轻量帧） | 60s，携带 `{status, active_threads, cpu_load}` |
| 重连 | 指数退避 + 抖动 | 1s→2s→…→封顶 300s，jitter ±20% |
| 会话恢复 | `hello{resume_channel_id}` + 影子 revision 对账 | 服务端按 revision 差下发 `shadow_delta` 补收请求；命令面不重放 in-flight（命令状态机已持久化，由服务端重建视图） |
| 兜底在线判定 | 隧道未建时复用云渠道 30s 日志心跳 | `last_seen_at` 超 2×周期判 `offline` |

本地端用户可见性沿用云渠道四态徽标，隧道状态作为其子状态（`互通: 已连接/重连中/已停用`）。

## 五、统一在线状态监控

### 5.1 统一状态模型

**节点状态**（呈现给用户的）：

| 状态 | 语义 | 判定（desktop/cli） | 判定（web） |
|---|---|---|---|
| `online` | 在线且空闲 | 隧道活 + beat 正常 | 任一 WS 活 |
| `busy` | 在线且执行中 | beat 携带 active_threads>0 | 有运行中线程 |
| `away` | 在线但闲置 | beat 携带 idle>10min | 页面隐藏>10min（visibilitychange） |
| `reconnecting` | 断线恢复中 | 本地状态机=reconnecting（经补发心跳体现为 TTL 未过期但通道断） | WS 重连窗口内 |
| `offline` | 离线 | 二者皆过期 / 显式登出 / 吊销 | 无连接且超 TTL |

**聚合规则**（用户卡片一个总状态，对标 Slack/Discord 多端裁决）：任一节点 `online/busy` → 用户在线；全部 `away` → away；全部离线 → 离线，同时在线节点数并显（`3 台设备在线`）。

### 5.2 舰桥治理监控面（「互通舰队」导航组）

1. **舰队总览页**：在线/总数、按 client 分布、24h 在线率热图、隧道质量（RTT 分位、重连次数 TopN）。
2. **节点详情抽屉**：影子摘要、生效能力集、策略 overrides、最近命令 20 条、最近隧道开合记录。
3. **命令台账页**：跨用户远程命令检索（kind/状态/时长/审批状态），点入看生命周期时间线。
4. **策略操作**：per-device 收敛（禁用指定 kind / 强制审批 / 暂停互通）、吊销设备（复用既有 revoke，联动关隧道）、密钥强制轮换。

### 5.3 蜂巢「我的设备」面板

设置区新增「我的设备」页 + 侧栏状态入口：
- 设备卡片：名称/类型徽标/在线状态点/最近活跃/影子 revision 时间；点击进入「远程工作区」（§6.3）。
- 「允许云端互联」总开关（kill switch）：关闭即服务端拒绝隧道并 30s 内拆除既有隧道；重新开启需该设备下一次心跳携带确认（防止云端单方面变成本地永远不可达）。
- 登录新设备通知（复用既有用户通知通道）：新设备首次建隧道时向其他在线节点广播 `event{kind:"node.joined"}`。

## 六、本地工作区云端可见（工作区影子投影）

### 6.1 投影内容（白名单，红线：无正文）

| 投影项 | 内容 | 上限 |
|---|---|---|
| 节点概要 | os/arch/app_version/引擎版本、云模型键清单、工作区用量 | — |
| 线程目录 | id、标题、状态、agent、更新时刻、消息数 | 最近 200 条 |
| 定时任务 | id、调度、启停、下次触发 | 100 条 |
| 目录树 | 相对路径、类型、大小、mtime（深度≤3） | 500 条目 |
| 运行态 | active_threads、排队数、最近错误摘要 | — |

**明确不投影**：消息正文、文件内容、工具参数、本地绝对路径（仅工作区相对路径）、本地记忆/知识库内容。

### 6.2 同步机制（Snapshot → Delta → Replay 复用）

1. **建链即全量**：`hello_ack` 后本地计算首份 `shadow_full`（revision=1）上报。
2. **事件驱动增量**：本地线程创建/状态变更/重命名、目录写操作（经引擎统一文件链路挂钩，不监听文件系统）→ 合并窗口 2s 上报 `shadow_delta{revision=N}`。
3. **周期兜底全量**：`shadow_interval_s`（默认 300s）一次 full，服务端以最新 full 为准丢弃旧 delta。
4. **服务端落库即投影**：写 `interlink_node_shadows`，revision 单调；蜂巢按 revision 做客户端缓存与补水（断线后携带 last_revision，服务端差量补发——与既有 Replay 语义同构）。
5. **隐私降级开关**：节点在 hello caps 中可声明 `shadow:minimal`（仅概要+运行态，不报线程目录与目录树）；管理员策略可强制升级 minimal。

### 6.3 蜂巢前端：工作区「节点切换器」

工作区页顶栏新增节点选择器：`☁ 云端工作区（默认） | 🍯 pc-01 · desktop · 在线 | ⚙️ nas · cli · 离线`。

- 选中本地节点：
  - **文件区**：先渲染影子目录树（置灰水印「投影 · 更新于 2 分钟前」）；点击文件 → 发起按需拉取（§6.4）→ 成功后进入只读预览器（大文件分页，文本/图片/常见格式渲染与既有工作区预览复用）。
  - **会话区**：线程目录来自影子；点击进入**远程会话视图**（§7.4）；顶部常驻「远程会话 · pc-01」标识条与「回到云端」出口。
  - **操作区**：按能力集渲染（§7.1）；无权限/离线的操作置灰并给出原因文案。
- 选中云端：完全既有行为零变化。
- URL 形态 `/workspace?node=device:<id>`，可分享（接收者须为同账号）。

### 6.4 文件内容按需拉取（云读本，命令化的数据面）

```jsonc
// 蜂巢点击文件 → POST /wunder/interlink/commands
{ "to":"device:pc-01", "kind":"workspace.read", "args":{ "path":"notes/today.md", "max_bytes":1048576 } }
// 服务端 → 隧道 command → 本地校验（相对路径、fence、大小上限）
// 小文件：结果内联于 command_result（base64 ≤1MB）
// 大文件：本地开 stream_id，二进制帧分片（256KB/片，限速 4MB/s，可停帧 flow-control）
//       服务端落临时缓存（内存环形缓冲 + .rundata 溢出，TTL 10min）
//       蜂巢经 GET /wunder/interlink/commands/{id}/blob 拉取（支持 Range/断点）
```

写入反向（云写本，L2）：`workspace.write/mkdir/move/copy/delete` 走同一路径但强制审批（§7.3）；写操作一律先备份（被改目标复制到本地 `工作区/.interlink_backup/<command_id>/`，保留最近 50 份），审计含前后 SHA256。

## 七、云端控制本地（云控本，C2L）

### 7.1 操作目录与分级

| 级别 | kind | 说明 | 默认策略 |
|---|---|---|---|
| L0 只读 | `node.summary` / `shadow.refresh` / `workspace.list|search|stat|read` / `threads.list|get` | 查询类 | 免审批 |
| L0+ | `workspace.read:binary` | 拉取二进制文件 | 免审批+审计 |
| L1 会话 | `thread.create` / `thread.message` / `thread.cancel` / `thread.answer`（答复问询面板） | 在本地引擎驱动线程 | **默认需审批**（可降为免审批） |
| L2 工作区写 | `workspace.write|mkdir|move|copy|delete` | 改本地文件 | 强制审批（不可降） |
| L3 执行 | `tool.exec`（白名单命令） / `agent.spawn` | 执行工具/子智能体 | 强制审批 + 管理员默认禁用（可开） |

风险级映射：L0/L0+=low，L1/L2=medium，L3=high → `interlink_approvals.risk_level`。

### 7.2 执行路径（以「蜂巢向蜂窝发消息」为样例）

```
蜂巢 → POST /wunder/interlink/commands {kind:"thread.message", to:pc-01, args}
舰体：鉴权 → 目标在线? → kind ∩ caps? → 需要审批? → 落 interlink_commands(issued, approval pending)
舰体 → 隧道 → command 帧 → 蜂窝
蜂窝：能力复验 → 弹窗（§7.3）→ 用户批准 → command_ack
蜂窝：引擎层执行 = 复用线程创建/消息投递既有路径（来源标记 source:"remote:web:<conn>"）
蜂窝：线程事件 → 本地 Slint UI 正常播放 + 远程订阅通道广播
蜂窝 → command_result（含 local_thread_id）→ 舰体 → 台账 + 蜂巢通知 + remote_ws 订阅者
```

**关键落点**：远程消息进入本地后，与该线程本地输入的消息**完全同权**地进入 orchestrator 队列与 ThreadLog；本地 UI 显示「来自云端 · 蜂巢」来源徽标，本地用户可随时接管、打断、取消——本地人对本地引擎永远有最高控制权。

### 7.3 审批框架（人在回路）

1. **弹窗形态**：蜂窝为原生模态（Slint 对话框：来源节点、操作类型、目标、参数摘要、倒计时、批准/拒绝/「本次会话内记住该类许可」）；舵机为 TUI 确认行 + 非 TTY 时按 `approval_default` 处理（默认拒绝并审计）。
2. **决策规则优先级**：管理员 per-device 强制 > 用户本地 `approval_defaults` > 服务端 `require_approval_defaults` > kind 默认。
3. **记住许可**：作用域记忆（`允许 蜂巢·本次会话 对 pc-01 的 L1 操作 30 分钟`），以 `(from_user, kind_level, ttl)` 记录，本地 UI 可撤销；**L2/L3 永远不可记忆**。
4. **超时即拒绝**（120s），审批单全程入 `interlink_approvals` + audit。
5. **防风暴**：同一来源 1 分钟内审批弹窗合并为队列视图，不连续抢占；pending 上限 5，超出直接拒绝。

### 7.4 远程会话视图（实时回显）

- 蜂巢 `WS /wunder/interlink/remote_ws?target=device:<id>&thread=<local_thread_id>`：服务端作为**隧道事件的转发器**，把本地该线程的公开事件流（与本地 Slint 消费的同一增量序列）转发给蜂巢，复用 Snapshot→Delta→Replay：首包快照=本地线程当前投影（本地引擎即时生成序列化快照），随后 delta。
- 多观察者：服务端按 `(device, thread)` 聚合订阅，隧道方向只做一份本地→舰体上行（N 个网页订阅不放大本地上行）。
- 视图权属：远程视图默认**只读 + 控制按钮**（发消息/取消/答复问询=发 L1 命令）；蜂巢不持久化远程消息正文（刷新即重快照），本地永为唯一数据源——保证「内容不沉淀上云」。

## 八、本地控制云端（本控云，L2C）

### 8.1 对称抽象：云端即节点

本地端把舰体视为节点目录中的特殊节点 `cloud`（`node_type:"server"`）：
- 蜂窝「远程位置」面板与舵机命令组共用同一抽象：目标选择器 = `local | cloud | <其他登录设备>`。
- 本控云**不新增服务端执行语义**：全部落到既有舰体 API（`/wunder/workspace/*`、线程/会话 API、`chat_ws`）与既有能力与额度体系（云端线程在服务端跑，扣该账号额度——与蜂巢同源）。
- 命令方向：`POST /wunder/interlink/commands {to:"cloud", ...}` 仅作为**统一台账入口**（审计+幂等服务），实际执行是舰体本地调用既有 handler，不经隧道。

### 8.2 云端工作区本地挂载

- 蜂窝：文件侧栏新增「云端工作区」分组（REST 拉目录树 500 条缓存 60s）；文件打开/下载/上传复用既有 workspace API；编辑走「下载→本地改→上传」三段式（不再造在线编辑器桥）。
- 舵机：
  - `wunder-cli cloud ws ls [path] / cat <path> / pull <path> [-o local] / push <file> [-d path]`
  - `wunder-cli cloud threads`（云端线程目录）/ `cloud thread show <id>`
  - `wunder-cli cloud send [--thread <id>] [--agent <a>] "消息"`（向云端线程投递；`--attach` 进入流式回显，等价于远程会话视图）
  - `wunder-cli cloud watch --thread <id>`（JSONL 流输出，纳入脚本管线）
- 状态整合：`cloud status` 输出扩展为「账号/额度/设备/互通隧道/云端工作区用量/其他设备在线列表」。

### 8.3 端控云与云控本的对称约束

- 端控云 L1（云端线程驱动）默认**免审批**（云端线程本就是用户自己的服务端资源，审批的意义是保护本机环境）；但云端侧仍按账号权限体系校验。
- 蜂窝经隧道操控**另一台本地设备**（本地互访）按云控本路径处理（舰体中转），审批与被控端策略不变——拓扑对称、策略一致。

## 九、安全设计（企业级合规对齐）

### 9.1 身份与认证

| 层 | 机制 | 细节 |
|---|---|---|
| 用户身份 | 既有账号体系 + scope 隔离 | 互通沿用 `local_desktop/local_cli` scope；蜂巢侧为 default scope；L2C/L0 查询不扩 scope 语义 |
| 设备身份 | 节点密钥 | 注册时服务端生成 32B 随机密钥，响应一次性下发；服务端只存 `HMAC(server_pepper, secret)`；轮换走「旧版本宽限 24h 双密钥并存」 |
| 通道身份 | 一次性 ticket + HMAC 握手 | 见 §4.1；ticket 与 (device, ip) 绑定 |
| 传输 | TLS 强制（生产） | 内网 HTTP 仅限显式配置 `allow_plaintext:true`；mTLS 列为企业版选项 |
| 会话 | 刷新令牌沿用 | 云渠道既有轮换/复用检测/连坐语义不变 |

### 9.2 授权与能力模型（Capability）

- **能力声明**：本地 hello 携带声明集（受构建/平台制约，如 Win7 无 sandbox 则不带 `tool.exec:sandbox`）。
- **三方求交**：生效集 = 节点声明 ∩ 管理员策略 ∩ 服务端全局许可；求交结果在 `hello_ack.caps_granted` 回落，双方按生效集渲染与执行，**任一侧越集直接拒绝并审计**。
- **能力即 kind 前缀**：`workspace.*`、`thread.*`、`tool.exec:<whitelist>`、`agent.spawn`、`shadow:full|minimal`。
- **最小授权默认值**：新注册设备默认 `shadow:minimal + L0 + L1(需审批)`；L2 需用户首次在本地显式开启；L3 需管理员开启。

### 9.3 数据保护红线

1. 影子/审计/台账**一律脱敏**：只存摘要、hash、统计与相对路径；不存消息正文、文件正文、工具明文参数。
2. 远程会话正文**流经不沉淀**：舰体只做转发与临时缓冲（≤10min TTL，内存优先），不落库、不进日志；远程视图刷新即重拉快照。
3. 本地诊断导出排除 `node_secret`、tunnel 帧与审批记录正文（沿用既有密钥排除约定）。
4. 删除权：设备吊销时联动清理影子与缓冲区；用户「清空云影子」端点 `POST /interlink/nodes/{id}/purge_shadow`。

### 9.4 审计（Compliance Trail）

- 每条远程操作链：`command.issued → approval.decided → command.acked → … → command.finished` 于 `interlink_audit` 成链可查；舰桥支持 CSV 导出（时间窗/用户/设备/kind/结果 筛选）。
- 告警钩子（webhook 预留）：L3 执行、审批拒绝风暴（同设备 10min 内 ≥5 次拒绝）、密钥复用检测 → 可接企业 IM。
- 保留期：命令台账 180 天、审计 365 天（可配），后台清理任务复用既有 monitor 清理模式。

### 9.5 威胁模型与缓解

| 威胁 | 缓解 |
|---|---|
| token 窃取后冒建设备通道 | 节点密钥二次握手；ticket 短寿命；密钥不出本地 0600 文件；异常 IP 建链触发用户通知 |
| 服务端被攻陷后向本地投毒命令 | 节点密钥双向校验 + 能力交集 + 本地审批人对命令来源/参数可见 + L2/L3 审批不可降 |
| 本地设备丢失 | 舰桥/蜂巢远程吊销 + 密钥轮换；吊销后隧道与全部云端点 401 |
| 重放命令 | command_id 24h 去重 + ticket 一次性 + HMAC in-hello |
| 中间人 | 生产 TLS 强制；明文仅限显式内网开关并启动 banner 警示 |
| 数据帧洪泛 | 分片限速 4MB/s、单流窗口、每节点 inflight 上限、影子条目硬上限 |
| 隐私越界 | 投影白名单 + 内容不沉淀 + 远程视图来源水印 + kill switch |

## 十、可靠性、性能与边界

1. **有界性**：影子条目（200/100/500）、离线队列（32）、inflight（8）、审批待决（5）、文件分片窗口（16）、blob 缓冲（单文件 64MB 上限、TTL 10min）、远程订阅每节点 ≤8。
2. **性能预算**：隧道建链 < 800ms（TLS 已含）；影子全量本地计算 < 500ms（500 条目）；L0 命令端到端 P95 < 1s（同区内网）；远程视图首包 < 2s；隧道对本地引擎主链零阻塞（独立 tokio 任务，帧入队有界、满则降级为汇总事件）。
3. **降级矩阵**：隧道断 → 云模型代理仍走 REST（互不影响）；影子服务故障 → 蜂巢远程工作区入口隐藏（云端工作区不受影响）；审批服务故障 → 需审批命令一律拒绝（fail-closed）。
4. **多副本演进**：本期舰体单实例，`interlink_channels.instance_id` 恒 `local`；多副本时经 Redis 路由表（channel→instance）+ 命令转发，接口字段已预留，不阻塞本期交付。
5. **兼容**：未升级的老本地端（无隧道）在节点目录中正常呈现为「在线(仅日志心跳)/不可控」，云端功能不报错；老舰体带新本地端时握手协商失败回退纯云渠道模式。

## 十三、验收标准

### 13.1 P0 在线状态

1. 同一账号同时登录蜂巢、蜂窝、舵机：`/interlink/nodes` 返回 3 节点，类型/状态/最近活跃正确；蜂窝端运行线程时状态转 busy。
2. 断蜂窝网络 5 分钟：舰桥显示 offline → 恢复后 ≤60s 回到 online；期间蜂巢页面状态点自动翻转（无需刷新）。
3. 网页端无任何本地线程/影子内容暴露（P0 阶段隔离承诺不破）。

### 13.2 P1 影子与只读可见

4. 蜂窝新建 3 线程（其一 ≥50 消息）：≤2s 蜂巢影子线程目录出现 3 条，标题/状态/消息数正确、无正文。
5. 本地目录树 >500 条目：影子恰截断 500 且带 truncated 标记；蜂巢渲染与影子一致。
6. 蜂巢点击影子文件（800KB）：按需拉取成功、预览正确；审计含该次 `file.read` 记录；文件不入服务端库表。
7. 杀掉蜂窝进程：蜂巢远程工作区入口 30s 内显示节点离线，进行中的拉取返回 `NODE_OFFLINE`。

### 13.3 P2 云控本

8. 蜂巢向蜂窝发起 `thread.message`：蜂窝弹窗（来源/内容摘要/倒计时）→ 批准 → ≤3s 本地线程创建并开始执行；蜂巢 remote_ws 收到与本地一致的事件序列（文本逐段对拍无差）。
9. 审批拒绝 / 超时（0 操作 120s）分别落 rejected/expired，本地不产生任何执行副作用。
10. 同一 command_id 重发 3 次：仅执行一次，台账单条。
11. 断线下发（离线队列开启）：命令入队，设备上线后 FIFO 执行；队列深度超 32 时新命令立即失败返回结构性错误。
12. 蜂窝本地用户可在任意时刻取消远程驱动的线程；取消后蜂巢视图同步 canceled。

### 13.4 P3 端控云

13. 舵机 `cloud ws ls` 显示云端工作区；`cloud send --attach "…"` 向云端线程投递并流式回显，额度扣减与蜂巢同源可见。
14. 蜂窝云端工作区面板 pull 文件到本地；双向操作均出现于台账（direction=l2c）。
15. 蜂窝经舰体向同账号舵机设备发 L1：舵机弹审批行，批准后执行（本地互访对称成立）。

### 13.5 P4 安全与治理

16. kill switch 关闭：30s 内隧道拆除、蜂巢远端入口消失、云端侧下发命令全部 401/403；期间云模型调用不受影响。
17. 管理员将某设备 `workspace.write` 收敛为禁：蜂巢相关按钮置灰，直接 API 调用 403 且审计。
18. 设备吊销：隧道即刻断开，所有互通端点 401，影子按策略保留期后清除。
19. 审计导出：一次完整远程会话（发消息→回显→读文件→写入）在 CSV 中成链，字段无正文泄漏。
20. 密钥轮换：旧密钥 24h 宽限后失效，期间双密钥可握手；宽限后旧密钥握手拒绝并告警。

### 13.6 性能与边界

- 隧道空闲 CPU < 1%、内存增量 < 30MB；影子全量计算不阻塞 Slint 帧（≥55fps 保持）。
- 1000 节点台账审计查询 P95 < 500ms（索引：`interlink_commands(user_id,created_at)`、`interlink_audit(created_at)`）。
- 远程订阅 8 网页×1 设备：本地上行不放大（单流聚合）。

## 十四、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 远程控制被滥用为「肉鸡」通道 | 高 | L3 默认管理员关；审批不可降；kill switch；审计告警；能力三向求交 |
| 隧道成为新攻击面 | 高 | ticket+HMAC 双因素建链；协议版本协商；帧 schema 严格校验（unknown field 拒绝）；模糊测试纳入 CI |
| 本地资源被遥控耗尽 | 中 | inflight/分片/订阅全有界；线程驱动仍受本地引擎既有 guard 与（L3 情形的）沙箱约束 |
| 隐私争议（公司在看本地什么） | 中 | 影子白名单、minimal 模式、内容不沉淀、本地可见的审计自查页（舵机 `cloud audit --mine` / 蜂窝审计卡片） |
| 多副本路由复杂度 | 低 | 单实例先交付，字段预留；Redis 路由独立专题 |
| Slint/TUI 审批体验差导致用户改用默认值 | 低 | 默认即安全（rejected）；记住许可限时 30min 且仅 L1 |
