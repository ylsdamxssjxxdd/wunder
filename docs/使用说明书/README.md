# 使用说明书维护指南

本目录是 wunder 使用说明书站点的唯一正式源。

## 目录边界

- 站点源：`docs/使用说明书/`
- 中文主文档：`docs/使用说明书/zh-CN/`
- 英文版：`docs/使用说明书/en/`（跟随 zh-CN 同步翻译，zh-CN 为权威版本）
- 站点导航：`docs/使用说明书/site.json`
- 站点构建：`python scripts/build_docs_site.py`

## 双语同步

新增或修改 zh-CN 页面时，需同步：

1. en/ 下对应页面（翻译，保持与中文同风格）。
2. `site.json` 中两个语言标签页的导航条目，避免孤儿页面或死链。

以下内容不要放进静态站源目录：

- 临时讨论稿
- 一次性实施清单
- 对标分析草稿
- 与用户阅读无关的内部备忘

## 写作目标

读者是**使用者与管理员**，不是开发者。每页确定三件事：这一页让用户完成什么（一页只讲透一件事）、照着做的最短步骤、出错时回到哪一页排查。

先讲「怎么用」，再补「为什么这样」。

## 硬性禁止（违反即判不合格）

- 不写 `read_when`、`source_docs` 这类面向维护者的 frontmatter。
- 正文不出现源码路径与行号（如 `crates/wunder-runtime/src/services/xxx.rs:12-34`）、模块名、函数名。
- 不搬内部实现噪音：config key 清单、错误码表、"本次改版要点"、日志字段、内部常量。
- 不写元叙述句式：「这页定义了……」「这页回答了……问题」「本页面向……」「本文将介绍……」「本节说明……」——有事说事，直接讲内容。
- 不写一切问句与设问句式，包括自问自答式的引导（如「一次消息穿过什么……什么？」「那么它是怎么做到的呢？」）——直接陈述原理、说明方法。
- 不写「何时读 / 适用场景 / 常见误区 / 检查清单」等模板化小标题的机械堆叠。
- 不写口号句（如「你最需要记住的是……」）。

## 允许且鼓励的技术细节

用**行为与效果**写技术细节：

- 好：「它会自动识别需要 JavaScript 渲染的页面，并改用浏览器重新读取。」
- 好：「重复访问同一页面时，短时间内直接返回缓存结果。」
- 差：「（`web_fetch_tool_impl.rs:1376-1412`）」

数字类细节只在**用户能感知**时保留，例如「网页正文默认最多取 12000 字」。

## Frontmatter 约定

- 必填：`title`、`summary`
- 可选：`updated_at: YYYY-MM-DD`
- 其它字段一律不加。

如果没填 `updated_at`，构建脚本会回退到文件修改时间。

## 页面结构建议

### 入口页（index / hubs）

- 先用一句话说清这是什么、给谁用
- 再给按场景的入口
- 最后给常见问题与延伸阅读

### 工具页（tools）

- 先说在什么情况下用它
- 再给怎么触发（用户视角，不是字段 schema 表）
- 再说它自动处理了什么（有意思的点）
- 再给出问题时怎么判断

工具分类以 `README.md` 的「工具矩阵」为准。已移除的工具（`a2a_*`、渠道工具、用户世界工具、`final_response`、`a2ui`）不保留说明页。

### 能力页（capabilities）

- 先说什么时候来查这一页
- 再给可复制的命令、端点或配置项
- 最后给边界与非目标（避免读者误以为做不到的事能做）

## 导航

站点为 4 个标签页：开始 / 工具 / 界面 / 能力（英文：Getting Started / Tools / Surfaces / Capabilities）。

- 「四个核心」总览页（`docs/总体设计.md` 定义的多 / 快 / 好 / 省）归在「开始 › 四个核心」，不增删。
- 逐项核心能力详情页（目标、兼容性、上下文压缩、子智能体、定时任务、渠道通信、记忆、多线程、多租户）归在「能力 › 核心能力」。
- 帮助类页面（帮助中心、故障排查、FAQ、术语表）归在「开始 › 帮助」。
- 核心之外的概念页与配置、接口等参考页统一归在「能力 › 深入了解」；功能速查归在「能力 › 概览」。

## 发布前检查

1. 运行 `python scripts/build_docs_site.py`
2. 运行 `python temp_dir/verify_nav.py`：校验导航页面存在性、孤儿页与内链死链，三项均须为零
3. 抽查入口页、工具页、FAQ 是否好读；确认全文无 `read_when`、`source_docs` 与源码路径
4. 通过 `python scripts/update_feature_log.py --type 文档 ...` 记录本次迭代
