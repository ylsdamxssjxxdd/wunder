## 运行形态

三种形态对应不同的适用对象与准备内容。

| 形态 | 适合谁 | 需要什么 |
|------|--------|----------|
| **蜂窝（desktop）** | 个人使用 | 下载安装包，开箱即用 |
| **舰体（server）** | 团队/组织 | 服务器 + 数据库 + 配置 |
| **本地开发** | 开发调试 | 本地编译环境 |

## 蜂窝部署

安装步骤：

1. 下载安装包
2. 安装并启动
3. 开始使用

不需要额外配置。数据存在本地，使用 SQLite。

详细步骤见 [蜂窝入门](/docs/zh-CN/start/desktop/)。

## 舰体部署

### 最低要求

| 组件 | 说明 | 是否必需 |
|------|------|--------|
| 后端服务 | 对外提供接口与调度 | 是 |
| PostgreSQL | 主数据库 | 是 |
| 工作区存储 | 用户文件空间 | 是 |
| 前端静态资源 | 蜂巢/舰桥页面 | 推荐 |
| MCP 服务 | 外部工具能力 | 按需 |
| 沙盒服务 | 隔离执行环境 | 按需 |
| 向量数据库 | 知识库检索 | 按需 |

### 推荐部署方式

推荐用 Docker Compose：

- 组件一次拉起，配置集中在同一份文件里
- 升级时替换镜像即可

### 需要准备的配置

部署时要准备好服务监听地址与端口、访问用 API 密钥、数据库连接信息、配置文件位置，以及沙盒服务地址（启用沙盒时）。Docker 环境下，服务端编译时默认启用了 MCP、主机指标和网页抓取三项能力。

### 网络规划

对外网络入口：

| 入口 | 用途 |
|------|------|
| 主服务地址 | 后端接口 |
| WebSocket 通道 | 实时通信 |
| 舰桥地址 | 管理后台 |
| 文档站地址 | 使用说明书 |

建议统一在同一域名下，通过路径区分。

### 启动后检查

启动完成后，按这个顺序检查：

1. 确认后端服务正常运行
2. 确认数据库连接正常
3. 确认 WebSocket 可建立连接
4. 确认舰桥可打开
5. 确认用户端可访问
6. 确认文档站可访问

### Docker 下的系统状态

管理员侧系统状态里的 CPU、内存、进程、负载和磁盘指标，来自服务端编译时启用的主机指标能力；用户侧的「网页抓取」工具来自网页抓取能力。当前默认发布的镜像已包含这两项。如果在配置里手动覆盖了编译选项，需要保留主机指标和网页抓取，否则系统资源指标会以 0 值降级显示，用户侧智能体工具列表也不会出现「网页抓取」。

管理员侧配置的抓取服务会同步给「网页搜索」；不过「网页搜索」入口在当前版本已经移除，无论抓取服务如何配置，用户侧智能体工具列表都不会出现它。

### Docker 下的浏览器

如果需要在 Docker 中使用浏览器工具：

- 确保镜像构建时安装了 Chromium
- 分配足够的共享内存（2 GB）
- 启用浏览器相关配置

### Docker 下的沙盒写权限

当前默认让沙盒容器保持可写根文件系统，方便文件工具访问容器内任意路径。沙盒的只读限制分两层：一层在 wunder 请求侧，一层由 Docker 的容器级只读开关控制。若文件工具写根路径（如 `/test_file.txt`）时提示「只读文件系统」，通常是在运行的容器仍在用旧的只读配置，重建沙盒容器即可。

## 升级策略

- 滚动更新：逐个替换实例，不中断服务
- 数据库迁移：系统自动处理，不需要手动操作
- 配置兼容：新版本会自动适配旧配置格式

## 常见部署问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 启动失败 | PostgreSQL 未准备好 | 确保数据库先启动 |
| WebSocket 连不上 | 端口或代理配置问题 | 检查端口和反向代理配置 |
| 工作区丢失 | 没有持久化存储 | 使用数据卷挂载 |
| 临时文件堆积 | 没有清理策略 | 配置定期清理任务 |
| 舰桥系统状态资源指标为 0 | 编译选项被覆盖后缺少主机指标能力 | 恢复默认编译配置并重建服务与沙盒 |
| 用户侧看不到网页抓取 | 编译选项被覆盖后缺少网页抓取能力 | 恢复默认编译配置并重建服务与沙盒 |
| 用户侧看不到网页搜索 | 网页搜索入口已移除，与抓取服务配置无关 | 属于当前预期行为，无需处理 |
| 浏览器工具不可用 | 镜像构建时没装 Chromium | 检查镜像构建配置 |
| 文件工具根路径写入失败 | 沙盒容器仍是只读根文件系统 | 确认沙盒可写开关为默认开启，并重建沙盒容器 |
