观测分五类，分别对应不同对象：线程状态、工具调用情况、链路延迟、上下文变长后的速度变化、模型能力变化。会话监控用于定位出问题的线程或工具，指标和日志用于确认影响范围，WunderBench 用于判断模型侧是否发生变化。

## 观测能力对照

| 能力 | 观测对象 | 主要用途 |
|------|----------|----------|
| **会话监控** | 线程运行细节 | 定位线程状态、卡点与异常 |
| **工具统计** | 工具使用情况 | 找出最忙或最不稳定的工具 |
| **性能采样** | 系统链路基线 | 判断承压能力与延迟瓶颈 |
| **吞吐压测** | 模型长度组合性能 | 观察上文变长后速度如何变化 |
| **WunderBench** | 任务完成质量 | 评估模型在 wunder 中的表现与退化 |

## 会话监控

可观察的内容：

- 活跃线程列表
- 每个线程的当前状态和阶段
- Token 占用统计
- 工具调用记录
- 事件时间线

用它排查线程卡住或异常、查看某个会话的执行详情、强制取消异常线程，以及触发上下文压缩。

## 工具统计

可观察的内容：

- 各工具的调用次数
- 工具调用成功率
- 哪些用户在使用哪些工具
- 工具调用与线程状态的关系

工具统计用于发现成为性能瓶颈或调用异常频繁的工具，也用于评估工具使用模式。

## 性能与吞吐

### 性能采样

测量单请求的延迟基线：

- 模型响应速度
- 工具执行速度
- 端到端延迟

### 吞吐压测

每次直连模型 API 测试一个模型、并发列表、输入长度和输出长度组合，按列表顺序逐项测试；每一项会并行发起该并发数的请求，观察各并发档的首字延迟、生成速度和实际用量。

输入和输出都保留常用档位，同时允许在安全范围内自由输入整数。默认并发列表为 `1,2,4,8`，输入为 `8.2k` Token，输出为 `128` Token。页面中 Token 数量从 1,000 起显示为 `k`，从 100,000 起显示为 `m`。仅支持的引擎能够接收定长控制参数，其余接口设置上限并验证是否达标。

选择虚拟模型可验证测量流程。在「模型配置 → 模拟速度」选择快、中、慢，默认快：预填充分别为 2000 / 500 / 100 Token/s，思考与生成分别为 200 / 50 / 10 Token/s。吞吐模拟先思考再生成内容，思考默认占指定输出总数的 1/4，可通过模拟思考开关与预算调整，详情中单列。详情标记模拟数据与速度，历史曲线按档位分组。首字延迟包含预填充等待；快档 1m 输入约需 524 秒，需相应提高模型超时，也可在等待期间停止。模拟测试同样会执行最大上下文与最大输出校验，超限记录为失败；默认上下文 128k，如需测到 1m，请将窗口设为足够容纳输入加输出。

测试不生成线程日志，历史仅保留最近 50 次摘要。详情与曲线会显示整体预填充/生成速度，以及「单预填充速度」和「单生成速度」；速度从 1,000 起使用 `k tok/s`，从 100,000 起使用 `m tok/s`。勾选历史数据可在并发数横轴上查看速度曲线；曲线纵轴以同一测试中并发 1 为 0% 基线，显示后续并发档的百分比变化，悬停可查看实测速度。结果不会用「达标/未达标」做额外标记。

### 两项的区别

- **性能采样**：单请求级别的延迟
- **吞吐压测**：不同上下文与输出长度下的模型 API 性能

## WunderBench 模型评测

可评估的内容：

- 任务完成质量评分
- 工具调用成功率、稳定性、效率与上下文消耗
- 不同模型的能力对比
- 版本间的能力回归检测
- 支持全量题库评测，也可按任务组或任务 ID 手动筛选复查

### 与吞吐压测的分工

- **吞吐压测**：关注不同长度组合的响应与生成速度
- **WunderBench**：关注能否在真实智能体链路中完成任务，以及是否退化

WunderBench 用于新版本发布前评估、不同模型能力对比、优化效果验证，以及为默认模型、裁判模型、工具启用策略提供依据。

### 输出与导出

评测结果给出：

- 可用性结论，分四档：production_ready、usable、risky、not_ready
- 任务平均得分
- 通过率口径的可靠性评分
- 工具结果成功率
- 完成率与多轮波动组成的稳定性评分
- 最需要复查的任务组和失败项

导出评测记录有两种方式：在 WunderBench 页面点击「导出评测记录」，或调用 `GET /wunder/admin/wunderbench/runs/{run_id}/export`。

导出的 JSON 包含运行信息、任务聚合、每次尝试的明细、题目规格、产物摘要、对话记录，以及每个模型尝试对应的持久化监控日志。新启动的 WunderBench 会使用管理员调试日志记录评测线程，导出文件可用于复盘模型请求、模型输出、工具调用、工具结果、工作区更新与 token/速度统计。

详细使用、评分口径和题库扩展说明见 [WunderBench 模型评测](/docs/zh-CN/ops/wunderbench/)。

## 关键指标

### 健康指标

| 指标 | 正常范围 | 告警阈值 |
|------|----------|----------|
| 活跃会话数 | < 最大限制的 80% | > 80% |
| 队列深度 | < 50 | > 100 |
| 错误率 | < 1% | > 5% |
| 平均延迟 | < 10s | > 30s |

### 资源指标

| 指标 | 关注点 |
|------|--------|
| CPU 使用率 | 是否有异常峰值 |
| 内存使用率 | 是否持续增长（可能有泄漏） |
| 磁盘使用率 | 工作区和日志是否过大 |
| 网络流量 | 是否有异常流量 |

### 业务指标

| 指标 | 关注点 |
|------|--------|
| 日活用户数 | 系统使用趋势 |
| 每日 Token 消耗 | 资源使用趋势 |
| 工具调用分布 | 用户使用模式 |
| 渠道消息量 | 各渠道使用情况 |

## 舰体日志

舰体（server）模式下，运行日志保存在 `config/data/logs/server/`：

- 按天轮转的 JSONL 文件
- 默认保留 14 天
- 包含请求、工具调用、错误等记录
- 出问题时优先查看最新日志

## 日常巡检与评估

### 每天

- 系统健康状态
- 错误率趋势
- 队列积压情况
- 磁盘空间

### 每周或每月

- Token 消耗趋势
- 工具使用统计
- 性能基线变化
- WunderBench 评测结果

## 排查顺序

遇到问题时按这个顺序走：

1. 看会话监控找到异常线程
2. 查看工具调用记录
3. 检查性能指标
4. 查看舰体日志
