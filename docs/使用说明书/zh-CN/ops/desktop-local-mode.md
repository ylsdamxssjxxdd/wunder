蜂窝本地模式在一台电脑上完成日常使用，是本地优先、目录持久的运行形态。它不是一个「小号 server」，也不是「少了管理员后台的 server」。

## 本地模式的特点

### 工作目录是持久的

本地模式下，工作目录不是临时沙盒，而是按持久目录处理，不走 24 小时自动清理。

### 工作目录是本地真实目录

本地形态下，工作目录直接落在用户本机的持久目录上：

- 目录内容持久保存，不走定期清理
- 智能体直接读写这个目录，不需要在「沙箱目录」和真实目录之间来回映射
- 与云端形态的区别只是位置：云端是服务端数据根下按用户划分的唯一目录，本地是本机上的持久目录
- 两种形态都是「一个用户一个智能体实例 + 一个工作目录」，没有容器分层

### 优先使用附带运行时

蜂窝本地模式优先使用安装包附带的 Python 运行时，减少首次配置成本。

## 本地模式覆盖的主链路

个人使用的完整主链路——用户侧界面、对话执行、工具调用、工作区文件、智能体设置、子智能体——在本地模式下都能覆盖，日常使用不需要再切换其他形态。

## 本地模式下的文件能力特点

本地模式下，内置文件工具可以访问本机绝对路径，比纯工作区限制更灵活。

## 一键重置工作状态

本地模式提供「一键重置工作状态」，用于以下情况：

- 会话卡在运行中
- 子智能体运行状态明显不一致
- 工作区里留下半截运行态文件
- 想让智能体回到干净的任务线程

执行后完成以下动作：

- 中止当前用户仍在运行的会话
- 清空排队任务
- 为智能体重建任务线程
- 清理对应工作态目录

## 重置后保留的内容

重置针对的是工作态，不碰长期资产。会保留的典型内容包括：全局配置、技能、知识库和用户长期配置。

它做的是把运行现场清干净，而不是恢复出厂设置。

## 改用舰体（server）的时机

只做个人使用时，本地模式通常已经够用。当开始需要多用户治理、管理员后台、单位/组织控制、统一渠道与服务接入时，改用浏览器访问蜂巢（web，随舰体提供）。

## 本地模式的边界

- 本地模式是有状态的：工作目录持久保存，不按无状态运行。
- 本地目录不再分「个人容器 / 智能体容器」：一个用户对应一个智能体实例和一个工作目录，没有容器分层。
- 修改提示词只对之后的任务线程生效，不会回写当前正在运行的老线程。
- 重置工作状态只清理当前工作态，不会删除长期技能或知识。
