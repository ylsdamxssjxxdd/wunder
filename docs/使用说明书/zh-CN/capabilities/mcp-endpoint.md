# MCP 入口

wunder 既能把自己暴露为 MCP 服务，也能作为 MCP 客户端接入外部服务。两个方向的入口与配置互不相同。

## 两个方向

| 方向 | 用途 |
| --- | --- |
| 对外暴露 | 让外部系统用 MCP 协议调用 wunder 的能力 |
| 接入外部 | 把外部能力接进来给模型使用 |

## 对外暴露

对外入口是一个地址，走 Streamable HTTP。

接通顺序：

1. 外部系统按 MCP 协议连上这个地址；
2. wunder 自动完成协议版本协商，与旧服务互通时按双方都支持的范围协商，不用手写初始化步骤；
3. 调用具体工具。

目前内置对外提供两个工具：`excute`（执行）和 `doc2md`（文档转 Markdown）。工具名就是 `excute`，照这个名字调用。

## 接入外部服务

在配置里声明要接的 MCP 服务，给它名字、地址和传输方式，然后打开开关。启用后 wunder 把它当成一个可调用的服务。外部服务同样用 Streamable HTTP；服务是 Python 写的时按 Python 侧的协议版本协商，不一定具备最新的全部能力。

文档里常提到的外部服务通常承载数据库查询、数据库导出、知识库查询这类工具。

## 设置与限制

- 接入顺序：先在配置里声明服务 → 在舰桥确认工具清单能拉到 → 再开放给模型使用。
- 舰桥里有 MCP 的配置和调试入口，可以刷新工具清单、直接调远端工具验证。
- MCP 工具不是旁路：它与内置工具、A2A 工具、技能、知识库工具、自建工具汇总进同一个工具视图。对模型来说，MCP 只是工具目录的一部分。
