# 目标

目标核心让智能体进入目标态并持续完成一项任务。把目标挂在会话上，智能体按目标自己接着做，直到完成、受阻或轮次预算用尽。

## 怎么运作

目标由三个工具驱动：

| 工具 | 作用 |
| --- | --- |
| `get_goal` | 读出当前目标及其版本号 |
| `create_goal` | 创建目标 |
| `update_goal` | 编辑、暂停、恢复、完成、报告受阻 |

目标的相位只有四种：`active`（活跃）、`paused`（挂起）、`blocked`（受阻）、`complete`（已完成）。

更新走 CAS-on-revision：更新必须带上目标当前的版本号，对不上就被拒绝。已启动轮次只增不减。

## 关键数字

| 项 | 值 |
| --- | --- |
| 默认目标轮上限 | 256 |
| 连续无进展自动受阻 | 3 轮 |
| 相位取值 | active / paused / blocked / complete |

## 从哪里用

| 入口 | 位置 |
| --- | --- |
| 接口 | `/wunder/chat/sessions/{id}/goal` |
| 斜杠命令 | `/goal` |

## 边界与当前限制

- 没有 token 预算，轮次之间也没有冷却。目标停下来只看轮次预算、相位与是否激活这三件事。
- armed 状态**不持久**：进程重启或会话 resume 之后，即使相位仍是 `active`，也需要显式 `update_goal action=resume` 重新 arm。判断「目标为什么不动了」，先看它有没有被 arm。
- 桌面端不开放目标选择，运行时按会话注入。
- 舰桥没有 goal 界面，目标操作在蜂巢 / 蜂窝 / 舵机里做。
