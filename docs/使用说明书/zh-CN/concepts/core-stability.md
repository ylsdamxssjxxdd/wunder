稳定性靠三件事：**控扩散**（一个环节出错不带崩别的）、**能恢复**（失败有正式恢复链路）、**可复盘**（错误结构化、能归类）。落地成四类硬约束：有界、预算、熔断、单写者。

## 队列都有界，满了就报忙

所有队列容量固定。写入在失败并超时后返回「队列忙」，同时记一条繁忙指标。**没有无界缓冲，也不会静默丢弃**。

| 队列 | 边界 |
| --- | --- |
| 单订阅事件写队列 | 256 |
| 慢客户端水位 | 剩余容量 ≤ 2 |
| 单次事件拉取 | 200 |
| 线程变更每页 | 200 |
| 渠道入站 | 容量 512 / 并发 8 / 入队等待 80 ms |
| 工作区写队列 | 2048 |

后台任务统一带标签启动，长运行会告警，某个循环崩溃也不会拖垮进程。排查时看日志里的任务标签就能认出是哪条循环。

## 限额与预算

| 项 | 值 |
| --- | --- |
| 用户输入上限 | 1,048,576 字符；图片附件不计入 |
| 模型调用默认超时 | 120 秒 |
| 工具默认超时 | 120 秒（下限 1 秒） |
| 工具并行度 | ≤ 4 |
| 轮次上限 | 非管理员默认 1000（下限 2） |
| 每轮工具调用预算 | 10000 |
| 每轮记忆召回预算 | 2000 |
| 会话锁有效期 / 心跳 | 120 秒 / 5 秒 |
| 活跃会话上限 | 默认 300（约束非管理员） |
| 审批批准缓存 | 600 秒 |

会话排队默认开启。把它关掉后，运行中再发消息会被直接判「用户忙」，也不再进排队条（舰体启动时会告警）。这属于配置取舍，不是故障。

## 会话锁与单写者

**同一任务线程串行执行，不同线程互不阻塞**：调度、锁与实时状态都按线程隔离。

会话锁用持久锁加有效期 120 秒，并每 5 秒心跳续约。等待方带退避而不是固定轮询：两次之后开始退避，退避上限 3 秒并带抖动，等待超过 30 秒会告警。这里刻意不做固定的 0.2 秒轮询，否则满载的系统会被自己的轮询变成存储风暴。

**单写者原则**：线程日志只有一个写出口。提交时：

1. 每个会话先经过一道门串行化，保证变更顺序与提交顺序一致；
2. 存储调用是一个短的阻塞事务；
3. **事务成功后才发布游标**给变更通道——通道只发唤醒信号，不是真相；
4. 幂等空操作（重放受理、状态未变、重复反馈）不产生变更、不发通知；失败的提交永不发布游标。

调用方不得自己拼游标，也不得在事务完成前通知变更通道。这条原则保证「客户端看到的顺序」与「落库顺序」一致，也是断线补水能无损的前提。

长持锁和慢客户端是两类被点名治理的问题：锁靠有效期加心跳兜住持有者消失，慢客户端靠水位检测先发 `resume_recommended` 再脱钩订阅（见 [实时性](/docs/zh-CN/concepts/core-realtime/)）。

## 恢复与熔断

| 场景 | 机制 |
| --- | --- |
| 流式卡住 | 空闲看门狗按「无活动时长」判定，不是按总时长掐 |
| 模型返回空或不可用输出 | 关闭思考后一次性重试 1 次，仍失败则报输出异常 |
| 上下文超限 | 渐进压缩（历史、溢出、预采样三处触发），溢出恢复最多 8 次 |
| 同类失败反复出现 | 按失败指纹熔断 |
| 网络或订阅断开 | 游标补水，不重放整段历史 |

重试熔断按同一指纹计数，阈值如下：

| 条件 | 阈值 |
| --- | --- |
| 非重试类失败 | 5 次 |
| 参数或结构类失败 | 2 次（确定性错误，重试不改变结果，两次后给出改道提示） |
| 可重试失败 / 同一工具连续失败 | 5 次 |
| 有成功但无进展 | 4 次 |

指纹细节最多记 240 字符。**熔断看的是「同一问题重复几次」，不是「总共调了几次」**：一万次的工具预算不会被一个死循环耗尽。

## 出错时对外长什么样

所有接口错误走同一个结构：标记失败，附上错误码、给用户看的说明、对应的 HTTP 状态、可执行的处理提示、便于追踪的 trace id 与时间戳，同时在响应头回写 trace id 与错误码。

**按错误码判断，不要按提示文案判断**——文案会随语言和版本变化，错误码与 HTTP 状态的映射才是契约。

## 该等还是该动手

| 现象 | 系统正在做什么 | 该做什么 |
| --- | --- | --- |
| 显示压缩中或排队中 | 正常处理 | 等 |
| 出现 `slow_client` 或 `resume_recommended` | 订阅被保护性脱钩 | 走补水端点重建投影 |
| 被判「用户忙」 | 该任务线程仍在执行（会话锁被持有） | 排队，或让出/取消该线程 |
| 反复同一工具失败后被停 | 指纹熔断已触发 | 改参数或换路径，重复提交无用 |
| 报输出异常 | 一次性恢复已用完 | 换模型配置或改问法 |
| 报额度不足 | 准入阶段扣减未通过 | 见 [额度与用量](/docs/zh-CN/concepts/quota-and-token-usage/) |
| 界面与后端状态不一致 | 投影落后 | 刷新或重进；仍不一致就看运行态 |
| 需要彻底重来 | — | 用「重置工作状态」（按用户取消会话与任务、清工作区，返回全新会话） |
