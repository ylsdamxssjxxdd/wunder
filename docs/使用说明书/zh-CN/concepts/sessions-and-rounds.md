# 会话与轮次

这套编号解决一件事：**把"用户问了几次"和"智能体走了几步"分开**。统计、回放、排队、Token 归集都需要这个坐标系。

## 层级

```
智能体（agent）
└── 任务线程（= 会话 session，一个智能体可同时有多条）
     └── 用户轮次 user_round（每次受理递增）
          └── 模型轮次 model_round（每次模型调用递增）
               └── 条目 item（可见回复、工具调用、审批、子智能体消息…）
```

| 概念 | 是什么 | 由谁决定 |
| --- | --- | --- |
| **线程 / 会话** | 一段连续执行与对话的主体，同一 `session_id` 贯穿调度、锁与状态 | 新建线程即新会话；子智能体是独立会话，靠 `parent_session_id` 回溯 |
| **用户轮次** | 一次被受理的人类输入 | 受理时对线程的 `latest_user_turn + 1`，唯一索引限定"每轮一个根" |
| **模型轮次** | 引擎主循环的**一次模型调用**，可包含一批工具调用 | 主循环每次采样自增一次 |
| **条目** | 时间线上可渲染的最小记录 | 落库时按稳定 `item_id` upsert |

结构体字段（`orchestrator/types.rs`）就是这四层的坐标：

| 字段 | 含义 |
| --- | --- |
| `user_round` | 属于哪个用户轮次 |
| `model_round` | 属于该轮内的第几次模型调用（未进入采样时为空） |
| `thread_turn_id` | 该用户轮次的持久 id，条目标识的前缀 |
| `is_goal_round` | 本轮由目标驱动器发起而非人类直接发消息，用于避免重复发出需要人类权限的目标管理调用 |

## 计数口径（以代码为准）

- **一个模型轮次 = 一次模型调用**，不是"一次动作"。工具调用属于同一个模型轮次内的批次，**不单独计模型轮次**。
- **一个模型轮次恰好一个可见输出项**，标识为 `{turn_id}:text-{model_round}`；同一个模型轮次多次刷新只会更新这一项，不会追加重复气泡。
- **时间线里的工具批次条目 ≠ 独立模型轮次**。每个工具调用是一个独立条目（按调用 id 合并"进行中→完成/失败"），所以"步骤数"通常大于"模型轮次数"。
- **续跑轮次不消耗用户轮次**：带根轮次引用的延续（如目标驱动器接管）复用同一用户轮次，只增加该轮内的模型轮次。
- 用户轮次只在**真正新建**时才对外发布变更游标；重放的受理是幂等空操作，不会产生新轮次也不通知订阅者。

## 幂等与排队

| 机制 | 口径 |
| --- | --- |
| 提交幂等 | 客户端消息 id 相同即复用既有轮次（返回 `created:false`），重试网络不会多出一轮 |
| 同线程串行 | 会话锁按线程隔离，TTL 120 秒、心跳 5 秒；异常退出由 TTL 释放 |
| 排队 | 队列开关默认开启；运行中再发的消息进入队列，按序执行 |
| 关掉排队的后果 | 运行中再发消息会被判"用户忙"且不排队（舰体启动会告警），不要当成性能优化关闭它 |
| 后台投递 | 定时消息走强制入队路径，避免与人工消息抢锁时丢失 |

## 时间线里有哪些条目

线程台账只收"有时间线信息量"的事件，白名单在 `services/thread_log.rs`：

| 条目类型 | 来源事件 | 状态流转 |
| --- | --- | --- |
| 工具调用 | `tool_call` / `tool_result` | 进行中 → 完成 / 失败（同一调用 id 合并） |
| 模型调用 | `llm_request` | 按模型轮次编号 |
| 可见回复 | `llm_output` | 即 `{turn_id}:text-{model_round}` |
| 审批 | `approval_request` / `approval_result` / `approval_resolved` | 等待 → 已决定 |
| 子智能体消息 | `subagent_message` | 用生产者给的消息 id 作持久标识，重放不会变新条目 |
| 排队台账 | `queue_enter` / `queue_start` | 挂起 → 运行（同条目 upsert），界面自行跳过 |

**不入账**：传输增量（`*_delta`）、心跳、`progress`、`context_usage`、`workspace_update`、`model_usage`、`llm_stream_retry`，以及生命周期回执 `final`、`thread_status`、`llm_response`（失败详情由 `turn_terminal` 携带）。这些能在流里看见，但不该变成时间线里的空条目。

## 界面读到的组织方式

- 聊天页**一个用户轮次一行**（默认页 12、上限 20），最终回复之外的一切中间内容折叠成"**工作过程**"。
- 工作过程默认收起，首次展开才按需拉取该用户轮次的持久条目（按线程轮次 id 取），不是把整条历史搬进前端。
- 逐条目全景在"**线程轨迹**"视图（默认页 80、上限 100），长正文按 8 KB 分块取。
- 目录列表读的是轮次尾巴（最高用户轮次、该轮状态、最近活动摘要、补水游标），一页线程一次批量查询。

## 实践

**什么时候开新线程**：换话题；需要应用新的智能体设定、提示词模板或长期记忆（已有线程的提示词已冻结）；上下文已很长且开始丢早期细节。

**什么时候续用**：同一任务未完、需要引用前面的产出。续用不会重算底座，只增加轮次。

**怎么定位"某一步"**：报坐标用 `用户轮次 + 模型轮次`，或直接给条目 id；工具批次只给条目序号，别把它说成"第几轮"。

## 常见误解

- **"一轮 = 一次问答"** —— 一个用户轮次可以包含很多模型轮次，每个模型轮次还能带一批工具调用。
- **"步骤数 = 轮次数"** —— 不相等，步骤（条目）通常更多。
- **"会话和线程是两个东西"** —— 在本系统里同一个 `session_id`：会话是对话与台账的载体，线程是它的执行主体。
- **"重复提交会重复计费轮次"** —— 带同一客户端消息 id 的重试是幂等的。
- **"子智能体的输入会出现在父线程"** —— 子会话的起始用户消息默认隐藏，且跳过自动记忆提取，避免污染用户记忆。
- **"Token 统计 = 供应商账单"** —— 线程记录的是上下文占用（只采信模型侧回报的观测值），不是计费口径。
