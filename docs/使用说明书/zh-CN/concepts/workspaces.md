# 工作区与工作目录

工作区是有明确隔离策略的文件空间。隔离只有一层：**按用户隔离**。

## 一层隔离

```
用户A的工作区
├── 用户的文件
├── 智能体生成的文件
├── 智能体可见的配置（技能、知识、全局设置）
└── 运行期快照与诊断

用户B的工作区（完全隔离，与 A 互不可见）
```

- 不同用户的文件完全隔离，互相看不到。
- 一个用户只有一个工作区，不再按"个人文件 / 智能体文件"再分一层。
- 用户、智能体实例、工作区一一对应：一个用户，一个智能体，一个工作区。

## 工作区在哪

| 形态 | 位置 | 怎么访问 |
| --- | --- | --- |
| 蛹（默认） | 本机上的持久目录 | 直接用系统文件管理器查看，智能体直接读写 |
| 舰体 | 服务端数据根下按用户划分的唯一目录 | 通过蜂巢左栏"工作目录"区上传、下载、编辑 |

三条硬约定：

| 约定 | 说明 |
| --- | --- |
| 唯一 | 每个用户同一时刻只有一个工作区，不替第二个智能体再开目录 |
| 固定 | 分配后固定，用户不能新增、删除或更换 |
| 相对路径 | 界面展示与接口收发的路径一律是工作区相对路径，不暴露绝对路径 |

## 它承担什么

- **数据隔离**：任何用户只能访问自己的工作区；以用户根为界做路径校验，越界读写会被拒绝；智能体的文件工具以这个目录为根，不再派生第二个根。
- **文件持久化**：工作区不会自动清理，你放进去的文件、智能体生成的文件都会长期保存。需要长期保留的放工作区，临时中转放临时目录。
- **配置的根**：工作区同时是"智能体能看到的配置"的根目录——技能目录、知识文件、全局设置，智能体启动时读它们来初始化。**智能体的模型、提示词、工具与审批模式由管理侧预设绑定和设置页管理**，不是靠你在工作区里手写文件。

## 怎么用

- **访问**：蛹直接用文件管理器，应用内左栏"工作目录"区有文件树和工具栏；蜂巢在左栏工作区下方的"工作目录"区，含文件树与上传 / 新建 / 刷新 / 多选工具栏。
- **对话中使用**：把文件交给智能体，或让它直接读写工作区里的文件。
- **引用到聊天**：文件行菜单选"引用到聊天"，把文件带进输入区。
- **下载（蜂巢）**：在文件树里选中文件下载，多选可打包下载。

组织建议：按项目或主题建子目录，一个项目一个目录、目录内再分资料与产物；要让智能体分析的文件先放进工作区，再在消息里说明路径或文件名；智能体生成的报告、脚本也落在同一目录树下，需要时自行整理。不需要的文件及时删，文件名取有意义的名字。

## 用量与空间

- 文件区底部显示已用容量、文件数与目录数。
- 统计走有界遍历，大目录下会标注统计为下界。
- 舰体若配置了配额，超限时上传会被拒绝并提示清理；没配配额时只显示已用量，不显示配额分母。

## 蛹的本地边界

蛹在本地运行，工作目录是本机上的持久目录，而不是临时沙箱：

- 内容持久保存，不走定期清理。
- 智能体能否访问本机路径，取决于本机安全设置。

## 容易搞错的地方

- 工作区不能换目录，也不能新增第二个。
- 智能体越多，工作目录不会越多：每个用户只有一个智能体实例，也只有一个工作区。
- 文件不用再分"个人容器"和"智能体容器"，这个分层已取消，用户和智能体共用同一个工作区。
- 别写绝对路径：接口收发都是相对工作区根的路径，绝对路径不对外暴露。
