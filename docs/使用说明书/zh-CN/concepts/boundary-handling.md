# 边界处理

长对话、网络抖动、工具报错、并发请求都属于边界情况。wunder 在这些情况下的目标是稳住，而不是整段崩掉。

## 三条处理原则

- **控扩散**：一个环节出错，不把其它环节带崩。
- **能恢复**：系统留有恢复链路。
- **可复盘**：同类问题能归类、复现、验证。

## 上下文超限：分级压缩

对话越来越长、工具结果越堆越多，总 Token 可能超过模型上限。系统按四级渐进压缩：

| 级别 | 做法 | 损失 |
| --- | --- | --- |
| 1 级 | 移除工具的中间结果 | 很低 |
| 2 级 | 把历史对话做摘要 | 中等 |
| 3 级 | 移除较早的对话 | 较高 |
| 4 级 | 紧急降级 | 很高 |

**系统提示词不参与压缩，始终冻结**，所以压缩不会改掉智能体的行为设定。

## 网络断开：自动重连 + 事件补发

连接可能因网络抖动断掉。断线后界面先给出提示，再按指数退避自动重连（1 秒 → 2 秒 → 4 秒 → 8 秒 → 16 秒，最长 32 秒）。断开期间没推送到的事件会被缓存，重连成功后补发；补发也失败，再提示手动刷新。

## 工具失败：分类型处理

| 失败类型 | 处理 |
| --- | --- |
| 参数写错 | 让智能体自己改参数、重试 |
| 权限被拒 | 停下来等你审批 |
| 临时错误（文件被占、网络抖动） | 自动重试 |
| 系统错误 | 有限重试 + 降级 |

## 工具输出过大：三层收口

| 层级 | 作用 |
| --- | --- |
| 执行层预算 | 限制单次输出大小 |
| 结果裁剪 | 超限时保留头部和尾部 |
| 入模检查 | 进模型前再精简一次 |

被裁剪的结果会明确告诉智能体"这里被裁了"。

## 多个请求一起来：排队 + 优先级

同一会话在忙时，新请求不会被打回，而是排进队列，等空闲后依次执行。优先级从高到低：管理员 > 高优先级 > 普通 > 低优先级。

## 你能做的

- **长对话**：留意上下文占用，必要时用 `/compact` 主动压缩；一个话题谈完就开新会话。
- **网络抖动**：界面显示"连接断开"时等它自动重连，别反复刷页面；重连失败再按提示手动刷新。
- **工具失败**：看失败提示找原因，按提示调整（比如给出正确的文件路径）；反复失败就找管理员看系统日志。
- **系统异常**：长时间无响应先尝试取消或重置；状态明显不对用"重置工作状态"；反复出现找管理员排障。

## 容易搞错的地方

- 智能体回答了，不代表一切正常。
- 重试有适用范围，不同错误类型走不同处理。
- 长对话和复杂任务里经常出现边界情况。
