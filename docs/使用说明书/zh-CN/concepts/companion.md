# 形象系统

形象（companion）是一层视觉陪伴：根据会话的运行状态播放对应动画、偶尔冒一个消息气泡。**它不参与执行、不影响调度，删掉形象不会改变任何功能。**

## 形象包长什么样

一个形象包就是一个 ZIP，里面恰好放两样东西：一份清单，一张精灵表图片。

- 清单是一份 JSON，写明形象 id、显示名、描述，以及精灵表文件的位置。
- 精灵表是一张图片，路径由清单指定。
- 大小上限：整个 ZIP 不超过 24 MB，精灵表单文件不超过 18 MB。
- 导入时会做压缩包内的路径穿越防护。

形象文件放在固定的形象目录里；蜂窝、舵机这类内嵌运行的形态会把这个目录固定到各自的数据目录。当前没有内置任何形象包，列表为空属于正常。

## 精灵表规格

- 每帧固定 **192 × 208** 像素，同一状态的帧在同一行里横向排；**一个状态占一行**。
- 行号就是状态（行 0–8）：

| 行 | 状态 | 行 | 状态 |
| --- | --- | --- | --- |
| 0 | 待机 idle | 5 | 失败 failed |
| 1 | 向右跑 running-right | 6 | 等待 waiting |
| 2 | 向左跑 running-left | 7 | 运行 running |
| 3 | 挥手 waving | 8 | 检阅 review |
| 4 | 跳跃 jumping | | |

- 会话运行状态映射到动画行：运行中 → running（第 7 行）、完成 → jumping（第 4 行）、等待 → waiting（第 6 行）、出错 → failed（第 5 行），其余回落到 idle（第 0 行）。点击形象播放一次挥手（waving）动画。
- 形象包可以少声明帧数：越界的行或帧会被边界检查降级处理，不会崩。

## 各形态怎么呈现

| 形态 | 呈现 |
| --- | --- |
| 蜂窝（Windows） | 原生浮窗：每只宠物一个独立窗口，拖拽与帧时钟走独立消息线程，不占界面线程 |
| 蜂窝（Linux） | 没有等价浮窗，桌面宠物只有 Windows 有 |
| 蜂巢 | 页面内浮层，跟着聊天状态 |
| 舰桥 | 形象管理面板：上传、编辑、删除、导出全局形象 |
| 舵机 | 没有形象界面，只把形象目录指到本地数据目录 |

## 缩放与位置

| 项 | 范围 |
| --- | --- |
| 存储 / 菜单缩放 | 0.5–1.6（预设 0.5 / 0.8 / 1.0 / 1.2 / 1.4 / 1.6） |
| 渲染缩放 | 0.5–1.8 |
| 位置 | 按屏幕工作区夹紧并保持边距，拖拽结果会保存 |

蜂窝把位置、每只形象的显示 / 缩放覆盖、全局消息提示开关存到本地文件；蜂巢存在浏览器本地（清理浏览器数据会重置位置与偏好）。

## 谁能改形象

- 用户侧只能查看：看全局形象列表、看某一只的详情、取它的精灵表、导出它的包。
- 增删改全部在管理员侧（列表、导入、改删、精灵表、导出包），导入请求体上限和 ZIP 上限一致（24 MB）。
- 蜂巢里的"私有形象"只在当前浏览器本地生效，不上传服务端；全局形象由管理员经舰桥上传后，所有用户可见。

## 容易搞错的地方

- 形象不是"另一种智能体"，它只是某个智能体的视觉外壳，一个智能体绑一只形象。
- 用户不能在蜂巢里把形象传到服务器；服务端形象一律由管理员经舰桥管理，私有导入只在本地浏览器。
- Linux 蜂窝没有桌面浮窗。
- 形象动画不影响任务执行：是运行状态驱动动画，反过来不成立。
- 系统不内置形象包，要管理员自己上传。
