出问题时，线索集中在四个地方：**日志**记录发生过什么，**运行时指标与告警**反映当前负载与告警状态，**监控与会话轨迹**还原某条线程经历了什么，**性能与压测**测的是系统能承受多少。四类入口各自独立、各管一段。

## 日志

日志同时输出到两处：控制台一层带颜色，文件一层每行一条 JSON。文件按天滚动，文件名以 `server.jsonl` 开头，默认放在 `./config/data/logs/server`。

默认级别是 `info`，可用环境变量 `RUST_LOG` 覆盖；内置了对第三方库噪声的降噪。

保留期默认 0，也就是**永不自动清理**：只有显式设置一个正整数天数，系统才会按天删除旧文件。长期运行的部署要么显式配好保留期，要么自己轮换日志目录。注意 sandbox 模式下不写文件，只有控制台输出。舵机和 bridge 的日志默认更严（warn 起）且都不落文件。

## 运行时指标与告警

管理端暴露一份运行时指标快照，类别固定：阻塞池按数据库、文件、CPU、外部调用分类，给出调用数、排队等待与超时；有界队列给出积压与繁忙拒绝；后台长任务给出运行数与告警；调度循环给出心跳是否停摆。

告警带阈值与严重度。同一个阻塞池会先判超时类（critical）再判延迟类（warning），所以看到延迟警告时，先确认没有排队或执行的超时。

## WebSocket 与渠道事件日志

WebSocket 的连接过程有结构化日志，覆盖建立、就绪、握手、握手失败、消息、解析失败、关闭这几个阶段。连接建不上、握手失败、消息解析出错，都能在这些阶段里分辨。

渠道运行日志放在内存环形缓冲里，只留最近 300 条，相同内容在 20 秒内会去重，且不写数据库，进程重启即清空。查询分两路：用户面查自己的渠道日志（`/wunder/channels/runtime_logs`，加 `/probe` 做主动探测），管理面查全部（`/wunder/admin/channels/runtime_logs`，同样支持 `/probe`）。主动连通性用探测，长连接异常用重连。需要长期审计时，把渠道日志接到外部日志系统。

## 监控与线程轨迹

管理端监控是治理视图的入口：会话按状态标注为运行中、等待中、排队中、已完成、出错、取消中、已取消，可以按会话导出线程日志、翻页查看轮次、拉取快照（形如 `/wunder/admin/monitor/{session_id}/thread-log/export|turns|snapshot|changes`）。

舰桥调试面板右侧的日志区是**线程轨迹视图**，用于追单个线程的执行记录。

## 三类性能入口

| 入口 | 用来做什么 | 关键上限 |
| --- | --- | --- |
| 吞吐量 | 压模型流式能力，按并发 × 输入/输出 token | 并发 ≤ 1024；输入预设 1024…1,048,576、输出预设 1024…8192，硬上限输入 16,777,216、输出 1,048,576；历史保留 50 条 |
| 性能采样 | 真实环境体检，对命令、IO 等采样 | 用一个固定的管理采样用户，数据落在工作区的 `.wunder_perf`，单命令超时 5 秒 |
| 线程渲染压测 | 造大量轮次数据，测前端渲染与投影 | 用户轮次 ≤ 2000、模型轮次 ≤ 2000、总条目 ≤ 6,000,000；并发追踪 job ≤ 8，生成超时上限 1 小时 |

吞吐量与性能采样属管理面（`/wunder/admin/throughput/*`、`/wunder/admin/performance/sample`）。吞吐量的实时观看通道靠一次性 ticket 免管理员鉴权。线程渲染压测刻意放在用户面（`POST /wunder/chat/stress-threads`），用普通用户凭据即可调用；单个 job 的数据量上限很高。三者对象与口径不同：网络与模型承压、环境采样、前端数据量，别当成同一个面板。

## 性能评分口径

蛹、蜂巢、舰体三种形态**各自独立**按 0–100 加权评分，不能跨形态相加。对比一律按「同环境、同入口、改前/改后」进行，配套基线在文档的《性能基线》目录里。换机器、换入口得到的数字不可互比。

## 排障顺序

1. **拿结构化错误**：接口出错时统一返回一个错误对象，含错误码、说明、HTTP 状态、给用户的处理提示、这次的 trace id 和时间戳，同时在响应头回写 trace id 与错误码。先把 trace id 记下来。
2. **查监控**：按会话看状态与轮次；线程卡住时先分清是「等待人工」还是「排队/等锁」。
3. **对日志**：用 trace id 在日志文件里检索；实时连接问题过滤 WebSocket 连接阶段；渠道不通查运行日志与探测结果。
4. **进轨迹**：在线程轨迹视图里逐轮核对模型调用、工具批次与结果，找出第一处偏离。
