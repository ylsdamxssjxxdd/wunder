# 流式执行

执行过程实时到达界面，界面读到的数据与会话记录同源，断线后按游标接回。

## 落库与通知

引擎发一个事件，会先同步写进会话记录（每个会话一条串行通道、单事务），事务成功后才发布变更游标、唤醒订阅者。由此有三条保证：

- **提交顺序 = 变更顺序**：每条会话一个通道，写入在短事务里完成；失败的提交**不会**发布游标。
- **幂等不吵**：重放的受理、状态没变、重复反馈都不产生变更，也不通知。
- **唤醒只是加速**：进程内的唤醒通道不保证正确，服务端续传始终保留轮询兜底（250 毫秒起、指数退避到 4 秒），多实例靠轮询收敛。

界面显示的文本与刷新后读到的文本同源，不存在"流里有、库里没有"的中间态。

## 通道

| 通道 | 用途 |
| --- | --- |
| `/wunder/chat/ws` | 聊天会话主通道：提交、续传、旁观、取消、审批 |
| `/wunder/ws` | 通用请求面（提交一次执行并流式接收） |
| `/wunder/interlink/remote_ws` | 浏览器旁观远端设备的单条会话，纯转发不落库 |
| `/wunder/user_world/ws`、`/wunder/desktop/lan/ws` | 站内会话与局域网协同 |

蛹默认形态**不经过本机 HTTP / WebSocket**：同进程原生事件通道（有界，容量 128 条）直接投递；丢订阅或关窗口不会取消已在服务端受理的轮次。

⚠️ **聊天没有 SSE 兜底**。服务端确有 SSE，但只用于对外集成面和模型代理调用，不是聊天的降级通道。

## 事件分类

| 类别 | 是否进时间线 | 用法 |
| --- | --- | --- |
| 条目事件（工具调用、模型调用、可见回复、审批、子智能体消息、压缩、轮次终态） | 是 | 按稳定的条目 id 覆盖更新 |
| 传输增量（助手正文尾块、命令输出增量） | 否 | 只补字：助手正文走尾块，命令输出走增量 |
| 状态与回执（会话状态、结束、错误、会话关闭、排队） | 部分（排队是持久记录） | 判断生命周期，不渲染成条目 |
| 唤醒与补水（视图变更、需要重取视图、需要快照、流溢出、慢客户端、建议重连） | 否 | 客户端据此续传或整体重拉 |

统计类（上下文占用、Token 用量、轮次用量、模型用量、额度）只用于面板刷新，不进时间线。

## 断线与补水

客户端保存**持久游标**（变更序号），重连时带上：

| 情况 | 服务端信号 | 客户端该做 |
| --- | --- | --- |
| 落后但不多 | 从游标续发变更行 | 就地增量应用 |
| 落后超过窗口 | 流溢出 + 建议重连 | 先收信号再断开该订阅，按游标重连 |
| 持久窗口已被裁剪 | 需要快照 | 放弃续传，拉一次原子快照 |
| 展示视图落后 | 需要重取视图 / 视图变更 | 重取分页视图，不逐条拼接 |

补水接口是成套的：会话变更列表、原子快照、事件分页、单条目正文。

## 有界默认值

| 参数 | 值 |
| --- | --- |
| 每连接写队列 | 256（满即判慢客户端） |
| 慢客户端水位 | 2（队列深度超过即告警 / 降级） |
| 续传每页 | 200 |
| 事件读取上限 | 200 |
| 心跳 | 15 秒 |
| 单条消息 | 512 KiB（超出即拒收；远端旁观 256 KiB） |
| 聊天页 / 轨迹页 | 12（上限 20）/ 80（上限 100），响应预算 128 KB / 192 KB |
| 正文分块 | 8 KB |

前端消费的是**视图**：聊天一页只装 12 个用户轮次，每个轮次除最终回复外的中间内容折叠成"工作过程"，展开时才拉该轮条目。轨迹是逐条目视图（每行子智能体卡片上限 8 个）。

## 故障判断

- **一轮是否结束**：看轮次终态（带状态、停止原因、可选错误与恢复动作），不靠"好像不动了"。等待审批或等待补充信息时，会话仍在生命周期内。
- **看到重复气泡**：多半是客户端没按条目 id 覆盖更新、而是又追加了一条。用"轮次 id + 模型轮次"定位同一项。
- **丢字**：检查是不是把增量当成了唯一来源。增量只负责连续展示，正文真相在条目里；重连后走补水接口。
- **刷新后内容变长**：刷新读的是落库正文，可能比流式尾块更完整。

## 限制

- 流式和落库不是两条路：发事件时同步落库，游标在事务之后才发布。
- 断线不等于执行中断：执行在服务端继续，客户端按游标重连接上即可。
- SSE 不是聊天的降级方案，聊天只有 WebSocket。
- 多拉几次拿不到全量历史：视图有意有界，全量搬运是设计上要避免的。
- "看到字在出"不等于"循环转了很多轮"：文本增量与模型轮次是两种粒度，一轮内可能有成千上万个增量。
