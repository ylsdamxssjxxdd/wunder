# 子智能体控制

工具名 `子智能体控制`，别名 `subagent_control`。

子智能体是主智能体临时创建的工作单元：一次派一个任务线程，任务结束就回收。现在只有这一种协作形态。

## 什么时候用

- 一块工作能独立做完、结果只要摘要回来：派一个子智能体。
- 同一个目标要多路并行尝试或互相复核：一次派一批。
- 已经派出去的要看状态、等结果、纠偏、打断或关掉。
- 子智能体自己要向父线程回话（只有子智能体能用）。

这些动作都挂到当前这条线程下。线程本身的新建、切换、归档是另一件事，用 [会话线程控制](/docs/zh-CN/tools/thread-control/)。

## 怎么用

一次调用指定一个动作：

- `list`：列出某父线程下的子线程。
- `history`：读某个子线程的消息历史。
- `send`：给某个子线程追一轮指令。
- `report`：子线程回报父线程。
- `spawn`：派生一个子智能体。
- `batch_spawn`：一次派生一批，带策略和剩余分支的处置。
- `status`：读目标当前快照，不等待。
- `wait`：等到完成条件达成或超时。
- `interrupt`：取消运行。
- `close`：关闭会话，可选级联。
- `resume`：恢复为活跃；带消息时等同一次追加指令。

不指定目标时，默认把当前会话当成父线程，也可以用派生的运行 id、会话 id 或批次 id 指派目标。

派生时可以顺带指定：

- `label`：给子线程起个便于辨认的名字。
- `agent_id`、`model`：覆盖子智能体或它使用的模型，两者都受当前用户的智能体归属校验。
- `run_timeout_seconds`：单次运行的超时；在同步派生里同时也是等待时长。
- `fork_turns`：把最近若干轮用户上下文复制过去，0–16，默认 0。
- `context_summary`：附加一段背景摘要。
- `cleanup`：收尾方式，`keep`（默认，保留可查）或 `delete`（清理掉）。

## 它自动处理了什么

**上下文继承。** 复制过去的上下文和背景摘要是「引用数据」，不会改子智能体的系统提示词：父线程最近若干轮会作为「引用背景」拼在任务文本前面，一次最多复制 256 条历史、总量 64 KiB，超出就标记为截断。`fork_turns` 超过 16、或摘要超过 16384 字节会直接失败；`fork_turns` 为 0 且没写摘要时不读历史。子智能体的工具集默认继承父会话，它的工具系统提示词在首次确定后保持冻结，长期记忆和背景注入只在初始化时发生一次。

**派一个和派一批。**

- 派一个：超时设成 0 或负数时立即返回、放到后台跑；设成正数则同步等结果，期间每隔 5 秒发一次进度，超时就返回超时。
- 派一批：先给每个任务都准备好上下文，只要有一个准备失败，整批都不派（不会留下半个批次）。随后逐个派，某个起步失败就回收它并记为失败。完成条件看策略：并行全跑 / 先复核再合并 → 等全部；首个成功 → 第一个成功就完成。提前完成后，剩下的分支默认「保留」，若是「首个成功」策略则默认「打断」。

**等待、发送和回报。** 等待会先订阅完成信号，没有信号就按固定间隔轮询，间隔落在一秒左右（0.2–5 秒之间）。等待可能因为三件事结束：完成条件达成、超时、或父线程收到一条消息。子线程正在跑当前轮且信箱开着时，发给它的消息会直接进当前轮，否则另起一轮；把消息发给它自己会报错。子线程回报时，父线程空闲会被自动唤醒去接，同一条消息重复提交不会重复入箱。

**打断和关闭。** 打断只请求取消运行，不改会话状态；关闭会把会话状态置为已关闭并顺带取消运行，还可以级联处理它的后代；恢复把状态改回活跃。

## 出问题时怎么判断

- 目标一次最多选到 200 个，超了直接报「目标太多」。
- 读历史、发消息这类单目标动作要求「恰好一个」子线程：先按 id 精确找，找不到就在同父线程下找一个名字相近的唯一目标，再不行就退化成「只有一个子线程就选它」，仍不唯一就报错，并让你用派生或列表返回的准确 id。
- 目标必须和调用方同根，根线程不能当被派目标；嵌套深度上限 32 层。
- 批次一次最多 64 个任务，超了整批拒绝而不是截断。
- 每个子线程的待发消息与回执缓存都是有限的，满了按拒绝处理；列表一次最多 200 条，默认 50 条。
- 条目里的结果预览和状态消息会被截到 160 个字符，完整内容去历史或该子线程的轨迹里取。
- 蜂窝里这个工具默认额外启用；其它形态需要管理员勾选。
