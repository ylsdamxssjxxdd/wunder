# 扩展与动态工具

模型看到的工具名，一部分来自内置表，另一部分会在运行时按配置动态注册，按工具、技能、能力、用户工具四层分派。

## 四层分别是什么

| 层 | 是什么 | 谁在用 |
| --- | --- | --- |
| **工具** | 执行体：有参数定义、有分派分支，能产生副作用或读取数据 | 模型调用，运行时执行 |
| **技能** | 知识 + 脚本：一个目录，含 `SKILL.md`（带 frontmatter）与入口脚本 | 既可以被当工具调用，也可以只读正文当资料 |
| **能力** | 管理员选择层的条目，不是执行体：把工具与技能统一成可选、可授权的项 | 舰桥 / 蜂巢勾选、授权、共享 |
| **用户工具** | 用户自带的扩展：MCP / 技能 / 知识库，带别名路由 | 用户面配置，运行面按别名命中 |

“选了一个能力”就是把一个工具名或技能名放进该智能体的选择集，真正的执行仍由工具层或技能层完成。

## 名字冲突时谁说了算

工具分派的命中顺序是固定的：

1. 先把英文别名归一到中文规范名。
2. **用户工具别名表命中** → 直接路由到你的用户 MCP、用户技能或用户知识库。自己也有的技能可以直接用技能名，别人的技能要写成“主人@技能名”。
3. **技能名命中** → 直接执行技能入口脚本。
4. **名字里带 `@`** → 按 MCP 处理。
5. **知识库名命中** → 按库执行检索。
6. 其余走内置工具。

注意第 2 步**优先于内置工具**：用户工具和内置工具同名时，路由会被用户工具改掉，这是预期行为。

## MCP

### 作为客户端：`server@tool`

把外部 MCP 服务器接进来后，每个被放行的工具都会注册成 `服务器名@工具名`。

- **打包模式**：把服务器标成打包后，它整体折成**一个**工具，动作只有三个——列出可用工具、取某个工具的说明、调用某个工具。这样几十个工作细节不会一次性塞进上下文，模型按需查看。
- **只支持一种传输**：streamable-http。旧的传输类型会在列工具或调用时被拒绝，stdio 在 wunder 侧不支持。
- 工具列表有短缓存：30 秒内、最多 128 条。
- 参数只接受对象；非对象会被当成无参数。
- **返回形态**：直连调用返回 MCP 自己的结果结构；经用户工具别名路由的调用，会再包一层统一外壳。

### 作为服务端：`/wunder/mcp`

舰体 / 蛹会在 `/wunder/mcp` 上挂一个 MCP 服务，暴露两个工具：

- `excute`：执行一个智能体任务并返回最终回复（工具名就是这个拼写，对接时以此为准）
- `doc2md`：解析文档并返回 Markdown

端点跑任务时，会现算给智能体的工具集，并显式移除自己，避免端点驱动的智能体回调端点本身。

### 独立的示例服务

此外还有一个独立的 MCP 服务示例，注册了数据库查询、数据库导出、知识库查询，以及 PPT 读取 / 写入 / 删除 / 精修 / 模板读取等工具。要连它，就按上面的规则配一个 streamable-http 端点。

## 技能

- 一个技能就是一个目录：`SKILL.md` 带 frontmatter，入口脚本按固定顺序探测（`run.py` → `skill.py` → `main.py`）。
- **技能名本身就是可调用的工具名**，不需要再经过“技能调用”。
- `技能调用`（别名 `skill_call`）负责的是“读正文”：返回技能名、描述、路径、根目录和正文，并把正文里的技能根占位符替换成真实路径。名字可以写成“主人@技能名”或裸技能名，重名时会报歧义并列出候选。
- 打包导入（含压缩档案与重名处理）由平台负责。
- 全局技能目录由配置提供，脚本执行器路径可以覆盖。

## 知识库

- **按库名动态注册**：每个启用的库，其库名直接成为一个工具名；和技能同名时，让位给技能。
- 参数：可以给查询词，也可以给关键词数组（关键词优先，多关键词会分组检索并去重），还可以限制条数。
- 库分三型：字面检索、内置向量检索、外部 RAGFlow。向量检索失败或没有可用嵌入档案时，会**回落字面检索**，结果里能看到当前是不是回落模式。
- 命中 0 条时会提示收窄查询；结果里的文档项会被压缩，少占上下文。

## 出问题怎么判断

| 症状 | 先查什么 |
| --- | --- |
| 配了 MCP 却没有工具 | 检查服务器是否启用、放行名单是否拦截、传输类型是否为旧值 |
| 提示不再支持旧版传输类型 | 改成 streamable-http |
| 提示未知内置工具 | 名字既不是规范名 / 别名，也不带 `@`、不是技能名、不是库名 |
| 技能调用失败 | 入口脚本是否缺失或非零退出；先看技能调用能否读到正文 |
| 知识库名字调不到 | 库是否启用、根目录是否为空，或名字被同名技能占用 |
| 用户工具“抢”了内置名 | 别名路由优先于内置分派，属预期行为 |
| 工具整体消失 | 可能被临时下架或桌面隐藏，见 [工具](/docs/zh-CN/tools/index/) |

## 边界

- 动态注册的名字和内置名共用一张表：给技能 / 知识库取名时避开内置规范名与别名，否则语义会被别名改写。
- MCP 工具列表和调用都受放行名单约束，打包折叠后仍会逐次校验。
- 技能执行是**子进程跑脚本**，超时 60 秒；它继承平台的路径与权限边界，不要把特权操作写进技能脚本。
- 扩展项进入模型上下文前，仍会经过能力选择集与模型可用性过滤（视觉类、多模态类、桌面类的门槛各不相同，见 [工具](/docs/zh-CN/tools/index/)）。
