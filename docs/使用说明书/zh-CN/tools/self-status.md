# 自我状态

规范名 `自我状态`，别名 `self_status`。只读，不执行任何业务动作，也不触发审批、不进沙箱执行；默认返回当前会话的阶段、状态、模型轮次和上下文占用，用来判断要不要压缩上下文或收尾。它默认不在工具集里，需要管理员在能力面板上显式勾选才会出现。

## 参数

模型调用只接受一个可选参数 `detail_level`：

- 默认 `basic`，用于模型的下一步决策。
- `full` 只允许管理员在明确诊断时使用，会附带有限的近期事件和系统资源指标。
- 其他档位和事件、系统指标开关均会被拒绝。

## 返回字段

执行层会保留完整的授权诊断对象；模型上下文始终只保留下一步所需的紧凑摘要：

- `stage`、`status`、`round` 和 `context_tokens`。
- 运行态提供时会带 `context_ratio` 或 `last_error`。
- 不回显会话标识、模型地址、完整运行时快照、事件原文或系统指标；这些仅保留在执行审计和管理员 full 诊断中。

几处值得注意：

- 数据来自内存里的运行态，不是数据库台账。要看全量历史请去线程轨迹，别指望这里的事件数覆盖整个生命周期。
- full 档的近期事件固定限制为 20 条，避免诊断数据无界增长。
- 「正在用的模型」来自事件流，可能和配置的默认模型对不上。
- 上下文有几组数值口径不同、并列返回、互不换算，别把不同口径的数字混着比。

## 错误与处理

- 参数写错时，错误信息会原样返回，执行层记为失败。
- 监视器不可用、没有编排器都不算错误，对应字段直接为空。
- 它在蛹、蜂巢、舵机、舰体都能用。
