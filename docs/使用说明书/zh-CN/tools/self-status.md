# 自我状态

规范名 `自我状态`，别名 `self_status`。只读，不执行任何业务动作，也不触发审批、不进沙箱执行；返回当前会话的模型、上下文占用、轮次进度和事件计数（模型请求、工具调用、审批），用来判断要不要压缩上下文或收尾。它默认不在工具集里，需要管理员在能力面板上显式勾选才会出现。

## 参数

可以按需要选详细程度：

- 默认 `standard`，够日常查看；`basic` 更精简，`full` 最全。
- 除了这三档，`lite`、`summary`、`detail`、`detailed`、`verbose` 也能填，会归一到大致档位；填了不认识的值会落回 `standard`。
- 想看最近的事件列表，把 `include_events` 打开（`full` 档默认就开）；`events_limit` 控制返回多少条，范围 1–200，默认 20。

## 返回字段

它会直接给一个状态对象，而不是通用成功骨架：

- 会话标识：用户、会话、工作区、智能体，以及是否管理员。
- 正在用的模型：从最近一次模型请求事件反推，没有事件时为空。
- 配置的默认模型：没配默认时为空。
- 上下文占用与峰值等几组数值。
- 监视器状态、阶段与摘要。
- 用户轮次与模型轮次相关的计数。
- 事件总数、最近事件 id，以及按类型分的计数；开了事件列表还会带最近若干条。
- 编排器的会话运行时快照，没有编排器时为空。

几处值得注意：

- 数据来自内存里的运行态，不是数据库台账。要看全量历史请去线程轨迹，别指望这里的事件数覆盖整个生命周期。
- 事件条数上限只裁剪最近事件列表，事件总数仍是缓冲区里的全量计数。
- 「正在用的模型」来自事件流，可能和配置的默认模型对不上。
- 上下文有几组数值口径不同、并列返回、互不换算，别把不同口径的数字混着比。

## 错误与处理

- 参数写错时，错误信息会原样返回，执行层记为失败。
- 监视器不可用、没有编排器都不算错误，对应字段直接为空。
- 它在蛹、蜂巢、舵机、舰体都能用。
