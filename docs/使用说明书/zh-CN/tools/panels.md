# 计划面板 / 问询面板 / 会话让出

三个工具同属“交互控制”类，都不产生业务副作用，只改变前端呈现或当前轮次的结束方式。

| 规范名 | 别名 |
| --- | --- |
| `计划面板` | `update_plan` |
| `问询面板` | `question_panel`、`ask_panel` |
| `会话让出` | `sessions_yield`、`yield` |

独立的“休眠等待”工具已删除，等待语义由 `会话让出` 承担。

## 计划面板

任务要多步、而且用户要看进度时，用它建立并维护执行清单。一次就能做完的事不要建计划。

计划是一组步骤，1 到 12 项，每项是“步骤 + 状态”；步骤留空的项会被丢弃。状态有 `pending` / `in_progress` / `completed`，也接受 `in-progress`、`done`、`complete` 等写法归一。可以附一句计划变更说明。

调用是**全量替换**，不是增量补丁。**同一步只允许一个进行中**，出现第二个时它会被降级为待办。

计划为空、或全部步骤被丢弃时会报错。结果里不回显计划内容，计划通过前端事件推给用户。

## 问询面板

存在多条合理路线、需要用户拍板再动手时用它。开面板就是**把当前轮次交给用户**，不要在同一轮里继续假设答案。

可以问 1 到 4 个问题，每个问题配 1 到 4 个选项；选项可以是“标签 + 描述 + 是否推荐”，也可以直接给字符串。每个问题可以设成多选，默认单选。兼容旧的单题扁平写法（顶层直接给问题、选项和是否多选）。选项标签里含“推荐”，或标了推荐标志的，会被识别为推荐项。

超过 4 个问题只取前 4 个；**没有任何选项的问题会被整题丢弃**；全部丢弃后就报错。

面板以“保持打开”的方式发出，本轮就此收尾，最终给用户的文案是“等待用户在问询面板里作答”，停止原因记为问询面板：**开面板 = 本轮结束，等用户下一条消息**。

## 会话让出

本轮已经没事可做，但要显式声明“现在让出、等待外部事件”时用它，而不是硬编一段收尾话。它不是最终回复的替代品，也不是定时器。定时唤醒由 [定时任务](/docs/zh-CN/tools/schedule-task/) 负责。

可以给一句让出说明，向用户交代当前状态；留空时用默认等待文案。返回状态是“已让出”，并把本轮答案设为这句说明，停止原因记为让出。

桌面模式（蛹）把 `会话让出` 列为隐藏工具，不对智能体开放。

## 错误与处理

三者都走统一失败外壳。最常见的失败是参数校验：计划面板的空计划、问询面板没有可用选项，以及参数结构不对导致的解析错误。

## 限制

- 面板不鉴权、不审批：它们只管呈现和轮次控制，和写文件、执行命令的审批档位无关。
- 计划和问询的结果都很薄，目的是少占上下文；不要把详细内容塞进说明里让模型重复读回。
- 前端断流时面板事件可能不渲染，但**轮次结束语义仍然生效**——问询或让出之后，不要指望同一轮继续。
- 上限：计划项最多 12、问题最多 4、每题选项最多 4，超出部分会被拒绝或裁剪。
