# 桌面控制

| 规范名 | 别名 |
| --- | --- |
| `桌面控制器` | `desktop_controller`、`controller` |
| `桌面监视器` | `desktop_monitor`、`monitor` |

## 什么时候用

- 目标只有一个**图形界面入口**、没有命令行或接口可用时，才用 `桌面控制器` 去点、去输。
- 需要看桌面当前状态、或确认上一步动作有没有生效，用 `桌面监视器`。
- 能用命令、文件或浏览器工具解决的，不要走桌面控制：它更慢、更易错，而且直接操作用户真实的屏幕。

## 前置条件

三条都满足才能用：

1. 安装版本编译了桌面控制能力（默认不带）。
2. 处于桌面模式，并显式打开桌面控制开关（默认关闭）。
3. 当前模型支持视觉，否则桌面控制、桌面监视器和读图工具都会被过滤掉。

形态差异：蜂窝（桌面模式）默认把这三个工具列入额外启用集；舰体、蜂巢、舵机形态下桌面工具不可用。

## 怎么用

### 桌面控制器

一次调用要给出**位置**和**动作**：

- 位置用归一化坐标：可以是 `[x1,y1,x2,y2]` 四元组，也可以是中心点的二元组。坐标基于默认 `1000×1000` 的归一网格，运行时取中心后线性映射到真实屏幕像素。
- 动作有 17 个：`left_click`、`left_double_click`、`right_click`、`middle_click`，`left_hold` / `right_hold` / `middle_hold` 与其对应的 `left_release` / `right_release` / `middle_release`，`scroll_down` / `scroll_up`，`press_key`、`type_text`、`delay`、`move_mouse`、`drag_drop`。
- 相关参数：按键用 `key`，输入文本用 `text`，延迟用 `delay_ms`，拖动时长用 `duration_ms`（不给时按约 400 毫秒平滑拖动），滚动步数用 `scroll_steps`，拖动终点用 `to_bbox`。

也接受宽松别名：`keyboard`→`press_key`、`send_text`→`type_text`、`sleep`→`delay`、`move`→`move_mouse`、`drag`→`drag_drop`，连字符和空格会自动归一。未知动作会报“未知动作”。

动作描述只用于屏幕提示，缺省时用动作名本身。

### 桌面监视器

给出等待时长（0–30000 毫秒，超过会被夹到 30000），可以附一句观察备注，备注会原样回显。等待参数也接受 `wait`、`delay_ms` 等写法。

## 它自动做了什么

- **每次动作后都会截一张图。** 控制器不返回动作前的屏幕状态，动作结果由紧随其后的视觉输入给出。
- 成功返回后，编排器会用截图拼一条**用户角色的多模态消息**追加给模型：文字提示 + 动作前的截图（若有）+ 当前截图。也就是说，模型看到的工具结果本身不含图像，画面是通过这条追加消息进来的。规划任务时按“一次动作 = 一次调用 + 一次看图”估算成本。单张截图进上下文上限 8 MiB，超出即失败。
- 屏幕上会给提示：动作执行前在真实屏幕显示“AI 正在点这里”的红点，完成后收起；监视器则有倒计时提示。

## 出问题怎么判断

- 没编译桌面控制能力：调用直接失败，并提示能力未启用。
- 不是桌面模式、或没打开开关：返回“桌面控制已禁用”。
- 参数缺失：位置、动作、等待时长都是必填，缺哪个报哪个；位置格式不对会报非法坐标。
- 截图失败：捕获超时默认 5000 毫秒（下限 100 毫秒），失败会向上报错。

## 边界

- **动作是真实输入注入，没有回滚。** `left_hold` 和 `left_release` 必须成对使用，否则鼠标状态可能残留；`drag_drop` 是按下、平滑移动、松开三步。
- 坐标随分辨率变化，归一化坐标只保证同一次观察与动作之间一致；换屏或改分辨率后要重新观察。
- 截图会另存一份到用户容器目录；持久化失败只记警告，不影响结果。
- 截图目录按帧保留，只留最近几张（默认 3），避免临时文件无限堆积。
- 判定遵循最小权限：需要用户显式开关，不静默常驻截屏，也不把系统能力暴露给远端。
