# 工作区文件

本地工作区里最常用的是这几个动作：看目录、搜内容、读文件、改文件、写文件。

## 什么时候用哪个

- 先摸清目录结构：`list_files`。
- 已经知道要找什么词，定位它在哪：`search_content`。
- 知道路径，想读某一段：`read_file`。
- 要整份新建或覆盖：`write_file`。
- 做一次精确的文本替换：`edit_file2`。

## 看目录

给一个路径就能列目录，可以限制往下看几层、一次返回多少条。目录项会带斜杠区分，条目多时分页；返回里会告诉你还有没有下一页，以及继续翻页要用的游标。

## 搜内容

按关键词在目录里搜，返回命中的文件和位置。可以限定文件类型、是否大小写敏感或按正则匹配、命中前后各带几行上下文，也能限制最多命中多少条、最多扫多少个文件。结果被截断时会说明原因；只想先看看搜索计划、不实际跑，可以打开试运行。

## 读文件

知道路径就读这一段：给起止行，一次读一个文件，也可以一次给多个文件和行段批量读。返回里把内容拼成可直接阅读的文本，并给每个文件的摘要；默认窗口放不下或预算被截断时，会提示需要继续读。

## 改文件

`edit_file2` 做的是「把一段原文换成新文」的精确替换：

- 原文必须和文件当前内容完全一致。
- 要删除就把新文设成空字符串。
- 一次要替换多处时，可以让它要求匹配次数完全一致，对不上就报错。
- 如果不小心把读文件时带的文件头或行号复制进了原文，匹配失败时它会尝试自动去掉。
- 文件用的是 CRLF 换行时，它会按目标文件的换行风格重试匹配。
- 如果这个替换已经唯一完成，它会直接告诉你已经应用过，避免重复调用报错。

它适合「已经拿到精确原文、一次替换、不需要正则或多步逻辑」的修改。要做复杂替换、正则替换、跨多段或带条件逻辑的编辑，改用 [执行命令](/docs/zh-CN/tools/exec/) 写脚本；要整份生成或覆盖，用 `write_file`；要做小范围代码补丁并带上下文审查，用 `文本编辑` 的补丁形态。

## 写文件

`write_file` 用来整份新建或覆盖一个文件。如果工作区里有对应的语言服务，写入时会顺带做一次诊断。它不适合小范围精确改代码（用补丁形态），也不用来跑脚本或构建（用 [执行命令](/docs/zh-CN/tools/exec/)）。

## 出问题时怎么判断

这几个工具失败时都会把原因放进结果里，重点看错误码、提示和附加数据，通常能直接看出是路径不存在、参数不对还是文件读不了。
