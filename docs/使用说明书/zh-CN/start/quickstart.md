# 快速开始

个人用户从**蛹（desktop）**开始：下载对应产物即可运行，不需要先部署舰体（server）。四节内容按安装、模型配置、首条消息、执行过程的顺序排下来。

## 下载安装

从 Releases 下载匹配系统的产物。蛹面向 32 位 Win7 与 Ubuntu 18.04，也覆盖现代 Windows / Linux。

- **老系统**（32 位 Win7、Ubuntu 18.04）：下载 `setup` 或 `.run` 安装包，安装后自带完整运行环境，但为了兼容性，部分第三方功能受限。
- **新系统**：直接下载 `.exe` 或 `.AppImage` 主程序，依赖本机环境，或在后续联网时补全运行环境。

安装或解压后启动即可。

开发环境下也可以直接跑启动脚本（Windows 下是 `run.bat`，或直接执行 `wunder-frontend-slint`）。它同进程原生调用引擎——不占用本机端口，也不需要本机 HTTP/WebSocket 中转。

## 配置模型

打开「设置 → 模型」，填入 API Key 与接口地址（形如 `https://example.com/v1`），保存前用「测试连接」验证一次；模型名与参数按提供方指引填。

数据留在本机：默认本地 SQLite，配置目录 `~/.wunder`；模型请求走你配置的远程端点。

## 发第一条消息

回到对话页，输入：

```
帮我列出当前工作目录的文件
```

回车发送即可。

## 执行过程

一次执行按 **用户轮次 / 模型轮次** 展示：

- 用户轮次 = 你每发送一条消息记 1
- 模型轮次 = 引擎主循环的**一次模型调用**（可含一批工具调用），工具调用不单独计模型轮次

时间线出现工具批次、每轮的「工作过程」条目与最终回复，本次执行就跑完了。

## 本地可用的能力

- 本地优先：数据留在本机，可离线；网络只用于访问模型与网页
- 桌面控制：桌面控制（需 vision 模型）
- 交互式终端：Windows 下基于 winpty，Linux 下基于 PTY
- 截图采集、语音输入、托盘、系统通知与全局热键
- 一个智能体可以同时拥有**多个独立任务线程**，工作区也可以有多个（本地 + 云端 + 通过设备互通访问的远程设备工作区）
- 直接编辑智能体：随时改系统提示词、审批模式与工具集合

## 首次运行成功的判据

- 可以成功发起一次对话
- 可以看到中间步骤和工具调用批次
- 可以拿到最终结果并复制
- 上滚查看历史时，后续输出不会把你拽回底部
- 失败时知道该看哪一页

## 失败后的入口

| 现象 | 先看 |
| --- | --- |
| 启动页长时间不结束 | [首次运行排查](/docs/zh-CN/start/troubleshooting-first-run/) |
| 模型请求 401/403 | 设置 → 模型 → 测试连接；[配置说明](/docs/zh-CN/capabilities/config/) |
| 运行中发消息被判「用户忙」 | 会话队列是否被关闭 |
| 界面卡、消息不刷新 | [故障排查](/docs/zh-CN/help/troubleshooting/) |

## 其他形态

舰体、蜂巢、舵机按场景选装：

- **舰体（server）**：多人共用、权限管理、渠道接入、智能体应用发布与治理。见 [舰体部署](/docs/zh-CN/start/server/)。
- **蜂巢（web）**：随舰体提供的云端 AI 工作台，浏览器访问；页面由独立的网页服务容器下发，默认 18001。见 [蜂巢界面](/docs/zh-CN/surfaces/frontend/)。
- **舵机（cli）**：手工本地操作入口，终端与自动化。见 [舵机使用](/docs/zh-CN/start/cli/)。
