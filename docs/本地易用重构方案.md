# 蜂窝桌面端「本地易用」重构方案

> 适用范围：`frontend-slint/`（Rust + Slint，默认前端）与 `crates/wunder-desktop/`（NativeDesktop 本地后端）。
> 参考设计："C:\Users\sjxx\Pictures\Screenshots\ 目录里的 `参考主页面.png`、`设置页面.png`、`新建工作区.png`、`聊天页面形式.png`。
> 前提：当前为原型阶段，**不考虑兼容性**，老旧/不合适的字段与架构直接移除，保持项目干净。

---

## 一、背景与目标

### 1.1 现状问题

桌面端前端完全参照网页版（舰桥/蜂巢的多智能体治理形态），对个人用户过重：

1. **多智能体并列**：每个智能体都要单独设置模型、提示词、工具、渠道、定时任务、记忆，配置重复。
2. **以智能体为中心**：左栏是「消息 / 智能体 / 工具 / 文件」，中间是智能体列表，用户的注意力被「智能体设置」占据，而非「要做的工作」。
3. **工作目录是隔离沙箱**：智能体在应用私有沙箱容器里工作，与用户真实项目文件夹脱节，文件需要来回映射。
4. **消息为 IM 气泡形态**：用户/智能体都带头像气泡，工具过程被折叠在「智能体循环」里，不直观；补丁（apply_patch）缺少清晰的 diff 呈现。
5. 右侧另有 WorkDock（文件浏览 + 线程），三栏 + 侧栏，信息密度高、操作路径长。

### 1.2 重构目标

1. **单智能体**：整个应用只有一个内置智能体，承担全部工作，用户无需创建/切换/重复配置。
2. **工作区为中心**：核心对象是「工作区」——用户指定的一个**可读写真实文件夹**。用户把注意力放在工作目录上，而不是智能体设置上。
3. **工作区下挂线程**：一次会话 = 一个线程，线程归属工作区，在左栏以树形展示在工作区下方。
4. **配置全部收进设置页**：把原先散落在每个智能体上的配置项，拆出来集中到全局唯一的设置页（12 个分类）。原桌面版的「动态形象」不再作为工作区线程，而是以「桌宠」分类在设置中复用。
5. **聊天条目化**：去掉头像气泡与「智能体循环」，改为全宽时间线——每个思考、每次工具调用、每次正式输出都是独立条目；补丁以 diff 卡片呈现。
6. **输入区直接切模型**：输入框右下角可直接切换模型与推理强度。
7. 风格统一为参考图的**简约、专业、浅色、低饱和暖色**风格。

### 1.3 设计原则

- 配置最小化：能复用的不重设，能默认的不询问。
- 主操作路径短：新任务 → 选工作区 → 干活。
- 密集、清晰、可扫描（沿用治理界面的可扫描性，但不做营销化装饰）。
- 性能默认：列表虚拟/限量、事件缓冲有界、增量更新、不整列重算。
- 一切从后端/源头解决，不在表层缝补。

### 1.4 非目标（本次不做）

- 不做多智能体、不做智能体市场/导入导出（智能体维度）。
- 不做多租户、用户/群组/单位管理（server 治理概念）。
- 不做远程协作、LAN 节点、站点、自动化、扩展市场等 Qoder 顶部/底部概念。
- 不做 Markdown 富文本扩展（图片、表格、公式等仍降级处理，沿用既有约束）。

## 二、核心范式转变

| 维度 | 旧（网页版照搬） | 新（本地易用） |
|---|---|---|
| 中心对象 | 智能体（Agent） | **工作区（Workspace = 真实文件夹）** |
| 智能体数量 | 多个，可创建/删除/排序 | **固定一个内置智能体**，不可创建/删除 |
| 工作目录 | 应用私有沙箱容器（1–10 隔离） | **用户指定的任意主机文件夹，直接读写** |
| 线程归属 | 绑定智能体 | **绑定工作区**（展示在工作区下方） |
| 主导航 | 左 Rail + 智能体列表 + 聊天 + 右 Dock（四栏） | **左 Sidebar + 右工作区（两栏）** |
| 左栏内容 | 消息/智能体/工具/文件 + 智能体卡片 | 新任务、工作区/线程树、底部设置 |
| 配置位置 | 每个智能体各自配置 | **全局设置页 12 分类，集中配置** |
| 用户消息 | 带头像气泡 | 无头像、右上浅灰气泡 |
| 智能体消息 | 带头像气泡 + 折叠「智能体循环」 | 无头像气泡、**全宽时间线条目** |
| 补丁呈现 | 折叠在循环里的文本 | **独立 diff 卡片（行号 + 高亮）** |
| 模型切换 | 静态文本，需进智能体设置 | **输入框右下角直接切换** |

## 三、总体信息架构

### 3.1 顶层视图状态

窗口只有两种顶层模式，互斥切换：

```
ViewMode
├── workbench   // 工作区（默认）：左侧栏 + 右侧（欢迎页 或 聊天页）
└── settings    // 设置页：全屏覆盖，左设置导航 + 右内容
```

- 从工作区左下角「设置」进入 `settings`；设置页左上角「返回应用」回到 `workbench`。
- 工作区对话框（新建/编辑）、模型切换浮层、各类删除确认，均为**模态层**（Overlay），不改变顶层模式。

### 3.2 页面地图

```
workbench
├── 左侧栏 Sidebar（固定）
│   ├── 新任务按钮
│   ├── 搜索框（过滤工作区/线程）
│   ├── 「工作区」分组
│   │   └── WorkspaceRow（图标+名称+更多）
│   │       └── ThreadRow（缩进，线程标题+状态）
│   └── 底部：设置按钮
└── 右侧主区
│   ├── 无选中线程 → 欢迎页（空状态）
│   └── 选中线程  → 聊天页（顶栏 + 时间线 + 输入区）
└── 右下角：帮助悬浮按钮（?）

settings（全屏）
├── 左：返回应用 + 搜索 + 12 个分类导航（含桌宠）
└── 右：分类标题 + 分组卡片（设置项行）

overlay（模态）
├── 新建/编辑工作区对话框
├── 模型切换浮层
├── 工作区/线程删除确认
└── 目标（暂停任务）条内联操作
```

### 3.3 选中态模型（前端状态）

- `active-workspace-id`：当前工作区。
- `active-session-id`：当前线程（属于某工作区）。
- 工作区展开集合：`expanded-workspaces: [string]`（默认含当前工作区）。
- 选中工作区时：若该工作区有线程则选中最近线程，否则显示欢迎页（可直接输入创建首个线程）。

## 四、数据模型与后端改造

> 原则：工作区是**新的一等实体**，与旧「沙箱容器」彻底分离；会话直接绑定工作区；工具直接以工作区文件夹为根。

### 4.1 工作区实体（新表 `workspaces`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `workspace_id` | TEXT PK | 稳定 ID（生成，不依赖路径） |
| `user_id` | TEXT | 本地用户（单用户固定） |
| `name` | TEXT | 工作区显示名，默认取文件夹名 |
| `root_path` | TEXT | 用户指定的**主机文件夹绝对路径**（规范化） |
| `icon` | TEXT | 图标 key（见 §6.2，14 选 1，默认 `folder`） |
| `color` | TEXT | 颜色 key（见 §6.3，15 选 1，默认 `blue`） |
| `sort_index` | INTEGER | 左栏排序，新建递增 |
| `created_at` | INTEGER | 创建时间（Unix 秒） |
| `updated_at` | INTEGER | 更新时间 |

约束：
- `(user_id, root_path)` 唯一：**同一文件夹不能被多个工作区重复添加**。
- 不复制文件、不做隔离映射，`root_path` 即真实工作目录。

### 4.2 会话归属工作区

`chat_sessions` 表改造：

| 改动 | 说明 |
|---|---|
| 新增 `workspace_id` | 线程归属工作区（外键到 workspaces） |
| 弱化 `agent_id` | 固定为内置 `__default__`，不再作为区分维度 |
| 查询 | 列表按 `workspace_id` 分组、按 `last_message_at` 排序 |

- 新建线程必须落在某个工作区下。
- `NativeSession` 投影增加 `workspace_id`、`workspace_name`、`workspace_color`，便于左栏分组与状态展示。
- 旧数据迁移：若存在历史会话，一次性创建一个「默认工作区」（可让用户首次启动选文件夹，或归入系统临时默认区），全部旧会话挂到该工作区；迁移后不再保留多智能体字段。

### 4.3 工作目录直连（工具 cwd / root）

核心链路改造（`api/chat.rs::build_native_chat_request` 及工具运行时）：

1. 发送线程消息时，按 `session.workspace_id` 读取 `root_path`。
2. 构造请求时把 `root_path` 注入执行配置：
   - 文件工具（read/write/list）、命令工具（command/terminal）、`apply_patch` 的 **cwd / root 统一为 `root_path`**。
   - 复用 `WorkspaceManager` 的 `container_roots` 机制，将 `root_path` 映射为该请求的容器根；或直接设置 `config.workspace.root`。
   - 路径安全校验（`is_within_root`）以 `root_path` 为界，禁止越界写。
3. 工具返回的文件路径相对/锚定到 `root_path`，前端展示时用工作区相对路径（如 `src/foo.rs`），不暴露主机绝对路径。

> 效果：模型直接在用户的真实项目文件夹里读写、执行、打补丁，无需经过应用私有沙箱。

### 4.4 单智能体固化

- 启动时确保存在内置智能体 `__default__`（名称固定、记录冻结、不可删除）。
- 移除「创建智能体 / 删除智能体 / 智能体排序 / 智能体卡片导入导出」能力。
- 智能体的可配置内容（system prompt、工具开关、默认模型、推理强度、渠道绑定、定时任务、记忆、欢迎语等）**全局唯一一份**，全部迁入设置页对应分类。
- 系统提示词冻结规则不变：线程首次确定后保持冻结，长期记忆仅在线程初始化时注入一次。

### 4.5 后端 façade 接口清单

**新增（建议放 `native_workspace.rs`，与旧 sandbox 容器区分）**：

| 方法 | 说明 |
|---|---|
| `list_workspaces() -> Vec<NativeWorkspace>` | 工作区列表，含每个工作区的线程总数、活跃线程数、运行状态 |
| `create_workspace(input) -> NativeWorkspace` | 新建工作区（校验路径） |
| `update_workspace(id, input) -> NativeWorkspace` | 编辑（名称/图标/颜色/可更换文件夹） |
| `delete_workspace(id) -> DeleteSummary` | 删除工作区；其线程按策略归档或一并删除（见 §6.4） |
| `reorder_workspaces(ids) -> ()` | 保存工作区排序 |
| `validate_workspace_path(path) -> PathReport` | 存在性、可读、可写、是否已被占用、是否嵌套其他工作区 |

**改造**：

| 旧 | 新 |
|---|---|
| `create_session_for_agent(agent_id)` | `create_session(workspace_id)` |
| `list_sessions()` | 支持 `workspace_id` 过滤，返回带工作区字段 |
| `navigation_order()` | 去掉 `agents`，保留 `workspaces + threads` 排序 |
| `create_agent / delete_agent / update_agent`（多智能体部分） | 移除；仅保留对 `__default__` 的设置更新 |
| `send_chat` / `build_native_chat_request` | 按 `workspace_id` 注入 `root_path` 为工具根 |

**复用（不改动语义，仅前端重新组织与换肤）**：

| 能力 | 现有接口 |
|---|---|
| 工具管理 | `list_tools`、`tool_manager`、`save_mcp_server`、`save_knowledge_base`、工具资源读写 |
| 渠道 | `native_channels.rs` 全套（账号/绑定/扫码/重连/日志） |
| 记忆碎片 | `expert_memories`、`save_expert_memory`、`delete_expert_memory` |
| 归档线程 | `expert_archives` |
| 运行记录 | `expert_runtime`、`thread_log_page`、`thread_log_turn` |
| 提示词包 | `native_prompts.rs` 全套（包/分段/启用） |
| 定时任务 | state 中的 cron 能力（现有 `CronPage` 后端） |
| 终端 | `terminal_*`（作为聊天内工具保留，不做独立入口） |
| 模型 | `save_model`、`delete_model`、`set_default_model`、`probe_model_*` |
| 桌宠（动态形象） | `list_companions`、`import_companion`、`delete_companion`、`export_companion_to`、`companion_spritesheet`；悬浮态 `companion_overlay_state` / `save_companion_position` / `save_companion_override`（位置、缩放、显示、气泡提示） |

#### 5.2.1 「新任务」行为

- 已选中某工作区 → 直接在该工作区下创建线程并进入。
- 未选中工作区但有工作区 → 在最近工作区下创建；并展开该工作区。
- 一个工作区都没有 → 弹出「新建工作区」对话框，建好后自动创建首个线程。

### 5.3 欢迎页（空状态）

当选中工作区但未选中线程（或工作区尚无线程）时显示：

- 居中偏上：工作区问候语（如「在 &lt;工作区&gt; 开始一个新任务」）。
- 可选：最近线程快速入口、工作区文件夹概览（文件数/最近文件，点击打开文件）。
- 输入区始终可用：直接输入即创建该工作区的首个线程。
- 全局无任何工作区时：显示「添加工作区」主按钮（打开新建工作区对话框）。

> 参考图中部的营销插画/积分热力图不照搬（非目标）；保持简洁、专业。

## 六、新建 / 编辑工作区对话框

> 模态、居中、浅色卡片，圆角 14px；标题「新建工作区」/「编辑工作区」，右上角关闭 X。遮罩半透明。

### 6.1 字段与交互

| 字段 | 控件 | 规格 / 校验 |

## 七、聊天时间线（条目化）

> 去掉头像与气泡（智能体侧），改为全宽时间线；每条思考、每次工具调用、每段正式输出都是独立条目。样式对齐 `聊天页面形式.png`。

### 7.1 结构总览

```
顶部：工作区名 / 线程名
─────────────────────────────────────
[用户消息]                          （右上浅灰气泡，无头像）
   已处理  ▸                         （折叠组：已完成的模型/工具轮次）
   正文段落……（每次正式输出一块，直接打印）
   执行工具 6 次  ▸                   （折叠组）
   正文段落……
   执行工具 11 次  ▾                   （展开组）
     ├─ ✅ 已思考 · 摘要
     ├─ ✅ 读取文件   [file.rs]
     ├─ ✅ 已思考 · 摘要
     ├─ ✅ 编辑文件   [file.rs]
     │     └─ [补丁 diff 卡片]
     └─ ✅ ……
   正文段落……（含下载/复制按钮，hover 显示）
   [已暂停目标条 · 计时 · 描述  编辑/删除/继续]
─────────────────────────────────────
输入区
```

### 7.2 用户消息

- **无头像、无左侧标识**；右对齐浅灰气泡（`#F3F2F0`），圆角 12px，内边距 8×12，14px，最大宽 70%。
- 支持纯文本/段落/列表/代码块（沿用最低必要 Markdown）；原始内容完整保留。
- 多条用户消息按时间顺序各自成气泡。

### 7.3 智能体条目类型（无头像、无气泡、全宽，左右 padding 约 24px）

**A. 正文块（正式输出）**

- 每次 assistant 正式输出（`llm_output_delta` / `final`）聚合为**一个正文块**，直接以页面正文打印（14px、`#1F2329`、行高 1.7），不套气泡。
- 流式追加，光标停在活动块尾部；完成后该块稳定，不再变动（后续输出另起新块）。
- hover 时块右上显示「复制」「下载」（保存为 .txt/.md）。

**B. 思考条目（已思考）**

- 绿色对勾圆（16px，`#3E9C7E` 系）+「已思考」+ 思考摘要（一行省略，灰色）。
- 点击展开完整思考（浅灰底、等宽/正文，可滚动、限高），再点折叠。
- 流式中显示「正在思考…」+ spinner，完成后变对勾。

**C. 工具调用条目**

- 每个工具调用一个条目：对勾圆（执行中 spinner / 成功对勾 / 失败红色）+ 工具显示名（如「读取文件」「编辑文件」「运行命令」）+ 目标标签（文件名/路径，浅灰底圆角小标签，如 `[patch_log.rs]`）。
- 失败：红色状态 + 错误摘要，可展开看错误详情。
- 长输出（如读取文件、命令输出）：条目内可展开为限高预览，超出折叠。

**D. 工具分组折叠条**

- 同一轮（或连续）的工具调用聚合为一个分组条：「执行工具 N 次」+ 箭头（▸ 折叠 / ▾ 展开）。
- 展开后为**竖线时间线**（左侧 1px 竖线连接各条目），逐条列出 B/C 类型条目。
- 已完成的历史轮次（正文 + 工具 + 模型调用）可整体折叠为「已处理 ▸」，默认把较早的轮次折叠、当前轮次展开，保持可扫描。

### 7.4 补丁 diff 卡片（重点：编辑文件 / apply_patch）

> 参考图点开的「编辑文件」展开形态即为补丁卡片标准样式。后端已有结构化数据（`files[]`、`diff_blocks[]`、`old_line/new_line`、`added_lines/deleted_lines`），新增专用卡片组件渲染，替代当前纯文本行。

卡片规格：

```
┌─────────────────────────────────────────────────────────────┐
│  📄 patch_log.rs                              +41   −41       │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ 变更片段                                                 │ │  ← 表头（浅灰底）
│  ├──────┬──────────────────────────────────────────────────┤ │
│  │  行号 │ 代码（等宽字体，12.5px）                          │ │
│  │  136 │  fn run(...) {                                    │ │  普通行：白底
│  │  137 │ -     let old = ...;                    （红）    │ │  删除行：#FDECEC 底
│  │  138 │ +     let new = ...;                    （绿）    │ │  新增行：#EAF7F0 底
│  │      │                                                   │ │
│  └──────┴──────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- 卡片头：文件图标 + 文件路径（工作区相对路径，14px 加粗）；右侧统计 `+N`（绿 `#1A8A5C`）、`−N`（红 `#D04A43`）。
- 「变更片段」表头：浅灰底（`#F5F4F2`），13px 深灰。
- 行号列：固定宽（约 56px，右对齐，灰字 `#9AA0A6`），与代码列 1px 分隔。
- 代码列：等宽字体（内嵌 YaHei 等宽回退 / 可用 `Consolas` 回退，无则系统等宽）；
  - 新增行：前缀 `+`（绿）、底 `#EAF7F0`、字 `#14532D`；
  - 删除行：前缀 `−`（红）、底 `#FDECEC`、字 `#7F1D1D`；
  - 上下文/普通行：前缀空、白底、`#3D3D3D`。
- 多文件补丁：每个文件一个卡片（或卡片内多 tab），按文件分组；默认展示前 8 个文件、每文件前若干行，超出显示「另有 N 个文件 / N 行未展示」，可展开。
- 卡片限量：每卡片最多渲染约 200 行（虚拟/折叠），避免长补丁拖垮列表。
- 补丁在**工具结果未返回前**显示为「待应用」预览（提交内容，标记为预览，不暗示已修改）；成功后才是正式 diff 结果。

### 7.5 目标条（暂停 / 继续任务）

- 时间线底部（输入区上方）以粉色（`#FBEAE5`）条显示：「已暂停的目标 · 已用时 8:11:13 · 目标描述」。
- 右侧操作：编辑（铅笔）、删除、继续（播放，主色）。
- 目标进行中显示运行状态与计时；中断/取消后转为「已暂停」。

### 7.6 流式与折叠状态

- 沿用现有事件流（`reasoning*`、`tool_call/start/result/output`、`llm_output_delta`、`compaction*`、`turn_terminal`）。
- 事件缓冲有界、按帧合并（约 16–33ms）；只更新活动尾块/尾条目，不重算整段历史。
- 自动跟随：用户在底部时跟随输出；上滚查看历史时保持位置，并显示「回到最新」。
- 上下文压缩（compaction）作为一个条目呈现（「上下文压缩」+ 摘要），与工具条目同风格。

### 7.7 块导航（可选细节）

- 滚动条右侧可显示各「块/轮次」的短横线标记，点击跳到对应轮次；对齐参考图右侧的小横线。

## 八、输入区与模型切换

> 输入区为底部悬浮的大圆角卡片，对齐 `聊天页面形式.png` 与 `参考主页面.png`。

### 8.1 布局

- 容器：左右 padding 16px、底部 12px；输入框圆角 22px、1px 边框 `#E8E6E3`、白底、内边距 10×14。
- 文本区：多行、自适应增高（最小 1 行，最大约 8 行后内部滚动），14px，占位文字「给 &lt;工作区&gt; 发送消息…（长按语音）」。

### 8.2 控件布局

| 位置 | 控件 | 说明 |
|---|---|---|
| 左下 | 「+」 | 32×32 圆形浅底：更多（新建线程、上传文件、截图、工作区操作） |
| 左下 | 回形针 | 添加附件（截图/文件，沿用 attachments 能力，显示附件 chip，可移除） |
| 左下 | 权限模式 | 「完全访问」下拉：选择权限模式（如完全访问 / 只读确认 / 执行需确认），见 §8.4 |
| 右下 | **模型选择器** | 见 §8.3（核心改动） |
| 右下 | 历史 | 查看线程/最近会话 |

| 右下 | 发送 | 圆形 34px，主色 `#C96443`，白色上箭头；有内容时点亮，空内容禁用；执行中变为「停止」（■） |

### 8.3 模型切换浮层（核心）

- 触发器：模型选择器显示「模型图标（16px）+ 模型名（13px）+ 推理强度（灰色，如「极高」）+ 下拉箭头」。
- 点击弹出浮层（贴输入框上方，宽约 300px，圆角 12px，白底，阴影，1px 边框）：
  - 模型列表：每行模型图标 + 名称 + 能力标签（上下文长度/来源）+ 默认标记；当前模型打勾。
  - 顶部搜索：过滤模型。
  - 底部：推理强度选择（低 / 中 / 高 / 极高，或沿用现有 `reasoning-effort` 档位）。
- 选择后：立即切换当前线程的模型与推理强度（实时生效，不必进设置）；
  - 复用现有 `set_default_model`、`save_session_reasoning_effort`；模型列表来自 `models`（含默认标记）。
- 空模型时：引导「设置 → 模型设置」添加模型。

### 8.4 权限模式

- 「完全访问」：默认（本地直连，允许读写工作区与执行）。
- 可选「写入需确认 / 命令需确认 / 只读」等模式，作为安全边界；高危操作仍以后端鉴权为准，前端确认不替代后端。
- 仅个人本地使用时可固定为「完全访问」，下拉保留扩展位。

### 8.5 状态栏

- 输入框下方一行（12px 灰）：工作区文件夹名（📁 wunder）、本地模式（● 本地）、版本控制分支（如检测到 Git，显示 main；无则不显示）。
- 右侧：上下文用量（进度条，如 58%），沿用 `context-usage`；超额时提示压缩。

### 8.6 发送键与中断

- 发送键沿用偏好设置（Enter / Ctrl+Enter / 无）。
- 执行中发送按钮变为停止（或独立停止按钮），点击 `stop_generation` / `cancel_chat`；终端/目标有独立中断。

## 十二、验收标准

### 12.1 功能

- 全程只有一个内置智能体，无创建/切换/删除智能体入口。
- 可添加/编辑/删除工作区（图标 + 颜色），工作区绑定真实文件夹，线程归属工作区并在左栏树形展示。
- 模型可在输入区直接切换、推理强度即时生效；权限模式可选。
- 聊天无头像气泡（智能体），思考/工具/正文/压缩均为独立条目；补丁以 diff 卡片呈现，行号与增删高亮正确。
- 设置页 12 分类（含桌宠）全部可加载、保存、校验；返回应用正常。
- 暂停目标可继续、编辑、删除；归档线程可查看/恢复。

### 12.2 性能

- 工作区/线程/消息/日志列表均虚拟或限量；无一次性渲染大量 DOM。
- 事件缓冲有界、按帧合并、不丢字；只更新活动尾块/尾条目，无整列重算与大对象复制。
- 无无界队列/缓存、无分页查询、无深层 watch；启动首帧不被运行时初始化阻塞。
- 流式期间输入、选择、复制、滚动不被阻塞。

### 12.3 渲染与质量

- slint-viewer 下与四张参考图在布局、间距、字号、颜色、圆角、图标风格上一致（像素级对齐）。
- 代码、测试、日志、文档中不出现真实业务名称、真实身份、密钥或绝对路径示例。
- 关键链路（工作区 CRUD、线程归属、工具 cwd、补丁解析）有单测；`cargo build` 与冒烟通过。

## 十四、风险与注意事项

1. **真实文件夹直写风险**：工具直接在用户文件夹读写，必须保留根边界校验（`is_within_root`）与权限模式；删除/重命名等高风险操作需要明确反馈，且禁止提供「删除工作区磁盘内容」能力。
2. **工作区与沙箱概念区分**：新 Workspace 是「用户文件夹」，务必与旧 sandbox container 命名/类型隔离，避免后端两套「workspace」混淆。
3. **路径变更**：编辑工作区更换文件夹后，线程历史中的相对路径可能失效，需明确提示并保留会话记录。
4. **提示词冻结**：单智能体与工作区改造不得破坏「线程首次确定后 system prompt 冻结、长期记忆仅注入一次」的缓存规则。
5. **长补丁/长输出**：必须限量 + 虚拟渲染，防止 diff 卡片与文件预览拖垮消息列表。
6. **跨平台**：以现有内嵌字体与软件渲染为准；目录选择、路径规范化、Git 分支探测需在真实环境验证。
7. **多任务并行**：调度、锁、实时状态仍按线程隔离；工作区聚合展示时不能把线程间状态互相污染。
