# 总体设计

9 个核心

| 核心 | 设计目标 | 核心能力 | 关键约束 |
| --- | --- | --- | --- |
| 兼容性 | 让桌面版本与命令版本能在旧操作系统环境中被明确约束并可运行 | Windows 7 与 Ubuntu 18.04 适配、桌面版本与命令版本双形态、运行时版本锁定、依赖降级、启动自检 | 兼容性特指桌面版本与命令版本；不把兼容性作为服务端或网页端的覆盖范围 |
| 上下文压缩 | 在长会话中控制上下文规模并保留有效信息 | 手动压缩、自动压缩、溢出恢复、压缩摘要回注、压缩前后对比与回放 | 压缩结果必须可追溯；压缩不能伪造事实；压缩过程与终态要可观测 |
| 子智能体 | 在单一线程内派生子任务，由独立执行体完成并回传结果 | 子任务拆解、子智能体创建与回收、结果汇聚、父子会话关联 | 子智能体只承担单线子任务；与蜂群的协作调度职责分开，不互相混淆 |
| 定时任务 | 支持系统级周期执行与后台治理 | 定时触发、计划任务、后台巡检、自动维护、异步执行链路 | 定时任务必须与在线线程语义区分；失败重试和执行记录要可追踪 |
| 渠道通信 | 支持多入口接入同一运行时能力 | HTTP、WebSocket、Desktop、CLI、第三方渠道、网关适配 | 多入口共核，只允许接入面差异，不允许演化成多套独立系统 |
| 记忆 | 支持长会话与长期资料利用，但不污染线程核心认知 | 线程初始化记忆注入、知识库、工作区文件、长期资料读取 | 长期记忆只允许在线程初始化注入一次；线程首次确定后的 system prompt 必须冻结 |
| 蜂群 | 支持母蜂调度多个工蜂并完成协作任务 | 任务拆解、工蜂派发、节点状态同步、汇总结果、父子会话关联 | 母蜂与工蜂职责分离；不能把蜂群误当普通子智能体链路；协作过程必须持续可见 |
| 多线程 | 在单进程内通过并发控制提升吞吐与资源利用 | 工作线程池、任务并发调度、线程间隔离、资源上限控制、竞态与死锁防护 | 多线程只做计算与 IO 并发，不替代进程级隔离；共享状态必须受控 |
| 多租户 | 支持服务版本的组织、用户、租户与权限治理 | 租户隔离、组织与用户体系、权限控制、Token 账户治理、管理后台 | 多租户特指服务版本；数据隔离、权限边界和治理能力不能后补 |

## 总体原则

| 原则 | 说明 |
| --- | --- |
| 一切围绕线程 | 会话、工具、压缩、蜂群、回放最终都要落回线程语义上统一治理 |
| 一切围绕事件 | 实时同步、排障、回放、监控都应建立在事件与状态变更之上 |
| 一切围绕约束 | prompt 冻结、记忆一次性注入、指标口径统一、事实与画像分离都是硬约束 |
| 一切围绕性能 | 高并发访问、长会话、工具链执行和多前端同步必须优先考虑速度与资源成本 |
