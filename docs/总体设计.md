# 总体设计

wunder（心舰）是一个**智能体调度平台**：把目标交给智能体，它把目标拆成任务，调用工具一步步执行，最后交付结果。四个形态各有定位：蜂窝（desktop）是本地 AI 工作台，蜂巢（web）是云端 AI 工作台，舵机（cli）是手工本地操作入口，舰体（server）是用户与智能体管理平台。

9 个核心

| 核心 | 设计目标 | 核心能力 |
| --- | --- | --- |
| 目标 | 让智能体进入目标态并持续完成一项任务 | 目标态进入与维持、持续执行、进度追踪、完成判定 |
| 兼容性 | 让蜂窝与舵机能在旧操作系统环境中被明确约束并可运行 | Windows 7 与 Ubuntu 18.04 适配、蜂窝与舵机双形态、运行时版本锁定、依赖降级、启动自检 |
| 上下文压缩 | 在长会话中控制上下文规模并保留有效信息 | 手动压缩、自动压缩、溢出恢复、压缩摘要回注、压缩前后对比与回放 |
| 子智能体 | 在单一线程内派生子任务，由独立执行体完成并回传结果 | 子任务拆解、子智能体创建与回收、结果汇聚、父子会话关联 |
| 定时任务 | 支持系统级周期执行与后台治理 | 定时触发、计划任务、后台巡检、自动维护、异步执行链路 |
| 渠道通信 | 支持多入口接入同一运行时能力 | HTTP、WebSocket、蜂窝（desktop）、舵机（cli）、第三方渠道、网关适配 |
| 记忆 | 支持长会话与长期资料利用，但不污染线程核心认知 | 线程初始化记忆注入、知识库、工作区文件、长期资料读取 |
| 多线程 | 在单进程内通过并发控制提升吞吐与资源利用 | 工作线程池、任务并发调度、线程间隔离、资源上限控制、竞态与死锁防护 |
| 多租户 | 支持舰体（server）的组织、用户、租户与权限治理 | 租户隔离、组织与用户体系、权限控制、Token 账户治理、舰桥 |
