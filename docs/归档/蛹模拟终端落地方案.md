# 蛹模拟终端落地方案

## 目标

在蛹的本地工作区内打开独立的模拟终端窗口。终端以当前工作区目录作为进程工作目录，窗口中的键盘输入直接写入同一个持久 shell，shell 输出经过终端屏幕解析后实时绘制，聊天输入区继续只服务于聊天。

## 范围与边界

- 终端会话按工作区隔离；切换工作区后不复用旧目录的 shell。
- Windows 优先使用现有 winpty 控制台后端，未安装 winpty 时降级为管道后端；Linux/macOS 使用现有伪终端或管道实现。
- 首期支持 ANSI/VT 屏幕、颜色、光标、清屏、滚动、备用屏幕、窗口尺寸同步和常用控制键。
- 管道降级模式保证普通 shell 命令可用；依赖真实控制台输入模式的全屏程序能力以运行环境为准，并在窗口状态中显示后端类型。
- 终端窗口关闭只隐藏窗口并保留会话，显式退出终端才关闭 shell；程序退出时由已有 NativeDesktop 生命周期回收。

## 实施状态与分阶段节点

### 阶段一：窗口与工作区会话（已完成）

1. 从聊天区域拆出独立 TerminalWindow。
2. 输出区域复用 TerminalGrid，窗口尺寸变化同步到 runtime。
3. 从当前选中工作区读取绝对目录，启动 shell 时传入 cwd。
4. 会话与 transcript 使用工作区 ID 隔离，窗口关闭后可重新打开。

验收：打开工作区 A 后执行 `cd`/目录查询，显示目录属于 A；切换到工作区 B 后新窗口显示 B 的目录，聊天消息不被终端面板替换。

### 阶段二：真实键盘输入（已完成）

1. 终端屏幕获得焦点，打印字符逐字写入 shell，不再依赖聊天 Composer 或整行命令框。
2. 映射 Enter、Backspace、Tab、Escape、方向键、Home/End、Delete、PageUp/PageDown、Insert、F1-F12。
3. 映射 Ctrl+A-Z、Ctrl+Space、Ctrl+[ 和 Alt+字符；Ctrl+C 发送中断字节。
4. 支持终端窗口内粘贴，限制单次写入大小并保持字节顺序。

验收：在 shell 提示符中逐字输入、编辑、补全、历史上下翻页和中断命令；`python`/`node` 等交互式程序可以读取连续输入。

### 阶段三：屏幕语义与交互完善（已完成）

已落地：终端窗口使用独立 Slint `Window`，终端焦点由 `FocusScope` 持有；键盘字节和粘贴内容通过有界队列送入后台线程；Unix 使用 `portable-pty`，Windows 继续优先 winpty 控制台，状态栏区分 `PTY`、控制台和管道后端；终端会话、屏幕网格和 transcript 按工作区 ID 隔离；聊天 Composer 不再发送终端命令。屏幕模型已覆盖备用屏幕、滚动区域、隐藏光标、宽字符、16/256/真彩色；粘贴回调已连接系统剪贴板，自动跟随 bracketed paste；方向键跟随 DEC application cursor；鼠标按键、释放、拖动和滚轮按 X10、UTF-8 或 SGR 报告模式编码后通过有界输入队列转发，未启用报告时保留本地滚动。

剩余节点：

1. 在 Windows 7、Windows 新版本、Ubuntu 18.04 的真实环境核对默认 shell、winpty 控制台和管道降级。
2. 继续校准复杂 OSC、IME、文本选区/复制和少数终端私有协议。
3. 对长输出、快速输出和窗口连续缩放做跨平台手工验收。

验收：运行编辑器/分页器类全屏程序后能正确进入和退出备用屏幕；长输出不会无界增加内存，窗口拖动时 shell 与画面列数一致。

### 阶段四：兼容性与回归（进行中）

已完成：native terminal facade 的 cwd、输入字节、取消、resize、transcript 隔离测试；Slint 编译检查；TerminalGrid 的鼠标报告、bracketed paste、application cursor 与屏幕回归用例；终端窗口截图预览。

待执行：Windows 7、Windows 新版本、Ubuntu 18.04 的真实环境验收，以及文本选区/复制、IME 和复杂 OSC 协议的兼容性收尾。

## 技术约束

- UI 线程只处理按键事件、有限增量和屏幕投影；shell 读写继续由 runtime 后台任务负责。
- 输入与输出都必须有界，禁止按 token 或按字节重建整段历史。
- 终端路径只允许来自已选本地工作区记录，不回退到进程当前目录。
- 不把远端工作区或云端路径当作本地 shell cwd；没有可用本地目录时明确拒绝启动。
