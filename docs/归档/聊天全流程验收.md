# 聊天全流程常规测试

在仓库根目录或 `frontend` 执行 `npm run test:chat`。首次安装依赖后在 `frontend` 执行 `npx playwright install chromium`。无需启动后端、数据库、模型或工具服务；Playwright 自动启动 Vite 提供真实页面。

固定入口依次执行测试代码严格类型检查、durable 协议与恢复回归、独立日志分析器回归、1000-token 性能专项、真实页面十一轮模拟交互。浏览器测试单 worker 运行；性能失败不会跳过后续截图测试。GitHub Actions 在相关 push/PR 自动运行，失败也上传证据，保留 7 天。

## 测试边界与交互

模拟器只替换 HTTP/WebSocket。登录、输入、发送、点击停止、命令处理、客户端重连、生产 store、投影、组件和虚拟列表均使用真实代码，不直接修改前端 store。

固定流程：页面问候 → 两轮工具调用 → 部分回复后停止 → 继续发送 → 被动压缩 → `/compact` 独立轮次 → 再次发送 → `/goal` 并完成 → 连接中断期间继续执行并重放 → 调度排队再执行 → 含工具失败但正常完成的回复。每次普通回复包含两次工具调用；显式压缩不伪造工具调用。重复 durable 投递贯穿最后两轮，流式尾部和持久化正文块均经过 WebSocket。

当前输入框在运行时禁止再次发送。因此覆盖的是“请求已发送、模拟调度端排队、恢复执行”，不是“忙碌时第二次发送”。不要把被拦截的输入算作排队成功。真实后端调度、模型压缩算法、工具执行和进程重启不在该门禁的证明范围。

## 固定产物

`temp_dir/chat-user-review/`：

- `index.html`：全部对话逐窗截图；覆盖虚拟列表历史，不能仅截图底部。
- `after-stop/index.html`：停止及随后继续发送的截图。
- `tools/index.html`：展开工具参数与结果的完整截图。
- `reloaded/index.html`：刷新恢复后的截图。
- `performance.json`：生产 `wunderPerf` 实际浏览器采样，含帧间隔、长任务及渲染计数。
- `thread-changes.jsonl`、`thread-snapshot.json`、`thread-export.jsonl`：模拟线程持久化序列、快照与带完成标记的导出；明确标记 mock-service，不冒充后端实测日志。
- `rendered-rows.json`、`transport.json`：渲染结果、请求轨迹、连接次数及浏览器错误指纹。
- `analysis.json` / `analysis.md`：独立自动分析及未证明的覆盖项。

线程内容脱敏为稳定指纹；截图仅使用合成数据。历史分析与性能文件在覆盖前保留。1000-token 专项报告按时间写入 `temp_dir/chat-lifecycle-review/stream-performance-*.json`，失败 trace/video 位于 `frontend/test-results/`。这些数据可用于排查前端，不能替代后端线程诊断。

## 断言与诊断

不以模拟器自身“完成”为通过条件。独立断言 11 个用户轮次的完整交替顺序、每轮一个助手气泡、正文、取消终态、耗时/速度统计、工具文件参数与结果、压缩摘要、刷新前后全部正文一致性。每 50ms 有界采样重复气泡和终态复活；有限采样不保证捕获全部瞬时闪烁。

分析器检查孤儿条目、缺失稳定正文、未完成工具、游标缺口/重复/倒退、revision 倒退、终态复活、缺失日志、浏览器错误及覆盖缺失。错误使测试失败；50ms 长任务在生命周期报告中标为 needs-review，250ms 主线程阻塞或帧间隔 p95 上界超过 100ms 为错误。1000-token 专项维持零 50ms 长任务、token 到渲染 p95 小于 100ms、恢复小于 1s 的严格门槛。

`passed`、`needs-review` 与测试进程退出码需同时查看。截图正确不能抵消性能失败；重跑成功也不能证明此前失败无害。

## 脚本收敛

移除直接注入 store 的重复生命周期探针及两条重叠 E2E，移除未验证且依赖真实账号/服务的聊天验收脚本及配置；保留 1000-token、协议乱序、快照恢复等独立覆盖。43 个重复 esbuild 命令改用统一回归执行器，单个进程最多运行 60 秒。原有独立回归命令保留兼容，避免误删边界覆盖。

新增场景应扩展现有 mock peer、独立预期和证据检查，避免再写一份绕开发送管线的演示 harness。触及聊天发送、状态、工具、压缩、渲染或恢复的修改，常规执行 `npm run test:chat` 并查阅分析报告；可通过 `npm run test:chat-realtime` 执行更广的历史回归。

## 本次验证记录

严格测试类型检查、Vue 类型检查、协议与分析器回归通过；十一轮页面交互通过。详情补水与实时输出的竞态回归已随新增原子快照请求修正，并通过。1000-token 专项现将路由初始布局排除在流式窗口外，按帧小批量应用 1000 个真实 reducer tail；最近一次 p95 为 18ms、恢复 35ms、无 50ms 长任务。生命周期相册仍将长任务保留为 `needs-review`，以便区分截图和页面装载带来的浏览器工作与流式专项。
