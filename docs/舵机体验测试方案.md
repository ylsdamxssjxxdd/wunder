# 舵机体验测试方案

舵机是手工本地操作入口，服务于终端操作、脚本化和自动化。本方案由外部 Python 进程启动正式 CLI，检查命令响应、流式 JSONL、恢复会话、本地大线程读取和失败恢复。无需蛹程序、舰体、浏览器或终端交互桌面。

## 执行方式

入口为 [`measure-cli.py`](../scripts/experience-bench/measure-cli.py)，依赖、基线比较和场景选择见[驱动说明](../scripts/experience-bench/README.md)。先构建当前源码，构建时间不计入测试：

```powershell
cargo build --offline --release -p wunder-cli --bin wunder-cli
python scripts/experience-bench/measure-cli.py --binary target/release/wunder-cli.exe --output temp_dir/cli-run --profile daily
```

每个场景新建独立 `WUNDER_HOME`、配置、工作目录、SQLite 和临时文件，受控 SSE 模型只监听本机随机端口。配置在隔离目录预置，避免 CLI 自动回写影响仓库或用户配置。记录二进制 SHA256；不能把过期构建的结果当作当前源码验收。

## 当前自动化场景

| 场景 | 计时与体验 | 必须满足的正确性 |
| --- | --- | --- |
| `offline` | 帮助、诊断、工具目录、配置读取，各命令启动至退出 | 正常退出、有效输出、帮助命令面准确；不保存原始配置输出 |
| `stream` | 进程创建至首个 JSON 事件、首段真实文本、退出 | JSONL 可解析，启动/结束事件齐全，多次递增输出，最终原文准确，无意外重试，导出文本正确 |
| `stdin` | 通过标准输入发送一轮的相同指标 | stdin 入口和正式 `exec` 结果一致 |
| `resume` | 首轮完成并退出后，新进程恢复同线程并发送 | 线程身份不变、正式 JSONL 契约、回复完整；准备的首轮不计入恢复耗时 |
| `slow_consumer` | 延迟消费 stdout 后的完成 | 每行暂停 10 ms，输出不重排不丢字；默认负载只验证慢消费，不保证管道已填满 |
| `failure_recovery` | 模型失败至非零退出；同一隔离环境继续发送 | 产生 `error` 或 `turn.failed`，退出非零；后续执行成功 |
| `large_trajectory` | 大线程轨迹首个有界页与较早页，分别进程计时 | 正式 `trajectory --json` 返回正确身份、非降级、每页不超过 12 条、游标存在、分页无重复 |

流式 `item.updated` 的 `text` 是累计内容，测试逐次校验前缀，不把累计内容重复拼接。完整回复通过 `item.completed` 核验；`exec` 还校验 `--output-last-message` 文件。`resume` 不接受该参数，使用自己的正式命令契约。

## 大线程与计时边界

大线程由正式 `stress-thread` 命令在隔离数据目录生成，默认 100 用户轮次 × 每轮 100 模型请求，额外工具动作另记；固定 seed=42、typical。生成耗时单列。报告记录实际用户轮次、请求、工具与模型动作数，不能把它称为蛹严格 100×100 动作的同一夹具。

`trajectory` 是舵机当前提供的日志检查命令；它的耗时表示命令启动、运行时准备和有界轨迹读取，不能代替聊天页打开或 TUI 首帧。无提问的 `resume` 需要 TTY，本套非交互脚本不模拟 TUI 绘制。`--help` 主要覆盖参数解析，也不能替代整个运行时启动时间。

所有命令时间使用测试进程的单调时钟。记录命令进程 RSS、CPU 时间、线程与句柄/文件描述符峰值及采样数，约 10 ms 一次；短命令可能采不到完整峰值，CPU 时间可能超过墙钟时间。受控模型记录源端等待和输出节奏。启动读取不是 OS 冷缓存试验，机器负载和安全软件也会影响进程创建。

## 持续门禁与优化顺序

smoke 每场景 1 次用于链路验收；daily 预热 1 次、采样 10 次；release 预热 2 次、采样 30 次。原始逐次结果、P50/P95/最大值、正确性失败与资源数据都写入报告。缺失场景、失败基线和负载不同均不能比较；P50/P95 增幅同时超过 20% 与 5 ms 退出非零。

先优化冷启动中的配置迁移、资源释放与数据库初始化；再根据首事件至首文本的差距排查线程准入和上下文构建；随后优化模型结束后的事件排空、持久化与退出；最后处理大日志投影读取和连续运行的资源增长。报错耗时包含正式重试等待，不应删掉重试等待制造低耗时。

待补覆盖：PTY/TUI 首帧与输入延迟、滚动选择复制、Ctrl+C 优雅取消与退出码、工具执行和审批、长时间资源趋势、同用户多进程竞争、强杀恢复、配置迁移/损坏、32 位 Win7 与 Ubuntu 18.04 发行环境。当前宿主 smoke 不能代替这些兼容性验收。
