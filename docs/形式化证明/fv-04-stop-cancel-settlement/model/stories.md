## 1. 已结清并重开新轮次<br/>（旧轮次的取消标志已全部复位）

Rule broken: 目标2（应为反例）：结清后永远不能再开新轮次 —— 反例路径即"停止后可再发言"。
Why: 停止语义失配.
In the model, one step leads into this bug: "停止结清后，用户再次发言（新轮次）". The steps below are the shortest path that TLC found.

0. Start: 轮次终态：执行中<br/>监视器：执行中<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：未发起
1. 执行超时，按失败结清. Now: 轮次终态：已失败<br/>监视器：已失败<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：未发起
2. 停止结清后，用户再次发言（新轮次）. Now: 已结清并重开新轮次<br/>（旧轮次的取消标志已全部复位）

With the fix you see the same states and steps, so the fix does not change this path.

## 2. 轮次终态：已停止<br/>监视器：已完成，取消已可见<br/>终态帧：完成，目标结局：完成<br/>外部命令：已结束<br/>停止管线：轮次已取消

Rule broken: 规则1：取消已受理（轮次终态为 cancelled）之后，任何呈现面都不得出现完成语义。 涉及：execute_tools.rs:185-276（finish_request_success）、execute.rs:2221/2265-2270。
Why: 收尾不读持久层写入结果，轮次已停止仍发出完成语义.
In the model, one step leads into this bug: "收尾：持久层拒绝完成写入，但仍发出完成语义（终态帧/监视器/目标结局）". The steps below are the shortest path that TLC found.

0. Start: 轮次终态：执行中<br/>监视器：执行中<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：未发起
   (1 hidden step: 执行体通过最后一个取消检查点，进入收尾)
1. 用户按下停止. Now: 轮次终态：执行中<br/>监视器：执行中<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：已请求
2. 停止受理：执行围栏置位，监视器进入停止中. Now: 轮次终态：执行中<br/>监视器：停止中，取消已可见<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：已受理（取消可见）
3. 持久控制面把活跃轮次写为已停止. Now: 轮次终态：已停止<br/>监视器：停止中，取消已可见<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：轮次已取消
4. 收尾：持久层拒绝完成写入，但仍发出完成语义（终态帧/监视器/目标结局）. Now: 轮次终态：已停止<br/>监视器：已完成，取消已可见<br/>终态帧：完成，目标结局：完成<br/>外部命令：已结束<br/>停止管线：轮次已取消

With the fix, step 4 (收尾：持久层拒绝完成写入，但仍发出完成语义（终态帧/监视器/目标结局）) cannot happen, so you stay at: 轮次终态：已停止<br/>监视器：停止中，取消已可见<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：轮次已取消.

## 4. 轮次终态：已失败<br/>监视器：已停止，取消已可见<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：命令已结束

Rule broken: 规则2：平息后，轮次终态与监视器终态必须同语义（完成↔finished，取消↔cancelled，失败↔error）。 涉及：runtime.rs:1828-1832（is_task_cancelled 提前返回）与 :1835-1843/:2020-2021（fail_task 的 mark_cancelled）。
Why: 停止受理后收尾仍写监视器为已完成，且没有任何环节把它改回已停止.
In the model, 2 different steps lead into this bug: "执行体已不在，取消方补写监视器终态" and "收尾：持久层拒绝完成写入，但仍发出完成语义（终态帧/监视器/目标结局）". The steps below are the shortest path that TLC found.

0. Start: 轮次终态：执行中<br/>监视器：执行中<br/>终态帧：未发<br/>外部命令：运行中<br/>停止管线：未发起
1. 执行超时，按失败结清. Now: 轮次终态：已失败<br/>监视器：已失败<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：未发起
2. 用户按下停止. Now: 轮次终态：已失败<br/>监视器：已失败<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：已请求
3. 停止受理：执行围栏置位（监视器已是终态，保持不变）. Now: 轮次终态：已失败<br/>监视器：已失败，取消已可见<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：已受理（取消可见）
4. 持久控制面：轮次已是终态，写入被拒. Now: 轮次终态：已失败<br/>监视器：已失败，取消已可见<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：轮次已取消
5. 执行体已不在，取消方补写监视器终态. Now: 轮次终态：已失败<br/>监视器：已停止，取消已可见<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：命令已结束

With the fix, step 5 (执行体已不在，取消方补写监视器终态) happens as "无外部命令需要结束" and takes you to: 轮次终态：已失败<br/>监视器：已失败，取消已可见<br/>终态帧：失败，目标结局：失败<br/>外部命令：已结束<br/>停止管线：命令已结束.
