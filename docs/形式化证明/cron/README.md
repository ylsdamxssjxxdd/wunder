# 定时任务并发状态审计

日期：2026-10-27。蛹是本地 AI 工作台，蜂巢是随舰体提供的云端 AI 工作台；两端共用引擎调度与存储语义。

## 结论

原实现不能评价为“功能和状态全部正常”。普通增删改查、执行及工作区绑定通过回归，但代码审计与 TLA+ 有界模型复现四类并发风险。本次修复共享引擎和 SQLite/PostgreSQL 存储，不以 UI 测试替代状态正确性论证。

## 模型边界

模型位于 `docs/形式化证明/cron/models/`。原实现与修复模型使用相同规则，只改变 `Fixed` 配置；动作条件标注代码位置。模型包含一个任务、两个执行者，各最多领取一次；枚举手动读取/领取、定时领取、完成读取/提交、一次停用、一次编辑、一次删除、一次租约到期的交错。租约和配置代次有限抽象，事务视为不可分割动作。

原实现拆开历史与状态提交，修复模型合并。编辑和停用在模型中直接原子化，未展开旧 API 自身的全部读取窗口，所以反例清单是风险下界。模型不是 Rust 程序，映射仍依赖代码审查及实现测试。

| 规则 | 要求 | 原模型 | 修复模型 |
| --- | --- | --- | --- |
| NoResurrection | 删除后旧快照不得复活任务 | 反例 | 通过 |
| ExclusiveClaim | 未失效的执行权不得重复授予 | 反例 | 通过 |
| NoStaleCompletion | 旧完成不得覆盖编辑、停用或新租约 | 反例 | 通过 |
| AtomicHistory | 删除或换代后不得单独追加旧历史 | 反例 | 通过 |
| HistoryWithCommit | 历史和完成状态一起提交 | 不适用 | 通过 |

本目录 `summary.json` 是保留结论与计数的精简摘要，移除了机器路径和被隐藏路径的长列表；复验输出保留完整摘要。两个模型合计 42,844 个状态、73,664 条迁移；不是修复模型单独计数或生产执行次数。五条规则逐条检查后再次检查完整状态图，`uncited` 为空。`--cover` 仅简化图示，不改变检查范围。

## 反例与修复

编号与 `bug-1.mmd` 至 `bug-4.mmd`、对应 PNG 及 `stories.md` 一致。

| 编号/规则 | 最短读者路径 | 实现回归证据 | 修复结果 |
| --- | --- | --- | --- |
| 1 / ExclusiveClaim | 1 手动读取 → 2 定时领取 → 3 手动旧快照写入 | 双线程只有一个领取胜者；旧快照不覆盖定时领取 | 第 3 步比较失败 |
| 2 / NoResurrection | 1 手动读取 → 2 删除 → 3 手动旧快照写入 | 删除后的比较交换拒绝插入 | 不复活 |
| 3 / AtomicHistory | 1 领取 → 2 完成读取 → 3 停用 → 4 单独写历史 | 换代后不写历史；历史失败时更新/删除均回滚 | 历史无独立提交窗口 |
| 4 / NoStaleCompletion | 1 领取 → 2 完成读取 → 3 停用 → 4 完成旧快照写入 | 旧配置/租约比较失败；真实停用后保留租约并结算 | 重读后结算，不恢复启用 |

反例在模型复现；Rust 测试验证对应存储原语及真实停用流程，不声称完整服务交错均经网络并发重放。

SQLite 使用 `BEGIN IMMEDIATE`、PostgreSQL 使用 `SELECT ... FOR UPDATE`，比较完整快照、替换/删除任务、写历史在同一事务完成。手动领取、编辑和开关不再无条件 upsert；新建 ID 由引擎生成，不能覆盖旧任务。停用只停止后续自动调度，不取消在途任务或清空租约。完成冲突最多重试八次，超过上限记录错误，不强行覆盖。

## 其他修复与性能

- cron 直接取当前时间后的匹配，不预加一秒漏掉紧邻秒级触发；非法时区拒绝，不静默回退 UTC。
- 下次唤醒考虑逾期任务及有效租约到期，不把逾期任务过滤为没有计划。
- 数据库分页每页最多 200 条，额外一条判断后续页；蜂巢按页替换不无限累积；蛹保留最近 200 条有界列表。
- 状态数据库聚合，工作区绑定按页批量查询，移除全量拉取和每任务一次会话查询；分页解析错误不静默吞掉。
- 两端展示有效租约的运行中状态；蜂巢历史请求校验代次及所选任务，旧响应不覆盖新任务。页面不是实时订阅，以刷新时快照为准。

## 复验

准备 Node、Java 11 以上、TLC 与 statechart 技能。设置 `JAVA` 指向 Java、`TLA2TOOLS` 指向 jar；未设置 jar 时技能可用 mise 安装。产物必须在仓库外：

```text
python scripts/check_cron_formal.py --statechart <技能目录>/scripts/statechart.mjs --out <仓库外报告目录>
```

脚本复制模型到临时目录，运行 `from-spec --fixed --expect-broken NoResurrection,ExclusiveClaim,NoStaleCompletion,AtomicHistory --cover --png`。报告含 PNG、Mermaid、故事、summary 及原始日志；拒绝缺少修复日志、TLC 异常或未完整遍历。不能把已打印反例后的工具崩溃当作通过。

## 未证明范围

不是整个 Rust 程序的定理证明或无限状态证明。未建模真实模型调用、外部工具副作用、OS 调度、崩溃、时钟回拨、网络分区、多任务、数据库损坏或日历/DST。未验证活性、公平性，不能保证任务一定完成。

租约到期接管仍是至少一次语义，心跳丢失不撤销外部副作用，不能承诺全链路恰好一次。去重键不是唯一索引，并发新建严格幂等性未证明。全局并发上限仍分开计数和领取，多个调度进程及手动执行的严格全局限流未证明。PostgreSQL 本次只编译，未连接真实数据库做并发集成测试。以上不能被五条单任务规则通过替代。
