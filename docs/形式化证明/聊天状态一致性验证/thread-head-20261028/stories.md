## 1. 线程完成，气泡仍运行

规则：`ImmediateTerminalAgreement`。已知某个执行轮次完成时，对应可见气泡不能仍处于运行态。

路径：受理后提交展示窗 → 目录先返回完成态。

旧实现结果：线程完成、气泡仍运行。修复后，目录终态按 `status_turn_id` 与当前执行轮次匹配，并同步结清对应气泡。

## 2. 传输已收尾，气泡仍运行，却提示完成

规则：`NoUnverifiedSuccess`。请求传输收尾没有执行身份，不能宣布任务成功。

路径：受理后提交展示窗 → 请求传输先收尾。

旧实现结果：请求结束被当成本轮完成。修复后，收尾事件改为 `transport_final`，只关闭请求并保留线程观察；完成提示等待带 `sessionId`、`turnId` 的持久终态。

## 3. 传输收尾与目录终态交错

规则：`ImmediateTerminalAgreement`。

路径：受理后提交展示窗 → 请求传输先收尾 → 目录先返回完成态。

旧实现结果：传输收尾已经触发错误完成语义，气泡仍可能运行。修复后请求收尾不改变执行状态，持久终态与对应气泡共同确认完成。

## 4. 同轮迟到运行快照重新打开终态

规则：`TerminalDoesNotReopen`。同一执行轮次的终态一旦确认，迟到 `running` 快照不能重新打开它。

路径：受理后提交展示窗 → 目录先返回完成态 → 展示帧稍后到达 → 同轮次迟到运行快照到达。

旧实现结果：线程与气泡从完成退回运行。修复后，终态水位按同一执行身份拒绝状态回退，只允许补齐内容。

## 5. 刷新放大传输收尾与迟到快照交错

规则：`TerminalDoesNotReopen`。

路径：受理后提交展示窗 → 请求传输先收尾 → 目录先返回完成态 → 展示帧稍后到达 → 同轮次迟到运行快照到达。

旧实现结果：刷新后仍可能显示错误完成通知和旋转中的首个思考条目。修复后，传输收尾不产生终态，刷新只补水带身份的持久线程视图；通知按 `sessionId:turnId` 去重。
