# 聊天流式管线根治：主智能体执行书

## 任务定位

你是主线集成智能体，负责把两个从智能体的改动合并到聊天流式管线根治方案中，并完成最终验收。主线依据是 `docs/聊天流式管线根治方案.md`，其中的不变量 I1–I6 优先于局部历史行为。

本任务不创建分支、不提交 git，不回滚其他开发者的修改。不要为了恢复旧测试而重新引入第二套聊天事实源。

## 工作范围

1. 维护协议和集成边界：`change_seq` 是 v2 唯一恢复游标，`thread_log_changes` 是 durable 事实源，tail 只能作为带 `base_seq` 的可丢增量。
2. 审核从智能体一、二的改动，解决接口冲突，保证一个会话只启用一套 v1/v2 watcher。
3. 收敛 `start`、`watch`、`resume`、snapshot-required、overflow 的服务端和前端语义。
4. 审计剩余 v1 聊天恢复引用；能移除的移除，必须保留的明确限定在兼容分支。
5. 运行后端、前端和跨存储回归，更新根治方案、功能迭代记录和必要的经验教训。

## 执行顺序

1. 先阅读两个从智能体任务文档和当前 diff，建立改动清单；不要覆盖无关改动。
2. 用 `rg` 搜索所有 `after_event_id`、`load_stream_events`、`get_max_stream_event_id`、`commit_thread_item`、`update_thread_turn`，确认 v2 路径没有绕回旧游标。
3. 检查每个协议入口：首次 start 不跳过 accept turn；watch/resume 不双推；协议切换先取消旧管线；snapshot cursor 不倒退。
4. 处理冲突后，先跑定向单测，再跑完整 runtime check、前端测试和 typecheck。
5. 将实际完成项写回根治方案的“当前落地状态”，不能把仅有单测的内容写成浏览器性能验收已完成。

## 必须满足的验收条件

- durable 帧按严格递增 `change_seq` 发出，重复帧可幂等折叠。
- tail 只有在 `lastSeq >= base_seq` 且 offset 正确时才进入投影。
- gap、snapshot-required、慢客户端 overflow 都有有限重试和明确终止边界。
- v1 与 v2 不同时写同一会话的前端状态。
- 断线恢复结果与原子 snapshot 加 durable replay 一致。
- SQLite 与 PostgreSQL 至少完成编译检查；涉及存储语义的改动必须有对应测试。
