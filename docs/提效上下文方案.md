# 工具与上下文提效方案

> 状态：持续实施；已接入结果预算、完整请求本地准入、紧凑工具规格注入与规格引用、单一 `browser(action=...)` 与 `goal(action=...)` 严格联合 schema、浏览器世代校验、技能按需读取与源头限量，以及受限完整结果载体与恢复入口。浏览器正文已支持无状态 `next_cursor` 续读，游标绑定标签和页面世代；桌面控制、`self_status` 与 MCP package call 的模型面也已完成专门收敛。下文分别标明已接入能力、当前边界和待实施目标。
> 目标：在保留工具原意、可恢复性和安全约束的前提下，降低工具定义与工具结果的上下文占用，让长任务更稳定。
> 证据来源：工具测试 JSONL（本地导出）、仓库代码审查与 DeepSeek harness 参考项目。日志中的身份、路径、URL、密钥和业务内容不写入本文档。字符数、UTF-8 字节数与 token 数分别统计；近似 token 计量仅供预算治理，不等同于模型 tokenizer 的精确结果。

## 结论先行

1. **压缩模型观察，同时保留真实恢复入口。** 成功结果先按工具语义投影，再按最终 JSON 信封的近似 token 成本限额。超 transport 上限或模型预览丢失内容时，按需保存接受到的规范化结果；保存成功才返回 `result_handle`，复用 `read_file` 分页读取或搜索。
2. **20,000 字符不再是模型结果的统一硬限制。** 当前分类预算为 512 / 2,000 / 4,000 / 6,000 近似 token，同轮新增观察公平分配。1 MiB transport 防护另行负责序列化结果体积；出站前还会估算消息、reasoning、tool calls、图片、原生工具定义、输出预留和 safety reserve，超限先触发压缩并在最终请求点拒绝。
3. **工具描述保留必要细节，返回结果保持简明。** 调用条件、参数语义、副作用、安全边界和续读方式不能为省 token 而删除。full / compact / tiny 规格对象已建立，模型目录注入 compact 规格，工具调用日志使用稳定 schema 引用；命名 profile 已在线程首次执行时选定并持久化其工具 ID 快照。
4. **技能首调已改为 manifest，正文通过 `action=read` 按需读取。** 资源正文、资源树、目录扫描、技能数量和元数据前缀均有上限；manifest 与 read 分别使用 cursor。生产者仍须继续按真实任务验证这些限额下的发现覆盖率与读取体验。
5. **浏览器模型目录已收敛为一个 `browser` 工具。** 通过 `action` 的严格联合 schema 调用导航、标签页、观察、交互、等待、截图和批处理；每个 action 独立限制字段、必填项与互斥条件，服务端在进入 bridge 前重复校验。旧 `browser_*` 模型名不解析；`evaluate`、原始 JavaScript、状态与关闭会话不在模型 action 中。页面和 DOM 世代变化会使旧 ref 失效并指引重新观察；`action=observe_text` 的正文可使用返回的 `next_cursor` 续读，游标绑定标签和 `page_generation`。

## 统一协议设计

### 工具规格分层（已接入）

| 层 | 用途 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| full | 执行校验、管理员界面、审计、开发诊断 | 完整描述、参数解释、兼容字段、错误码、示例 | 直接注入模型历史 |
| compact | 模型 function-call 或工具提示 | 清晰用途、调用条件、必要约束和 JSON Schema、分页/副作用边界；长度服从消除歧义 | 内部实现、重复别名、无助于调用的长示例、UI 文案 |
| tiny | 工具路由、能力选择、缓存键 | id、短标签、读写/副作用类别、profile | 参数细节和执行结果 |

当前内置工具事件和日志已持久化 tool_id、args 及包含 schema_ref、catalog_version、schema_hash 的引用对象，MCP package get 也返回相同引用元信息；完整规格仍由 catalog 或 MCP get 提供。轨迹界面已兼容显示 schema_ref，但按引用自动回填完整规格、跨版本恢复和旧事件迁移仍待实施。模型历史使用原生 tool call 参数和精简观察，不能把带 schema 的审计事件直接作为模型正文重放。

compact 当前递归移除 title、examples、$comment 和 UI 扩展标注，保留描述、参数解释、required、enum、范围与组合约束；它不通过任意截短描述来缩减规格。动态工具的共享校验器定义了名称 256 字节、description 8 KiB、schema 64 KiB、深度 24 和节点 4,096 的上限；用户可控注册入口额外要求数组 maxItems≤4,096 与对象 additionalProperties=false。用户 MCP 保存、别名绑定、能力目录及配置导入均已接入；外部 MCP provider 目录复用大小/深度/节点边界，但不强制注册专用约束，以免改变合法远端 schema 语义。

`$ref` 和 `anyOf` / `oneOf` / `allOf` 可以自己定义类型，规范化时保留这一语义，不为缺少顶层 `type` 的组合节点猜测 `string`。例如“字符串或数组”的 `anyOf` 仍须允许数组，“对象 action 分支”的 `oneOf` 仍须允许对象；否则压缩后的规格虽然更短，却会在模型侧排除执行器原本支持的合法参数。运行时依据原始 action schema 定向恢复被传输层字符串化的非字符串 JSON 值，然后继续执行字段、范围、权限和状态规则校验。

### 结果信封

成功：{"ok":true,"data":{"items":[],"next_cursor":"..."}}
当前失败字段：{"ok":false,"error":"可执行的下一步","error_code":"TOOL_X_FAILED","retryable":true}。错误码和 retryable 按可用信息出现，不强求统一固定壳；code/message 统一命名仍待协议收敛。

- provider、duration_ms、内部 trace、绝对路径、重复的 path/resolved_path 等运行时噪声按内置工具语义投影，目标是只保留下一步所需信息。通用或远端应用字段不能仅因同名就删除，当前尚非所有工具的统一白名单。
- 成功结果只输出模型下一步需要的字段。计数、原始参数、诊断细节和 UI 展示字段按需返回。
- truncated、retryable、has_more、next_cursor 只在 true、非空或确实需要续读时出现。
- 文本、命令、网页内容使用工具级近似 token 预算，并共享新增观察的同轮预算；UTF-8 字节上限另作 transport 防护。当前数组 32 项、表格采样等投影仍有损，通用超预算结果可能退化为 JSON 字符串头尾预览；检测到省略时按需保存接受到的结果，保存成功才提供 result_handle。原生 cursor/offset 与载体恢复分别标明，不能将下一页游标当成当前页缺失条目的恢复入口。
- 附件只给 artifact_id、mime、尺寸或受控引用；模型不接收 base64、重复公开 URL 和本地绝对路径。

### 统一 20,000 字符限制的评估

20,000 字符可作为初期防止超长结果进入模型的兜底，但不适合作为长期统一预算。相同字符数的中文、英文、代码和 JSON 使用不同 token 数；单条结果合格也不能约束同轮多个结果的总量。简单从字符串中间截断还可能丢失错误尾部、破坏列表结构或删除分页信息。

当前模型工具结果预算通过 `approx_token_count` 按 **UTF-8 字节数 / 4** 估算，对最终序列化的完整 JSON 信封计价，包含 `ok`、错误说明、截断标记和续读信息，不只计算 `data` 正文。这不是路由模型的真实 tokenizer，不能据此承诺请求一定不会溢出；路由模型的实际 usage 与完整请求的上下文检查仍需负责校正和防护。

| 维度 | 统一 20,000 字符的局限 | 收敛方式 |
| --- | --- | --- |
| 语言与内容 | 相同字符数无法稳定代表 token 成本 | 使用统一近似 token 计量，记录实际 usage 校正偏差 |
| 工具语义 | 写入确认和文件正文共用预算，浪费空间或丢失内容 | 按结果类别给预算；状态保字段、列表保完整条目、命令优先保留错误尾部 |
| 并行调用 | 多个单条结果仍会叠加到下一次模型请求 | 同时约束单条与同轮总预算，预算根据路由容量与剩余空间动态收紧 |
| 可恢复性 | `truncated=true` 无法说明如何拿到省略内容 | 保留原生 cursor/offset；本轮接入 `result_handle`/spill，成功保存才承诺载体可读 |
| 审计与回放 | 先修改执行结果再发审计事件，会让审计也丢失正文 | 执行、审计、模型观察分别投影；模型历史只使用观察结果 |
| 内存与序列化 | 结果生成后才裁剪，不能避免生产阶段的大内存开销 | 生产者先限制扫描、条目、单行和流缓冲；序列化后加 UTF-8 字节最终防护 |

### DeepSeek harness 的分层对照

参考项目没有用 20,000 字符统一截断模型工具结果。其 `ContextBody.tsx` 与 `JsonBlock.tsx` 中的 `MAX_CHARS = 20_000` 属于 UI 展示限制，不改写生产者结果和模型请求。模型结果治理采用下列分层；表中路径均为参考项目内的相对路径。

| 层次 | 参考实现与默认值 | 触发时机与行为 | Wunder 可借鉴点 |
| --- | --- | --- | --- |
| 文件生产者 | `packages/fs/tool-fs/src/read.ts`、`read-render.ts`：默认/最大 2,000 行，单行 2,000 字符，选中正文 50 KiB；文件达到 10 MiB 或大小未知时流式读取 | 读取时限制窗口和行缓冲；输出说明下一个 offset | 在读取源头有界，保留行号与可执行的续读参数；无需为了续读再次保存已有文件 |
| 搜索生产者 | `packages/fs/tool-fs-search/src/search-core.ts`：原始输出上限 20,000,000 字节；格式化匹配/路径另设条数和单行预算，过量格式化结果可 spill | 不解析被截断的原始搜索流；结果保留条目边界，提示缩小查询或读取完整载体 | 区分内部采集上限和模型输出预算，不能把不完整扫描伪装为完整结果 |
| 命令生产者 | `packages/shell/bash-local/src/index.ts`：每流内存 64,000 字节，spill 上限 64 MiB；`tool-bash/src/render.ts` 附省略说明与完整输出位置 | 流写入阶段保持有界尾部，溢出写文件；超过 spill 上限后也不能承诺保有完整输出 | Wunder 读取器只保留有界 head/tail；模型观察发生省略后由编排层统一写入带用户/线程/工作区归属、TTL 和容量上限的 `tool_result_store`，成功才返回句柄。命令读取阶段不暴露裸路径 |
| 网页生产者 | `packages/web/tool-web/src/index.ts`、`fetch.ts`：抓取输出默认 200,000 字符，转换前先限制源输入，完整输出再限额；`search.ts`：最多 8 个来源、4 条查询 | 限制同步 HTML 转换工作量，截断后提示获取更具体页面；多查询合并后仍限制来源总数 | 正文提取前先约束输入与处理成本；列表合并后再次限额，避免并发放大 |
| 单结果 token spill | `packages/spill/spill-policy/src/index.ts`、`retention.ts`；基础组合 `packages/bundle/base/cordis.patch.yml` 配置 `maxInlineTokens: 12500` | 已接受结果超过近似预算时，先保存完整格式化结果，再扣除提示开销，剩余预算由头尾各占一半；提示包含精确省略 UTF-8 字节数、图片数、locator 与读取指引 | 先保证可恢复，再缩减模型预览；计价覆盖提示和图片说明。12,500 是该组合配置，不应原样当成所有模型的合理值 |

| 压力下历史剪枝 | `packages/compaction/compaction-tool-result-pruner/src/config.ts`：文本超过 8,192 个 Unicode code points，保留头 4,096、尾 1,024 和省略标记 | 仅达到上下文压力或确认溢出后执行；替换当前模型可见 surface，完整原事件仍保留在会话日志 | 近期结果先追加；历史重写只在有收益时发生，保留原事件、调用配对和可回放来源 |
| 动态摘要 | `packages/compaction/compaction-basic/src/config.ts`、`index.ts`：阈值 `floor(min(W × 0.8, W − O − B))`，默认 `B = 65,536`；近期保留预算为 `(W − O) × 0.16` | 达到阈值后先剪枝并重新计量，仍超压才摘要最旧的平衡范围；`W` 为路由上下文窗口，`O` 为生效输出预留，`B` 为额外余量 | 使用路由容量与输出预留，不用固定历史条数触发；小窗口需要更小余量，不能照搬 65,536 |

参考实现也存在边界：spill 后端缺失、存储失败、通知容不下预算或计量失败时，它会记录原因并保留原内联内容。因此 spill 是可恢复预览策略，不替代生产者边界和请求前的最终上下文检查。

### Wunder 的结果预算与当前实施边界

下表列出分类预算和目标保留策略，**“保完整条目”等目标尚未全部实现**；当前通用投影的有损行为和续读限制见表后说明。

| 结果类别 | 单条近似 token 预算 | 目标保留策略 | 原生续读与待办 |
| --- | ---: | --- | --- |
| 状态、点击、写入/编辑确认 | 512 | 状态、变更位置、错误码和必要下一步，不回显原参数或正文 | 无正文时无需续读 |
| 列表、搜索、目录 | 2,000 | 保完整条目、排序、总量/省略量和 cursor；不将 JSON 条目切成字符串片段 | 原生分页、缩小查询；模型省略的已接受结果可按需保存为载体 |
| 命令与命令会话 | 4,000 | 保退出状态与 stderr；正文保头尾并优先错误尾部，会话只返回增量 | 会话游标；读取器 head/tail 和会话 ring buffer 已有界；模型投影省略时由统一结果载体保存已接受的完整命令结果，载体失败则只给预览，不能恢复生产者此前主动丢弃的流 |
| 文件读取、网页观察、技能正文、browser action=batch | 6,000 | 保定位、正文窗口、页面 refs/行号与续读信号，避免同时重复多种正文视图 | 文件/技能原生窗口与受限结果载体；浏览器 `observe_text` 通过绑定页面世代的 `next_cursor` 续读，refs 和 batch 不表示通用正文分页 |
| 其他工具 | 4,000 | 保状态、必要数据和错误；逐步增加语义投影 | 复用预算与受限结果载体，不表示每个工具已有完整分页协议 |

当前同轮新增工具观察以 **8,000 近似 token 为目标，12,000 为正文软限**。运行时从已观测历史的剩余上下文空间中扣除输出预留与 safety，再收紧新增观察预算；这是增量预算，**不包含本轮 assistant 消息、tool calls 或 image followups**。完整请求准入已将这些部分以及实际原生工具定义共同估算；单条分类预算是上界，不是必须填满的配额。

为保留每个调用的结果协议，当前还按每条结果预留至少 256 近似 token；大量工具调用时，该预留可以突破 12,000 的正文软限。例如 100 个工具结果的协议预留合计为 **25,600**，不能将“同轮 12k”表述为所有结果合计的硬上限。请求装配阶段已纳入 assistant/tool calls、图片、固定前缀和实际工具定义执行统一检查；观察预算仍不能替代该检查。

当前 transport 对序列化后的整个 `data`/`error`/`meta` 共同施加 **1 MiB** 防护，先以无分配 writer 检测上限，只有超限才使用固定 **32 KiB** 头尾 writer 完整计数和保留预览，避免为了检测超限先构造另一份无界完整字符串。超限结果先尝试保存完整载体，再执行 transport 预览；小于上限时不改写原始 `data`，在随后模型投影检测到省略时按需保存。保存失败仍执行有界预览并标明 `recoverable:false`，不能为保持完整而无限回退到内联正文。存储日志仍有自身约 4k 级裁剪边界，结果载体也不保存所有审计事件或保证所有被语义投影省略的字段均有副本，因此不能宣称完整审计。

当前语义投影仍包括数组 32 项上限、表格采样等有损处理；通用 token 超预算分支可能返回 JSON 字符串头尾预览，尚未做到对所有结构逐条分页。游标以原字段名和原值完整保留，容不下时整项省略，不能截短成不可用的新游标。结果省略当前页时，保存成功优先给出载体入口；没有载体则提示**重新读取当前页并减小 limit**。`next_cursor` 只能前往下一页，不能恢复当前页已省略条目。原生 offset/cursor 继续遵循工具自身协议。

字节 transport 上限、近似 token 观察预算、生产者扫描/流缓冲上限与存储日志上限各有职责，不能互相当作完整性保证。生产者的最大扫描量、最大行长、条目数、流缓冲与执行/审计存储仍需分别有界。

### 本轮接入：完整请求本地准入

完整请求预算与 provider 返回的 usage 分开：前者负责决定是否可以发出请求，后者仍是实际占用和计费依据。请求估算不会写成已观测或已计费 token。

| 项目 | 当前行为 | 边界 |
| --- | --- | --- |
| 计量范围 | 正文、reasoning、tool calls 参数、tool call id、图片估算和实际原生工具定义 | 文本和 JSON 使用本地近似计量，图片使用现有内容估算；不等于 provider 的真实 tokenizer |
| 输入预算 | 路由上下文容量减去生效输出预留与 safety reserve | 输出预留沿用发送到 provider 的配置；未配置时使用运行时默认值，不暗中压至窗口的一半 |
| safety reserve | `min(clamp(W/32,64,4096),W/8)`，W 为生效上下文容量 | 随小窗口收紧，仍不能保证覆盖所有 tokenizer 偏差 |
| 执行循环 | 每次模型轮次前估算完整请求，超预算时要求既有 compaction 压缩历史 | 不改写线程初始化后冻结的 system prompt，不删去工具调用/结果配对 |
| 最终检查 | 规范化并清理消息后、真正调用 provider 前，使用实际消息和 tools 再次检查 | 超限返回 `CONTEXT_WINDOW_EXCEEDED`，detail.source 为 `local_request_admission`；此错误不能当成 provider 观测值写入 usage |

### 本轮接入：技能源头限量

| 层次 | 当前上限 | 续读与失败边界 |
| --- | --- | --- |
| 技能发现 | 最多 128 个配置扫描路径、每个根最多 4,096 个目录项、最多加载 4,096 个技能 | 按需 fallback 查找不构建完整 registry；达限不表示发现了根下的全部技能 |
| 元数据 | 每个 SKILL.md 最多读取 64 KiB 前缀 | 索引不为提取名称或说明读取完整正文 |
| manifest | 最多扫描 4,096 个资源项、每页最多 64 项、序列化正文目标上限 1,600 字符 | `manifest_cursor` 续读，`index_scan_limited` 明示扫描达到上限；目录过大时不能承诺完整索引 |
| 正文 read | 默认 16 KiB/160 行，最大 64 KiB/400 行；每片段最多 4 KiB；每次章节定位最多扫描 256 KiB | cursor 续读，绑定资源路径、大小和修改时间；文件变化要求重新读取，不将无界长行整行读入内存 |

技能读取得到相对资源定位和 UTF-8 边界安全的片段；源头限量与后续模型观察预算共同生效。章节定位未完成时仍需依据返回 cursor 继续，不能把扫描窗口结束误报为章节不存在。

### 本轮接入：完整结果载体与恢复协议

保存对象是**工具已返回、已规范化且被运行时接受的结果**。超过 1 MiB 的结果在 transport guard 前保存；其他结果在模型投影产生 `truncated`、`__truncated`、`rows_omitted` 等省略信号时按需保存，原文来自投影之前。生产者此前省略的文件范围、命令流、网页片段和搜索条目不在载体中，不能据此承诺恢复原始输入或完整执行过程。

| 项目 | 当前契约 | 边界 |
| --- | --- | --- |
| 模型入口 | 复用 `read_file`，`path` 为 `tool-result:<32 位小写十六进制 ID>`；不新增常驻工具 | 线程仍需拥有读取文件工具权限，保存结果不会自动扩大工具授权；句柄不包含所有者或物理路径，不能作为普通工作区文件路径解析 |
| 顺序读取 | `offset` 从 0 起，单位为载体 JSON 的 UTF-8 字节；`limit` 默认 8,192、最大 16,384 字节；低于 4 时抬至 4，保证一个 UTF-8 scalar 可容纳 | offset 必须处于 UTF-8 边界；使用返回的 next_offset 续读；JSON 字符串转义仍按序列化形式返回 |
| 字面搜索 | 同一入口传 `query`；入口限制最多 512 UTF-8 字节；搜索序列化 JSON 文本 | 每次扫描最多 256 KiB，最多 32 个匹配，每条摘要最多 160 字节，所有摘要正文合计受 limit 限制；next_offset 指向首个未返回的匹配或下一扫描窗口；不提供正则或语义搜索 |
| 所有权 | user + session + workspace 共同限定所有权 | 不同任务线程不能借句柄读取其他线程的载体；错误不暴露真实存储路径 |
| 保存与失败 | 保存成功后返回 result_handle、大小及到期信息；载体读取自身分页，不再次自动 spill | 超大、磁盘错误、锁超时或容量不足时仍保留有界预览，标明 recoverable:false，不返回假恢复入口 |
| 保留时间 | 最长 24 小时可读，读写时惰性清理 | 空闲时不保证恰在到期时删除磁盘文件；容量治理可更早驱逐旧载体；TTL 不是 24 小时必然可读保证；过期或驱逐后应重新调用来源工具 |
| 单项与线程配额 | 单项正文最多 8 MiB；每个所有权范围最多 32 MiB / 128 项 | 磁盘配额计算包含每项 128 字节私有头；不先构造另一份完整 JSON 字符串再写入 |
| 全局配额与扫描 | 每个本机 store 根最多 256 MiB / 1,024 项；目录扫描最多 4,096 项 | 超扫描边界拒绝新增；清理、计数和写入不依赖无界缓存或队列 |
| 跨进程竞争 | 内核文件锁串行化配额修改，获取锁最多等待 100 ms | 这是获取锁的等待上限，不是整个序列化或磁盘写入耗时上限 |
| 存储位置与重启 | 位于数据库父目录的 tool-results；未配置数据库路径时使用项目相对目录 config/data/tool-results | 不写入默认用户工作文件目录；同一持久目录可重启后读取；多节点未共享 store 时句柄不能跨节点恢复 |

读取示例：`read_file({"path":"tool-result:0123456789abcdef0123456789abcdef","offset":0,"limit":8192})`。搜索示例：同一调用增加 `"query":"sample"`。示例 ID 仅说明格式；实际必须使用当前线程返回且尚未失效的句柄。

## 浏览器工具专项方案

### 单一 `browser` 严格 action 工具

模型只看到一个 `browser` 工具。它不是所有字段均可选的巨型对象：顶层 schema 以 `oneOf` 枚举 action 分支，每个分支独立声明 `properties`、`required` 与 `additionalProperties:false`。执行入口重复执行同样的字段白名单、类型、范围与互斥校验；因此直接提交原始 JSON 也不能借由 schema 外字段到达 bridge。

重复的字段约束、元素目标与 batch 步骤定义使用本地 `$defs/$ref` 引用，以减少每轮原生 tool 定义的重复字节；引用不会改变分支自己的字段白名单。OpenAI 不接受根 `oneOf` 时，仅在该 provider 的出站定义上投影为 `action` 枚举和可选字段；执行端继续使用原始严格分支校验。

当前浏览器 schema 的等价序列化对比为 **6,882 / 9,311 UTF-8 字节**（本地引用 / 全部内联），减少约 **26.1%**。这只衡量相同严格分支消除重复后的 schema 字节收益；API 的完整工具定义还包含名称、描述及 provider 规范化，实际 token 仍以请求计量和 usage 为准。

| action | 用途 | 关键约束 |
| --- | --- | --- |
| `navigate` / `back` | 导航或后退 | `navigate` 必须提供 URL；导航默认不附正文 |
| `tabs_list` / `tabs_new` / `tabs_select` / `tabs_close` | 列出、创建、选择、关闭标签页 | 选择/关闭必须提供 `target_id` 或非负 `index` |
| `observe_refs` / `observe_text` / `screenshot` | 获取可操作引用、分页正文或截图 | 正文 cursor 绑定标签和 page generation；截图转为附件引用 |
| `click` / `type` / `hover` / `select` / `drag` / `press` | 页面交互 | 元素动作严格要求一种 ref 或 selector；拖放要求一对来源和目标；输入、选择、按键有 action 专属必填字段 |
| `wait` | 等待加载状态、文本、选择器、URL 或有界时间 | 固定等待不等同于成功验证 |
| `batch` | 顺序执行 1–10 个依赖步骤 | 步骤也是严格 `oneOf`；禁止嵌套 batch |

`evaluate`、原始 JavaScript、浏览器状态和关闭浏览器会话仅保留给控制面，不属于模型工具。旧 `browser_*` 名称既不出现在模型目录，也不被模型调度、授权或 provider 解析。

浏览器 runtime、Playwright bridge 和 `/wunder/browser/*` REST 控制 API 仍按各自职责保留；模型工具合并不改变这些内部或管理接口。bridge 为每个页面维护 `page_generation`；导航、返回、DOM/iframe 状态或开放 shadow root 变化都会使旧 refs 失效。`observe_text` 的 `next_cursor` 经过 HMAC 签名并绑定标签、世代和 UTF-16 偏移；页面变化或 bridge 重启会明确拒绝旧 cursor，要求重新观察，且不保存无界页面全文缓存。

### 浏览器结果投影

结果携带执行后的 `data.action`，投影层据此选择最小下一步数据，而不是只按工具名猜测：导航保留 URL/标题，标签页保留列表和活动 ID，观察保留正文、refs、截断与 cursor，交互保留 action、目标引用、URL 与 page generation，等待保留匹配状态，batch 保留进度。截图移除 base64，仅返回保存后的附件引用。事件与审计仍保留原始结构化结果。

## 验收与监控

以下分为现有协议的回归检查与后续量化目标；目标数值须以新的测试样本验收，不作为当前保证。按规范工具名统计，不能把别名算成多个工具：

- **规格（目标）**：首轮模型工具定义 <= 6,000 token；profile实施后评估缓存复用与新增规格成本，工具定义不能仅靠客户端引用省略API实际需要的schema；浏览器模型目录只保留一个 `browser` 工具。
- **结果（目标）**：普通成功结果 <= 1,000 字符；命令、网页和文件正文按最终信封近似 token 预算验收，省略必须标明 truncated 与真实恢复边界，只有生产者确实返回时才提供 next_cursor；技能首调 <= 2,000 字符。
- **浏览器（目标）**：普通动作结果 <= 120 字符；导航默认不附正文；batch成功结果 <= 400 字符。失败定位信息和必要ref/URL不得为达标而删除。
- **桌面观察**：动作后首等 320ms，以 120ms 间隔检查、连续静默至少 320ms，最多 10 次；首帧使用配置截图超时，后续探测共享从观察开始计算的 2 秒剩余预算；显式 `wait` 不重复动作首等。每次只向模型注入最新一帧；动画、加载、失败或超时达到探测边界时返回 `observation_stable:false` 和短提示，不能将“动作已派发”当作“界面已稳定”，也不能宣称视觉业务结果已经验证。
- **载体（本轮回归）**：分页拼接应逐字节重建已接受结果的JSON，中文/emoji边界不损坏；字面搜索覆盖跨扫描边界；用户/线程/工作区隔离；过期/驱逐、超8MiB、磁盘失败、配额与锁等待均有明确失败边界；载体读取不递归spill。
- **历史（目标）**：模型回放不混入完整审计envelope或重复schema、path/resolved_path、tabs；schema引用和完整审计恢复能力仍需单独验收，本轮载体不替代审计系统。
- **正确性**：旧浏览器与旧目标工具名均不能解析；文件读写、命令、浏览器 ref、原生 cursor、result_handle、错误码和权限边界回归通过；新增 page_generation、请求准入和规格/技能限额须以当前最终工作树的定向测试确认，不能套用此前回归结果。
- **运行效果**：记录 input_tokens、output_tokens、工具定义字符数、结果字符数、缓存命中、工具错误率和重试次数；不能只看总上下文值来归因某个工具。

### 可重复的收益量化

仓库提供 `scripts/tool_context_metrics.py`，从脱敏后的工具事件 JSONL 生成聚合 JSON 与 Markdown 报告。脚本只读取 `tool_result` 的 `data`、`model_observation`、`ok` 和截断元数据，输出按规范工具名聚合的调用数、错误率、截断率、原始/观察字符与 UTF-8 字节数、近似 token、观察覆盖率、token 节省比例和状态一致性；历史浏览器子工具、旧目标工具名和中英文定时任务别名会先归并到当前工具面。它不会把参数、路径、URL、正文或错误文本复制进报告。

```powershell
python scripts/tool_context_metrics.py --input <tool-events.jsonl> `
  --output target/tool-context-metrics.json `
  --markdown target/tool-context-metrics.md
```

近似 token 统一使用 UTF-8 字节数除以 4，与运行时 `approx_token_count` 的保守估算一致；它用于跨版本回归，不替代 provider 的真实 tokenizer 或 usage。比较版本时优先看同一工具的 `token_reduction_ratio`、`error_rate`、`truncation_rate`、`observation_coverage` 与 `status_mismatch_rate`，不把缺失 `model_observation` 的旧事件误报为零成本。截断率上升只有在恢复入口和错误率不退化时才可接受。

对当前脱敏工具测试样本的可重复基线：50 条工具结果，模型观察覆盖 64.0%；原始 data 约 10,370 个近似 token，已产生观察样本的原始/观察 data 成本为 4,506/3,345，data 节省约 25.77%；完整模型结果信封为 3,990 个近似 token，包含状态、工具标识等协议字段。错误率和截断率均为 0%。这些是样本基线，data 节省率不等于整个模型请求的节省率，也不是所有工具或 provider 的承诺值。

## 取舍与边界

- 浏览器采用单一 `browser` 工具以便统一管理；执行端每个 action 都有独立严格分支。支持根组合的 provider 使用 `oneOf`，OpenAI 出站使用兼容的 `action` 枚举与共享可选字段，再由执行端校验所选 action；兼容投影不等同于按 action 动态加载规格。
- 不为压缩而删除页面 refs、错误码、分页句柄、artifact 引用和安全边界；这些字段直接影响下一步调用。
- 优先按工具语义投影，再做有界截断；当前字符串预览和条目采样仍有损，已接入载体只恢复成功保存且未失效的已接受结果，结构化条目分页仍需继续推进。
- 命名 profile 已在首次执行固定并保存 profile、revision 与规范工具 ID；后续请求覆盖不改变已冻结线程的选择，当前权限和模型能力仍可缩小集合。显式 profile 升级 API 和跨版本动态 schema 快照仍待设计；已有线程 system prompt 和初始化记忆继续冻结。
- 审计和模型上下文使用不同序列化投影；明确记录transport、生产者与日志的省略。受限结果载体已接入，完整审计载体仍待实现。
