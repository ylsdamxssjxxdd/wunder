# 工具与上下文提效方案

> 状态：分阶段实施；下文包含目标设计与当前实现边界，不能将目标验收项视为已实现保证。  
> 目标：在保留工具原意、可恢复性和安全约束的前提下，降低工具定义与工具结果的上下文占用，让长任务更稳定。  
> 证据来源：工具测试 JSONL（本地导出）、仓库代码审查与 DeepSeek harness 参考项目。日志中的身份、路径、URL、密钥和业务内容不写入本文档。字符数、UTF-8 字节数与 token 数分别统计；近似 token 计量仅供预算治理，不等同于模型 tokenizer 的精确结果。

## 结论先行

1. **先分离三种数据形态，再改文案。** 工具规格、执行结果、审计事件和模型观察不能混用。目标固定为 full（运行时与审计）、compact（模型调用）、tiny（路由/选择）三档；当前 transport 和日志仍有各自有损上限，尚不能保证完整审计。
2. **工具面按线程初始化时的 profile 固定。** 不按每个模型轮次频繁增删原生工具，避免破坏提示词/API 前缀缓存。线程选择 minimal、development、research 或 browser profile；能力升级产生新的 profile_version，从下一个模型轮次生效。
3. **模型结果使用最小信封。** 成功默认 {"ok":true,"data":{...}}；失败默认 {"ok":false,"code":"...","message":"...","retryable":true}。只有分页、续读、截断或下一步确实存在时才发送 next_cursor、has_more、truncated、next_step。
4. **技能正文改为按需读取。** 技能调用当前一次返回完整说明和目录，是测试中最大的单项结果；首调用只返回 manifest、摘要和入口，正文按章节或路径读取。
5. **浏览器从 17 个常驻子工具收敛为 6 个模型工具。** 推荐固定面：browser_navigate、browser_tabs、browser_observe、browser_interact、browser_wait、browser_batch。status、close 转为会话生命周期/诊断动作；evaluate 默认高级授权；截图是 observe 的可选模式。

## 统一协议设计

### 工具规格分层

| 层 | 用途 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| full | 执行校验、管理员界面、审计、开发诊断 | 完整描述、参数解释、兼容字段、错误码、示例 | 直接注入模型历史 |
| compact | 模型 function-call 或工具提示 | 一句用途、必要约束、必要 JSON Schema、分页/副作用边界 | 内部实现、重复别名、长示例、UI 文案 |
| tiny | 工具路由、能力选择、缓存键 | id、短标签、读写/副作用类别、profile | 参数细节和执行结果 |

持久化工具调用保存 tool_id、args、schema_ref、catalog_version、schema_hash，不保存每次完整 schema。UI 或审计查看器按引用恢复完整规格。模型历史只重建原生 tool call 参数和 compact 结果，不能从带 schema 的审计事件重建上下文。

### 结果信封

成功：{"ok":true,"data":{"items":[],"next_cursor":"..."}}  
失败：{"ok":false,"code":"TOOL_X_FAILED","message":"可执行的下一步","retryable":true}

- tool、provider、duration_ms、内部 trace、绝对路径、重复的 path/resolved_path 默认不进入模型结果；审计事件可以保留。
- 成功结果只输出模型下一步需要的字段。计数、原始参数、诊断细节和 UI 展示字段按需返回。
- truncated、retryable、has_more、next_cursor 只在 true、非空或确实需要续读时出现。
- 文本、命令、网页内容使用工具级近似 token 预算，并共享新增观察的同轮预算；UTF-8 字节上限另作 transport 防护，不再用统一 20,000 字符代表模型预算。当前数组 32 项、表格采样等投影仍可能丢失内容，通用超预算结果也可能退化为 JSON 字符串的头尾预览；完整条目保留是后续目标。仅在原生 cursor/offset 确实存在时提供续读信息，不虚构通用恢复入口。
- 附件只给 artifact_id、mime、尺寸或受控引用；模型不接收 base64、重复公开 URL 和本地绝对路径。

### 统一 20,000 字符限制的评估

20,000 字符可作为初期防止超长结果进入模型的兜底，但不适合作为长期统一预算。相同字符数的中文、英文、代码和 JSON 使用不同 token 数；单条结果合格也不能约束同轮多个结果的总量。简单从字符串中间截断还可能丢失错误尾部、破坏列表结构或删除分页信息。

当前模型工具结果预算通过 `approx_token_count` 按 **UTF-8 字节数 / 4** 估算，对最终序列化的完整 JSON 信封计价，包含 `ok`、错误说明、截断标记和续读信息，不只计算 `data` 正文。这不是路由模型的真实 tokenizer，不能据此承诺请求一定不会溢出；路由模型的实际 usage 与完整请求的上下文检查仍需负责校正和防护。

| 维度 | 统一 20,000 字符的局限 | 收敛方式 |
| --- | --- | --- |
| 语言与内容 | 相同字符数无法稳定代表 token 成本 | 使用统一近似 token 计量，记录实际 usage 校正偏差 |
| 工具语义 | 写入确认和文件正文共用预算，浪费空间或丢失内容 | 按结果类别给预算；状态保字段、列表保完整条目、命令优先保留错误尾部 |
| 并行调用 | 多个单条结果仍会叠加到下一次模型请求 | 同时约束单条与同轮总预算，预算根据路由容量与剩余空间动态收紧 |
| 可恢复性 | `truncated=true` 无法说明如何拿到省略内容 | 优先原生 cursor/offset；无原生续读的大结果需要 `result_handle`/spill |
| 审计与回放 | 先修改执行结果再发审计事件，会让审计也丢失正文 | 执行、审计、模型观察分别投影；模型历史只使用观察结果 |
| 内存与序列化 | 结果生成后才裁剪，不能避免生产阶段的大内存开销 | 生产者先限制扫描、条目、单行和流缓冲；序列化后加 UTF-8 字节最终防护 |

### DeepSeek harness 的分层对照

参考项目没有用 20,000 字符统一截断模型工具结果。其 `ContextBody.tsx` 与 `JsonBlock.tsx` 中的 `MAX_CHARS = 20_000` 属于 UI 展示限制，不改写生产者结果和模型请求。模型结果治理采用下列分层；表中路径均为参考项目内的相对路径。

| 层次 | 参考实现与默认值 | 触发时机与行为 | Wunder 可借鉴点 |
| --- | --- | --- | --- |
| 文件生产者 | `packages/fs/tool-fs/src/read.ts`、`read-render.ts`：默认/最大 2,000 行，单行 2,000 字符，选中正文 50 KiB；文件达到 10 MiB 或大小未知时流式读取 | 读取时限制窗口和行缓冲；输出说明下一个 offset | 在读取源头有界，保留行号与可执行的续读参数；无需为了续读再次保存已有文件 |
| 搜索生产者 | `packages/fs/tool-fs-search/src/search-core.ts`：原始输出上限 20,000,000 字节；格式化匹配/路径另设条数和单行预算，过量格式化结果可 spill | 不解析被截断的原始搜索流；结果保留条目边界，提示缩小查询或读取完整载体 | 区分内部采集上限和模型输出预算，不能把不完整扫描伪装为完整结果 |
| 命令生产者 | `packages/shell/bash-local/src/index.ts`：每流内存 64,000 字节，spill 上限 64 MiB；`tool-bash/src/render.ts` 附省略说明与完整输出位置 | 流写入阶段保持有界尾部，溢出写文件；超过 spill 上限后也不能承诺保有完整输出 | 内存缓冲、持久载体、模型预览分别有界；命令保尾，退出码和 stderr 不随预览丢失 |
| 网页生产者 | `packages/web/tool-web/src/index.ts`、`fetch.ts`：抓取输出默认 200,000 字符，转换前先限制源输入，完整输出再限额；`search.ts`：最多 8 个来源、4 条查询 | 限制同步 HTML 转换工作量，截断后提示获取更具体页面；多查询合并后仍限制来源总数 | 正文提取前先约束输入与处理成本；列表合并后再次限额，避免并发放大 |
| 单结果 token spill | `packages/spill/spill-policy/src/index.ts`、`retention.ts`；基础组合 `packages/bundle/base/cordis.patch.yml` 配置 `maxInlineTokens: 12500` | 已接受结果超过近似预算时，先保存完整格式化结果，再扣除提示开销，剩余预算由头尾各占一半；提示包含精确省略 UTF-8 字节数、图片数、locator 与读取指引 | 先保证可恢复，再缩减模型预览；计价覆盖提示和图片说明。12,500 是该组合配置，不应原样当成所有模型的合理值 |
| 读取循环保护 | `packages/spill/spill-policy/src/index.ts` 对顶层 `read` 跳过再次 spill；规范程序值不随显示副本被截断 | 模型按 offset/limit 读取 spill 文件时，不再把读取结果不断变成新的 spill | 有界读取工具自身负责分页，避免“读取句柄又得到句柄”的循环 |
| 压力下历史剪枝 | `packages/compaction/compaction-tool-result-pruner/src/config.ts`：文本超过 8,192 个 Unicode code points，保留头 4,096、尾 1,024 和省略标记 | 仅达到上下文压力或确认溢出后执行；替换当前模型可见 surface，完整原事件仍保留在会话日志 | 近期结果先追加；历史重写只在有收益时发生，保留原事件、调用配对和可回放来源 |
| 动态摘要 | `packages/compaction/compaction-basic/src/config.ts`、`index.ts`：阈值 `floor(min(W × 0.8, W − O − B))`，默认 `B = 65,536`；近期保留预算为 `(W − O) × 0.16` | 达到阈值后先剪枝并重新计量，仍超压才摘要最旧的平衡范围；`W` 为路由上下文窗口，`O` 为生效输出预留，`B` 为额外余量 | 使用路由容量与输出预留，不用固定历史条数触发；小窗口需要更小余量，不能照搬 65,536 |

参考实现也存在边界：spill 后端缺失、存储失败、通知容不下预算或计量失败时，它会记录原因并保留原内联内容。因此 spill 是可恢复预览策略，不替代生产者边界和请求前的最终上下文检查。

### Wunder 的结果预算与当前实施边界

下表列出分类预算和目标保留策略，**“保完整条目”等目标尚未全部实现**；当前通用投影的有损行为和续读限制见表后说明。

| 结果类别 | 单条近似 token 预算 | 目标保留策略 | 原生续读与待办 |
| --- | ---: | --- | --- |
| 状态、点击、写入/编辑确认 | 512 | 状态、变更位置、错误码和必要下一步，不回显原参数或正文 | 无正文时无需续读 |
| 列表、搜索、目录 | 2,000 | 保完整条目、排序、总量/省略量和 cursor；不将 JSON 条目切成字符串片段 | 原生分页、缩小查询；无原生分页时待接入结果载体 |
| 命令与命令会话 | 4,000 | 保退出状态与 stderr；正文保头尾并优先错误尾部，会话只返回增量 | 会话游标；完整命令输出载体待接入 |
| 文件读取、网页观察、技能正文等长文本 | 6,000 | 保定位、正文窗口、页面 refs/行号与续读信号，避免同时重复多种正文视图 | 文件行窗口、页面/技能 cursor；无原生续读时待接入结果载体 |

当前同轮新增工具观察以 **8,000 近似 token 为目标，12,000 为正文软限**。运行时从已观测历史的剩余上下文空间中扣除输出预留与 safety，再收紧新增观察预算；这是增量预算，**不包含本轮 assistant 消息、tool calls 或 image followups**，也不是对整体下一次模型请求的 admission 保证。单条分类预算是上界，不是必须填满的配额。

为保留每个调用的结果协议，当前还按每条结果预留至少 256 近似 token；大量工具调用时，该预留可以突破 12,000 的正文软限。例如 100 个工具结果的协议预留合计为 **25,600**，不能将“同轮 12k”表述为所有结果合计的硬上限。需要在请求装配阶段纳入 assistant/tool calls、图片与固定前缀后统一检查，才能形成整体 admission 边界；此处的工具观察预算不能替代该检查。

当前 transport 对序列化后的整个 `data`/`error`/`meta` 共同施加 **1 MiB** 防护，先以无分配 writer 检测上限，只有超限才使用固定 **32 KiB** 头尾 writer 完整计数和保留预览，避免为了检测超限先构造另一份无界完整字符串。小于上限时保留原始 `data`，不进行 transport 结构改写；超限时尚未写入 spill，只保留有限控制字段、最多 **8 KiB** 错误信息和不可恢复标记。这不是完整结果存储。存储日志仍有自身约 4k 级裁剪边界，因此即使模型观察与事件投影已分离，也不能宣称审计日志完整保存原文。

当前语义投影仍包括数组 32 项上限、表格采样等有损处理；通用 token 超预算分支可能返回完整 JSON 字符串的头尾预览，尚未做到对所有结构逐条分页。游标以原字段名和原值完整保留，容不下时整项省略，不能截短成不可用的新游标。结果省略当前页内容时，应提示**重新读取当前页并减小 limit**；`next_cursor` 只能前往下一页，不能恢复当前页已省略的条目。文件、技能等原生 offset/cursor 继续遵循各自协议，是否能重新读取以工具能力为准。

字节 transport 上限、近似 token 观察预算、生产者扫描/流缓冲上限与存储日志上限各有职责，不能互相当作完整性保证。生产者的最大扫描量、最大行长、条目数、流缓冲与执行/审计存储仍需分别有界。

**尚未实现的完整性能力：**通用 `result_handle`、完整结果 spill、按句柄读取/搜索和载体清理策略。现有原生 cursor/offset 可以继续使用；仅有 `truncated` 或 `preview` 的结果不能被描述为“已保存完整原文”或“可通过句柄恢复”。后续接入时需要以任务线程隔离所有权、在预览缩减前保存受控完整结果，并为单载体大小、线程总量、有效期和清理设置边界。

本轮验证：`cargo test -p wunder-runtime --lib tool_result_payload --no-default-features` 通过 46 项；同一构建产物的 transport 保护测试通过 5 项、整轮预算分配测试通过 4 项。覆盖中文/emoji、JSON 转义、错误头尾、游标原值或整项省略、当前页省略提示、data/error/meta 大结果和 1/2/20/100 条并行结果分配。上述检查验证本轮预算与保护逻辑，不代表完整 spill 或整体请求 admission 已实现。

### 稳定 profile 与能力升级

| Profile | 固定工具族 | 使用时机 |
| --- | --- | --- |
| minimal | 文件检索、读取、写入、编辑、命令、网页基础能力 | 默认工作线程 |
| development | minimal + PTC、LSP、线程/子智能体、目标、调度 | 开发与复杂执行 |
| research | minimal + 网页、知识库、记忆、多媒体 | 调研与素材任务 |
| browser | minimal + 6 个浏览器工具 | 明确需要网页交互 |

线程首次确定 profile 后冻结其 system prompt 与工具集合。高级能力通过固定的 enable_capability/profile revision 升级，而不是同一轮随机改变工具数组。每轮记录 profile_version、工具目录版本和结果预算，便于比较缓存命中、工具错误率和上下文增长。

## 浏览器工具专项方案

### 当前 17 个工具与目标面

| 当前工具 | 归并到 | 处理方式 |
| --- | --- | --- |
| browser_navigate、browser_navigate_back | browser_navigate | action=navigate/back；当前标签页默认，不重复传 target |
| browser_tabs | browser_tabs | action=list/new/select/close；close 不再单独注册 |
| browser_snapshot、browser_read_page | browser_observe | mode=refs/text；同一页面只返回一种正文视图 |
| browser_take_screenshot | browser_observe | mode=screenshot；只返回附件引用，视觉需要时显式请求 |
| browser_status | 生命周期/诊断 | 不作为常驻模型工具；启动失败时由错误码附带最小诊断 |
| browser_click、browser_type、browser_select_option、browser_hover、browser_press_key、browser_drag | browser_interact | action discriminator；仅允许该 action 对应的 target/value 字段 |
| browser_evaluate | browser_interact 高级动作 | 默认 capability 关闭；需要显式授权、脚本预算和审计 |
| browser_wait_for | browser_wait | condition=selector/text/url/load，按条件使用字段 |
| browser_batch | browser_batch | 保留串行依赖操作；步骤数有界，默认不带 snapshot |
| browser_close | browser_tabs 或生命周期 | 会话结束自动关闭；显式释放标签使用 tabs action=close |

推荐默认固定注册 6 个浏览器工具：

    browser_navigate  browser_tabs  browser_observe
    browser_interact  browser_wait  browser_batch

公共的 include_snapshot、max_chars、snapshot_timeout_ms、默认 tab、会话 timeout 由服务端保存，不能在每个子 schema 重复。多标签时先 browser_tabs(action=select)，后续工具默认操作当前标签。页面变更递增 page_generation，旧 ref 自动失效，避免模型重复传长 selector 和旧 target。

### 浏览器结果投影

| 场景 | 模型默认结果 | 只在以下条件附加 |
| --- | --- | --- |
| click/type/select/hover/press/drag 成功 | {ok:true,data:{action,target_ref?}} | URL 变化时附 url；动作需要等待时附 pending |
| navigate/back | {ok:true,data:{url,title?}} | observe=true 或导航后需要决策时附有界 snapshot |
| snapshot/读取正文 | {ok:true,data:{text,refs?,truncated?,next_cursor?}} | refs 只给可操作元素；不同时返回 tabs/title/url 副本 |
| evaluate | {ok:true,data:{value}} | 超预算返回摘要和句柄；脚本错误回 code/message |
| wait | {ok:true,data:{matched,elapsed_ms?}} | 超时只回当前 URL、条件和可重试提示 |
| batch | {ok:true,data:{completed_steps,failed_step?,url?,snapshot?}} | 失败保留失败步骤和短错误；不回每一步重复 tabs |
| tabs | {ok:true,data:{tabs:[{id,title,url}],active_id}} | 仅显式 list/new/select/close 时返回 |
| screenshot | {artifact:{id,mime,width,height}} | 不回 base64、重复 path、下载 URL |
| status/close | 不作为常驻工具结果 | 只进入诊断事件或生命周期状态 |

目标是由审计载体保留受控的 Playwright bridge 响应、截图原始元数据和每步 batch 结果，模型观察层只接收上述投影。当前 transport 与存储日志仍会限额，尚不能保证完整审计；普通动作预计由约 460–480 字符压到 50–80 字符，动作结果可减少约 84%–89%。

## 验收与监控

每次修改同时记录以下指标，按规范工具名统计，不能把别名算成多个工具：

- **规格**：首轮模型工具定义 <= 6,000 token；固定 profile 之后单轮新增定义 <= 500 token；浏览器默认 6 个工具。
- **结果（目标）**：普通成功结果 <= 1,000 字符；命令、网页和文件正文按最终信封近似 token 预算验收，省略必须标明 truncated 与真实恢复边界，只有生产者确实返回时才提供 next_cursor；技能首调 <= 2,000 字符。
- **浏览器**：普通动作结果 <= 120 字符；导航只在需要时返回 snapshot；batch 结果 <= 400 字符（不含显式 snapshot）。
- **历史（目标）**：模型回放中不出现完整工具 schema、完整审计 envelope、重复 path/resolved_path、重复 tabs；后续完整载体落地后再验收审计恢复能力，当前日志上限不支持该保证。
- **正确性**：所有旧工具别名仍能解析；读写、命令、浏览器页面 ref、分页 cursor、失败 code 和权限边界回归通过。
- **运行效果**：记录 input_tokens、output_tokens、工具定义字符数、结果字符数、缓存命中、工具错误率和重试次数；不能只看总上下文值来归因某个工具。

## 取舍与边界

- 不把所有浏览器动作合成一个没有类型约束的 browser(action,args) 巨型工具；browser_interact 只合并语义相近动作，并用 discriminator/oneOf 保留参数约束。
- 不为压缩而删除页面 refs、错误码、分页句柄、artifact 引用和安全边界；这些字段直接影响下一步调用。
- 优先按工具语义投影，再做有界截断；当前通用字符串预览和条目采样仍有损，后续以结构化分页和完整载体替代。
- 不在每轮随机改变工具集合；能力升级必须有明确 profile revision，并记录版本。
- 审计和模型上下文使用不同序列化投影；明确记录 transport 与存储日志的省略，完整审计载体尚待实现。
