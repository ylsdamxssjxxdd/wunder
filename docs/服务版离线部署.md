# 服务版离线部署

目标：在外网机器完成所有下载与构建，把产物拷到无网服务器后 `docker compose up -d` 即可运行，不再访问外网。

## 需要联网的环节（都发生在外面）

| 环节 | 命令 | 产物 |
| --- | --- | --- |
| 构建镜像 | `docker compose -f docker-compose-x86.yml build` | `wunder-x86` 镜像（apt/pip/npm/Playwright 都在这步下载） |
| 生成 Node/Remotion 运行时 | `scripts/prepare-node-runtime.sh` | `config/runtime/<平台>/*.tar.gz`（含 Chrome Headless Shell 与 npm 离线缓存） |
| 打包离线包 | `scripts/prepare-offline-bundle.sh` | `dist/offline/`（镜像 tar + 运行时 + 前端依赖） |

这三个步骤只在有网机器执行一次；换版本时重跑对应步骤即可。

## 外网机器

```sh
# 1. 构建镜像（首次或镜像内系统依赖变化时）
docker compose -f docker-compose-x86.yml build

# 2. 生成运行时包（Node / Remotion / 浏览器 / npm 离线缓存）
scripts/prepare-node-runtime.sh                      # linux/amd64
scripts/prepare-node-runtime.sh --platform linux/arm64   # linux/arm64

# 3. 打包：镜像 + 运行时 + 前端依赖
scripts/prepare-offline-bundle.sh
```

`prepare-offline-bundle.sh` 会从 compose 文件里解析镜像清单（`wunder-x86`、`postgres`、`nginx`、`onlyoffice`、`drawio`、`node`）导出为 `images.tar`，并附带 `node_modules-linux-x86`（前端离线构建用）与 `config/runtime`。

视频项目若需要 Remotion 生态的额外依赖，默认已预取 `mediabunny`、`zod` 与同版本的 `@remotion/transitions`、`paths`、`shapes`、`layout-utils`、`noise`、`zod-types`、`captions`、`media-utils`、`motion-blur`；要再加包时覆盖即可：

```sh
scripts/prepare-node-runtime.sh --extra-deps "mediabunny @remotion/three three @react-three/fiber"
```

## 无网服务器

```sh
# 1. 导入镜像、运行时与前端依赖
scripts/load-offline-bundle.sh dist/offline

# 2. 启动（镜像已导入，compose 不会再拉取）
docker compose -f docker-compose-x86.yml up -d

# 3. 校验
docker compose exec wunder-sandbox bash -lc 'command -v remotion && node -v'
```

启动时 `docker-rust-entry.sh` 会把运行时解包到 `/opt/wunder-runtime`、把 npm 离线缓存解包到 `NPM_CONFIG_CACHE`，并注册 `PATH`/`NODE_PATH`。这些步骤全部是本地解压。

## 运行期还会联网的情形

以下几项不属于部署依赖，但确实需要网络，请按需准备：

- **模型 API**：智能体调用模型本身需要网络；内网模型请改成内网地址。
- **项目额外依赖**：项目里 `npm install` 需要包在离线缓存中；用 `npm install --offline` 安装，缺失时明确报错而不是卡在网络超时。缓存里没有的包必须在外面补进 `--extra-deps` 后重新生成运行时包。
- **远程素材与字体**：`@remotion/google-fonts`、`<Img src="https://…">`、远程音频、地图瓦片都要改为本地 `public/` 资源。
- **业务类工具**：网页搜索、网页抓取、通道（企微/飞书等）、OnlyOffice 授权校验等由各自配置决定。

## 注意

- **registry 必须一致**：npm 离线缓存按 registry 地址寻址。生成运行时包用的 `NPM_CONFIG_REGISTRY` 与容器运行时的必须相同（默认都是 `https://registry.npmmirror.com`），否则 `npm install --offline` 会报 `ENOTCACHED`。改源后需要重新生成运行时包。
- 服务器与运行时包必须同架构：`linux-x64` 对应 amd64，`linux-arm64` 对应 arm64。x86 机器可以用 qemu 生成 ARM 包（`--platform linux/arm64 --image <arm64 镜像>`，实测约 11 分钟），也可以直接在 ARM 机器上生成。
- ARM 运行环境需要 Chrome 共享库（`libnss3`、`libnspr4`、`libgbm1`、`libasound2` 等）；正式镜像由 Dockerfile 的 `playwright install --with-deps` 提供，精简基础镜像需要自行补齐。
- `WUNDER_SANDBOX_DOCKER_READ_ONLY=true` 会让 `/opt/wunder-runtime` 不可写，运行时无法解包，需要保留可写层。
- 镜像与运行时都按 glibc 2.36（Debian bookworm）构建；服务器内核与 Docker 版本需支持对应平台。
- 离线包体积可观（镜像十几 GB、运行时约 320 MB、前端依赖数百 MB），拷贝前确认目标磁盘。
