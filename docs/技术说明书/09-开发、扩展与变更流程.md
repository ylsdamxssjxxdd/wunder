# 开发、扩展与变更流程

各节按「落点清单 → 必须写明的东西 → 不要做什么」组织。术语与分层见 [01](./01-系统总览与术语.md)、[02](./02-仓库结构与模块职责.md)。

## 1. 开发原则

- **先判职责再选目录**，不按调用方便跨层写；跨形态类型进 `wunder-core`，执行语义进 `orchestrator`，领域逻辑进 `services`。
- **不在超大文件里继续堆功能**：新增能力拆新文件，`web/app.js`、`MessengerView.vue` 这类装配文件只做装配。
- **durable 写入只有一条路**：线程日志一律经 `crates/wunder-runtime/src/orchestrator/thread_log_committer.rs`，不在别处拼 change cursor、不在事务前唤醒 hub。
- **性能是默认要求**：见 §10 红线。任何列表、日志、面板都要满足分页、有界、不做全量重算。
- **关键逻辑写英文注释**，面向用户的文案走 i18n。
- **文档同步**：接口变化同步 `docs/API文档.md`，边界变化同步 `docs/设计文档/`，运行/改动口径变化同步本说明书，功能迭代记 `docs/功能迭代.md`（§9）。
- **证明归档**：形式化模型、配置、反例、结果摘要及复验说明统一放在 [`docs/形式化证明/`](../形式化证明/README.md) 对应主题，更新总索引与必做清单；复验脚本读取该目录，临时报告与 TLC 工作状态放仓库外。

## 2. 新增接口

```
crates/wunder-runtime/src/api/<域>.rs        路由 + handler（薄）
crates/wunder-runtime/src/services/<域>.rs   业务逻辑
crates/wunder-runtime/src/api/mod.rs         在 build_router 里 .merge(<域>::router())
docs/API文档.md                               更新接口事实
```

约定：

- 路径前缀统一 `/wunder/<域>/...`，管理面 `/wunder/admin/...`，用户自建能力 `/wunder/user_tools/{mcp|skills|knowledge}`，内置 MCP 服务端 `/wunder/mcp`。示例：`/wunder/chat/sessions/{session_id}/messages`。
- 鉴权与语言在中间件层统一处理（`api_key_guard`、`language_guard`、CORS、trace、静态缓存与 panic 守卫，见 `crates/wunder-server/src/main.rs:121-133`），handler 里不重复实现。
- 返回体是**展示读模型**时，走 `wunder-core/src/thread_view.rs` 的分页与预算契约，不在 handler 里现算全量历史。
- 路由文件不写业务逻辑；舰体形态的静态资源与中间件接线在 `crates/wunder-server/src/main.rs`，不在这里加接口。

不要：在 `crates/wunder-server/src/main.rs` 里加路由；改接口不更新 API 文档。

## 3. 新增工具

```
crates/wunder-runtime/src/services/tools/<tool>.rs   实现
crates/wunder-runtime/src/services/tools/catalog.rs  ToolSpec 注册（name / description / input_schema）
crates/wunder-runtime/src/services/tools/dispatch.rs 内置工具分支
crates/wunder-runtime/src/services/tools/registry.rs ToolDescriptor：kind / parallel_safe / arg_aliases
crates/wunder-runtime/src/services/default_tool_profile.rs 是否默认启用、是否桌面隐藏
docs/API文档.md、docs/技术说明书/05-*.md             更新说明
```

必须明确（缺一项就不要合）：

| 项 | 落在哪 | 说明 |
| --- | --- | --- |
| 规范名与别名 | `catalog.rs`（`resolve_tool_name` 归一） | 模型侧规范名多为中文；英文别名要一并给出 |
| 影响分档 | `registry.rs` 的 `ToolKind::{Read, Write, Exec, Control}` | 决定 `core::exec_policy` 的审批与风险归档；只读工具才可能并行 |
| 并行性 | `registry.rs` 的 `parallel_safe`，被 `orchestrator/tool_parallel.rs:43` 读取 | 并行度上限见 `orchestrator/constants.rs:39` `DEFAULT_TOOL_PARALLELISM` |
| 参数别名 | `registry.rs` 的 `arg_aliases`，由 `tools/pipeline.rs` 回填 | 只做「缺省才补」，不改写已给的主键 |
| 可用性门槛 | `services/agent_abilities.rs`、`default_tool_profile.rs` | 需要 vision / 桌面模式 / 外部配置的工具要能被过滤掉 |
| 超时与错误模型 | `orchestrator/execute_tools.rs` 编排；`tools/tool_error.rs` | 默认 LLM/工具超时见 `orchestrator/constants.rs`（120s） |
| 宿主能力 | `tools/capabilities.rs`（能力 seam） | 工具只依赖 trait，不直接耦合本地/沙箱/远程实现 |

不要：往 `services/tools.rs`（re-export 壳）堆实现；只改 `orchestrator/tool_exec.rs` 就当工具已注册；把展示裁剪（`services/tool_result_display.rs`）当模型输入裁剪（`orchestrator/execute_tools.rs` 的 `finalize_tool_result`）——两条通道，见 [11 工具结果裁剪与观测链路](./11-工具结果裁剪与观测链路.md)。

## 4. 新增渠道

```
crates/wunder-runtime/src/channels/<name>.rs      实现 ChannelAdapter（adapter.rs:30）
crates/wunder-runtime/src/channels/registry.rs    进 build_default_channel_adapter_registry()
crates/wunder-runtime/src/channels/catalog.rs     加 ChannelCatalogItem（display_name / webhook_mode / docs_hint）
crates/wunder-runtime/src/api/channel.rs          webhook 接线（已有泛型 /wunder/channel/{provider}/webhook）
config/wunder.yaml                                channels 段（:793）
```

必须处理：inbound 队列（`inbound_queue.rs`）、outbox 与重试（`outbox.rs`）、限流（`rate_limit.rs`）、媒体与附件（`media.rs`、`outbound_attachments.rs`）、运行日志（`runtime_log.rs`）、工作区路由（`workspace_routing.rs`）。

不要：在 `api/channel.rs` 里写收发细节；为单个渠道另造一套会话与绑定存储（用 `ChannelBindingRecord` / `ChannelUserBindingRecord` / `ChannelSessionRecord`）。

## 5. 新增存储方法与表

```
crates/wunder-core/src/storage_backend.rs    分域 trait 加方法（契约在核心）
crates/wunder-runtime/src/storage/sqlite/<域>_store.rs
crates/wunder-runtime/src/storage/postgres/<域>_store.rs   ← 两侧同名成对，必须同时实现
crates/wunder-runtime/src/storage/sqlite/schema_*.sql / postgres/schema.rs  角色/控制面建表
```

- 先确定数据是 canonical 原件、可重建投影还是不可丢弃业务状态，再修改对应 schema；角色 SQLite 使用干净初始定义，本次无旧单体库兼容迁移。PostgreSQL 控制面有 schema 指纹，不能与投影水位混用。
- 记录类型放 `crates/wunder-core/src/storage_records.rs`，常量放 `crates/wunder-core/src/storage_constants.rs`；`storage/backend.rs` 只是 re-export。
- 新域要同时过 feature 门控：`sqlite-storage` / `postgres-storage`（选型见 `storage/factory.rs:8-17`）。
- 落库前必须有界：canonical policy 负责语义与输出限制，writer 同时限制命令数与字节；诊断只保存有限计量事实，不另存完整工具输出。

不要：只实现一侧就合并；在同步线程里做长阻塞 IO（用 `core/blocking.rs` 或 `core/long_task.rs`）；绕过 `thread_log_committer.rs` 直写 `thread_items`。

## 6. 新增实时事件或展示字段

```
orchestrator/event_stream.rs            发射（实时 delta 与 canonical 完成态分离）
orchestrator/thread_log_committer.rs    应用事件适配到统一 ThreadStore
services/thread_change_feeder.rs        读侧：每页 200、通道 256，空闲等待提交信号
wunder-core/src/thread_view.rs          展示读模型契约（分页/预算常量在这里）
storage/thread_history.rs               rollout 完成态投影与有界预览；canonical_thread_log.rs 统一查询适配
api/chat_ws.rs / *_ws.rs                WS 接线
frontend/src/realtime/ 或 frontend-slint/src/native_*.rs   消费
```

必须写清：事件是否有 durable 语义、断线 replay 与补水怎么恢复、慢客户端水位（`orchestrator/constants.rs` 的 `STREAM_EVENT_SLOW_CLIENT_QUEUE_WATERMARK`）。

不要：在单个 WS 路由里私造状态机；把 `thread_change_hub.rs publish` 当状态广播（它只是唤醒信号）；把执行快照（`orchestrator/runtime_snapshot.rs`、`services/chat_runtime_projection.rs`）当分页契约。

## 7. 新增前端能力

| 目标 | 落点 | 约束 |
| --- | --- | --- |
| 蜂巢（`frontend/`，Vue 3 + TS） | 页面编排 `src/views/messenger/sections/`、组件 `src/components/messenger/` 与 `src/components/chat/`、实时 `src/realtime/`、状态 `src/stores/`、请求 `src/api/`、文案 `src/i18n/messages/` | 列表与日志必须分页/限量；不往 `MessengerView.vue` 堆 |
| 蛹（`frontend-slint/`，Rust + Slint） | `ui/*.slint` 界面 + `src/native_*.rs` 接 `crates/wunder-desktop` 的强类型 façade；本地能力放 `crates/wunder-desktop/native_*.rs` | Markdown 走最低必要能力，流式连续性优先；按帧合并增量、事件缓冲有界；能用官方标准控件就用 |
| 舰桥（`web/`，原生 HTML + JS） | 业务模块 `web/modules/`、样式 `web/styles/`、共享小工具 `web/shared/` | 表格/日志/监控面板必须分页；确认框不能替代后端鉴权 |

**不要基于 Electron 或 Tauri 开发**：Electron 全仓零残留；Tauri 只剩死链（`crates/wunder-desktop/scripts/build-win7.ps1` 读 `tauri.conf.json`，而仓库内既无 `tauri.conf.json` 也无 `src-tauri`，脚本必然失败）。正确落点：桌面壳与本地能力 → `crates/wunder-desktop/` + `frontend-slint/`；Web 用户端 → `frontend/`；治理端 → `web/`。

## 8. 构建与验证命令

### 8.1 Rust 日常（64 位链）

日常开发与回归用 64 位 toolchain，不要依赖当前默认的 i686 链。本机默认是 `1.95.0-x86_64-pc-windows-msvc`（`rustup show active-toolchain`）。

```bash
cargo fmt --all
cargo +1.95.0-x86_64-pc-windows-msvc check --lib -j 8                      # 只检引擎库
cargo +1.95.0-x86_64-pc-windows-msvc check -p wunder-runtime --lib -j 8     # 单 crate 库
cargo +1.95.0-x86_64-pc-windows-msvc check -p wunder-server -j 8            # 舰体（默认 postgres-storage）
cargo +1.95.0-x86_64-pc-windows-msvc check -p wunder-desktop -j 8           # 蛹后端（默认 sqlite-storage + web-fetch）
cargo +1.95.0-x86_64-pc-windows-msvc check -p wunder-cli -j 8               # 舵机（默认 sqlite-storage）
cargo +1.95.0-x86_64-pc-windows-msvc clippy --lib -j 8                      # 必要时
```

跑测试要显式带 feature：`crates/wunder-runtime/Cargo.toml` 里 28 个 `[[test]]` 多数 `required-features = ["sqlite-storage"]`，不带 feature 会被跳过而不是失败，容易误判为「测试通过」。

```bash

cargo +1.95.0-x86_64-pc-windows-msvc test -p wunder-runtime --features sqlite-storage --lib -j 8
```

集成测试在 `crates/wunder-runtime/tests/`（29 个文件：路由契约、互通、cron、gateway、记忆、吞吐模型等）。大范围删改后先跑分诊再跑 cargo：

### 8.4 分发构建

```bash
build.bat -t desktop|cli -a linux-arm64|linux-amd64|win7-x86   # → builders/build.ps1
build.sh  -t desktop|cli -a ... [--native|--docker]            # → builders/build.sh
build.bat -All                                                  # 主机构建的全部发行版
```

Linux 入口按 `uname -m` 自动选择离线 SDK：ARM64 主机用 `Rust-builder/kylin-arm` 原生构建全部目标；x86_64 主机用 `Rust-builder/kylin-x86`，其中 linux-amd64 原生构建，linux-arm64 与 win7-x86 通过 SDK 的交叉工具链构建。`--docker` 固定使用 ARM64 Ubuntu 18.04 镜像并读取 `kylin-arm`，与宿主架构无关。目标与参数以 `builders/build.ps1:2-4`、`builders/build.sh` usage 为准：Linux 桌面产物是 AppImage（Ubuntu 18.04/glibc 2.27 基线），CLI 是 ELF；`win7-x86` 用 `i686-win7-windows-gnu` + `-Z build-std`，并做 PE 位数与 Win7 不支持导入的门禁。Win7 专用链见 `builders/build-win7-slint.ps1`、`builders/build-win7-offline.ps1`。**32 位产物不能用日常 64 位命令代替验收**，且 Win7 真机验证不能由当前主机结果替代。

## 9. 变更记录口径

```bash
python scripts/update_feature_log.py --type <类型> --scope <范围> "记录内容"
```

- `--type` 白名单（脚本 `CATEGORY_ORDER`）：**新增 / 变更 / 修复 / 性能 / 文档 / 重构 / 安全 / 工程 / 测试 / 移除 / 弃用**，默认「变更」；英文别名会被归一（`fix`→修复、`perf`→性能、`infra`/`build`/`tooling`→工程）。
- `--scope` 可重复或逗号分隔（如 `backend,docs`）；`--date YYYY-MM-DD` 指定日期；`--path` 默认 `docs/功能迭代.md`；重复内容需 `--force`。
- 一次任务一条，写「做了什么 + 影响面」，不写实现细节；性能类要带可核对的口径（分页大小、上限、耗时）。

## 10. 性能红线

改动自查与验收回查使用同一口径。数值都有出处，改数值要同时改文档。

| 红线 | 当前口径与出处 |
| --- | --- |
| 列表必须分页且有上限 | 聊天页 12（上限 20）、轨迹页 80（上限 100）：`wunder-core/src/thread_view.rs:5-8`；线程目录 `MAX_PAGE_SIZE = 100`：`services/thread_catalog.rs:16` |
| 响应有字节预算 | 聊天 128KB、轨迹 192KB、正文分块 8192B：`wunder-core/src/thread_view.rs:9-11` |
| 搜索扫描有界 | 目录搜索 10 页 × 100 条 = 1000 条上限：`services/thread_catalog.rs:17-21` |
| 队列与缓冲必须有界 | 变更喂给每页 200、通道容量 256：`services/thread_change_feeder.rs:19-24`；事件队列 256：`orchestrator/constants.rs:26`；工作区单写队列 2048：`services/workspace.rs:40`；Slint 原生事件通道 128 |
| 不做全量重算 | rollout 追加后增量投影，列表使用预览/写时计数与 keyset 分页；恢复和重建显式触发、有界推进；空闲不 discovery、polling 或后台重建 |
| 缓存必须有界 | 工作区树缓存 TTL 5s、树 320 行、单目录 120 条：`services/workspace.rs` |
| 不长时间持锁 | 会话锁 TTL 120s、心跳 5s、忙等指数退避（上限 3s）：`orchestrator/constants.rs:14-25`；锁与状态按任务线程隔离 |
| 治理必须有上限 | 轮次上限、日配额、重试熔断、流式空闲看门狗、工具预算见 `orchestrator/{quota,retry_governor,stream_timeout,execute_support}.rs` 与 `constants.rs`；活跃会话受 `server.max_active_sessions` 约束（Rust 默认 300，仓库实配 4：`config/wunder.yaml:23-29`） |
| 前端不做逐 token 重建 | 按帧合并增量（约 16–33ms 刷新节奏）、完成块稳定、历史限量加载；见 `AGENTS.md` 蛹条目 |

## 12. 做错回哪儿查

| 症状 | 先查 |
| --- | --- |
| 时间线出现两条同轮次回复、刷新后正文重复 | 是否新增了一次模型轮次（`orchestrator/execute.rs:435`）或改了 `{turn_id}:text-{model_round}` 的 id 规则 |
| 前端卡在「输出中」、刷新后内容补齐 | 是否绕过 `thread_log_committer.rs`，或提交前就 publish 了 hub cursor |
| 提示词每轮被改写、缓存失效 | 是否在没有复用已存 prompt 的分支里重新组装（唯一落点 `orchestrator/prompt.rs`） |
| 长会话首屏慢、内存飙升 | 是否用执行快照当分页、是否全量重算投影（§10） |
| 新工具模型看不见 | `catalog.rs` 是否注册、`default_tool_profile.rs` 是否默认/隐藏、可用性门槛是否被过滤 |
| `cargo test` 一片「通过」但行为没变 | 是否漏了 `--features sqlite-storage`（§8.1） |
| 本地形态多开了端口 | 是否误走 bridge 路径；默认应是同进程 `NativeDesktop`（`crates/wunder-desktop/native.rs`） |
| 蜂群字样又出现了 | §11 残留清单，属未清理文案而非能力回归 |
