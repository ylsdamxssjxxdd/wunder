# 舵机实测验收（2026-10-16）

舵机是手工本地操作入口。本次通过 `build.bat -t cli -a win7-x86 -Jobs 4` 构建 Win7 兼容的 32 位发布文件，在 Windows 11 x64 上实际执行；Win7 系统与 Ubuntu 18.04 系统本身未参与运行验收。

模型使用用户指定的 OpenAI 兼容服务与 `Qwen/Qwen3.8-27B`，隔离用户配置、SQLite 和工作目录，不继承日常模型或云登录状态。服务凭据仅用于本地临时配置，不记录于报告、测试代码或版本库。模型轮次上限设为 64，以容纳多次工具执行和错误恢复。

## 已复现并修复的问题

1. **互通常量未导入导致构建失败**：补齐协议常量导入；后续并行修改新增公开导出后，补齐文件锁模块、结构体与方法的可见性，保持现有集成测试入口可编译。
2. **新建线程后下一条输入退出 TUI**：`/new` 原先更换线程标识，却继续使用旧线程的占用租约。改为先取得新线程租约，再切换状态并释放旧租约。
3. **流式文本空白与重复内容丢失**：推理增量被逐块 trim，正文丢弃纯空白，文本重叠算法将合法重复 token 当作重放。增量按原字节追加，重放按既有事件身份去重，完整快照保持独立处理。
4. **SQLite 增量统计失败**：UPSERT 的 `excluded` 必须引用目标列 `tool_records` / `chat_records`，不能引用 SELECT 别名 `delta_records`；修复两条语句，并覆盖首次增量、已有汇总更新和重复对账。
5. **快捷键提示与行为不一致**：空草稿输入 `?` 打开帮助；已有草稿中的问号正常作为文字输入。
6. **终端历史插入后短暂空白**：`insert_before` 清除内联视口后主动请求重绘，避免等待下一次按键、流事件或租约心跳。
7. **Windows 多行粘贴误发送**：旧控制台可能将粘贴拆成普通按键事件；连续快速字符后的即时 Enter 作为换行，输入停顿后的 Enter 正常发送；实测 Windows 将粘贴中的 LF 编码为 Ctrl+Enter，亦按换行处理，覆盖短行。
8. **JSONL 工具条目标识重复**：原编号取自当前未完成列表长度，工具结束后会重复使用。改用单调序号，命令条目亦使用独立单调序号。

## TUI 检查方法与边界

使用 Windows ConPTY 驱动真实发布程序，发送按键、粘贴和窗口大小变化；捕获实际终端输出并解析为字符单元，保存状态快照。检查 120×36、80×24、50×18 尺寸，以及计划、工具、线程轨迹、任务中心、新建线程、恢复和中断操作。

首次空闲测量：首屏约 0.25 秒，工作集约 27 MiB，连续 3 秒 CPU 时间增量与输出字节均为 0。该结果属于当前机器的暖启动测量，不代表 Win7 或所有首次启动环境。

验收脚本以持久线程完成状态和程序输出共同判定完成，不能仅匹配用户提示词或思考文本中的结束标记。多行粘贴、帮助和新线程操作需实际驱动入口，不能仅用测试夹具直接设置内部字段。

## 修复版复测

第一版修复构建成功，新增 5 项舵机回归和 1 项 SQLite 回归通过；既有事件输出 7 项、文本与状态处理 51 项通过。真实 JSONL 复测约 51 秒，实际进行 6 次工具调用，18 项项目测试通过，7 个开始条目标识互不重复，正常输出 `turn.completed`，stderr 为零。

独立发布复测通过：冷初始化约 623 ms，热启动约 161 ms，三组双进程冷初始化约 501–537 ms，均无 stderr。该指标为配置命令完成时间，不是首屏时间。

首轮修复版终端复测验证了帮助与新线程租约，但随后发现粘贴 LF 被编码为 Ctrl+Enter；原断言仅检查屏幕文字，无法排除半条消息已提交，故该轮不计完整 TUI 通过。已增加真实控制台事件诊断、Ctrl+Enter 回归，并用持久会话数量检查粘贴不得创建消息。

发布版核心流程另行完整复测通过（避开尚未重新打包的多行粘贴路径）：依赖排序项目约 237 秒，生成 16 项测试全部通过，10 项独立用例通过，包含 5000 节点链；随后轨迹、详情页签、任务中心、新建线程、恢复列表、Esc 中断、状态查看和退出均成功，进程正常结束。任务期间工作集峰值约 42 MiB。构建高负载下首屏曾达约 8 秒，因此不能将暖启动的亚秒结果视为所有运行条件的保证。

终端单元重建图与原始字符输出一并检查：主输入、实时进展和错误恢复可用；轨迹台账较密集，部分类型仍显示 `tool_message` 和 JSON 摘要，Markdown 表格保留为文本，可读性仍有改进空间。它们不影响工具执行，但不宜据此评价为交互已完全打磨。

窗口缩放单独复测时，80×24、50×18 和恢复 120×36 均正确重绘；初次捕获中部分空白随终端异步缩放的时序变化而变化，后续验收延长稳定时间再断言，不将单张过早快照视为程序异常。
