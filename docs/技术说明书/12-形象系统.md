# 形象系统

## 1. 概述

形象系统（Companion System）是 wunder 蜂窝（desktop）与蜂巢的视觉陪伴层，通过精灵动画形象在界面上提供陪伴组件。形象系统独立于引擎运行，只作为前端渲染层存在，不影响后端执行链路。

## 2. 核心概念

### 2.1 形象包（Companion Package）

形象包是一个 ZIP 压缩文件，包含：

| 文件 | 说明 |
| --- | --- |
| `pet.json` | 清单文件，定义 id、displayName、description、spritesheetPath |
| `{spritesheetPath}` | 精灵表图片，支持 WebP/PNG/GIF/JPEG |

**清单示例：**

```json
{
  "id": "cat-assistant",
  "displayName": "小助手",
  "description": "一只可爱的小猫形象",
  "spritesheetPath": "spritesheet.webp"
}
```

### 2.2 形象作用域

| 作用域 | 存储位置 | 管理方式 |
| --- | --- | --- |
| `global` | 舰体（server）`config/data/companions/global/` | 管理员上传，所有用户可见 |
| `private` | 浏览器 IndexedDB | 用户自行导入，仅本地可用 |

### 2.3 精灵状态

形象支持以下动画状态：

| 状态 ID | 触发场景 |
| --- | --- |
| `idle` | 默认静止状态 |
| `running` | 智能体执行中 |
| `running-left` | 拖拽向左移动 |
| `running-right` | 拖拽向右移动 |
| `waving` | 点击形象 |
| `jumping` | 智能体执行完成 |
| `failed` | 智能体执行失败 |
| `waiting` | 等待用户确认 |
| `review` | 展示消息气泡 |

## 3. 架构设计

### 3.1 前端组件

```
frontend/src/
├── stores/companions.ts              # 形象状态管理
├── components/companions/
│   ├── CompanionFloatingLayer.vue    # 浮层容器
│   └── CompanionSprite.vue           # 精灵渲染
└── utils/companionPackage.ts         # 包解析工具
```

### 3.2 后端服务

```
src/
├── services/companions.rs            # 形象包管理服务
└── api/companions.rs                 # HTTP 接口
```

### 3.3 数据流

```
用户导入形象包
    ↓
前端解析 ZIP → 提取精灵表 → 存储（网页：IndexedDB；蜂窝：本地形象目录）
    ↓
用户选择形象 → 网页写入 localStorage，蜂窝写入智能体 icon 配置
    ↓
渲染：网页 CompanionFloatingLayer / 蜂窝原生分层窗口
    ↓
监听智能体运行状态 → 切换精灵动画
```

## 4. API 接口

### 4.1 获取全局形象列表

```
GET /wunder/companions/global
```

**响应：**

```json
{
  "data": {
    "items": [
      {
        "id": "cat-assistant",
        "display_name": "小助手",
        "description": "一只可爱的小猫形象",
        "spritesheet_path": "spritesheet.webp",
        "spritesheet_mime": "image/webp",
        "spritesheet_url": "/wunder/companions/global/cat-assistant/spritesheet?v=1715049600",
        "imported_at": 1715049600.0,
        "updated_at": 1715049600.0
      }
    ]
  }
}
```

> 列表接口返回 `CompanionSummary`，不再内嵌 `spritesheet_data_url`；精灵表通过 URL 引用。data URL 仅存在于单条详情 `GET /wunder/companions/global/{id}` 的 `CompanionRecord`。

### 4.2 下载形象包

```
GET /wunder/companions/global/{id}/package
```

返回 ZIP 文件流。

### 4.3 管理员接口

```
POST   /wunder/admin/companions                  # 上传形象包
GET    /wunder/admin/companions/{id}             # 形象详情
PATCH  /wunder/admin/companions/{id}             # 更新元信息
DELETE /wunder/admin/companions/{id}             # 删除形象
GET    /wunder/admin/companions/{id}/spritesheet # 精灵表文件
GET    /wunder/admin/companions/{id}/package     # 下载形象包
```

（旧 `POST/PUT/DELETE /admin/companions/global(/{id})` 已废弃：无 `/global` 段，更新方法改为 PATCH。）

## 5. 前端状态管理

### 5.1 Store 结构

```typescript
interface CompanionSettings {
  selectedId: string;        // 当前选中的形象 ID
  enabled: boolean;          // 是否启用形象
  position: { x: number; y: number };  // 屏幕位置
  scale: number;             // 缩放比例 (0.5 ~ 1.6)
  messageHintsEnabled: boolean;  // 是否显示消息气泡
}

interface AgentCompanionOverride {
  show?: boolean;            // 该智能体是否显示形象
  scale?: number;            // 该智能体的形象缩放
  updatedAt: number;
}
```

### 5.2 智能体关联

智能体可通过 `icon` 字段配置形象：

```json
{
  "icon": {
    "kind": "companion",
    "scope": "global",
    "id": "cat-assistant",
    "show": true,
    "scale": 1.0,
    "messageHints": true
  }
}
```

## 6. 蜂窝集成

默认蜂窝（`frontend-slint/`，Rust + Slint，无 WebView）用操作系统级分层窗口渲染动态形象，行为对齐网页版浮层。

### 6.1 为什么不走 Slint 窗口

vendored 的 winit 后端在软件渲染路径上把 `set_transparent()` 实现为空操作，Slint 侧拿不到每像素 alpha 的透明窗。形象浮窗因此不经过 Slint 窗口体系，由一条独立的原生窗口线程持有，不依赖 DWM，也不引入浏览器渲染链。

### 6.2 模块划分

| 文件 | 职责 |
| --- | --- |
| `frontend-slint/src/companion_sprite.rs` | 精灵表解码、按行动画常量（行号/帧数/时长与网页状态表一致）、帧缓存与整表缓存（有界、引用感知） |
| `frontend-slint/src/pet_window/mod.rs` | 平台无关的浮窗契约：`PetCommand`、`PetEvent`、`PetVisual`、`PetService` |
| `frontend-slint/src/pet_window/win32.rs` | Windows 分层窗口：独立线程消息循环、`WS_EX_LAYERED` + `UpdateLayeredWindow(ULW_ALPHA)`、双线性放大与预乘、GDI 文本排版生成气泡遮罩、本地拖拽与系统右键菜单 |
| `frontend-slint/src/companion_pet.rs` | 悬浮形象控制器：资格判定、状态机、位置/缩放夹紧、气泡文本裁剪、菜单与事件回读、与网页一致的防抖 |
| `crates/wunder-desktop/native_companion_overlay.rs` | 桌面侧持久化：`companion.overlay.json`，位置、每智能体 show/scale 覆写、消息气泡开关 |

### 6.3 线程与数据流

- 浮窗线程拥有全部形象窗口：每窗约 30ms 帧时钟、合成、拖拽与命中判定。全透明像素天然点击穿透，形象轮廓即命中区，无需额外命中测试。
- UI 线程只做投影差分：约 120ms 的 `slint::Timer` 排空事件、比较形象身份串，只有变化的对象才下发 `Present` / `Update` / `Move`；命令经 `PostThreadMessageW(WM_APP, …)` 传递，是有界的小值。
- UI 线程不持有像素缓冲。整表 RGBA 每形象一份，缓存容量有界且带引用计数保护，正在显示的表面不会被淘汰；没有精灵表的形象按固定退避重试，不每帧重复解码。
- 会话打开、菜单选择等回调可能重入控制器，因此事件处理与重投影分离，Slint 调用在借用释放之后执行。

### 6.4 与网页版的行为对齐

| 维度 | 桌面实现 |
| --- | --- |
| 资格 | `icon.kind == "companion"` 且形象存在；`effectiveShow = override.show ?? config.show` |
| 身份键 | `agentId:scope\|\|global:id\|\|name` |
| 缩放 | 覆写优先；菜单与存储夹 0.5~1.6，渲染层再夹 0.5~1.8 |
| 默认位置 | 阶梯 `(28 + (i % 4) * 46, 28 + floor(i / 4) * 34)`，按工作区边框夹紧后取整 |
| 动画行 | idle / running-right / running-left / waving / jumping / failed / waiting / running / review，逐帧时长 = 时长 / 帧数 |
| 临时态优先级 | 点击 → waving 700ms；拖拽 → running-left/right；拖拽结束 → waiting 900ms；完成 → jumping 直到该轮被确认 |
| 运行状态 | 由会话行状态归一为 idle/done/error/pending/running，按优先级仲裁；当前会话的 running/error 覆盖智能体级判定 |
| 气泡 | 消息提示 3200ms、96 字截断（含省略号）、Markdown 降级为纯文本；无消息时用名称气泡 1800ms；每个会话首次观测到的气泡不弹跳 |
| 右键菜单 | 打开会话（1200ms 防抖）/ 显示·隐藏 / 尺寸预设，预设只写本地覆写不改智能体配置 |
| 生命周期 | 删除形象或重新绑定设置时清理浮窗与本地覆写；`--native-smoke` / `--native-restore` 不启动浮窗线程，避免截图比对抖动 |

Linux 暂无等价的每像素 alpha 浮窗实现，`pet_window::available()` 返回 false 时控制器只维护数据投影而不创建窗口。

### 6.5 Tauri 桥接（遗留）

> Tauri/WebView 壳已停止日常维护，本节仅适用于遗留壳客户端。默认蜂窝（frontend-slint，Slint 原生、无 WebView）没有本节桥接，也无独立浮窗形象层。

蜂窝通过 `wunderDesktop` 全局对象与前端通信：

```typescript
interface DesktopCompanionBridge {
  showCompanion(payload: CompanionState): Promise<boolean>;
  updateCompanion(payload: CompanionState): Promise<boolean>;
  hideCompanion(payload?: { persistEnabled?: boolean }): Promise<boolean>;
  getCompanionState(): Promise<CompanionSettings>;
  onCompanionStateChanged(callback: (state: CompanionSettings) => void): () => void;
}
```

### 6.6 状态同步（遗留壳）

- 前端 → 桌面：通过 `showCompanion` / `updateCompanion` / `hideCompanion` 推送
- 桌面 → 前端：通过 `onCompanionStateChanged` 监听并应用

默认蜂窝不使用该桥接：形象投影、浮窗渲染与状态持久化都在同一进程内完成，不经本机 HTTP/WebSocket。

## 7. 安全约束

1. **包大小限制**：ZIP 包最大 24MB，精灵表最大 18MB
2. **路径安全**：禁止 `..` 路径穿越，禁止绝对路径
3. **ID 规范化**：仅保留字母、数字、下划线、连字符
4. **文本长度**：displayName 最大 80 字符，description 最大 240 字符
