# 系统总览与术语

## 1. 系统定位

wunder 是一个面向组织与个人的智能体调度系统。三种运行形态共享同一套引擎（wunder-runtime）与核心（wunder-core）：

| 形态 | 入口 | 场景 |
| --- | --- | --- |
| `wunder-server` | 舰体 | 服务端，多租户、多用户、多渠道、组织级部署 |
| `wunder-desktop` | 蜂窝 | 桌面应用，个人用户主推形态，本地即用 |
| `wunder-cli` | 舵机 | 命令行，脚本化、批处理、自动化流水线 |

三种形态背后是同一段代码，分两层，蜂窝与舵机不依赖舰体：

| 代码层 | 中文名 | 职责 |
| --- | --- | --- |
| `wunder-core` | 核心 | 配置、鉴权、存储契约、执行策略等基础设施 |
| `wunder-runtime` | 引擎 | orchestrator、线程运行时、工具、渠道、网关等执行链路 |

舰体（`wunder-server`）在引擎之上叠加多租户与云端服务能力，是引擎的主要宿主；蜂窝与舵机直接对接引擎，不经舰体。

wunder 的立足点不是聊天，而是**可持续执行的智能体运行时**。所有入口最终都落到统一的线程运行时、工具治理、投影发布和存储抽象上。

## 2. 核心能力

| 能力 | 职责 | 主要代码 |
| --- | --- | --- |
| 智能体运行时 | 线程生命周期、turn 执行、prompt 冻结、上下文管理、工具治理、恢复链 | `crates/wunder-runtime/src/orchestrator` `crates/wunder-runtime/src/services/runtime` |
| 实时投影 | 面向前端和外部观察者的状态发布层 | `crates/wunder-runtime/src/services/presence` `crates/wunder-runtime/src/services/runtime` |
| 工具化能力 | 文件、命令、浏览器、MCP、技能、A2A | `crates/wunder-runtime/src/services/tools` `crates/wunder-runtime/src/orchestrator/tool_exec` |
| 多入口接入 | HTTP、WebSocket、gateway、channels、desktop、CLI | `crates/wunder-runtime/src/api` `crates/wunder-runtime/src/gateway` `crates/wunder-runtime/src/channels` |

## 3. 对象模型

wunder 围绕以下核心对象构建：

```
用户 (User)
 ├── Agent                    — 每用户唯一实例，由预设绑定生成角色、提示词、工具面、模型设置
 │    └── Thread × N          — 单智能体连续执行上下文
 │         ├── 用户轮次 × N   — 一次用户输入到最终回复
 │         │    └── 模型轮次 × N — 一次模型 API 调用
 │         ├── Subagent × N   — 任务中临时派生的子智能体，任务结束回收
 │         └── Checkpoint × N — 可恢复的执行截面
 │
 ├── Workspace                — 智能体读写的文件与目录；云端为每用户唯一目录
 ├── Memory                   — 跨线程的长期记忆
 └── Knowledge                — 检索型知识资料
```

## 4. 术语表

以下术语在技术文档中使用时有严格含义，不应混用：

| 术语 | 定义 | 常见错误理解 |
| --- | --- | --- |
| **Thread** | 单智能体的连续执行上下文，跨越多轮对话 | ≠ session id，≠ 数据库行 |
| **用户轮次** (User Round) | 用户发来一次输入，到智能体产出最终回复的全过程 | ≠ 一条消息，≠ 一次模型调用 |
| **模型轮次** (Model Round) | 模型一次 API 调用 + 输出解析 | 一轮用户轮次可包含多轮模型轮次 |
| **Turn** | 当代码中使用时，通常指一轮用户轮次 | ≠ 单条消息 |
| **TurnState** | orchestrator 中用户轮次的执行状态机 | 包含 pending / running / completed / failed |
| **Tool Surface** | 当前线程当前模型可见的工具集合 | ≠ 系统全部工具 |
| **Subagent** | 主智能体在任务中临时创建的工作单元，任务结束即回收 | ≠ 独立智能体，≠ 用户拥有的第二个智能体 |
| **Orchestrator** | wunder 的智能体执行调度引擎，管理 turn / prompt / context / tools 全链路 | ≠ 简单路由器 |
| **Companion** | 形象系统中的精灵动画形象，前端视觉陪伴层 | ≠ 智能体本身，≠ 后端运行时组件 |
| **Companion Package** | 形象包，包含精灵表和清单的 ZIP 文件 | ≠ 单张图片 |
| **Goal** | 目标态系统中的任务目标，绑定到会话的长期任务描述 | ≠ 简单的待办事项 |
| **Goal Continuation** | 目标延续，智能体自动继续执行直到目标完成 | ≠ 简单的循环调用 |

## 5. 硬约束

技术实现必须长期遵守：

1. **Prompt 冻结** — 线程首次确定 system prompt 后冻结，后续用户轮次不得改写。
2. **记忆单次注入** — 长期记忆只在线程初始化时注入一次，后续通过工具检索。
3. **投影单向消费** — 前端和外部观察者只能消费投影，不能反向篡改后端运行态。

## 6. 产品边界

- `server / desktop / cli` 是同一系统的三种运行形态，不是三套独立产品。
- 前端页面是投影消费层，不是运行时真相源。
- 技能是能力组织方式，不是引擎原语。
- MCP 是外部资源接入机制，不是独立运行时。
