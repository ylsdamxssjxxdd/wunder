# 视频制作技能运行环境

`视频制作`是一个技能说明与流程包。Windows 补充包现在同时携带可离线使用的通用 Node.js 和锁定的 Remotion 运行时；Chromium 和视频素材仍按任务与系统单独准备。

补充包布局如下：

| 路径 | 内容 |
| --- | --- |
| `opt/node` | Windows 补充包和 Linux 补充包均提供 Node.js 16.20.2；含 `node`、`npm`、`npx` |
| `opt/remotion` | Remotion 4.0.538、`@remotion/cli`、React 19.2.3 及生产依赖；`bin/remotion.cmd` 使用相对路径，可在导入后的任意安装目录运行 |
| `opt/python/Lib/site-packages/playwright/driver/node.exe` | Playwright bridge 的驱动 Node。它只负责启动 Playwright 驱动，不替代 `opt/node` |

蛹和舵机启动时会把 `opt/node`、`opt/remotion/bin` 加入 PATH，并注册 `WUNDER_NODE_BIN`、`WUNDER_NPM_BIN`、`WUNDER_REMOTION_ROOT`、`NODE_PATH`；导入补充包后无需手工修改系统 PATH。

## 按任务准备

| 任务 | 必需环境 |
| --- | --- |
| 读取技能、规划视频 | wunder 已挂载 `视频制作` |
| 创建或修改 Remotion 项目 | 补充包的通用 Node/npm/npx，或项目锁文件对应的包管理器；项目本地依赖优先，缺少时可使用 `opt/remotion` 的离线运行时 |
| Studio 预览 | 上述环境 + Python Playwright bridge + Chromium/Chrome/Edge + wunder 的两个浏览器开关 |
| 渲染 MP4/WebM/透明视频 | 上述 Node/Remotion 环境 + 可运行的 Remotion Chromium 渲染器 |
| 媒体探测、转码、抽音频 | `ffmpeg` 与 `ffprobe`；可用 `WUNDER_FFMPEG_BIN`、`WUNDER_FFPROBE_BIN` 指定路径。当前 Windows 7 补充包只提供 `opt/ffmpeg/bin/ffmpeg.exe`，不提供 `ffprobe` |
| Win7 ia32 简单 MP4 交付 | `opt/python` 的 Pillow + `opt/ffmpeg/bin/ffmpeg.exe`；使用 `视频制作/scripts/make_compat_video.py` 先生成 PNG 帧再编码 H.264 |

Windows 和 Linux 补充包均使用 Node 16.20.2，并固定 Remotion 4.0.538、React 19.2.3。项目已有锁文件时优先遵循项目版本。

## wunder 配置

浏览器预览需要同时开启：

```yaml
tools:
  browser:
    enabled: true
browser:
  enabled: true
  provider: playwright
```

浏览器可使用 wunder 补充包中的浏览器，也可配置 `browser.playwright.channel`（如系统 Chrome/Edge）、`executable_path` 或 CDP attach。默认使用受控 headless 浏览器；Studio 仍由项目命令启动并通过 HTTP URL 访问。浏览器工具只允许 `http(s)`，不支持 `file://`。

## 旧系统边界

蛹和舵机主要面向 32 位 Win7 与 Ubuntu 18.04。Linux 补充包使用 Node 16.20.2，并配套对应架构的 Remotion compositor 与 Headless Shell。Remotion 4.0.538 的 CLI 可由 Node 16 启动；当前官方 compositor 由 Ubuntu 22.04 独立环境构建，运行它需要 glibc 2.35，Ubuntu 18.04（glibc 2.27）仍使用技能提供的 Python/FFmpeg 兼容渲染路径。

### 32 位（ia32）渲染器

Remotion 上游只有 `@remotion/compositor-win32-x64-msvc`，因此 ia32 补充包自带一份自编的 `@remotion/compositor-win32-ia32-msvc`，配合 `@esbuild/win32-ia32` 与 renderer 的 ia32 分支，32 位运行时也能完整出片（不再只有 Pillow 路径）。

编译链与 wunder 主程序一致：`nightly-2026-03-14` 的 64 位 host + 内置 target `i686-win7-windows-gnu` + `-Z build-std=std,panic_abort`。产物只依赖 `msvcrt.dll`，没有任何 Win10 时代导入，并已设 `LARGE_ADDRESS_AWARE`（4GB 地址空间）。详细编译流程、补丁与验收记录见 `scripts/win-ia32-compositor/README.md`。

32 位的瓶颈不是 compositor（它稳定在 410–430MB），而是 `ffmpeg.exe` 里的 libx264：线程数按 CPU 数分配，每线程持有全分辨率帧缓冲。实测 4K 在 32 核机器上按默认 48 线程会把 32 位进程的 4GB 地址空间吃穿，编码器直接 OOM，上层报 `EPIPE`。所以注入脚本会给 renderer 加线程上限（≥4K 用 6、≥1440p 用 8），并给 compositor 的帧缓存加上 1.5GB 上限。

实测（同一台 32 核机器，32 位 node + 32 位 compositor + 32 位 ffmpeg）：

| 用例 | 耗时 | ffmpeg 峰值 | 备注 |
| --- | --- | --- | --- |
| 1080p / 10 秒 | 32 s | — | 约 3× 实时 |
| 1080p / 3 分钟 | 243 s | — | 约 1.4× 实时 |
| 1080p / 10 分钟（18000 帧） | 649 s | 1450 MB | 内存不随时长增长 |
| 1440p / 60 秒 | 113 s | 1154 MB | |
| 4K / 10 秒 | 64 s | 2289 MB | |
| 4K / 60 秒（1800 帧） | 249 s | 2289 MB | 与 10 秒时峰值相同 |

使用时注意两点：**32 位 Windows 主机需要 32 位 `node.exe`**（补充包默认的通用运行时是 x64，只能在 64 位 Windows 上跑）；8K 与超长 4K 没有验证，建议分段渲染后拼接。

`scripts/make_compat_video.py` 的 Pillow 帧 + FFmpeg 路径仍然保留，用于不需要 Remotion 组件、只要标题/字幕卡 MP4 的场合，或目标机不方便带 Chrome 的情形。

## 服务版（Docker）

服务版不使用 Windows 补充包。镜像只负责系统级依赖：Node 22 与 npm/npx、`ffmpeg`/`ffprobe`（含 libx264、libvpx-vp9、ProRes、AAC、`drawtext`、`subtitles`）、Playwright Chromium 与 Headless Shell、Chromium 共享库、Noto CJK 与彩色 emoji 字体、`shm_size: 2gb`。npm 镜像源、`NODE_PATH`、`TMPDIR` 等由 `docker-compose-*.yml` 的环境变量提供，Dockerfile 不需要为此改动。

Node/Remotion 运行时不进镜像，由 `config/runtime/` 挂载提供，容器启动时解包到 `/opt/wunder-runtime`。这样升级 Node 或 Remotion 只需重跑生成脚本并重启容器，**不必重建镜像**。

### 运行时包

```
config/runtime/linux-x64/          # 或 linux-arm64
  node.tar.gz                      # Node 官方 Linux 包（符号链接已换成脚本）
  remotion.tar.gz                  # remotion + @remotion/cli + React + 预下载的 Headless Shell
  npm-cache.tar.gz                 # npm 离线缓存：Remotion 全量依赖 + 常用扩展 + 项目侧解析版本
  manifest.env                     # 记录版本与浏览器相对路径
```

生成的默认预取集合（`--extra-deps` 可覆盖）：`mediabunny`、`zod`，以及同版本的 `@remotion/transitions`、`paths`、`shapes`、`layout-utils`、`noise`、`zod-types`、`captions`、`media-utils`、`motion-blur`。缓存按项目安装时的解析方式生成，因此 `npm install mediabunny` 这类不带版本的写法也能离线命中；项目里 `react`/`react-dom` 建议与运行时一致（19.2.3），运行时 bundler 始终使用自身版本。

生成或更新：

```sh
scripts/prepare-node-runtime.sh                            # linux/amd64
scripts/prepare-node-runtime.sh --platform linux/arm64     # linux/arm64
scripts/prepare-node-runtime.sh --remotion 4.0.560 --node 22.22.2
```

脚本在容器内完成下载、安装、浏览器预取与打包，产物直接落到 `config/runtime/<平台>/`。之后重启容器：`docker compose up -d --force-recreate wunder-sandbox`（server 同理）。不需要 build 镜像，也不需要联网重装。

容器启动时 `scripts/docker-rust-entry.sh` 会按包大小指纹判断是否需要重新解包，写入 `/opt/wunder-runtime`，并通过 `/etc/profile.d/wunder-runtime.sh` 注册 `PATH`、`NODE_PATH`、`WUNDER_REMOTION_ROOT`。登录 shell（Linux 上执行命令走 `bash -lc`）因此能找到 `remotion`、`node`、`npm`。

### 容器内运行约定

- 没有额外依赖的项目可直接用 `remotion render <id> <out>`；项目自带 `node_modules` 时用 `npx remotion ...`，优先项目锁定版本。运行时的 `remotion` 包装脚本只在项目既无 Remotion 依赖、也无 `node_modules/.remotion` 时才注入预装浏览器，不会覆盖项目自有版本。
- 输出路径放在 `/workspaces` 之下（挂载卷），否则产物无法被下载或预览。
- `TMPDIR` 与 `NPM_CONFIG_CACHE` 指向 `/workspaces/.cache`。sandbox 容器的 `/tmp` 是内存 tmpfs，渲染中间帧与浏览器临时目录留在 `/tmp` 会挤占容器内存。
- 浏览器仍由 wunder 的 `browser` 工具控制：`browser.deployment = sandbox` 时 Studio 与浏览器 bridge 同在 sandbox 容器，`npx remotion studio --no-open` 给出的本机 URL 可以直接访问。
- 若把 `WUNDER_SANDBOX_DOCKER_READ_ONLY` 打开，`/opt/wunder-runtime` 与 `/etc/profile.d` 不可写，运行时无法解包；需要保留可写层或改用只读挂载点。
- **不要直接把 `node_modules` 目录挂进容器**：Windows/macOS 宿主上大量小文件走文件共享，Remotion CLI 单次启动实测可达 40 秒以上（容器内不足 1 秒）。用运行时包 + 启动解包可避开该问题。
- ARM 使用同一套脚本（`--platform linux/arm64`），Remotion compositor 与 Headless Shell 都有 linux-arm64 构建。已在 qemu 下用 glibc 2.31 的 ARM 载体验证：解包、离线装包、渲染 H.264 均通过。ARM 容器必须带 Chrome 共享库（`libnss3`、`libnspr4`、`libgbm1`、`libasound2` 等），正式镜像由 Dockerfile 的 `playwright install --with-deps` 提供；精简镜像缺库时会报 `Failed to launch the browser process! Closed with 127`。

### 离线

运行时包里已含浏览器、Remotion 依赖与 npm 离线缓存，因此无外网也能创建、预览、渲染项目。项目需要额外依赖时用 `npm install --offline`（缓存里没有的包要在外面用 `--extra-deps` 补进运行时包后再生成一次）。镜像、运行时与前端依赖的完整离线打包与导入流程见 `docs/服务版离线部署.md`。

## 离线部署

离线环境可直接使用补充包的通用 Node/npm/npx 和 `opt/remotion`；项目额外依赖仍需提前准备锁文件与 `node_modules`。同时准备 Playwright Python 包、浏览器二进制、FFmpeg/FFprobe 和字体/媒体素材。没有浏览器时，可以运行命令和关键帧渲染（若渲染器可用），但不能完成 Playwright 交互验收。

## 智能体授权

建议给执行视频任务的智能体授权：`视频制作`、`技能调用`、`执行命令`、`读取文件`、`写入文件`或`文本编辑`。需要打开 Studio 和检查画面时，另外授权 `浏览器`。技能不会绕过后端工具开关、工作区路径或命令执行策略。
